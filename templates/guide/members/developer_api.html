Developer API

Access Parliament data programmatically for personal integrations

1 What is the Developer API?

Parliament includes a REST API that lets you access chapter data programmatically. Whether you want to build a personal dashboard, integrate with home automation, or pull your attendance records into a spreadsheet — the API gives you read-only access to the data you already have permission to see.

Key facts:

  • The API is read-only — you can query data but cannot make changes through it
  • Authentication uses a personal access token — a unique key tied to your account
  • Access is gated behind the rest_api feature flag, which must be enabled by an admin before you can use it
  • You only see data you already have permission to see — the same rules that apply in the app apply in the API

Note: If you do not see a Developer API section in your Preferences, the feature has not been enabled for your chapter yet. Contact your chapter officers or admin.

2 Requesting Your Token

Your personal access token identifies you to the API. Each member has their own token — it is not shared with anyone else. Tokens require you to specify which data types you need access to (scopes), and may require admin approval depending on your chapter's settings.

To request a token:

  1. 1 Go to Preferences → scroll to the Developer API section
  2. 2 Give your token a descriptive name (e.g. "Home Dashboard Script") and select the scopes you need
  3. 3 Optionally describe your intended use, then click "Request Token"
  4. 4 Once active, your token key is shown in the preferences panel — use the copy button and save it somewhere safe

Approval required? Your chapter admin may require manual approval before a token becomes active. If your request shows a Pending status, wait for an admin to approve it — you'll see the token key in preferences once it's approved.

Keep it secret. Treat your API token like a password. Anyone who has it can read your Parliament data on your behalf. Do not paste it into public places, commit it to source code, or share it with others.

3 Available Endpoints

The API is organized into five resource groups. All endpoints are prefixed with /api/v1/.

Endpoint Description
GET /api/v1/members/
GET /api/v1/members/me/ 		Active member directory. Use /me/ to retrieve your own record.
GET /api/v1/events/
GET /api/v1/events/upcoming/ 		Events visible to you. Use /upcoming/ for events in the next 30 days.
GET /api/v1/legislation/
GET /api/v1/legislation/active/ 		Non-removed legislation. Use /active/ for legislation with open votes.
GET /api/v1/committees/
GET /api/v1/committees/mine/ 		Committees visible to you. Use /mine/ to list only committees you belong to.
GET /api/v1/attendance/ Your attendance records only. Filter with ?type= (e.g. excused, present) and ?year=.

4 Making Requests

Include your token in the Authorization header on every request:

Authorization header

Authorization: Token <your-token>

Example curl request

curl -H "Authorization: Token <your-token>" https://am-parliament.org/api/v1/members/me/

Common response codes:

  • 401 Missing or invalid token — double-check your Authorization header
  • 403 The Developer API feature flag is disabled for your chapter — contact your admin
  • 200 Success — the response body contains your data in JSON format

5 Setting Up Your First Integration

Once your token is active, here's how to actually use it. The examples below are the most common starting points — pick the one that matches how you're building.

Storing your token safely

Never hardcode your token directly in a script or file you might share. The standard approach is an environment variable:

Shell / .env file

export PARLIAMENT_TOKEN="your-token-here"

Or in a .env file (never commit this file)

PARLIAMENT_TOKEN=your-token-here

Add .env to your .gitignore before creating it. A token accidentally pushed to a public repo should be revoked immediately.

Python Python script using requests 

import os
import requests

TOKEN = os.environ["PARLIAMENT_TOKEN"]
BASE  = "https://am-parliament.org/api/v1"

headers = {"Authorization": f"Token {TOKEN}"}

# Fetch your own member record
me = requests.get(f"{BASE}/members/me/", headers=headers)
me.raise_for_status()
print(me.json())

# Fetch upcoming events
events = requests.get(f"{BASE}/events/upcoming/", headers=headers)
for event in events.json():
    print(event["title"], event["date_time"])

Install the library first: pip install requests

JS JavaScript / Node.js using fetch 

const TOKEN = process.env.PARLIAMENT_TOKEN;
const BASE  = "https://am-parliament.org/api/v1";

const headers = { "Authorization": `Token ${TOKEN}` };

// Fetch your attendance records
const res = await fetch(`${BASE}/attendance/?year=2026`, { headers });
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const records = await res.json();
console.log(records);

Works in Node 18+ (native fetch) and any modern browser environment.

Shell Shell script with curl and jq 

#!/usr/bin/env bash
# Source your token from a file or set it in the environment
# export PARLIAMENT_TOKEN="your-token-here"

BASE="https://am-parliament.org/api/v1"
AUTH="Authorization: Token $PARLIAMENT_TOKEN"

# Pretty-print active legislation
curl -s -H "$AUTH" "$BASE/legislation/active/" | jq '.[] | {title, status}'

# Save upcoming events to a JSON file
curl -s -H "$AUTH" "$BASE/events/upcoming/" -o upcoming_events.json
echo "Saved to upcoming_events.json"

jq is optional but useful for pretty-printing JSON. Install via brew install jq on macOS.

GUI Postman or similar API clients

  1. 1 Create a new request and set the method to GET
  2. 2 Enter a URL such as https://am-parliament.org/api/v1/members/me/
  3. 3 Go to the Headers tab and add a header:
    Key: Authorization  ·  Value: Token your-token-here
  4. 4 Click Send — you should see a 200 response with JSON in the body

In Postman you can also store the token as a Collection Variable and reference it as Token {{PARLIAMENT_TOKEN}} so you only set it once.

6 Revoking Your Token

If your token is ever compromised or you no longer need API access, you can revoke it immediately.

To revoke your token:

  1. Go to Preferences → Developer API
  2. Click "Revoke Token"
  3. The token is immediately invalidated — any requests using it will receive a 401 response

Tip: After revoking, you can generate a new token at any time from the same page. Revocation is permanent — the old token cannot be restored.
