The activity log already existed and is detail-gated, but the case page led with static fields — and for a case that has moved through several states, "what happened and when" is usually the question being asked. Gated on can_view_report_details, matching the log's existing gate. Appeal and stand-in events appear here too, so the seat history is visible in one place. ⚠️ LAYOUT — WHY FLEXBOX AND NOT `absolute` The first version used the common Tailwind timeline pattern: `
    ` with each dot `absolute -left-1.5`. An absolutely-positioned element resolves against its nearest *positioned* ancestor, which was the `
      ` — not the `
    1. ` it belonged to — so the dots stacked at the top of the list and sat on top of the first entry's text instead of beside each row. This version has no absolute positioning at all. Each row is a flex pair: a fixed-width rail holding the dot and the connecting line, and the content beside it. Nothing can drift, at any font size or zoom level. {% endcomment %} {% if kai_access.can_view_report_details and activity_log %}
