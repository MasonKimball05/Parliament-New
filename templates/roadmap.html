Parliament 3.0 Roadmap

“Parliament becomes self-sustaining.” Real-time, mobile-ready, and operable by the next person without touching the codebase.

Back to Changelog
⚡

Real-Time & Async Infrastructure

The foundation everything else builds on — Celery + Redis

  • Celery + Redis — async email, background jobs, scheduled tasks
  • Scheduled vote open/close — no page load needed to trigger
  • Live vote result updates — counts refresh without a full page reload
  • Async email sending — emails no longer block server threads
  • Scheduled announcements — timezone-aware future posting
📱

Mobile & Push Notifications

Native-feeling app on every member's phone — no app store required

  • Web Push notifications — native alerts even with browser closed
  • PWA install — add to home screen, full-screen launch, app icon
  • Notification types — votes, announcements, Kai updates, attendance
  • Per-device subscriptions — one account, notifications on any device
  • iOS 16.4+ support — works via home screen install (Android works in any browser)
✨

Member Experience Overhaul

Members and officers can use Parliament without asking how it works

  • Slating rework — simplified forms and cleaner voting flow Early
  • Pledge onboarding redesign — welcome emails, progress feedback Early
  • Officer transition tools — guided handoff checklist for outgoing/incoming officers
  • Notification center — bell icon with unread count + push opt-in settings
  • Service hours portal — members view own submissions without asking an officer
🔧

Handoff Readiness

The next person manages Parliament from the UI, not the codebase

  • Self-service admin UI — feature flags, page toggles, and settings in admin without code changes
  • Admin dashboard — at-a-glance chapter health (users, flags, votes, Kai)
  • Automated DB backups — verified offsite backups with failure alerting
  • Staging environment — test migrations safely before they hit production
  • Codebase split — break models.py (5700+ lines) into maintainable sub-apps
