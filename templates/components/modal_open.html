{% comment %} The top half of a modal — v3.21.0. Pair with `components/modal_close.html`: {% include "components/modal_open.html" with modal_id="add-task-modal" title="Add Pledge Task" %} …body… {% include "components/modal_close.html" with modal_id="add-task-modal" submit_label="Add Task" %} ⚠️ WHY A PAIR RATHER THAN ONE INCLUDE. A Django `{% include %}` cannot wrap arbitrary markup — only template inheritance can, and inheritance is one-per-page, so it cannot serve three modals on one dashboard. An open/close pair is the honest way to share the shell. `src/test_modal_component.py` asserts every page has as many opens as closes, because an unbalanced pair is the one failure mode this shape adds. ⚠️ AND WHY IT EXISTS AT ALL: the overflow bug in v3.20.0 was present in all three modals on `education.html` because the shell had been hand-copied three times. The scroll behaviour lives here now, so the next modal cannot be born with it missing. `items-start` + `py-8` + `overflow-y-auto`, not `items-center`: a centred panel taller than the viewport clips at BOTH ends, hiding the title as well as the submit button. Params: `modal_id` (required), `title` (required), `subtitle` (optional). {% endcomment %}
