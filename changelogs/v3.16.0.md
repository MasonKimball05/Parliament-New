**Deployed:** ✅ 07-24-26 — shipped in `9c7c9d1`.
Mason-directed 07-24-26. The Django admin (`/admin/` — the raw-data escape

## Design rules (documented in the module docstring)

- **App-managed records are view-only.** Logs, audit trails, ballots, poll
  responses, and form responses get `ReadOnlyAdmin` (no add/change/delete) —
  editing them in admin would bypass in-app workflows, signals, and integrity
  guarantees. A `ViewDeleteAdmin` variant allows delete-only for prunable
  rows (notification logs, stale push subscriptions, tour progress, email
  verification tokens) and for **WebAuthn credentials — deleting a lost or
  compromised passkey is the deliberate escape hatch here**.
- **Secrets never render:** `APIToken.key` (list shows 8-char prefix),
  `EmailVerificationToken.token`, `PushSubscription.p256dh`/`auth`, and
  WebAuthn key material are all `exclude`d from detail views.
- **Vote integrity:** `SlatingBallot`/`SlatingVote`/`CommitteeVote` and
  poll responses are strictly read-only; `SlatingInterview` is read-only so
  the notes-destruction feature can't be reversed by an admin edit.
  Docstrings warn where anonymity is app-layer only (anonymous polls /
  anonymous committee votes still show identities to admins).
- **Content/config models are fully editable** with sensible list displays,
  filters, and search: CNB governing docs (with Article/Section inlines),
  landing page content, guide tours (step inline), pledge tasks (question
  inline), notification schedules, service/slating/recruitment/kai form
  builders, songs, chat permissions, role history, 2FA requirements.
- ContactSubmission: submitted data immutable, only `is_read` editable.
