## 🟡 Exports wrote member-typed text as spreadsheet formulas

### What was wrong
A spreadsheet program treats a cell that starts with `=`, `+`, `-` or `@` as a
formula. Ten exports wrote cells exactly as stored, and several of those cells
are text a member types:

| Export | Who downloads it | Member-typed columns |
|---|---|---|
| Service hours CSV | VPP, admins | Organization, Description |
| Directory CSV and XLSX | any signed-in member | Phone |
| Poll results CSV | officers | text answers, preferred name |
| Kai reports CSV (both) | Kai reviewers | Title, Description |
| Activity log, audit log, user list, event sign-ups, admin "Export selected" | officers, admins | names, descriptions |

Confirmed with tests on `main` (`da0dd30`): a member saved a formula as a
service-hours description and as their phone number through the normal forms.
The VPP's CSV carried the formula as typed. The directory XLSX stored the phone
as a real formula cell, because openpyxl turns any string starting with `=`
into one.

### What it could do
It depends on the program that opens the file, and that was **not tested**
(no Excel, Numbers or Google Sheets here). In general a formula can read other
cells in the sheet and build a link or a web request out of them. The cells
next to it in these files are members' names, emails and phone numbers.

### Fix
- New `safe_csv_writer` and `csv_safe_cell` in `src/utils/export_utils.py`.
  A text cell that starts with a formula character gets a leading apostrophe,
  so the program shows it as text.
- Left as typed: numbers, dates, and strings made only of digits and phone
  punctuation (`+1 (205) 555-0100`, `-3.5`). With no letters there is nothing
  to call or refer to.
- All ten `csv.writer` calls now use it: `src/admin.py`, `calendar.py`,
  `service_hours.py`, `directory.py`, `admin_v2.py`, `kai_reports.py` (2),
  `officer/announcement_polls.py`, `utils/export_utils.py` (2).
- Directory XLSX: a cell openpyxl would store as a formula is stored as text.
  No apostrophe is needed there.

### Side effect to know
A cell that really does start with `=`, `@`, or `-` followed by letters now
shows a leading `'` in the file (for example a description typed as
`- helped set up`).

## 🟡 Download filenames broke on an em dash, curly apostrophe or quote mark

### What was wrong
Four downloads put a title into the `Content-Disposition` header with an
f-string: chapter minutes PDF, committee minutes PDF, event sign-ups CSV and
the single-event `.ics`.

- A character outside Latin-1 (an em dash, a curly apostrophe, most accented
  letters in the `.ics` case) made Django encode the **whole header** as
  `=?utf-8?b?...?=`. Confirmed with a test: minutes titled
  `Chapter Meeting — Oct 5`.
- A `"` in the title ended the filename early.

Not checked in a browser. A header in that form is not a valid
`Content-Disposition`, so the expected result is a download with the wrong
name, or a PDF opening in the tab when a download was asked for.

### Fix
Those four use Django's `content_disposition_header`, the call `serve_media`
and the songbook views already use.
