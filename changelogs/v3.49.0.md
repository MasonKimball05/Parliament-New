## 🟢 GroupMe bot: announcements are echoed into the chapter's GroupMes

Mason, 10-17-26: "when someone sends an announcement on Parliament a bot echos
it on GroupMe … be able to invite/add the bot to groups on GroupMe and set what
the announcement channel is so in case the groupme group is moved in the future
it can be kept up from the dashboard." Decisions: officers manage it; a
checkbox on the announcement form, on by default; the chapter has a brothers-only
GroupMe and a brothers + pledges GroupMe, and "Visible to" decides which.

### The dashboard: Officers → GroupMe (`/officers/groupme/`)
- **Connect a GroupMe account.** Paste an access token from dev.groupme.com.
  Before saving, it's checked against GroupMe (`/users/me`). It's stored
  encrypted and never shown again. It's only needed to list groups and add or
  move bots, so bots keep posting if it's removed.
- **Channels.** Each channel is one bot in one group, plus who is in that group
  (Brothers / Pledges / Advisors). To add one, pick a group from the connected
  account and Parliament creates the bot there. A bot made by hand on
  dev.groupme.com can be added instead by pasting its ID (no token needed).
- **Move.** When the chapter's GroupMe changes, pick the new group. A new bot is
  made there and the old one is removed. Name, audience, history and the
  announcement form all stay the same.
- Send test (one per 30 s per channel), Edit (name / who / on-off), Remove.
- **Recent posts:** the last 50 posts with result. A failed one has a Retry
  button.
- Every change is a POST and is written to the activity log as
  `settings_changed` ("GroupMe: …").

### The rule: who is allowed to receive what
An announcement goes to a GroupMe only if **everyone in that GroupMe can see it
on Parliament** (`channel.audience ⊆ visible_to`; "visible to everyone" allows
all):

| Visible to | Brothers GroupMe | Brothers + Pledges GroupMe |
|---|---|---|
| Everyone | allowed | allowed, **pre-ticked** |
| Members | allowed, **pre-ticked** | not allowed |
| Pledges only | not allowed | not allowed |

- The form pre-ticks the widest allowed group, so brothers don't get it twice.
  It updates live as "Visible To" changes, and a group that isn't allowed is
  greyed out with the reason.
- The server keeps only allowed groups whatever the browser sends. It checks
  again **when sending**: if "Visible to" was narrowed after the boxes were
  ticked, that group is logged as *skipped* with the reason.

### Sending
- Published now: posted after the save commits (Celery). Scheduled: posted by
  the existing 5-minute `publish_scheduled_announcements` task when it goes
  live. That task also re-queues anything the broker didn't take. No new beat
  entry.
- **At most once per announcement per group.** `groupme_dispatched_at` is
  claimed with `select_for_update(skip_locked)`, and a unique constraint is on
  (announcement, channel). Editing an announcement after it went out does not
  repost it. The edit page shows what was sent where.
- Format: `📢 Title`, the text, then the link to /announcements/, kept under
  GroupMe's 1,000 characters. The text is trimmed with "…" if needed and the
  link is always kept. A setting can make it title + link only.
- Network errors, 429 and 5xx retry at 1, 2 and 4 minutes, then stay *failed*
  with Retry. Any other 4xx fails at once.

### Where to find it (added same day, after Mason couldn't find it)
- **Quick Links** on the home page (default and Modern layouts) and Officer Home: "GroupMe Bot".
  The officer subnav also has "GroupMe". All three show only to people the page allows
  (`ParliamentUser.can_manage_groupme`, which uses the same rule as `officer_required`),
  so advisors on Officer Home don't see a link that would 403.
- **Announcement form:** the GroupMe box used to be hidden entirely until a channel
  existed, so on a fresh install there was nothing to see. It now says "No GroupMe groups
  are connected yet" (or "Every GroupMe group is turned off") with a link to set it up.
  With channels, the box has a "Manage GroupMe groups" link.

### Security notes
- The access token is a GroupMe user's whole account. It's encrypted, sent only
  in the `X-Access-Token` header, never rendered or logged, and **never sent
  when posting**.
- Bot IDs can post as the bot. They're encrypted and shown masked (…ABCD).
- One fixed host (`api.groupme.com`), 10 s timeout, redirects not followed.
- None of the three models are registered in `/admin/`. Comment in
  `admin_extra.py`: if they ever are, `exclude` the token and bot_id.
