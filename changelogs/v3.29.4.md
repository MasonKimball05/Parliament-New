Requested by Mason: a "committee event/meeting" event type that can be
configured to only require/track/push-notify members of that committee,
rather than the whole chapter. Clarified mid-request: if someone outside
the committee signs up for a sign-up-enabled committee event, they should
still be tracked and notified too.

⚠️ **Note on how this landed in git**: a chunk of this work (the model,
migration, form, and the earliest view edits) was already on disk when
Mason committed `4afc446` under the message "v3.29.1" — that commit is
mid-build and incomplete on its own (it's missing `src/admin.py` and
several of the template/view changes below). This changelog describes the
feature as a whole, not just the delta since that commit; see "What's in
this changelog vs. what's already committed" at the bottom.

## New: `Event.committee`

Nullable FK, `on_delete=SET_NULL`. Deliberately independent of the
existing `visible_to` field:

- **`visible_to`** — unchanged — still controls who can *see* the event
  on the calendar.
- **`committee`** — new — controls who is *required*: who counts toward
  the roster on `/officers/attendance/<id>/`, who can submit an excuse
  for it, and who receives its push/email reminders.

These are separate axes on purpose. A committee meeting can still be
visible chapter-wide (the default) so members outside the committee can
see it exists and, if `requires_signup` is also on, opt in — which is
exactly the sign-up scenario Mason described. Set `committee` in the new
"Attendance Tracking" panel field when creating or editing an event
(`EventForm`, `create_event.html`/`edit_event.html`); leave it as
"Chapter-wide (default)" for a normal event.

## `Event.required_members()` — the audience for all three things

```
Chapter-wide event (no committee):  every Active member (unchanged).
Committee event:                    committee.attendance_eligible_members()
                                     UNION confirmed EventSignup rows
                                     (not cancelled, not on the waitlist).
```

An outside member who signs up is tracked and notified exactly like a
committee member would be; someone only on the waitlist is not, since
they aren't confirmed to attend. A committee member who *also* signs up
isn't double-counted (verified with a dedicated test — the union is a
real set operation, not summed counts).

New `Committee.attendance_eligible_members()` on the `Committee` model —
extracted from `edit_committee_minutes`
(`src/view/committee/committee_minutes_editor.py`), which has computed
"this committee's members and chairs, excluding advisors" this exact way
since it was built (Mason pointed this out: "Committee minutes already
tracks attendance for just that committee so it would not be too
difficult to extend it"). `edit_committee_minutes` now calls the shared
method instead of repeating the query inline, so the two attendance
systems can't drift apart on what "a committee's members" means.

## Everywhere `required_members()` now applies

- **`mark_event_attendance`** (`src/view/officer/event_attendance.py`) —
  the roster was unconditionally every Active member; now
  `event.required_members()`. An outsider no longer appears on a
  committee meeting's attendance sheet unless they signed up.
- **`Event.get_attendance_stats()` / `Event.prime_attendance_stats()`** —
  `total_members` was always the full chapter count; a committee event's
  stats (present/absent/excused/unmarked/rate) are now scoped to its own
  roster. The batched page-level version (`prime_attendance_stats`,
  used by `/officers/attendance/`) computes this without an N+1: one
  query per *distinct committee* on the page (not per event — bounded
  and small, same tolerance `_linkable_events` already accepts elsewhere
  in this file) plus one batched sign-up query, combined as real Python
  set unions so nothing is double-counted.
- **`submit_excuse.my_excuses` / `submit_excuse.submit_excuse`**
  (`src/view/submit_excuse.py`) — a committee event no longer appears in
  "Submit New Excuse" for someone outside its required-members set, and
  direct-URL submission is blocked server-side too (new
  `Event.user_is_required()`), not just hidden from the list.
- **`send_event_reminder_pushes`** (`src/tasks/notifications.py`) — push
  and email reminder eligibility for a committee event now comes from
  `required_members()` instead of the chapter-wide `visible_to` filter.
  `visible_to` is deliberately NOT additionally consulted for a
  committee event — `committee` is the intended scoping mechanism here,
  and combining both would mean an outside member who signs up could
  still be silently excluded by a `visible_to` type filter meant for the
  general chapter-wide calendar. Chapter-wide events are completely
  unaffected (verified with a regression test).

## Deliberately NOT touched

- **Calendar visibility** (`Event.is_visible_to_user`) — still governed
  only by `visible_to`. A committee meeting can be visible chapter-wide
  by default; that's what lets an outside member discover it and sign
  up in the first place.
- **`event_signup`** (`src/view/calendar.py`) — unchanged. It already
  doesn't consult `is_visible_to_user`, so it needed no change to let an
  outside member opt into a committee event. (Worth a note for later,
  out of scope here: that view has never checked visibility at all —
  any active member can sign up for any `requires_signup` event by
  hitting the URL directly, committee or not. Pre-existing, not
  introduced by this release, and not something Mason asked to change.)
- **QR self-check-in** — unchanged. Physically checking in at the
  meeting is treated as its own trust boundary regardless of committee
  scoping.

## UI

Committee badges (purple pill, matches the existing feature-area color
elsewhere in the admin) added next to the event title on
`mark_event_attendance.html`, `event_attendance_list.html` (all four
desktop/mobile × upcoming/past spots), and `review_excuses.html`, so an
officer can see at a glance which events are committee-scoped.
`select_related('committee')` added to the relevant querysets so this
costs nothing extra.

`/admin/` — `committee` added to `EventAdmin`'s `list_display`,
`list_filter`, and the "Attendance Tracking" fieldset.
