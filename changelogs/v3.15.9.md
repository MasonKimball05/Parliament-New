# v3.15.9 — backlog batch: CSP script fix (the big one), plurality bars, failed-login signal

Mason-directed session 07-23-26, from the Parliament-Feature-Ideas backlog. No
migration, no new deps, no collectstatic (vendored chart.min.js already ships).

## 🔴-adjacent find: CSP was silently killing scripts on 6 pages in prod

Prod CSP is `script-src 'self' 'nonce-…'` (no `unsafe-inline`, no CDNs). Six
templates had inline `<script>` blocks with **no nonce**, and chapter-stats
additionally loaded Chart.js from **cdnjs** — all blocked in production, while
dev (DEBUG=True sends no CSP header) worked fine. Casualties:

- **`officer/chapter_stats.html`** — the attendance + voting Chart.js charts
  (the backlog's "add charts" item) were already fully implemented but have
  never rendered in prod. Fixed: `{% static 'vendor/chart.min.js' %}` (v3.9.1,
  feature-compatible with the chart code) + nonce.
- **`committee/candidate_list.html` (×2)** — the inline candidate status-badge
  popover (another backlog item) was also already implemented and also dead in
  prod. Nonce added; the feature now actually works.
- **`committee/education.html`, `committee/recruitment_event_detail.html`,
  `committee/manage_recruitment_permissions.html`,
  `officer/transition_checklist.html`** — nonce added.
- `admin/base_site.html` left alone (Django admin path is CSP-exempt).

Grep-verified: zero bare `<script>` tags remain outside the admin exemption.
**Lesson for future reviews: any inline script without
`nonce="{{ request.csp_nonce }}"` is dead code in production**, and dev will
never show it.

## Plurality vote results — per-option bars (both result pages)

Pie slices are hard to compare in close races. Both `vote_result.html`
(chapter) and `committee/vote_result.html` now render horizontal per-option
bars above the chart: count + % of selections, width relative to the leader
(so near-ties stay visibly close), winner highlighted green. Computed in
`end_vote.py` / `committee/vote_result.py` (`plurality_bars`). On the
committee page this replaces the old legend row, whose per-option color
expression evaluated to the same blue for every option anyway.

## Profile — failed-login signal (completes "Recent Account Activity")

The v3.15.0 recent-logins card only showed successful logins. The profile now
also surfaces **failed/blocked attempts from the last 30 days** (count +
latest timestamp/city, amber warning box; quiet "none" line otherwise), so a
member can catch password guessing against their account themselves. No raw
IPs exposed; one extra indexed query.
