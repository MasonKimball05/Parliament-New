## Formerly v3.71.0 (`8f65583`)

### 🟢 Timed location check-in and study hours (VP of Education's request, 10-30-26)

Rules in `src/location_time.py`. Built on location check-in (v3.60.0): the
area, distance and accuracy checks, and the check-in key, are the same.

#### Minimum stay
- An attendance event can require time at the event (`Event.checkin_min_minutes`:
  15 minutes to 2 hours) instead of just arriving.
- The member is marked present once their total time inside the area reaches it.
  Visits add up, so stepping out briefly is fine.
- The same rule as a location check-in applies: only a missing or pending
  attendance row is filled, so an officer's marking stays as it was.
- The window is unchanged: an hour before the start until three hours after.

#### Study hours
- A study hours event (`Event.is_study_hours`) counts the time members spend
  inside its area, from the start for as long as it lasts (`duration_minutes`,
  1 to 12 hours).
- It's a length rather than an end time, so a recurring series carries it to
  every occurrence. It takes no attendance.
- Members can be given a weekly study hours requirement (`StudyHoursRequirement`).

#### How time is counted
- The app reports arriving (a position, checked as before) and leaving (`POST
  events/<id>/checkin/location/leave/`, with the same key).
- It uses iOS geofence enter and exit events, which need "Always" location
  access. With "While using", it reports what it sees each time the app is opened.
- A visit whose "left" never arrives (phone off, no signal) stops counting when
  the window ends, and is marked "didn't report leaving" for officers to check.
- A Celery job every two minutes (`tasks.location_time_tick`) credits members who
  reach the minimum while still inside, and closes those visits.

#### Manual changes
- Add or remove minutes, always with a reason (`LocationTimeAdjustment`, and
  logged).
- Who can: officers and chairs, the education committee's chairs, and members
  given the new **Time** permission (`EducationMemberPermission.can_adjust_time`)
  on the education permissions page.

#### Website
- The event form's location check-in section gains "Time needed at the event",
  "Study hours" and "Study hours last".
- `/officers/events/<id>/time/` (Time & adjustments): everyone's time, each visit,
  and the adjustments. It can add or remove time for anyone, including a member
  whose phone didn't count it. It's linked from the attendance page of a
  minimum-stay event.
- `/committee/<code>/education/study-hours/`: the week's study hours per member
  against their requirement (previous and next week), setting requirements, and
  the week's study hours events. It's linked from the Education dashboard.
- A pledge's My Tasks page shows this week's study hours against their requirement.

#### App API
- `events/checkin-areas/` includes study hours events, plus `timed`,
  `min_minutes`, `study_hours`, `inside` and `minutes` for each.
- `events/<id>/` gains `timed_checkin`: the member's minutes, whether they're
  inside, and the Time & adjustments link for those who may adjust.
- The education pledge detail (`committees/<code>/education/pledges/<pk>/`) gains
  `study`.

#### Tests
- `src/tests/mobile/test_location_time.py` (13).

## Fix: slating CSV import's Continue did nothing

Reported by Mason: on **Import Applications**, choosing the CSV and pressing
Continue left the page as it was, with no error.

**Cause.** core.js's CSRF guard takes over every POST form that holds a file
input: it refreshes the token, then resends the form with `fetch()` (the
v3.29.30 Safari fix). It follows a redirect but otherwise stays put. The
upload step doesn't redirect; it answers with step 2 (match the columns), so
that page was thrown away.

**Fix.** The file input now sits outside the form. Choosing a file reads it in
the browser (UTF-8, falling back to Windows-1252 as the server's `decode()`
does) into a hidden `csv_text` field and enables Continue, so the form posts
natively like any other. `import_applications` takes `csv_text` on the upload
step and still takes a `csv_file` upload. The 2 MB limit is checked in the
page and again in `parse_csv()`.

Any other file form whose POST renders a page instead of redirecting would
fail the same way.

**Test:** `test_the_page_posts_the_files_text`: the form holds no file input,
the posted text reaches the column step (BOM stripped), and blank text is
refused.

## Fix: file-upload forms with a mistake in them did nothing on submit

Follow-up to the slating import fix: every POST form with a file input was
checked for the same failure.

**Audit.** 25 templates hold a file input or a multipart form. Two are not
resent by core.js: `slating/import_applications.html` (fixed above) and
`user_list.html` (its CSV input sits outside any form; the page sends it
itself). Every other view **redirects on success**, so none needed the
`csv_text` treatment: bug report, feedback, committee vote / upload /
replace, chapter document upload, legislation upload / edit / new version /
drafts / add passed, Kai report and commendation, officer report upload,
passed resolutions, landing page (photo and content), profile picture,
service hours submit / edit, slating apply, songbook, excuse.

**What was broken.** The error side. Eight views re-rendered an invalid form
with its errors shown only beside the fields and queued no message:
`song_create`, `song_edit`, `create_resolution`, `edit_resolution`,
`submit_service_hours`, `edit_service_submission`, `submit_kai_report` and
`submit_kai_commendation`. core.js only shows the queued messages from that
response, so the member pressed Submit and nothing happened. A missing date
on a service hours form, for one.

**Fix.**
- `src/utils/form_messages.py`'s `queue_form_errors(request, form)` turns
  each form error into an error message ("Song Title: This field is
  required."). The eight views call it when the form is invalid.
- `JsResubmitEnvelopeMiddleware` adds "Your submission was not saved. Please
  check the form and try again." when a view re-renders in place and queues
  nothing, so a future form that forgets can't fail silently.

**Tests** (`src/tests/security/test_js_resubmit_envelope.py`):
`FormErrorsReachTheEnvelopeTests` posts an invalid form to each of the
eight views with the resubmit header and checks the field's error comes
back; `SilentRenderFallbackTests` checks the fallback message, and that a
redirect gets none.

## Slating import: fix an application's positions, time and GPA on the preview

Reported by Mason: the import preview flagged problems ("Couldn't read the
timestamp", "Unrecognised position text: "Recruitment brotherhood"", "No
positions matched") with no way to fix them except editing the CSV.

- **Google Forms timestamps.** Its export writes "2026/10/06 9:31:59 AM EST",
  which `parse_timestamp` didn't know, so every response was dated "now". It
  now reads 12-hour times, `YYYY/MM/DD` dates and a trailing zone (EST/EDT,
  CST/CDT, MST/MDT, PST/PDT, AKST/AKDT, HST, UTC/GMT, or `GMT-5`). Without a
  zone the time is the site's local time, as before. An unknown zone still
  warns.
- **Fix this application.** Each applicant on the preview has a box to set
  the submitted time, the GPA, and each position's choice (1st, 2nd, 3rd,
  Does not want, or none). *Update preview* shows the result; a fixed
  problem's warning goes away and the row says "Fixed by hand: …".
  Applications with notes start open.
  - Each control posts its value beside the CSV's (`fix_<member>_…` /
    `was_<member>_…`), and only a change counts. Remapping a column and
    previewing again still re-reads the CSV, and the import, which re-plans
    from the POST, applies exactly what the preview showed
    (`slating_import._apply_fixes`).
  - The imported application's review notes say what was set by hand.
  - Other answers are still corrected after the import with *Fill in
    answers*.

**Tests** (`src/tests/slating/test_import_applications.py`):
`TimestampTests` (Google Forms, other zones, unknown zone), and
`FixOnPreviewTests` (the controls render; unchanged controls change nothing;
fixes clear the warnings and are imported with a note; a remapped column is
read again).

## Slating import: choose who a row is, several files, undo an import

Mason (10-30-26), after a real import: six rows were skipped as "No
Parliament member matches" with no way to fix them, and there was no way to
manage more than one upload or take an import back.

**Choose who a row is.** Every row on the preview has a picker: *Match from
the CSV*, *Don't import this row*, likely matches, then every active member.
Unmatched and ambiguous rows offer it in the Skipped list; an imported
application has one per row it was built from. A row tied by hand is noted in
the application's review notes. Pickers post `who_<row>` and the import
re-plans with the same POST, like the other preview fixes.

**Better name matching** (`_NameMatcher`): the full name or preferred name +
last name exactly, then first + last ignoring middle names and initials
("Robert Alden Campbell", "Sawyer W. Guffey"). A first + last match shows a
warning to check it. When nothing matches, members with the same last name
are offered first.

**Several files.** Step 1 takes several CSVs at once and step 2 lists them,
with *Remove* on each and *Add more files*. Columns line up by question
(ignoring case and punctuation); rows are labelled with their file ("Treasurer.csv
row 3"). Column choices are kept by column name when a file is added or
removed (`colhead_<n>`).

**Undo an import.** The import page lists *Earlier imports*, grouped by
import, with *Remove this import* and *Remove* per application
(`remove_imported_applications`, POST only, same managers as the import).
Only imported applications, and only while still submitted or under review
with no interview and not slated; others are kept and named. Logged to
SlatingActivity and ActivityLog. A member who was already imported is now
skipped with "remove that application under Earlier imports" rather than
"already has an application".

**View the response.** Every row on the preview, imported or skipped, has
*View the response*: each question and answer exactly as submitted (one per
form for a combined application), beside what the application will contain.
Imported applications say *View application* on their row.

**Tests:** `TieRowsToMembersTests`, `SeveralFilesTests`, `RemoveImportTests`,
`ViewTheResponseTests` (11 new); existing import tests updated for the row
labels.
