## 💡 A poll response can now be edited while the poll is open

### What "multiple responses" turned out to mean, and what it deliberately doesn't

`AnnouncementPollResponse` already enforced exactly one response row per
(poll, respondent) via a DB-level `unique_together` constraint, and
`take_poll` flatly refused a second submission. That's unchanged — the
constraint is still there, still DB-enforced. What changed is that a second
submission now **updates** that same row's answers instead of being turned
away.

This was a deliberate scope decision, not an oversight: relaxing the
constraint to allow several rows per person would have forced a redesign of
everything downstream that assumes "one response row = one person's current
answer" — `poll_results`' respondent count, the anonymous-poll reveal
threshold (`anon_threshold_met = respondent_count > 2`), the non-respondent
list, and the CSV export. None of that had to change.

Also unchanged, and already present before this release: a `'multiple'`
question already let a member check more than one box (`AnnouncementPollAnswer
.selected_options` is a many-to-many, not a single choice) — that's a
different kind of "multiple" than what was asked for here, and it needed no
work.

### What changed

- **`src/models/announcements.py`** — `AnnouncementPollResponse` gets a new
  `updated_at` field. Deliberately **not** `auto_now` — it stays `null`
  until a response is actually edited, so "was this ever changed" is an
  exact fact (`updated_at is not None`) rather than a timestamp-comparison
  guess against `submitted_at` (two independent field-level "now" calls at
  creation time aren't guaranteed to land on the same microsecond).
- **`src/view/officer/announcement_polls.py`** (`take_poll`) — on a second
  POST from a respondent, while the poll is still accepting responses:
  deletes that response's existing `AnnouncementPollAnswer` rows, rebuilds
  them from the new submission, and sets `updated_at`. No new
  `AnnouncementPollResponse` row is created. On GET, a respondent who
  already answered gets the same form back — pre-filled with their previous
  picks (radio/checkbox `checked`, textarea text) — instead of a static
  "thanks" card, with a banner explaining they're editing and an "Update
  Response" button in place of "Submit Response". Editing stops the moment
  the poll closes, exactly like first-time submission — there is no path to
  changing an answer after `is_accepting_responses()` goes false; a
  respondent who answered before close still sees the same closed card
  everyone else does, now noting their answer was recorded before it closed.
- **`templates/announcement_poll.html`** — reworked accordingly: the
  "already responded, nothing else to do" static card is gone for open
  polls (replaced by the editable, pre-filled form); it's kept for closed
  polls, with updated copy.
- **`templates/announcements.html`** — the inline "Poll completed — Title"
  badge on each announcement is now a link back into `take_poll` (labelled
  "(edit)") when the poll is still open, so editing is reachable from where
  members already encounter polls day to day, not just from the new page
  below.

## 💡 New page: Polls (open and closed)

There was no page listing polls a member could actually answer — only the
per-announcement inline block, one poll at a time, and a "My Work → Polls &
Surveys" tab that lists polls *you created* (officer-only), not polls you
can answer.

- **New `polls_view`** (`/polls/`, URL name `polls_view`) — lists every poll
  attached to an announcement the member can see, split into **Open** (still
  accepting responses) and **Closed**, each row showing which announcement
  it's from, a Responded / Not yet answered badge, and — for open polls — a
  Take Poll / Edit Response button straight into `take_poll`.
- **Visibility is identical to the announcements page**, on purpose: same
  `is_active` / `publish_at` / `visible_to_q(member_type)` filtering
  `announcements_view` already uses, so this page can never show a poll a
  member couldn't already reach by opening its announcement. One query for
  the announcements+polls, one batched query for "have I responded" across
  all of them — same shape as `announcements_view`'s own
  `responded_poll_ids`, not a query per poll.
- **Linked from the Announcements page header** ("View All Polls", visible
  to everyone, next to the officer-only New/Manage buttons) — both so it's
  actually discoverable and so `src/tests/guards/test_reachable_pages.py`
  doesn't (correctly) flag it as a page nobody can click to.

### Tests

- **`src/tests/announcements/test_take_poll_ui.py`** — two pre-existing
  tests asserted the OLD refuse-on-resubmit behavior and were rewritten
  rather than left to rot: `test_already_responded_shows_confirmation_card_
  not_the_form` → `test_already_responded_on_an_open_poll_shows_the_
  editable_form_prefilled` (asserts the previously-picked option renders
  `checked` and the other option in the same question doesn't); `test_
  double_submission_is_rejected` → `test_resubmitting_updates_the_existing_
  response_rather_than_duplicating` (still asserts exactly one response row
  — that invariant didn't change — but now also asserts the row's answer
  actually changed and `updated_at` got set). Added a new closed-poll +
  already-responded case for the branch that's genuinely unchanged.
- **New `src/tests/announcements/test_polls_view.py`** (9 tests) — open vs.
  closed placement (including a poll closed by `closes_at` rather than
  `is_open`), responded/not-yet badges and the edit link, and every
  visibility boundary the page must respect: no poll → not listed, inactive
  announcement → not listed, not-yet-published (`publish_at` in the future)
  → not listed, scoped to a different member type (`visible_to=['Advisor']`)
  → hidden from a Member, and that the rendered Take Poll link is the real
  working `take_poll` URL, not just present-looking text.
