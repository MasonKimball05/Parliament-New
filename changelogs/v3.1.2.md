# v3.1.2 — CSP `unsafe-inline` Removal

**Release Date:** June 6, 2026

**Deployment Status:** Deployed

**Type:** Security

---

## Overview

Completes the multi-session inline event handler migration. Every `onclick=`, `onchange=`, `onsubmit=`, and `oninput=` attribute has been removed from all templates and replaced with `addEventListener` calls inside nonced `<script>` blocks. With no remaining inline handlers anywhere in the codebase, `'unsafe-inline'` is dropped from `script-src` in the Content Security Policy.

**Before:** `script-src 'self' 'nonce-{nonce}' 'unsafe-inline'`
**After:** `script-src 'self' 'nonce-{nonce}'`

---

## What Changed

### CSP `script-src` — Remove `'unsafe-inline'` (`src/middleware/security.py`)

The `'unsafe-inline'` keyword has been removed from the `script-src` directive. The browser now blocks any script that does not carry the per-request nonce — including injected scripts that bypass input sanitization, stored XSS payloads, and reflected values.

Context: when a nonce is present, CSP2+ browsers already ignore `'unsafe-inline'` for `<script>` blocks. The real reason `'unsafe-inline'` had to stay was inline event handlers (`onclick=`, `onchange=`, etc.), which the nonce spec explicitly does not cover. Those have now all been removed.

`style-src` retains `'unsafe-inline'` — inline `style=` attributes are used throughout the templates (Alpine.js, Tailwind dynamic widths) and cannot be nonced. Inline styles cannot execute code.

## Security Fixes

### Contact Form Rate Limiting (`src/view/landing.py`)

`contact_submit` now enforces a limit of 5 submissions per IP per 10 minutes using the Django cache backend. Exceeding the limit returns HTTP 429. This prevents an attacker from flooding officer email addresses by hitting the endpoint in a tight loop. Uses the same cache pattern as `PasswordResetRateLimitMiddleware`.

---

## Performance Fixes

### N+1 in `passed_legislation.py` — High Priority

Replaced per-legislation `Vote.objects.filter(legislation=leg).count()` calls (yes, no, abstain, total — 3–4 queries per item) with a single annotated queryset before the loop. A 20-item page now issues ~1 query instead of 60–80.

### N+1 in `kai_reports.py` — Medium Priority

Two per-category `.count()` loops (~14 queries for ~7 categories) replaced by one `values('category').annotate(total=Count('id'))` aggregation. Both `category_counts` and `category_data` are now derived from the same result dict.

### Per-IP DB Lookups in Admin User Security View — Medium Priority

Batch `IPWhitelist` and `IPBlacklist` lookups: collect all unique IPs first, then two `__in` queries, then check set membership in the loop. Eliminates 2N DB hits for a user with N distinct login IPs.

### Celery Dashboard Triple Query — Low Priority

`PeriodicTask` queryset evaluated once with `list()`. `task_count` uses `len()`, `disabled_count` uses a sum comprehension — down from three separate DB round-trips on every admin dashboard load.

### Feature Flag Loop Double Query — Low Priority

Feature flags grouped in one `order_by('category', 'name')` query + Python `setdefault` dict, replacing two queries (`.filter()` + `.exists()`) per category.

### Double Query in `calendar.py` — Low Priority

`AttendanceExcuse` lookup consolidated to a single `.first()` call; `has_excuse` derived from `excuse is not None`.

## Breaking Changes

None. All behaviour is preserved — confirm dialogs still fire, toggles still toggle, filters still navigate. The only change is that the browser now enforces the nonce boundary on every script.
