# v3.1.2 — CSP `unsafe-inline` Removal

**Release Date:** June 6, 2026

**Deployment Status:** Pending

**Type:** Security

---

## Overview

Completes the multi-session inline event handler migration. Every `onclick=`, `onchange=`, `onsubmit=`, and `oninput=` attribute has been removed from all templates and replaced with `addEventListener` calls inside nonced `<script>` blocks. With no remaining inline handlers anywhere in the codebase, `'unsafe-inline'` is dropped from `script-src` in the Content Security Policy.

**Before:** `script-src 'self' 'nonce-{nonce}' 'unsafe-inline'`
**After:** `script-src 'self' 'nonce-{nonce}'`

---

## What Changed

### CSP `script-src` — Remove `'unsafe-inline'` (`src/middleware/security.py`)

The `'unsafe-inline'` keyword has been removed from the `script-src` directive. The browser now blocks any script that does not carry the per-request nonce — including injected scripts that bypass input sanitization, stored XSS payloads, and reflected values.

Context: when a nonce is present, CSP2+ browsers already ignore `'unsafe-inline'` for `<script>` blocks. The real reason `'unsafe-inline'` had to stay was inline event handlers (`onclick=`, `onchange=`, etc.), which the nonce spec explicitly does not cover. Those have now all been removed.

`style-src` retains `'unsafe-inline'` — inline `style=` attributes are used throughout the templates (Alpine.js, Tailwind dynamic widths) and cannot be nonced. Inline styles cannot execute code.

## Breaking Changes

None. All behaviour is preserved — confirm dialogs still fire, toggles still toggle, filters still navigate. The only change is that the browser now enforces the nonce boundary on every script.

---

## Deployment Notes

No migration required. No new dependencies.

```
git pull origin main
python manage.py collectstatic --noinput
systemctl restart parliament-gunicorn
```

Purge Cloudflare cache after deploying — the updated `security.py` affects every response's `Content-Security-Policy` header.
