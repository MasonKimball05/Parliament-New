## Overview

This release addresses a gradual memory leak issue where RAM usage was steadily increasing over time (from 70% to 84% over 14 days). A comprehensive investigation identified several sources of memory growth and implements fixes to prevent future accumulation. This release also adds new management commands for monitoring and maintaining server health.

## Problem Analysis

### Root Causes Identified

1. **PerformanceMiddleware Memory Accumulation**
   - Was storing 1,000 request records per Gunicorn worker in a global list
   - Each record included full request paths (variable-length strings)
   - With 2 workers, this meant 2,000+ records persisting in memory

2. **Feature Flags Context Processor**
   - Queried database on every single request without caching
   - Created new QuerySet objects on each request

3. **Gunicorn Worker Lifecycle**
   - Workers recycled every 1,000 requests (too infrequent)
   - No cleanup hooks on worker exit
   - No periodic garbage collection

4. **LocMemCache Configuration**
   - 5,000 max entries per worker process
   - No timeout set, entries never expired automatically
   - Each Gunicorn worker had its own cache

5. **Logging Configuration**
   - Using `FileHandler` instead of `RotatingFileHandler`
   - Log files could grow unbounded

6. **No Automated Cleanup**
   - Expired sessions accumulating in database
   - Old login history, notifications, and activity logs never cleaned

## Fixes Implemented

### 1. PerformanceMiddleware Optimization

Reduced stored request records from 1,000 to 100 per worker.

**File:** `src/middleware/performance.py`
```python
# Before
'max_stored': 1000

# After
'max_stored': 100  # Reduced to prevent memory growth
```

---

### 2. Feature Flags Caching

Added 60-second caching to the feature flags context processor to eliminate database queries on every request.

**File:** `src/context_processors.py`
```python
def feature_flags(request):
    from django.core.cache import cache

    cache_key = 'context_feature_flags'
    cached_data = cache.get(cache_key)
    if cached_data is not None:
        return cached_data

    # ... fetch from database ...

    cache.set(cache_key, result, 60)  # Cache for 60 seconds
    return result
```

---

### 3. Gunicorn Worker Lifecycle Improvements

**File:** `gunicorn_config.py`

| Setting | Before | After |
|---------|--------|-------|
| `max_requests` | 1000 | 500 |

**New Hooks Added:**

- `child_exit()` - Closes database connections and clears cache when worker exits
- `worker_exit()` - Forces garbage collection on worker exit
- `post_request()` - Runs garbage collection every 50 requests and clears old performance metrics

```python
def post_request(worker, req, environ, resp):
    """Called after a worker processes a request"""
    if hasattr(worker, 'request_count'):
        worker.request_count += 1
    else:
        worker.request_count = 1

    # Every 50 requests, run garbage collection
    if worker.request_count % 50 == 0:
        gc.collect()
        clear_old_metrics()
```

---

### 4. LocMemCache Optimization

**File:** `Parliament/settings_postgres.py`

| Setting | Before | After |
|---------|--------|-------|
| `MAX_ENTRIES` | 5000 | 1000 |
| `TIMEOUT` | None | 300 (5 min) |
| `CULL_FREQUENCY` | Default | 3 (remove 1/3 when full) |

Also added database sessions fallback when Redis is unavailable:
```python
SESSION_ENGINE = 'django.contrib.sessions.backends.db'
```

---

### 5. Rotating Log Files

Changed from `FileHandler` to `RotatingFileHandler` to prevent log file growth.

**File:** `Parliament/settings_postgres.py`
```python
'handlers': {
    'file': {
        'class': 'logging.handlers.RotatingFileHandler',
        'maxBytes': 10 * 1024 * 1024,  # 10 MB per file
        'backupCount': 3,  # Keep 3 old log files
        'encoding': 'utf-8',
    },
},
```

## New Management Commands

### 1. `cleanup_sessions` - Comprehensive Cleanup

Cleans up expired data to prevent database/memory bloat.

**Usage:**
```bash
python manage.py cleanup_sessions
```

**What It Cleans:**
- Expired Django sessions
- Old read notifications (90+ days)
- Old activity logs (180+ days)
- Old login history (90+ days)
- Resolved login alerts (30+ days)
- Performance middleware metrics
- Django cache

**Also Runs:**
- Garbage collection
- PostgreSQL VACUUM ANALYZE

---

### 2. `memory_report` - Memory Diagnostics

Generates a comprehensive memory usage report for diagnostics.

**Usage:**
```bash
python manage.py memory_report
python manage.py memory_report --detailed
python manage.py memory_report --gc  # Run GC first
```

**Report Includes:**
1. Process memory usage (RSS, VMS)
2. System memory status
3. Database statistics (table sizes, connections)
4. Cache statistics
5. Session statistics
6. Log file sizes
7. Performance middleware status
8. Garbage collection stats (with --detailed)
9. Object counts by type (with --detailed)
10. Optimization recommendations

---

### 3. `server_maintenance.sh` - Automated Maintenance Script

Shell script for automated daily maintenance.

**Location:** `shell/server_maintenance.sh`

**What It Does:**
1. Runs `cleanup_sessions` command
2. Runs Django's `clearsessions`
3. Compresses old log files
4. Reports current memory status
5. Restarts Gunicorn if memory > 85%

**Cron Setup:**
```bash
# Run at 3 AM daily
0 3 * * * /var/www/Parliament-New/shell/server_maintenance.sh >> /var/log/parliament-maintenance.log 2>&1
```

## Deployment Instructions

### 1. Deploy Code Changes

```bash
cd /var/www/Parliament-New
git pull origin main
```

### 2. Restart Gunicorn

```bash
sudo systemctl restart gunicorn
# or
sudo systemctl restart parliament
```

### 3. Run Initial Cleanup

```bash
source .venv/bin/activate
python manage.py cleanup_sessions
python manage.py clearsessions
```

### 4. Verify Memory Status

```bash
python manage.py memory_report
free -m
```

### 5. Set Up Daily Cron Job

```bash
crontab -e
# Add this line:
0 3 * * * /var/www/Parliament-New/shell/server_maintenance.sh >> /var/log/parliament-maintenance.log 2>&1
```

### 6. (Recommended) Install Redis

For production environments, Redis is strongly recommended:

```bash
# Ubuntu/Debian
sudo apt install redis-server
sudo systemctl enable redis-server
sudo systemctl start redis-server

# Add to .env
echo "REDIS_URL=redis://localhost:6379/0" >> .env

# Restart Gunicorn
sudo systemctl restart gunicorn
```
