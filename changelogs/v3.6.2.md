# v3.6.2 — Onboarding Integration & Alpine.js

**Release Date:** June 14, 2026
**Deployment Status:** 🔲 Not Deployed
**Type:** Bug Fix

---

## Overview

Completes the onboarding feature introduced in v3.6.0/v3.6.1. The templates and view logic were in place but none of the integration wiring was connected — model fields, URL routes, login redirect, middleware exemptions, and AJAX support were all missing. This version closes every integration gap and resolves the Alpine.js asset blocker that made the wizard non-functional on first login.

---

## What Changed

### 1. Model Fields Added

`ParliamentUser` was missing `onboarding_complete` and `onboarding_data`, which are required by migration 0207 and every view and template in the onboarding flow. Both fields are now declared in `src/models/users.py`, making the migration safe to apply.

**Changed:** `src/models/users.py`

### 2. URL Routes Wired

`src/urls.py` had no onboarding routes. Added imports and six paths:

- `/onboarding/` → `onboarding_view`
- `/onboarding/complete/` → `onboarding_complete_view`
- `/onboarding/page-visited/` → `mark_page_visited`
- `/onboarding/dismiss-checklist/` → `dismiss_checklist`
- `/onboarding/skip-profile-item/` → `skip_profile_item`
- `/onboarding/reset/` → `reset_onboarding`

**Changed:** `src/urls.py`

### 3. Login Redirect

`login_view` now redirects to `/onboarding/` when `not user.onboarding_complete`, setting `session['in_onboarding']` to thread the wizard's multi-page flow without triggering the grandfather check.

**Changed:** `src/view/login_view.py`

### 4. Forced Password Change Redirect

After a successful password change during onboarding, `forced_password_change` now redirects to `/onboarding/?step=passkey` instead of home when `in_onboarding` is set in the session.

**Changed:** `src/view/forced_password_change.py`

### 5. Middleware Exemptions

`ForcePasswordChangeMiddleware` now exempts `/onboarding/` and `/set-email/` so new users can complete the wizard steps without being looped back to the password change page.

**Changed:** `src/middleware/security.py`

### 6. AJAX Support in `set_email`

The wizard's email step submits via `fetch()` with `X-Requested-With: XMLHttpRequest`. `set_email` previously only returned redirects. All four code paths (empty input, first-time set, address taken, send confirmation) now return `{"success": true/false, "message": "..."}` JSON when the request is AJAX.

**Changed:** `src/view/set_email.py`

### 7. Template Wiring

- Onboarding checklist included in `home_modern.html` and `home_classic.html` (the home view never renders `home.html`)
- Profile progress bar and page guide included in `profile.html` and `preferences.html`
- Page guides wired into all 9 remaining target pages: `announcements.html`, `vote.html`, `my_excuses.html`, `calendar.html`, `directory.html`, `chapter_documents.html`, `chat/index.html`, `service_hours/user_dashboard.html`, `committee/committee_index.html`
- `onboarding_page_seen` filter added to `custom_filters.py`
- "Restart Onboarding Tour" button added to Preferences

**Changed:** `templates/home_modern.html`, `templates/home_classic.html`, `templates/profile.html`, `templates/preferences.html`, all 9 page templates, `src/templatetags/custom_filters.py`

### 8. Alpine.js Asset + `x-cloak` CSS

`static/js/alpinejs.min.js` did not exist — both `wizard.html` and the checklist component depend on it. Added Alpine 3.14.3 (self-hosted, 44KB). Also added `[x-cloak]{display:none!important}` to both `base.html` and `wizard.html` so Alpine's pre-init hide behavior actually takes effect (without the CSS rule, `x-cloak` is a no-op and all wizard steps render stacked simultaneously before Alpine loads).

**Changed:** `static/js/alpinejs.min.js` (new), `templates/base.html`, `templates/onboarding/wizard.html`

---

## Deployment Notes

- Migration 0207 (`0207_user_onboarding_fields.py`) is now safe to apply — the model fields it requires are present. Apply it before deploying this version.
- `collectstatic` required — new `alpinejs.min.js` static asset.
- Cloudflare cache purge required after `collectstatic` (template changes + new JS file).
- Existing members are grandfathered automatically by the migration's `RunPython` step: users with `has_default_password=False` and an email set are marked `onboarding_complete=True` with all pages pre-visited.
