## Overview

This release introduces three major interconnected systems that significantly enhance Parliament's functionality and administrative capabilities:

1. **Calendar Subscription System** - Auto-updating calendar feeds that sync with external calendar apps
2. **Admin v2** - Advanced administration dashboard with dual authentication and comprehensive site controls
3. **Feature Flags System** - Granular control over site features and pages without code changes

These features provide users with better calendar integration, give administrators powerful tools for site management, and establish a foundation for controlled feature rollouts.

## Key Features

### 1. Calendar Subscription System

#### Overview
Users can now subscribe to their personal Parliament event calendar in external calendar applications (Google Calendar, Apple Calendar, Outlook, etc.). The subscription automatically updates when events are added, modified, or removed, eliminating the need for manual calendar exports.

#### Features

**Auto-Updating Feeds**
- Calendar apps poll the subscription feed periodically
- Changes to events (add/edit/delete) automatically appear in subscribed calendars
- No manual re-export or re-import required

**Platform Support**
- Google Calendar (refreshes every few hours)
- Apple Calendar for iPhone/Mac (refreshes every 5-15 minutes)
- Microsoft Outlook (refreshes daily, configurable)
- Any calendar app supporting webcal:// or https:// iCal feeds

**Permission-Based Filtering**
- Users only see events they have permission to view
- Respects existing event visibility logic (`Event.is_visible_to_user()`)
- Different users get different event subsets based on their permissions

**Secure Token System**
- Each user gets a unique 48-character URL-safe token
- Tokens are cryptographically secure (uses `secrets.token_urlsafe(48)`)
- Users can regenerate tokens if compromised
- One token per user (OneToOneField relationship)

**Usage Tracking**
- Tracks when subscription feeds are accessed
- Counts total number of accesses
- Shows last accessed timestamp
- Helps identify active vs. inactive subscriptions

**Time Window**
- Includes events from past 30 days
- Includes events up to 365 days in the future
- Provides historical context while focusing on upcoming events

**User Interface**
- Beautiful modal with Beta Theta Pi branding
- Dark mode support
- Quick subscribe buttons for Google Calendar and Apple/Outlook
- Manual URL copy with one-click copy button
- Token regeneration with security warning
- Detailed instructions for different calendar apps
- Expandable "How to subscribe" section with platform-specific steps

#### Routes
```python
# Get/create subscription URL for current user
GET /calendar/subscribe/

# Regenerate token (POST with CSRF)
POST /calendar/subscribe/regenerate/

# Subscription feed (no auth, uses token)
GET /calendar/feed/<token>/
```

#### File Locations
- **Model:** `src/models_calendar_subscription.py`
- **Views:** `src/view/calendar.py` (functions: `calendar_subscription_feed`, `get_calendar_subscription_url`, `regenerate_calendar_token`)
- **Template Snippet:** `templates/calendar_subscription_snippet.html` (integrated into `templates/calendar.html`)
- **Migration:** `src/migrations/0046_alter_loginhistory_ip_address_and_more.py`

### 2. Admin v2 Dashboard

#### Overview
Advanced administration system providing comprehensive site management tools with enhanced security through dual authentication. Designed for superuser-level administration beyond Django's standard admin panel.

#### Security Features

**Dual Authentication**
- Requires BOTH user password AND secret key
- User password: Standard Django authentication
- Secret key: Environment variable `ADMIN_V2_SECRET_KEY`
- Prevents unauthorized access even if password is compromised

**Restricted Access**
- Only accessible by user ID 73 (configurable in `ALLOWED_USER_ID` constant)
- All access attempts are logged in ActivityLog
- Failed attempts trigger security violation logs
- Session-based authentication with expiration

**Audit Logging**
- All Admin v2 access logged with timestamp and IP
- Feature flag toggle events recorded
- Page toggle events recorded
- Security violations tracked separately

#### Dashboard Features

**Site Statistics**
- **Users:** Total, active, officers, members, pledges
- **Legislation:** Total, draft, passed, removed
- **Events:** Total, upcoming, past
- **Committees:** Total, active
- **Announcements:** Total, active
- **Security:** Total logins, recent alerts, activity count

**Feature Flags Management**
- View all feature flags organized by category
- Toggle features on/off with single click
- Categories: Core, Voting, Committees, Events, Communications, Documents, Admin
- Visual indicators (/) for enabled/disabled state
- Shows last toggle time and user who toggled

**Page Toggles Management**
- Enable/disable specific pages site-wide
- Custom disabled messages for each page
- Override page access without code changes
- Visual status indicators

#### Routes
```python
# Login page
GET/POST /admin-v2/
GET/POST /admin_v2/  # Alternative route

# Dashboard (requires auth)
GET /admin-v2/dashboard/

# Toggle feature flag
POST /admin-v2/feature-flag/<flag_id>/toggle/

# Toggle page availability
POST /admin-v2/page/<toggle_id>/toggle/

# Logout
GET /admin-v2/logout/
```

#### File Locations
- **Views:** `src/view/admin_v2.py`
- **Models:** `src/models_feature_flags.py`
- **Templates:** `templates/admin_v2/login.html`, `templates/admin_v2/dashboard.html`
- **Decorators:** `require_admin_v2_auth` in `src/view/admin_v2.py`

### 3. Feature Flags System

#### Overview
Granular control system for enabling/disabling features and pages across the site without code deployments. Provides two levels of control: feature flags (for functionality) and page toggles (for entire pages).

#### Feature Flags

**Purpose**
- Control specific functionality within views
- Enable gradual rollouts of new features
- Disable features temporarily for maintenance
- A/B testing capabilities

**Implementation**
- Decorator: `@require_feature_flag('feature_name')`
- Applied to view functions
- Checks database for feature status
- Returns 403 with custom page if disabled
- Default behavior: enabled (fail-open)

**Categories**
- Core Features
- Voting & Legislation
- Committees
- Events & Calendar
- Communications (chat, announcements)
- Documents
- Admin Features

**Example Usage**
```python
from src.feature_flag_decorators import require_feature_flag

@login_required
@require_feature_flag('chats')
def chat_index(request):
    # View only accessible if 'chats' feature is enabled
    ...
```

#### Page Toggles

**Purpose**
- Enable/disable entire pages
- Show custom disabled messages to users
- Maintenance mode for specific sections
- Temporary page deactivation

**Implementation**
- Decorator: `@require_page_enabled('url_name')`
- Applied to view functions
- Custom disabled message per page
- Returns custom disabled page template
- Default behavior: enabled (fail-open)

**Example Usage**
```python
from src.feature_flag_decorators import require_page_enabled

@login_required
@require_page_enabled('announcements')
def announcements_view(request):
    # Page only accessible if enabled
    ...
```

#### Template Integration

**Context Processor**
- `src.context_processors.feature_flags`
- Makes feature flags available in all templates
- Usage: `{% if feature_flags.feature_name %}`
- Makes page toggles available in all templates
- Usage: `{% if enabled_pages.page_name %}`

**Example**
```django
{% if feature_flags.dark_mode %}
    <!-- Show dark mode toggle -->
    <button onclick="toggleDarkMode()">Toggle Dark Mode</button>
{% endif %}
```

#### Protected Features

**Chat System** (All protected with 'chats' feature flag)
- Chat index page (`chat_index`)
- Channel chat view (`channel_chat`)
- Get messages API (`get_channel_messages`)
- Send message API (`send_channel_message`)
- Edit message API (`edit_channel_message`)
- Delete message API (`delete_channel_message`)
- Active users API (`get_channel_active_users`)
- Create/edit/delete channel admin functions
- Committee chat views and legacy APIs

#### File Locations
- **Models:** `src/models_feature_flags.py`
- **Decorators:** `src/feature_flag_decorators.py`
- **Context Processor:** `src/context_processors.py`
- **Disabled Templates:** `templates/feature_disabled.html`, `templates/page_disabled.html`

### New Decorators

#### @require_feature_flag(feature_name)
```python
def require_feature_flag(feature_name):
    """Decorator to require a feature flag to be enabled."""
    def decorator(view_func):
        @wraps(view_func)
        def wrapper(request, *args, **kwargs):
            if not FeatureFlag.is_feature_enabled(feature_name):
                return render(request, 'feature_disabled.html', {
                    'feature_name': feature_name,
                }, status=403)
            return view_func(request, *args, **kwargs)
        return wrapper
    return decorator
```

#### @require_page_enabled(url_name)
```python
def require_page_enabled(url_name):
    """Decorator to require a page toggle to be enabled."""
    def decorator(view_func):
        @wraps(view_func)
        def wrapper(request, *args, **kwargs):
            try:
                toggle = PageToggle.objects.get(url_name=url_name)
                if not toggle.is_enabled:
                    return render(request, 'page_disabled.html', {
                        'page_name': toggle.display_name,
                        'disabled_message': toggle.disabled_message,
                    }, status=403)
            except PageToggle.DoesNotExist:
                pass  # Default to enabled
            return view_func(request, *args, **kwargs)
        return wrapper
    return decorator
```

#### @require_admin_v2_auth
```python
def require_admin_v2_auth(view_func):
    """Decorator to require Admin v2 authentication"""
    def wrapper(request, *args, **kwargs):
        # Check user authentication
        if not request.user.is_authenticated:
            messages.warning(request, 'Please login to access Admin v2')
            return redirect('login')

        # Check user authorization
        if not hasattr(request.user, 'user_id') or request.user.user_id != ALLOWED_USER_ID:
            messages.error(request, 'Unauthorized access')
            return redirect('home')

        # Check Admin v2 session
        if not request.session.get('admin_v2_authenticated'):
            messages.warning(request, 'Please authenticate to access Admin v2')
            return redirect('admin_v2_login')

        return view_func(request, *args, **kwargs)
    return wrapper
```

### New Views

#### Calendar Subscription Views

**calendar_subscription_feed(request, token)**
- Generates dynamic iCal feed for subscription
- No authentication required (uses token)
- Records access for analytics
- Filters events by user permissions
- Returns properly formatted iCalendar data
- Includes cache headers for optimal refresh

**get_calendar_subscription_url(request)**
- GET: Returns user's subscription URLs (webcal:// and https://)
- JSON response with token, URLs, and usage stats
- Creates subscription if doesn't exist

**regenerate_calendar_token(request)**
- POST: Regenerates user's subscription token
- Invalidates old token
- Returns new subscription URLs
- Requires CSRF token

#### Admin v2 Views

**admin_v2_login(request)**
- GET: Shows dual authentication form
- POST: Validates user password and secret key
- Creates Admin v2 session on success
- Logs all access attempts

**admin_v2_dashboard(request)**
- Shows site statistics
- Lists all feature flags by category
- Lists all page toggles
- Provides toggle controls
- Requires Admin v2 authentication

**toggle_feature_flag(request, flag_id)**
- POST: Toggles a feature flag
- Updates metadata (last_toggled_by, last_toggled_at)
- Returns JSON success response

**toggle_page(request, toggle_id)**
- POST: Toggles a page availability
- Updates metadata
- Returns JSON success response

**admin_v2_logout(request)**
- Clears Admin v2 session
- Redirects to login page

## API Documentation

### Calendar Subscription API

#### GET /calendar/subscribe/
Get or create calendar subscription URL for authenticated user.

**Authentication:** Required (session)

**Response:**
```json
{
  "webcal_url": "webcal://am-parliament.org/calendar/feed/TOKEN/",
  "http_url": "https://am-parliament.org/calendar/feed/TOKEN/",
  "token": "SECURE_TOKEN_STRING",
  "last_accessed": "2026-01-06T10:30:00Z",
  "access_count": 5
}
```

#### POST /calendar/subscribe/regenerate/
Regenerate subscription token (invalidates old token).

**Authentication:** Required (session)
**CSRF:** Required

**Response:**
```json
{
  "webcal_url": "webcal://am-parliament.org/calendar/feed/NEW_TOKEN/",
  "http_url": "https://am-parliament.org/calendar/feed/NEW_TOKEN/",
  "token": "NEW_SECURE_TOKEN_STRING",
  "last_accessed": null,
  "access_count": 0
}
```

#### GET /calendar/feed/<token>/
Get iCalendar feed for subscription.

**Authentication:** None (uses token)

**Response:** iCalendar file (text/calendar)
- Includes VCALENDAR wrapper
- VEVENT entries for each event
- Properly formatted timestamps (UTC)
- Event summaries, descriptions, locations
- REFRESH-INTERVAL header (1 hour)
- Cache-Control header (max-age=3600)

**Error Responses:**
- 404: Token not found or inactive
- 403: Token invalid

### Admin v2 API

#### POST /admin-v2/feature-flag/<flag_id>/toggle/
Toggle a feature flag.

**Authentication:** Admin v2 session required
**CSRF:** Required

**Response:**
```json
{
  "success": true,
  "enabled": true
}
```

#### POST /admin-v2/page/<toggle_id>/toggle/
Toggle a page availability.

**Authentication:** Admin v2 session required
**CSRF:** Required

**Response:**
```json
{
  "success": true,
  "enabled": false
}
```

## Security Considerations

### Calendar Subscriptions

**Token Security**
- 48-character URL-safe tokens provide 288 bits of entropy
- Tokens are indexed for fast lookup but not predictable
- One token per user prevents token enumeration
- Tokens can be regenerated if compromised

**Access Control**
- No authentication on subscription feed (by design for calendar app compatibility)
- Permission filtering ensures users only see authorized events
- Token acts as authentication credential (keep secret)
- Access tracking helps identify suspicious activity

**Recommendations**
- Users should treat subscription URLs as passwords
- Regenerate tokens if shared accidentally
- Monitor access counts for unusual patterns
- Consider token expiration in future versions

### Admin v2

**Dual Authentication Benefits**
- Password compromise alone doesn't grant access
- Secret key stored only in environment (not in database)
- Prevents unauthorized Admin v2 access even with valid user credentials

**Session Security**
- Session-based authentication with Django's built-in security
- Admin v2 session independent from normal user session
- Session expires after inactivity (Django default: 2 weeks)

**Audit Trail**
- All access attempts logged (success and failure)
- Security violations logged separately for monitoring
- Timestamps and IP addresses recorded
- User identification for all toggle actions

**Recommendations**
- Set strong `ADMIN_V2_SECRET_KEY` (minimum 50 characters)
- Rotate secret key periodically
- Monitor ActivityLog for suspicious patterns
- Restrict server access to `ADMIN_V2_SECRET_KEY` environment variable

### Feature Flags

**Default Behavior**
- Features default to enabled if flag doesn't exist
- Prevents breaking changes when adding new flags
- Fail-open approach prioritizes functionality over restriction

**Server-Side Enforcement**
- All checks happen server-side (can't be bypassed client-side)
- Decorators run before view execution
- Template tags check database on every render

**Recommendations**
- Create feature flags before deploying protected features
- Test feature disable behavior before relying on it
- Document which features are controlled by which flags
- Use page toggles for maintenance mode scenarios

## Deployment Guide

### Prerequisites
- Python 3.8+
- Django 5.1.7+
- PostgreSQL database
- Environment variables configured

### Step 1: Environment Variables

Add to your environment (`.env`, server config, etc.):

```bash
# Admin v2 Secret Key (REQUIRED)
ADMIN_V2_SECRET_KEY=your-very-long-random-secret-key-here-minimum-50-characters
```

**Generating a secure secret key:**
```python
import secrets
print(secrets.token_urlsafe(64))
```

### Step 2: Update Settings

Add context processor to `Parliament/settings_postgres.py`:

```python
TEMPLATES = [
    {
        'OPTIONS': {
            'context_processors': [
                # ... existing processors ...
                'src.context_processors.feature_flags',  # Add this line
            ],
        },
    },
]
```

### Step 3: Run Migration

```bash
# Development
python manage.py migrate

# Production with settings module
DJANGO_SETTINGS_MODULE=Parliament.settings_postgres python manage.py migrate
```

This creates the `calendar_subscriptions` table.

### Step 4: Configure Admin v2 Access

Edit `src/view/admin_v2.py`:

```python
ALLOWED_USER_ID = '73'  # Change to your admin user's user_id
```

Or keep as is if user ID 73 is correct.

### Step 5: Create Initial Feature Flags

Access Admin v2 dashboard at `/admin-v2/` and create feature flags:

**Recommended Initial Flags:**
- **chats** (Communications) - Controls all chat functionality
- **announcements** (Communications) - Controls announcements system
- **dark_mode** (Core) - For future dark mode UI control

### Step 6: Verify Deployment

**Test Calendar Subscriptions:**
1. Log in as a test user
2. Visit `/calendar/`
3. Click "Subscribe to Calendar"
4. Copy subscription URL
5. Add to a calendar app (Google Calendar recommended for testing)
6. Verify events appear
7. Create a new event and verify it appears in subscribed calendar (may take a few minutes)

**Test Admin v2:**
1. Log in as authorized user (user_id matches `ALLOWED_USER_ID`)
2. Visit `/admin-v2/`
3. Enter user password
4. Enter `ADMIN_V2_SECRET_KEY` value
5. Verify access to dashboard
6. Test toggling a feature flag
7. Verify feature is blocked when disabled

**Test Feature Flags:**
1. In Admin v2, disable the 'chats' feature
2. Try accessing `/chats/` as a regular user
3. Verify "Feature Disabled" page appears
4. Re-enable the feature
5. Verify chat access is restored

### Step 7: Monitor Logs

Check ActivityLog for:
- Admin v2 access attempts
- Feature flag toggle events
- Any security violations

## Known Issues

1. **Calendar app refresh timing:**
   - Google Calendar: ~2-4 hours between refreshes (not configurable by us)
   - Apple Calendar: 5-15 minutes (depends on iOS/macOS version)
   - Outlook: Daily by default (users can configure)
   - **Workaround:** Users can manually refresh their calendar app

2. **Modal scrolling on small screens:**
   - Fixed in this release with `max-h-[90vh] overflow-y-auto`
   - Should work on all screen sizes now

3. **Feature flag template caching:**
   - Template tags query database on every render
   - May impact performance with many template checks
   - **Future:** Consider caching layer for feature flags
