# v3.6.0 — New Member Welcome & Guided Onboarding

**Release Date:** June 12, 2026
**Deployment Status:** ✅ Deployed — June 22, 2026
**Type:** Feature

---

## Overview

First-time users now get a proper welcome experience. New members see a multi-step onboarding wizard on their first login, a collapsible getting-started checklist on the home page, page guide popups the first time they visit each major section, and a profile-completion progress bar on the Profile and Preferences pages.

Existing users are grandfathered in automatically — no disruption to anyone who already has a password and email set.

---

## What Changed

### 1. Model: Onboarding State (`ParliamentUser`)

Two new fields track per-user onboarding progress:
- `onboarding_complete` (BooleanField, default False) — set True once the wizard is finished
- `onboarding_data` (JSONField, default `{}`) — stores `pages_visited` list and `checklist_dismissed` flag

**Migration 0207** adds both fields and runs a data migration that marks existing established users (non-default password + email set) as complete with all pages pre-visited, so they see nothing new.

**Changed:** `src/models/users.py`, `src/migrations/0207_user_onboarding_fields.py`

### 2. First-Login Flow

The login sequence for new users is now:
1. Login → Welcome screen (coat of arms, Beta Theta Pi greeting)
2. Email setup (dismissable, uses existing `set_email` endpoint)
3. Password change (existing `forced_password_change` view, still mandatory)
4. Passkey suggestion (optional, full WebAuthn registration)
5. Guide explanation (explains checklist + page guides)
6. Home (with checklist)

`login_view` redirects to `/onboarding/` instead of home when `onboarding_complete=False`. It also runs a one-time grandfather check (non-default password + email) so users who predated the feature are silently marked complete on their next login.

`forced_password_change` detects `request.session['in_onboarding']` and redirects to `/onboarding/?step=passkey` instead of home after a successful password change.

`ForcePasswordChangeMiddleware` exempts `/onboarding/` so the wizard can show before the forced password change.

**Changed:** `src/view/login_view.py`, `src/view/forced_password_change.py`, `src/middleware/security.py`

### 3. Onboarding Wizard (`/onboarding/`)

Standalone full-screen template (does not extend `base.html` — avoids the email modal and navbar during setup). Multi-step Alpine.js flow with smooth transitions between steps.

Steps are driven by the `?step=` query param for the passkey/guide resumption after the password change redirect.

**New files:** `src/view/onboarding.py`, `templates/onboarding/wizard.html`
**New URLs:** `/onboarding/`, `/onboarding/complete/`, `/onboarding/page-visited/`, `/onboarding/dismiss-checklist/`

### 4. Home Page Checklist (`templates/components/onboarding_checklist.html`)

Collapsible card on the home page listing all major sections to explore:
Profile, Preferences, Announcements, Directory, Vote, Committees, My Excuses, Service Hours, Chats, Calendar, and Documents (hidden for pledges).

Items check themselves off as the user dismisses each page's guide. The whole checklist can be permanently dismissed via a "Dismiss" button. Dismissed state and per-page completion are persisted server-side in `onboarding_data`.

**New files:** `templates/components/onboarding_checklist.html`, `templates/components/_checklist_item.html`
**Changed:** `templates/home.html`

### 5. Profile Completion Progress Bar (`templates/components/profile_progress.html`)

Shown at the top of the Profile and Preferences pages while any profile fields remain empty. Tracks: email, phone, preferred name, profile picture, and about me. Hides automatically when all fields are filled.

**New files:** `templates/components/profile_progress.html`, `templates/components/_progress_item.html`
**Changed:** `templates/profile.html`, `templates/preferences.html`

### 6. Page Guides

First-visit guide modal on 11 pages: Profile, Preferences, Announcements, Directory, Vote, Committees, My Excuses, Service Hours, Chats, Calendar, Documents. Explains what the page does and how to use it. Dismissing marks the page visited (fires `POST /onboarding/page-visited/`) and checks it off the home checklist.

**New file:** `templates/components/page_guide.html`
**Changed:** templates for all 11 listed pages

### 7. Template Filter

`onboarding_page_seen` filter added to `custom_filters.py` — used by checklist and guide components to check per-page state.

**Changed:** `src/templatetags/custom_filters.py`
