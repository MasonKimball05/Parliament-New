# v3.7.1 — Security Fixes & Login Pipeline Cleanup

**Release Date:** June 14, 2026
**Deployment Status:** ✅ Deployed — June 22, 2026
**Type:** Bug Fix / Security

---

## Overview

Follow-up fixes to v3.7.0's security hardening work. Closes a correctness bug in the token approval scope narrowing, removes ~100 lines of duplicated post-auth logic from the login view, tightens profile email comparison, and improves distributed-lockout observability.

---

## What Changed

### 1. Token Approve "Uncheck All" Was a No-Op

`admin_approve_token` checked `if requested_scopes:` before applying scope narrowing — an empty list is falsy, so unchecking every checkbox silently granted all originally-requested scopes instead of zero. Fixed with a `scopes_submitted` hidden field: the approve modal always sends this marker, so the backend can distinguish "admin deliberately approved zero scopes" from "old client sent no scopes key at all."

**Changed:** `src/view/api.py`, `templates/admin_v2/api_tokens.html`

### 2. Login View Pipeline Deduplicated

`login_view` contained an inline copy of the post-authentication security pipeline (geo check, session flag injection, `LoginHistory` creation, `LoginAlert` for non-US logins, structured logging, watch-flag alert) that already existed as `run_post_auth_pipeline()` in `src/utils/security_utils.py` — the same function used by the passkey login path. Replaced the ~100-line block with a single `run_post_auth_pipeline(request, user, ip_address, user_agent, method='password')` call. Behaviour is identical; the two paths are now guaranteed to stay in sync.

**Changed:** `src/view/login_view.py`, `src/utils/security_utils.py`

### 3. Profile Email Comparison Now Case-Insensitive

`profile_view` compared the submitted email against `user.email` without lowercasing the stored value first. Emails are normalised to lowercase on save, but the comparison `new_email != user.email` could still produce a false "changed" result for any legacy mixed-case value in the DB. Changed to `(user.email or '').lower()`.

Also fixed: when an email error (address taken or rate-limited) occurred in the non-AJAX path, the view redirected immediately — silently discarding any username, preferred name, or phone changes the user had also submitted in the same form. Those fields are now saved before returning the error redirect.

**Changed:** `src/view/profile_view.py`

### 4. Distributed Lockout Logging

The per-account lockout counter now tracks a set of distinct IP addresses contributing to each account's failed attempts (same cache TTL as the attempt counter). When an account locks, the log message includes the distinct IP count. If three or more distinct IPs contributed, the log line is prefixed `[DISTRIBUTED LOCKOUT SUSPECTED]`, giving a searchable signal for targeted DoS attempts without requiring CAPTCHA or more invasive infrastructure.

**Changed:** `src/view/login_view.py`

### 5. Pipeline Blacklist Comment

`run_post_auth_pipeline`'s IP blacklist check is redundant for the password-login path (login_view already checks before `authenticate()`) but load-bearing for the passkey path (webauthn.py has no prior check). Added a comment to make the intent clear and prevent the check from being removed as "dead code."

**Changed:** `src/utils/security_utils.py`
