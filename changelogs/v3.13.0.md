# v3.13.0 — Officer Transition Checklist & Role-Transfer History

**Type:** Feature / Fix
**Status:** WIP — not yet committed or deployed
**Date:** 2026-07-08

Implements the Officer Transition Checklist (top feature pick since 07-04, planned in `Claude/AI/Officer-Transition-Checklist-Plan.md`). Semester handoffs now leave a proper history trail and hand the incoming officer a working checklist.

---

## Fix: `transfer_role` is now actually atomic

The docstring always promised an atomic swap, but there was no `transaction.atomic` block — a mid-transfer failure could leave a half-transferred role (removed from the outgoing holder but never assigned). The whole mutation section now runs in one transaction.

## Fix/Feature: `transfer_role` maintains `RoleHistory`

Previously the semester-handoff flow left **no** history records (only manual entry on the profile/admin pages created them). Now, inside the atomic block:

- Outgoing holder(s): open history rows for the role are closed (`end_semester` set). Covers the one-per-chapter auto-clear path too. Exact `role_name` match — differently-spelled manual entries are deliberately left alone.
- Incoming holder: a new open row is created (skipped if one is already open, so double-submits don't duplicate).
- Semester labels follow the chapter's real term structure (per Mason 07-08): terms run Jan-to-Jan with December/January handoffs, no Summer term. A December or January transfer closes the outgoing row at `Fall YYYY` and opens the incoming at `Spring YYYY(+1)`; rare off-cycle replacements use the semester in progress. Logic lives in `src/utils/semester.py` (`transition_semesters`).

## Feature: Officer Transition Checklist

- **Models** (`src/models/transitions.py`): `TransitionChecklistItem` (text, optional role scope, order, active flag — admin-editable data, not code) and `TransitionChecklistStatus` (item × RoleHistory completion state, unique-together). Anchored to `RoleHistory` so manually-entered terms can carry checklists too.
- **Auto-attach:** `transfer_role` bulk-creates statuses for the incoming holder's new history row from active items matching the role + global items (`ignore_conflicts` for idempotence).
- **View/UI:** `transition_checklist` page (progress bar + checkbox list, matching site styling) and `toggle_checklist_item` AJAX endpoint (CSRF, POST-only). Access: officers/chairs/admins **and the incoming holder themselves** — the new officer works their own list even before their member_type flips.
- **Entry points:** holder chips on Role Transitions link to open checklists; a successful transfer redirects straight to the new checklist.
- **Seeding:** `python manage.py seed_transition_checklist` (idempotent) creates 8 global + 8 role-scoped starter items; edit/extend in admin under *Transition checklist items*.
- **Admin:** both models registered (items list-editable; statuses read-mostly for audit/fixups).

## Review fixes (07-09, from the 07-09-26 auto-run report)

All three 🟡 findings fixed pre-commit:

1. **Chairs were 403'd from checklists** — `_can_access_checklist` only admitted `is_officer` (Officer/admin), but the Role Transitions page that links to checklists is `officer_required`, which admits Chairs. Predicate now mirrors the decorator (`+ member_type == 'Chair'`). Regression test added (`test_chair_can_view_and_toggle`).
2. **`</script>` breakout in the JSON script islands** — `roles_json`/`assignable_json` were raw `json.dumps` rendered with `|safe`; a member name containing `</script>` would have been stored XSS on the transitions page. New `_script_safe_json()` escapes `<` as `\u003c` (lossless, valid JSON) — verified empirically with a hostile payload roundtrip. Test added (`ScriptSafeJsonTests`).
3. **Checklist 403 was bare JSON on a full-page navigation** — now renders the styled `403.html` (same pattern as `src/middleware/security.py`); the AJAX toggle keeps its JSON 403. `test_other_member_forbidden` now asserts the template.
