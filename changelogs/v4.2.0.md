### 🔴 Anonymous ballots were written to the officer-visible log by name

`src/ballots.py` `cast()` and `cast_committee()` logged
`<username> voted 'no' on '<bill>'` to the `function_calls` logger for every
bill, anonymous or not. That logger writes `logs/django_actions.log`, and
`/officers/system-logs/` shows its last 200 lines to every officer (its
redaction only covers Kai lines). The old web vote view did the same before
v3.55.0; the shared ballot code carried it to app ballots and committee ballots
too.

- On an anonymous bill the line now reads `<username> voted (anonymous) on …`.
  Open bills still log the choice.
- Test: `src/tests/legislation/test_anonymous_ballot_log.py`.
- **Not done by this release:** lines already in prod's `django_actions.log`
  (and its rotated copies) still hold past anonymous choices. Scrubbing them is
  a server-side step for Mason; see the 10-28-26 auto-run report.

### 🟡 Location check-in

- **Hidden and archived events.** `POST events/<id>/checkin/location/` looked
  the event up by id only, so a member could check in to an event they can't
  see, and the `too_far` reply's `distance_m` let them find where it was. The
  lookup now uses the same rule as `checkin-areas/` (`visible_to_q`,
  `archived=False`); anything else is a 404.
- **An officer's "absent" or "excused" is kept.** A check-in only fills a
  missing or `pending` row. It used to overwrite anything but present/late, so
  the next geofence ping undid an officer's "absent". New refusal
  `checkin_already_marked` (409) with a message for the member.
- **`nan` / `inf` / out-of-range coordinates** are a 400 instead of a 500, and a
  non-finite or negative accuracy is `checkin_inaccurate`.
- **`MobileDevice.checkin_key_hash`** is now in `MobileDeviceAdmin.exclude` (and
  so out of the CSV export), like the other device hashes, and in the test's
  `SECRET_FIELDS`.

### 🟡 Admin v2 "Remove all roles" left Kai permissions in place

`roles.clear()` sends `m2m_changed` with `pk_set=None`, and the Kai and
Education permission resets in `src/signals.py` only run with a `pk_set`. So
bulk "Remove all roles" on an outgoing Kai chair (the end-of-year case the
action exists for) kept every `KaiMemberPermission` grant and Kai chat guest.
Bulk edit and `ParliamentUser.anonymize()` now use
`roles.remove(*roles.all())`, which goes through the same path as a single
"Remove role". Test in `src/tests/admin_v2/test_bulk_members.py`.

### 🟢 Admin v2 exports and bulk edit (10-29-26 auto-run)

- **Service-hours export no longer runs ~7 queries per member.** It called
  `get_user_service_stats()` for every member (about 1,000 queries for 150
  members). It now sums submissions, adjustments and expectation overrides
  once each for the whole roster. Same numbers: a test compares every column
  with `get_user_service_stats()` and checks the query count doesn't grow
  with the roster. (`src/view/admin_v2_exports.py`)
- **`?period=abc` (service export) and `?role=abc` (bulk edit) were 500s.**
  Non-numbers now fall back to the active period / an empty list.
- **`?status=` went into the CSV filename unchecked.** It's now limited to
  Active / Inactive / Alumni, anything else means "all".
- **Bulk edit's "Pick at least one member" redirect** copied the whole POST,
  `csrfmiddlewaretoken` included, into a GET URL (nginx logs, browser
  history). It now carries only the list filters.
- **API token expiry notice** printed the UTC date, so a token expiring after
  7 pm Central said the next day. Uses `timezone.localtime` (one more of the
  v3.60.1 kind).

Tests: `src/tests/admin_v2/test_v3_60_2_hardening.py` (5 of 6 fail without
the fix; the sixth guards the numbers matching).

## Formerly v3.69.0 (`a0600df`)

### 🟢 Slating: rounds as the bylaws run them — run-offs, office-by-office, floor nominations (Mason, 10-29-26)

Bylaws Art. II §3, plus the pending resolution "On the Adjustment of the
Slating Process to Better Enable Chapter Feedback" (run-off positions; the tie
rule is the final wording: the chapter decides). One engine,
`src/slating_rounds.py`, used by the web's slating pages and the app.

- **The first ballot is always the full slate** (pass/fail, the period's %).
  - Passing it elects every slated nominee except run-offs and
    floor-nominations positions, and affirms both run-off candidates.
  - It used to elect no one. Closing a slate vote set `slate.passed` and
    nothing else, so the results page and the officer transition read winners
    off the slate as a whole, and a run-off candidate overwrote the primary.
- **After that the chair picks each round:** the full slate again (for what's
  undecided), or **positions**, ticked one at a time in slate order as the
  bylaws run it, or several at once.
  - The round's threshold defaults to the period's, with 51% for a final
    ballot. Whether members can abstain is set per round.
  - The setup stays on the round (`SlatingRound.ballot`), and members see only
    those positions.
- **A position on a ballot is one of:**
  - **pass/fail** on its nominee. A failure goes back to the committee to
    renominate.
  - a **run-off**: pick one of the two.
  - **floor nominations**: pick one of the accepted nominees, which the chair
    can narrow to the top two.
  - A pick-one elects the leader only with at least the threshold of the votes
    cast for candidates and no tie.
- **Floor nominations:** `SlatingPosition.open_nominations`, switched on per
  position. `SlatingNominee` rows are added by the chair and must be marked
  accepted to go on a ballot.
- **The chapter's own decision:** the chair records a winner for a position (a
  tie, a tabled run-off) or leaves it unfilled (`left_unfilled`). A reason is
  required and goes in the activity log.
- **Web, setup page:**
  - a "Next round" form (full slate or positions; threshold, abstain, nominees)
  - a Positions panel showing each position's state, plus floor nominations
    and the chapter's decision.
- **Web, elsewhere:**
  - The slate ballot lists one row per position, a run-off with both names.
  - The per-position ballot shows pick-one positions.
  - Paper ballots count run-off candidates and nominees.
  - Results start with who holds each office.
  - The officer transition reads the winners, so write-ins work too.
- `src/view/slating/period_setup.open_voting_round` is the web's Open voting,
  shared with the app.
- **App:** the slating chair's "Run the vote" screen (`slating/periods/<id>/chair/`:
  open, close, positions), and the member ballot shows run-offs and floor
  nominations.
- Tests: `src/tests/slating/test_rounds.py` (the bylaws flow end to end), and
  mobile `ChairAppTests`. Earlier slating tests updated for position-keyed
  ballots (`vote_<position id>`, `approve_c<id>` paper fields).
