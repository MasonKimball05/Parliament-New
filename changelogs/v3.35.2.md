## 🧹 Education / recruitment templates named for their committee

Mason: "We are a little inconsistent on naming schemes … preferably the
education_ or recruitment_ instead of more ambiguous." In `templates/committee/`
most education and recruitment pages already had the prefix; five did not:

| Old | New |
|---|---|
| `committee/education.html` | `committee/education_dashboard.html` (pairs with `recruitment_dashboard.html`) |
| `committee/quiz_submissions.html` | `committee/education_quiz_submissions.html` |
| `committee/_quiz_analysis_body.html` | `committee/_education_quiz_analysis_body.html` (partials keep the leading `_`, like `_education_meeting_row.html`) |
| `committee/candidate_form.html` | `committee/recruitment_candidate_form.html` |
| `committee/candidate_list.html` | `committee/recruitment_candidate_list.html` |

Pure `git mv` — no template content changed except the `{% include %}` path in
`education_quiz_analysis.html` and `pledge/quiz_analysis.html`. All references
updated: the `render()` calls in `education.py` / `recruitment.py`, the test
files that name templates by path, and comments. Historical files
(`changelogs/`, `CODE_REVIEW.md`) keep the old names on purpose — they describe
the code as it was.

**URLs unchanged.** Only template *files* moved; no route, URL name or path
changed, so no link or bookmark breaks. Verified by requesting every education /
recruitment / candidate / pledge-quiz route as a chair of a committee that is
both the education and recruitment committee: every GET page returned 200 (or
its designed redirect — `candidate_list` → dashboard candidates tab), POST-only
routes returned 405, none raised `TemplateDoesNotExist` or 5xx. The quiz
analysis / submissions pages (which need a quiz task) are covered by the
existing education tests, which render them.

**Left as they are, deliberately:**
- Generic pages every committee uses (`detail`, `vote`, `attendance`,
  `documents`, `minutes_list`, …) — not education/recruitment-specific.
- `manage_education_permissions.html` / `manage_recruitment_permissions.html` —
  the shared `manage_<committee>_permissions` family with Kai and chat.
- URL **names** (`candidate_list`, `create_candidate`, …) — not asked for.

**New guard:** `src/tests/guards/test_committee_template_names.py` fails if the
education or recruitment views render (or include) a `committee/` template that
isn't `education_*` / `recruitment_*`. It also adds the first render test for the
candidate form.

**Noticed, not changed:** `recruitment_candidate_list.html` is only rendered by
`_candidate_list_legacy()`, which nothing calls (`candidate_list` redirects to
the dashboard's candidates tab). Both look like dead code.
