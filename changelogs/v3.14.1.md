# v3.14.1 — vote_view split, open-for-voting invariant centralized, handoff docs/tooling

Small maintainability batch toward the graduation-handoff goal: the
open-for-voting rules live in exactly one place now, disaster recovery is a
documented procedure instead of tribal knowledge, and untested code can't be
pushed by accident.

## `vote_view` endpoint split (Mason-directed 07-18; deferred item from 07-15)

**Why:** `vote_view()` was one ~495-line function multiplexing four unrelated
jobs on `request.POST.get('action')` — legislation upload, quick attendance,
ballot casting, and the GET page render. Any maintainer touching one behavior
had to read all of them, and a form-gate bug in one branch could swallow a
POST meant for another (the v3.13.3 silent-vote-drop class).

- **New endpoints** (same module, `src/view/vote_view.py`, all
  `@require_POST` + `@require_page_enabled('vote')`):
  - `POST /vote/cast/` → `cast_vote` (re-auth, validation, receipt mint)
  - `POST /vote/attendance/quick/` → `mark_attendance_quick` (JSON)
  - `POST /vote/upload/` → `upload_chapter_legislation` (chapter upload form;
    appointment votes keep their existing separate view). Non-officers now get
    an explicit error instead of the old silent fall-through.
- `vote_view` is now the GET page-builder. Shared attendance check factored
  into `_attendance_can_vote(user)`.
- **Legacy dispatcher kept on `POST /vote/`:** forwards old-style multiplexed
  POSTs to the split views, so tabs opened before the deploy don't get
  silently dropped; unrecognized POSTs get an explicit "page may be out of
  date" error. Safe to remove a release or two after v3.14.1.
- `vote.html`: upload + vote forms got explicit `action=` targets; attendance
  JS posts to the new URL. Behavior is otherwise identical.
- **Tests:** existing classes deliberately still POST to `/vote/` — that IS
  the legacy-dispatcher coverage now (noted in the file; don't "modernize"
  them). New `SplitEndpointTests` (7 tests) covers each endpoint directly,
  405 on GET, non-officer upload rejection, attendance 403, and the
  unrecognized-legacy-POST error path.

## `LegislationQuerySet` — `open_for_voting()` / `visible()` (planned in the 07-17 auto-run)

**Why:** the "which bills can be voted on right now" invariant
(`voting_closed=False` + `available_at` passed + scheduled start passed OR
blank-start auto-open, minus parked/terminal statuses) was hand-copied Q-logic
in `home.py` and `api/views.py`, partially reimplemented in
`passed_legislation.py`/`vote_view.py`, and had already rotted once — the
pre-v3.13.3 `status='active'` filters that never matched anything. A future
maintainer shouldn't need to know this invariant exists.

- `src/models/legislation.py`: new `LegislationQuerySet` with chainable
  `visible(now=None)` and `open_for_voting(now=None)` (the `now` parameter
  keeps tests deterministic; production callers omit it). Installed via
  `objects = LegislationQuerySet.as_manager()` — default manager behavior is
  unchanged. New `Legislation.CLOSED_STATUSES` constant replaces the copied
  `['pending', 'tabled', 'passed', 'failed', 'removed']` literals.
- Call sites swapped: `home.py` (active-legislation stat + pending-votes
  widget queryset) and `api/views.py` `GET /api/v1/legislation/active/`.
  `vote_view.py` and `passed_legislation.py` deliberately keep their own
  composition (they OR in author-visibility for not-yet-open bills — that's
  visibility, not open-for-voting; forcing it into the method would blur the
  invariant).
- New `src/test_legislation_queryset.py` (10 tests): the six planned predicate
  cases, CLOSED_STATUSES sweep, a queryset-vs-`voting_has_started()` parity
  test so instance and queryset logic can't drift, `visible()` coverage, and
  an anti-rot guard asserting home + the API endpoint actually call the
  method.

## Mobile broken-seal fix (Mason-reported 07-18: seal shows as empty image icon, site-wide, mostly mobile)

**Root cause:** every seal reference pointed at
`/exportable_media/am-coat-of-arms.png`, which is served by
`serve_exportable_media` — a `@login_required` Django view. Any request
arriving without a live session gets a 302 → login page HTML → the browser
renders a broken-image icon. That's why it hit:

- **mobile most** — iOS/Android evict session cookies aggressively and
  restore pages from bfcache with a dead session; every `<img>` then 302s;
- **anonymous pages always** — login, landing, 403/404/500, page-disabled
  all show the seal to logged-out users;
- **cookieless fetches always** — favicon/apple-touch-icon, the PWA
  manifest icons, and the service worker's push-notification icon;
- **intermittently even then** — Cloudflare default-caches `.png` by
  extension, so while its edge copy was warm the image worked for everyone,
  and when it expired the next fetch got the redirect → "quite often" not
  "always";
- **never in dev** — `if settings.DEBUG:` adds a public `static()` route for
  `/exportable_media/`, so the auth view is bypassed locally.

**Fix:** the coat of arms is a public brand asset (it's the favicon and sits
on the login page) and an identical 1024×1024 copy already lived at
`static/images/am-coat-of-arms.png` (the onboarding wizard used it). All 26
templates, `static/manifest.json`, and the service-worker ICON now use the
static path (`{% load static %}` added to the three standalone pages that
lacked it). Belt-and-braces for the remaining login-gated media (songbook
assets): `serve_exportable_media` now sends `Cache-Control: private,
max-age=86400`, and `/exportable_media/` joined `/static/` + `/media/` in the
Enforce2FAMiddleware exempt list (2FA-redirecting an `<img>` just breaks it).

**Deploy note:** static files changed → `collectstatic` + **Cloudflare
purge** (the known stale-404 gotcha applies directly here).

## 🔴 `/media/` was publicly served — now authenticated (found + fixed 07-18)

**Finding (confirmed live on prod):** the Kai binder — and by extension every
uploaded legislation document — was downloadable anonymously at
`/media/legislation_docs/<filename>`. Django never had a production route for
`/media/` (only the DEBUG static() helper in dev), so nginx served the folder
directly with no auth. Filenames are guessable, Cloudflare had cached PDFs
publicly, and any leaked URL was world-readable. Mirror image of the seal
bug: that was a public asset behind auth; this was private assets in front
of it.

**Fix:** new `src/view/serve_media.py` (`@login_required`, traversal guard,
`Cache-Control: private`) routed at `media/<path>` — registered
unconditionally so dev now behaves like prod (no more DEBUG masking this
class of bug). Optional `MEDIA_ACCEL_PREFIX` env enables the nginx
X-Accel-Redirect fast path (auth in Django, byte-streaming in nginx).
`src/test_serve_media.py` (5 tests) locks it in, including the
anonymous-must-bounce regression test.

**Deploy — REQUIRES an nginx change on the server (do this in the same
maintenance window as the pull):**

1. `sudo nano /etc/nginx/sites-available/<parliament site>` — find the
   `location /media/ { ... }` block (an `alias`/`root` to the media dir).
2. Either **delete it** (requests fall through to Daphne; Django streams the
   file — fine at chapter scale), or for the fast path **replace it** with:
   ```nginx
   location /internal_media/ {
       internal;
       alias /var/www/Parliament-New/media/;
   }
   ```
   and set `MEDIA_ACCEL_PREFIX=/internal_media` in the prod `.env`.
3. `sudo nginx -t && sudo systemctl reload nginx`
4. **Purge Cloudflare cache** — it has cached these PDFs publicly.
5. Verify from an incognito window:
   `https://am-parliament.org/media/legislation_docs/Kai-Binder.pdf` must
   redirect to login (it served the PDF anonymously before this fix).

Note: the hardcoded `/media/legislation_docs/*.pdf` links in
constitution_bylaws.html and the archive pages keep working unchanged —
they're just behind login now, like the pages that link them.
