# v2.12.0 - Landing Page Overhaul

**Release Date:** TBD

**Deployment Status:** In Development

**Type:** Feature

---

## Overview

Major overhaul of the public-facing landing page and its officer management tools. Officers can now fully customize landing page content, manage a photo library with inline rich-text embedding, configure contact form topics that route to specific officers by role, add custom form links, manage social/external links, control section visibility, display a recruitment banner, and set SEO metadata — all without touching code.

---

## New Features

### Officer: Full Landing Page Editor

A new editor at `/officers/edit-landing-page/` replaces the previous static content. Officers can edit all public-facing sections in a rich WYSIWYG editor (Quill.js).

**Editable sections:**
- **Who We Are** — rich text with inline photo embedding
- **What We Believe** — rich text with inline photo embedding
- **Chapter History** — rich text with inline photo embedding, customizable section title
- **Tagline** — short text shown in the hero section

**Rich text features:**
- Bold, italic, underline, blockquote, ordered/unordered lists
- Inline image embedding via `[photo:ID:size:align]` shortcodes (small/medium/large/full, left/center/right)
- Resizable images via left/right drag handles
- Image alignment toolbar (left, center, right, full width)

**Files Changed:**
- `templates/officer/edit_landing_page.html` *(new)* — full editor UI
- `src/view/officer/edit_landing_page.py` *(new)* — editor view with all POST actions
- `src/models.py` — `LandingPageContent` singleton model with all content fields
- `src/urls.py` — `/officers/edit-landing-page/` route

### Officer: Contact Form Topics & Routing

Officers can define contact form topics (e.g., "Recruitment", "General") and route each topic to a specific officer role. The appropriate officer's email is resolved at render time.

**Features:**
- Add/delete/toggle contact topics
- Each topic maps to a role code (e.g., `VPR`, `President`)
- Email resolves to the active member holding that role; falls back to President → VPR
- Topic dropdown shown on public contact form; recipient email set dynamically via JS

**Files Changed:**
- `src/models.py` — `LandingPageContactTopic` model
- `src/view/landing.py` — `_resolve_email_for_role()`, contact topics context
- `src/view/officer/edit_landing_page.py` — `add_contact_topic`, `delete_contact_topic`, `toggle_contact_topic` actions
- `templates/landing.html` — topic dropdown in contact form

### Officer Notes on Legislation

Admins and officers can now add a freeform note to any piece of legislation after voting closes. Notes are purely informational — they do not affect the vote result, status, or any other field.

**How it works:**
- An amber "Officer Note" banner appears on each legislation card on the Legislation Tracker page
- Admins and officers see an inline **Add officer note** prompt on legislation with no note, and an **Edit** button on legislation that already has one
- Clicking Edit or Add opens an inline textarea — no page reload needed
- The note is saved via a JSON endpoint; success/failure is shown inline
- Notes appear to all members viewing the Legislation Tracker (read-only for non-officers)
- The note field is a `TextField` with no length limit — suitable for multi-paragraph context, implementation status, follow-up actions, etc.

**Files Changed:**
- `src/models.py` — `admin_note` field added to `Legislation`
- `src/view/passed_legislation.py` — `update_legislation_note` view (POST, officer/admin only, saves via `update_fields`)
- `src/urls.py` — `/legislation/<id>/note/` route
- `templates/passed_legislation.html` — note display, inline editor, JS save/cancel/clear logic

### Vote & Legislation Bug Fixes

Several long-standing issues with the vote and passed legislation pages were resolved.

**Plurality and piecewise vote modes now fully supported:**
- The passed legislation page was unconditionally displaying yes/no/abstain/required% statistics for all vote modes. It now renders a mode-appropriate breakdown:
  - **Plurality** — shows each option with its vote count; the winning option is highlighted
  - **Piecewise** — shows yes count vs. required threshold alongside no and abstain counts
  - **Percentage** — unchanged, shows yes%/no%/abstain/required%

**Other fixes:**
- Auto-close for chapter legislation with a `voting_ends_at` deadline — previously the field was stored but never acted on; the vote page now auto-closes and calculates pass/fail on each page load (matching existing behavior in committee votes)
- Empty `vote_choice` validation — submitting a vote form without selecting an option now returns a proper error instead of storing a blank string in the database
- Validation added for non-plurality votes to reject unknown vote choices
- Removed 3 debug `print()` statements that were emitting attendance data to stdout in production

**Files Changed:**
- `templates/passed_legislation.html` — mode-aware vote statistics section
- `src/view/vote_view.py` — auto-close logic, vote choice validation, removed unused `authenticate` import

### Public Songbook

A read-only, publicly accessible songbook is available at `/songbook/public/` — no login required. It is intentionally implemented as a completely separate view and template from the authenticated songbook to guarantee zero management functions are reachable from the public surface, preventing any accidental privilege escalation.

**Features:**
- Search by title or lyrics
- Filter by category with song counts
- Compact list view linking to individual song pages
- Full lyrics display with audio player if available
- Dark mode support
- Linked from the landing page footer ("Songbook")

**Security design:** `src/view/public_songbook.py` imports only `Song` and `SongCategory` models and exposes only two read functions (`public_songbook_list`, `public_song_detail`). No permission helpers, no management actions, and no shared code path with the authenticated songbook views.

**Files Changed:**
- `src/view/public_songbook.py` *(new)* — read-only list and detail views, no auth
- `templates/public_songbook.html` *(new)* — standalone list page
- `templates/public_songbook_detail.html` *(new)* — standalone song detail page
- `src/urls.py` — `/songbook/public/` and `/songbook/public/<pk>/` routes
- `templates/landing.html` — "Songbook" link added to footer
