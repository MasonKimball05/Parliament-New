# v2.12.0 - Landing Page Overhaul

**Release Date:** TBD

**Deployment Status:** In Development

**Type:** Feature

---

## Overview

Major overhaul of the public-facing landing page and its officer management tools. Officers can now fully customize landing page content, manage a photo library with inline rich-text embedding, configure contact form topics that route to specific officers by role, add custom form links, manage social/external links, control section visibility, display a recruitment banner, and set SEO metadata — all without touching code.

---

## New Features

### Officer: Full Landing Page Editor

A new editor at `/officers/edit-landing-page/` replaces the previous static content. Officers can edit all public-facing sections in a rich WYSIWYG editor (Quill.js).

**Editable sections:**
- **Who We Are** — rich text with inline photo embedding
- **What We Believe** — rich text with inline photo embedding
- **Chapter History** — rich text with inline photo embedding, customizable section title
- **Tagline** — short text shown in the hero section

**Rich text features:**
- Bold, italic, underline, blockquote, ordered/unordered lists
- Inline image embedding via `[photo:ID:size:align]` shortcodes (small/medium/large/full, left/center/right)
- Resizable images via left/right drag handles
- Image alignment toolbar (left, center, right, full width)

**Files Changed:**
- `templates/officer/edit_landing_page.html` *(new)* — full editor UI
- `src/view/officer/edit_landing_page.py` *(new)* — editor view with all POST actions
- `src/models.py` — `LandingPageContent` singleton model with all content fields
- `src/urls.py` — `/officers/edit-landing-page/` route

---

### Officer: Photo Library

Officers can upload, caption, and manage a library of photos that can be embedded inline in any section via shortcodes.

**Features:**
- Upload photos with caption and display order
- Delete photos (also removes the file from storage)
- Reorder photos via display order field
- Embed photos in section editors using `[photo:ID]`, `[photo:ID:large:center]`, etc.

**Files Changed:**
- `src/models.py` — `LandingPagePhoto` model
- `src/view/officer/edit_landing_page.py` — `upload_photo`, `delete_photo`, `reorder_photo` actions

---

### Officer: Contact Form Topics & Routing

Officers can define contact form topics (e.g., "Recruitment", "General") and route each topic to a specific officer role. The appropriate officer's email is resolved at render time.

**Features:**
- Add/delete/toggle contact topics
- Each topic maps to a role code (e.g., `VPR`, `President`)
- Email resolves to the active member holding that role; falls back to President → VPR
- Topic dropdown shown on public contact form; recipient email set dynamically via JS

**Files Changed:**
- `src/models.py` — `LandingPageContactTopic` model
- `src/view/landing.py` — `_resolve_email_for_role()`, contact topics context
- `src/view/officer/edit_landing_page.py` — `add_contact_topic`, `delete_contact_topic`, `toggle_contact_topic` actions
- `templates/landing.html` — topic dropdown in contact form

---

### Officer: Custom Form Links

Officers can add externally-hosted form links (e.g., recruitment interest forms, survey links) to the landing page. Each link has a title, description, URL, and customizable button text.

**Features:**
- Add/delete/toggle form links
- Shown as cards on the landing page with a call-to-action button
- Officers can activate/deactivate links without deleting them

**Files Changed:**
- `src/models.py` — `LandingPageFormLink` model
- `src/view/officer/edit_landing_page.py` — `add_form_link`, `delete_form_link`, `toggle_form_link` actions
- `templates/landing.html` — form links section

---

### Officer: Social & External Links

Replaced the previous 5 hardcoded social media URL fields with a fully dynamic link manager. Officers can add any link (Instagram, Linktree, chapter blog, etc.) with a custom label.

**Features:**
- Add links with a label and URL
- Delete individual links
- Shown as pill-style buttons in the contact section and as text links in the footer

**Files Changed:**
- `src/models.py` — `LandingPageSocialLink` model; removed 5 hardcoded URLFields from `LandingPageContent`
- `src/view/landing.py` — `social_links` context
- `src/view/officer/edit_landing_page.py` — `add_social_link`, `delete_social_link` actions
- `templates/landing.html` — dynamic social link rendering in contact section and footer

---

### Officer: Recruitment Banner

Officers can display a dismissible recruitment banner at the top of the landing page. The banner auto-hides after a configurable end date.

**Features:**
- Enable/disable with a checkbox
- Custom message (up to 300 characters)
- Optional end date — banner disappears automatically after this date
- Visitor can dismiss the banner (removes it from DOM for the session)
- Banner renders inside the fixed navbar header so it's always visible

**Files Changed:**
- `src/models.py` — `recruitment_banner_active`, `recruitment_banner_message`, `recruitment_banner_end` fields on `LandingPageContent`
- `src/view/landing.py` — `show_banner` logic with date check
- `templates/landing.html` — banner markup in header, `adjustHeroPadding()` JS

---

### Officer: Section Visibility Controls

Officers can show or hide the "Parliament Info" box and the entire contact section from the landing page without deleting content.

**Files Changed:**
- `src/models.py` — `show_parliament_info`, `show_contact_section` fields on `LandingPageContent`
- `src/view/officer/edit_landing_page.py` — saves both checkboxes

### Officer: Contact Info Fields

Officers can set a physical meeting location, street address, and phone number that appear in the contact section of the landing page.

**Files Changed:**
- `src/models.py` — `contact_location`, `contact_address`, `contact_phone` fields on `LandingPageContent`

### Officer: SEO & Open Graph

Officers can set a meta description and upload an OG image that appear in search results and social media link previews.

**Features:**
- Meta description field (used for `<meta name="description">` and `og:description`)
- OG image upload (used for `og:image` in social previews)
- `og:title`, `og:type`, `og:url`, and `twitter:card` are automatically set

**Files Changed:**
- `src/models.py` — `meta_description`, `og_image` fields on `LandingPageContent`
- `templates/landing.html` — SEO and OG meta tags in `<head>`

---

### Contact Form: Server-Side Storage & Email Notifications

All contact form submissions are now saved to the database regardless of whether a recipient is resolved. Officers can view a full inbox.

**Features:**
- Every submission stored as a `ContactSubmission` record (name, email, message, topic, recipient)
- Email notification sent to the resolved recipient officer automatically
- Unread submissions show a badge on the officer home page
- Full inbox at `/officers/contact-messages/` with reply links, mark-as-read, and bulk mark-all-read

**Files Changed:**
- `src/models.py` — `ContactSubmission` model
- `src/view/landing.py` — `contact_submit` POST endpoint
- `src/view/officer/contact_submissions.py` *(new)* — inbox, mark read, mark all read views
- `templates/officer/contact_submissions.html` *(new)* — inbox page
- `templates/officer_home.html` — unread badge, recent submissions card
- `src/urls.py` — `/contact/submit/`, `/officers/contact-messages/` routes
- `src/middleware/security.py` — added `/contact/submit/` to SQL injection pattern skip list (free-text messages trigger false positives)
