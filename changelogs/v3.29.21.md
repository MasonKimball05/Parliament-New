Mason: "The pdf generator for the bylaws messes up the greek characters
for our motto a bit. Our motto is Ἀρετή Μονάζει. Can you fix this?"

## Root cause

`generate_cnb_document_pdf_buffer` (`src/view/officer/cnb.py`) renders
every governing document with ReportLab's base-14 built-in fonts
(Times-Roman/Bold/Italic/BoldItalic, per the "Times New Roman convention"
fixed in v3.29.8). Every ReportLab base-14 font only covers WinAnsi/
Latin-1 — there is no glyph for any Greek character in any of them, so
wherever the motto is quoted (currently the Foreword's preamble in
`src/management/data/cnb_data.py`, staged behind the `cnb_foreword`
flag), it rendered as missing-glyph boxes.

Confirmed directly with `fontTools`, not assumed:
- ReportLab's own bundled fallback font (`reportlab/fonts/Vera.ttf`,
  Bitstream Vera Sans) has **none** of the eleven distinct characters the
  motto needs.
- Liberation Serif (present on this machine) covers all but one — it's
  missing `Ἀ` (U+1F08, Greek capital alpha with rough breathing/dasia —
  the polytonic Greek block, not the plain modern-Greek block most fonts
  bother with).
- DejaVu Serif covers the entire string, polytonic mark included.

## Fix

New `src/utils/pdf_fonts.py`: registers a bundled DejaVu Serif family
(regular/bold/italic/boldItalic — `resources/fonts/dejavu/`, checked into
the repo rather than referenced by a system font path like `/usr/share/
fonts/...`, since a system path is only as reliable as whatever font
packages happen to be installed on whichever machine runs this) with
ReportLab once per process (`ensure_unicode_fonts_registered()`,
idempotent), plus `wrap_unicode_runs()`, which wraps any run of
non-Latin-1 characters in a `<font name="DejaVuSerif">` Paragraph tag.

`cnb.py`'s `esc()` — the one function every piece of document text
already passes through before becoming Paragraph markup (document
titles, article/section headings, preamble/body text, suspension notes)
— now also calls `wrap_unicode_runs()` on its way out. This is a single
choke-point fix rather than touching each of the twelve call sites
individually, and it means any *future* non-Latin-1 text anywhere in a
governing document (not just this specific motto) is covered too.

**Scoped to exactly the characters that need it.** Ordinary Latin-1 text
— which is the entire rest of every document — is untouched and keeps
rendering in Times-Roman exactly as before. Confirmed by generating a
real PDF and inspecting it with PyMuPDF: the Greek spans report font
`DejaVuSerif`, the surrounding English text in the same sentence reports
`Times-Roman`, and the plain-text extraction of the page recovers the
motto correctly.
