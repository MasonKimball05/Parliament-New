Mason: "when taking minutes, if you press enter it shoots you back to the
top, can we update the logic so it keeps the user where they are instead
of basically having to reset their position on the page every enter they
type?"

## Root cause

`templates/officer/chapter_minutes_editor.html` renders minutes in a
single auto-growing `<textarea>` (`renderSections()`). On every `input`
event it resizes with the standard trick:

```js
this.style.height = 'auto';
this.style.height = this.scrollHeight + 'px';
```

Setting `height` back to `'auto'` collapses the textarea to its
`rows`-based intrinsic height — a value computed once, at creation, from
the line count *at that time*, and never updated as the user keeps
typing. On a long minutes document with the caret well below the fold,
that momentary collapse-then-regrow was enough to make the browser
re-anchor page scroll near the top of the (briefly short) textarea.
Enter was the most visible trigger because a newline moves the caret onto
a fresh line, making that frame's height delta the largest of any
keystroke — but the same collapse happens on every keystroke, just less
noticeably.

This template is shared by **both** chapter minutes and committee minutes
(`src/view/officer/chapter_minutes.py` and `src/view/committee/
committee_minutes_editor.py` both render it), so both were affected
identically and one fix covers both.

## Fix

Save `window.scrollX`/`window.scrollY` immediately before the two height
assignments and restore them immediately after, so the momentary collapse
never becomes a visible scroll jump:

```js
const scrollX = window.scrollX;
const scrollY = window.scrollY;
this.style.height = 'auto';
this.style.height = this.scrollHeight + 'px';
window.scrollTo(scrollX, scrollY);
```

No form-submit-on-Enter, autosave-triggered re-render, or global keydown
handler was involved — ruled out by checking: the textarea isn't inside
the page's one `<form>` (that only wraps the separate Publish button), and
no autosave path re-renders the DOM or calls `scrollTo`/`scrollIntoView`.
