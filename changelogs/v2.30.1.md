# v2.30.1 — KaiMemberPermission Enforcement

**Release date:** 2026-06-03

## Summary

Wires the seven `KaiMemberPermission` flags introduced in v2.30.0 into actual view and template enforcement. Previously the model and management UI existed but all Kai views still gated solely on `is_chair or is_admin`, making the granular per-member permissions inert. This release makes them functional end-to-end: view access, action execution, bulk operations, CSV export, and sensitive identity fields in templates are all now gated by the appropriate flag.

---

## Changes

### View-Level Access Gates

Non-chairs with no `KaiMemberPermission` row (or a row with all flags `False`) are now redirected to home with an error message rather than reaching any Kai content.

| View | Required flag |
|---|---|
| `view_kai_reports` | `can_view_report_list` |
| `export_kai_reports_csv` | `can_view_report_list` |
| `manage_kai_report` | `can_view_report_details` |
| `print_kai_report` | `can_view_report_details` |
| `bulk_actions_kai_reports` (entry) | `can_view_report_list` |

Template management views (`manage_kai_templates`, `create_kai_template`, `edit_kai_template`, `delete_kai_template`) remain chair/admin only — these are administrative, not member-facing.

### Action-Level Gates in `manage_kai_report`

POST actions inside the manage report view are now checked individually. Submitting a disallowed action redirects back to the report with an error message.

| Actions | Required flag |
|---|---|
| Mark reviewed, mark pending, update deliberation, update tags, link/unlink reports, update accused, notify accused, notify submitter | `can_edit_open_cases` |
| Add activity, update notes | `can_add_activity` |
| Archive, approve closure, deny closure | `can_close_cases` |

### Bulk Action Gates

`bulk_actions_kai_reports` now checks the action before executing:
- `mark_reviewed` / `mark_pending` → `can_edit_open_cases`
- `archive` → `can_close_cases`

### Identity Redaction in Templates

Rather than blocking access entirely when a member lacks an identity flag, sensitive names are silently redacted so a member can see a case exists without learning who is involved.

**`view_reports.html` (report list):**
- Submitter name → "Anonymous" without `can_view_submitter_identity`
- Accused name → "Redacted" without `can_view_accused_identity`

**`manage_report.html` (report detail):**
- "Directed To" section → name replaced with "Redacted" without `can_view_accused_identity`
- Sidebar "Submitted By" → name replaced with "Redacted" without `can_view_submitter_identity`
- Related Reports submitter → "Anonymous" without `can_view_submitter_identity`
- Notify Accused section → hidden without both `can_edit_open_cases` and `can_view_accused_identity`
- Notify Submitter section → hidden without both `can_edit_open_cases` and `can_view_submitter_identity`
- Deliberation form → hidden without `can_edit_open_cases`
- Chair Notes form → hidden without `can_add_activity`
- Tags edit form → hidden without `can_edit_open_cases`
- Mark Reviewed / Mark Pending buttons → hidden without `can_edit_open_cases`
- Archive button → hidden without `can_close_cases`
- Closure requests card → hidden without `can_close_cases`

**CSV export:** Submitter and accused columns output `[Redacted]` for members lacking the respective identity flags.

### Helper Added

`_get_kai_access(user, committee)` added to `src/view/kai_reports.py`. Returns a dict of all seven boolean permission flags plus `is_full_access`. Chairs and site admins always receive all `True`. Other users get their `KaiMemberPermission` row values; users with no row get all `False`. Passed as `kai_access` in the template context for all affected views.
