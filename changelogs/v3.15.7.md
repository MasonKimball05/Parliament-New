## Mobile compatibility — security dashboard + all security sub-pages

Complaint: on phones, header buttons ran off-screen and the page itself
scrolled horizontally (which also made table scrolling miserable). Tables were
already wrapped in `overflow-x-auto` (v3.15.0); the remaining offenders were
**non-stacking flex rows** — page headers using `flex items-center
justify-between` with fixed button groups, which force the page wider than the
viewport. Once the page overflows, every scroll gesture fights the table
wrappers.

Fix pattern (same one honeypot_logs already used):
`flex flex-col sm:flex-row sm:items-center sm:justify-between gap-4` on
headers, `flex-wrap` on button rows/badge rows, so everything stacks at phone
widths and nothing exceeds the viewport.

Applied to **12 templates**: `security_dashboard` (header + lockdown banner),
`security_alerts` (header, bulk-actions bar, alert-card badge row, alert-card
action buttons now drop below content on phones), `quarantine_management`
(header + card rows), `lockdown_control` (header + status banner, right-column
text left-aligns on phones), `security_notifications`, `csp_violations`,
`lockouts` (header + button group), `audit_log` (header + Export CSV group +
pagination), `ip_blacklist`, `ip_whitelist`, `user_login_security` (header +
temp-password card: wraps, password `break-all`), `manage_login_history`
(header, filter form now wraps, pagination wraps).

Bonus fix while in `manage_login_history`: pagination links dropped the
user/suspicious filters on page change — they now carry them.

## Member-status filter options (was Active-only)

Three places, per Mason's picks:

1. **Page Visits dashboard** — new status dropdown (All / Active / Inactive /
   Alumni / Removed) beside the member name filter, on both the aggregate and
   drill views; combines with the name filter; carried through sort toggles,
   header links, drill links, and back link. Unknown status values are treated
   as All. Both filter forms also wrap on mobile now.
2. **Quarantine user picker** — was `is_active=True` only, so
   inactive/alumni/removed accounts (which still hold credentials) couldn't be
   quarantined. Now lists all non-quarantined users, ordered by status then
   name, with non-Active members labeled "— <status>" in the dropdown.
   (Template var renamed `active_users` → `selectable_users`.)
3. **Manage Users status filter** — added the missing `Removed` option.
