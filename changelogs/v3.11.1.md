# v3.11.1 — Security Fixes & Hardening (2026-06-28)

**Type:** Security Fix / Bug Fix / Performance

---

## Security Fixes

### `legislation_detail` — Added `@login_required`
The legislation detail view was publicly accessible without authentication. Any unauthenticated visitor who knew or guessed a `legislation_id` could view legislation records, vote counts, and vote breakdowns. Decorator added; unauthenticated requests now redirect to login.

### `view_kai_reports` — Added `@login_required` + `@require_feature_flag`
The Kai reports view had no authentication or feature-flag gate. Kai reports can contain sensitive member concern or disciplinary information. Both `@login_required` and `@require_feature_flag('kai_reports')` added.

### `serve_exportable_media` — Added `@login_required`
The exportable media file-serving endpoint had correct path-traversal protection but no authentication check, allowing unauthenticated users to download files by filename. Decorator added.

### Admin-v2 Passkey Auth — Rate Limit on Challenge Generation
`admin_v2_passkey_auth_begin` now checks the lockout counter before issuing a WebAuthn challenge. Previously, an attacker with a compromised Django session could spam the begin endpoint without hitting any rate limit. The check now matches the existing 5-attempt / 15-minute lockout used by password auth and `auth_complete`.

## New Features

### Admin-v2 Passkey Second Factor
Adds WebAuthn as an alternative second factor for the admin-v2 login page. Users with registered passkeys see a "Use a Passkey instead" button beneath the password form. The flow uses `generate_authentication_options` with `UserVerificationRequirement.REQUIRED`, scopes `allow_credentials` to the user's own keys, verifies with `verify_authentication_response`, updates the sign count on success, and writes to `ActivityLog` for both success and failure. CSRF-protected via `X-CSRFToken` header.

### Admin-v2 URL Explorer
New page at `/admin-v2/url-explorer/` that enumerates every registered URL pattern, grouped by prefix, with inferred auth level (admin-v2 / officer / login / public), view name, and first-line docstring. Built live from Django's URL resolver — no manual maintenance. Searchable/filterable with Alpine.js. Response cached for 1 hour.

### `PledgePageRestriction` Onboarding Banner
When no page restrictions are configured, the VPE settings panel now shows a prominent dashed-border onboarding card explaining what the feature does (with a concrete example), instead of a one-line empty state. Includes a direct "Restrict your first page" button that opens the add-restriction modal.

## Performance

### Changelog / Roadmap Page Caching
`changelog`, `changelog_detail`, and `roadmap` views now use `@cache_page(60 * 30)` (30-minute TTL). These pages read and parse markdown files on every request; caching eliminates redundant disk I/O and markdown rendering on repeat loads.

### URL Explorer Response Caching
The URL introspection in `admin_v2_url_explorer` (which calls `inspect.getsource()` on every view callback) is now cached for 1 hour. First load does the traversal; subsequent loads are instant.

### Admin Dashboard — Removed Dead Queryset
`admin_v2_dashboard` was passing `all_feature_flags` (a second full `FeatureFlag.objects.all()`) in context that the template never referenced. Removed — saves one DB query per dashboard load.

## Other Changes

### `seed_feature_flags` — Metadata Sync on Re-Run
The management command now syncs `display_name`, `description`, and `category` on existing flags/toggles without touching `is_enabled`. Previously it silently skipped existing records entirely.

### `db_dump_view.py` Deleted
The officer-facing database dump view is removed. Reduces attack surface.

### Guide Pages Added to Global Search
The 5 guide pages added in v3.11.0 (`guide_chat`, `guide_service_hours`, `guide_pledge_tasks`, `guide_recruitment`, `guide_education`) are now indexed in `PAGES` and `OFFICER_PAGES` so they appear in global search results.

### Guide Index — Search & New Links
The guide index page now has a client-side search bar (Alpine.js) that filters all cards and sections in real time. Sidebar links added for Chat Channels, Service Hours, and Pledge Task Tracker.

### Email Tasks — Bulk Send Refactor
`send_event_signup_announcements` now uses `send_mass_mail` (single SMTP connection for all recipients). `send_weekly_chapter_digest` now uses `get_connection` + `EmailMessage` objects (all messages sent over one connection). Both had been sending one `send_mail()` call per recipient, opening and closing an SMTP connection for each.
