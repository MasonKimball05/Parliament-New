## 🟢 Mobile Phase 3 (part 4): Chat endpoints

Under `/api/mobile/v1/chat/channels/`, for the app's Chat tab:

- **`GET chat/channels/`**: the channels the member can read, each with its
  unread count, last message, whether they can write, and their notification
  level. Newest activity first.
- **`GET …/<id>/messages/?before=|since=<message id>&limit=`**: a page of
  messages (default the latest 50, max 100), oldest first, each flagged
  `can_edit` / `can_delete`. Fetching marks the member active in the channel,
  so they aren't pushed while looking (same as the web chat's polling).
- **`POST …/<id>/send/`**, **`…/messages/<mid>/edit/`**, **`…/delete/`**.
- **`POST …/<id>/read/`** `{up_to?}`: moves the read marker.
- **`GET|POST …/<id>/notification-level/`**: `all`, `mentions` or `none`.

**Access is ChatChannel's one rule, with no admin override.** The app has no
"View All Channels" mode, so an admin sees only what the rule admits them to;
Kai committee chat appears only for someone on that committee. A channel the
member can't read is a 404, so ids can't be probed. Behind the `chats` flag
and the `chat_index` toggle and pledge restriction, as on the web. (This means
the open "admin View All can read Kai" question stays a web-only one.)

**One implementation.** Sending, editing, deleting and read markers moved out
of `src/view/chat/channel_chat.py` into `src/chat_service.py`. That covers:
- the write rule
- the 5-per-3-seconds rate limit, now shared with the web
- @mentions only reaching people who can read the channel
- push text hidden for non-open channels
- the websocket broadcast

The website's endpoints call the same code, with the same responses.

**Live updates.** The app opens `/ws/chat/<id>/` with a socket ticket (Phase 1)
and gets the web's events. Until websockets are confirmed in production it
polls `messages/?since=`.

## 🟠 App sockets no longer get the admin "View All" override

The chat websocket admitted any admin to any channel (`admin_override=True`),
for the web's admin preview mode. That applied to app sockets too, so an
admin's phone could subscribe live to a committee channel they aren't on.
Ticket-authenticated sockets now get exactly what the app's endpoints give:
the `chats` flag plus the plain read rule. Browser sockets are unchanged.

## 🟡 `ChatChannel.unread_map` counts in the database

The web chat index's unread counts (and now the app's) fetched one row per
undeleted message in every channel and compared timestamps in Python, so the
cost grew with chat history. It's now one grouped query, with the same rule:
no receipt, or no marker message, means everything is unread. A test checks it
against the per-channel `get_unread_count` for every case.
