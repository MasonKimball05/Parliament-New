## 💡→✅ Quote Book

Mason, in chat: *"We used to have a discord server with a 'quote book'
where if someone said something outrageous or funny someone would quote
them there. Can we make something like that on Parliament? But it's an
actual 'book' ui and each chapter is just a different member?"* Four
design questions asked and answered before writing any code (all via
`AskUserQuestion`, answered together):

- **Who can add a quote?** Any member.
- **Can the quoted person remove it?** Yes — they can flag it, and while
  flagged it's immediately hidden. No review/approval step; flagging *is*
  the removal.
- **How literal should the book UI be?** A real animated page-flip, not a
  book-styled list.
- **Is the submitter shown?** Yes, on every quote.

### Data model — `src/models/quote_book.py`

One model, deliberately small:

```
Quote: quoted_member (FK, CASCADE), text, context (optional),
       submitted_by (FK, SET_NULL — a quote outlives its submitter's
       account), created_at, flagged_at, flagged_by (FK, SET_NULL)
```

Soft-hide, not delete — `flagged_at`/`flagged_by` set, row stays —
matching this codebase's standing soft-delete convention (Kai retention,
etc.) rather than introducing a new one for this feature alone, **with
one deliberate exception carved out later the same day** (see "Second
round of live feedback" below: a quote someone wrote about themselves can
be deleted outright by that same person).
`QuoteQuerySet.visible()` (`flagged_at__isnull=True`) is the one place
"is this quote showing" is decided; every reader goes through it.
Indexed on `(quoted_member, flagged_at)`, the only lookup the app ever
does. Migration `0034_quote_book` — new table, no data step, safe on a
live DB.

Three permission methods, all on `Quote`, each answering a different
question and each added at a different point in the session as Mason's
requests came in:
- **`can_be_flagged_by(user)`** — originally quoted-member-or-officer;
  widened same day to also include the submitter ("the person who
  submitted the quote can also remove it/flag it").
- **`can_be_deleted_outright_by(user)`** — true only when `user` is BOTH
  the submitter and the quoted member of that exact quote. See the
  delete-outright section below.
- **`can_be_restored_by(user)`** — whoever flagged it, the quoted member,
  or an officer. See the flagged-quote review section below.

### Views — `src/view/quote_book.py`

- **`quote_book`** — builds the whole book (every visible quote, grouped
  into chapters by member) in one request, one query
  (`select_related` + `member_defer` on `quoted_member`/`submitted_by`,
  grouped in Python since the queryset is already ordered by
  `quoted_member__name`). Hands the reader a single JSON payload; the
  view knows nothing about the flip animation.
- **`submit_quote`** — GET renders the form (member picker excludes
  `Removed` status, keeps alumni — the book is a record, not a roster),
  POST creates the quote. The `ActivityLog` entry is **structural-only**
  (who added a quote to whose chapter, and the quote's id) — same
  discipline this codebase established fixing the v3.29.10 FeedbackRequest
  leak: `ActivityLog.description` is readable by every officer and chair,
  so free text a member wrote doesn't belong in it, even here where the
  quote itself is otherwise visible on the book page to every member.
  Tested directly (`test_activity_log_never_contains_the_quote_text`).
- **`flag_quote`** — AJAX-only (JSON in, JSON out), not a redirect+reload.
  A full page reload on a page-flip book throws the reader back to page
  1, which is a bad experience for "reading, notice something, remove it,
  resume reading." Permission-checked via `can_be_flagged_by`, idempotent
  (a second flag call is a no-op, not a second `ActivityLog` row or an
  error — covered by `test_flagging_is_idempotent`).

Both `submit_quote` and `flag_quote` also log structural-only entries;
`quote_submitted` / `quote_flagged` added to `ActivityLog.ACTION_TYPES`
(migration `0035`, choices-only).

### Stored-XSS fix applied on the way in, not found after

Quote text and context are free-text member input, and `book.html`
embeds the whole chapters payload straight into a `<script>` block for
the page-flip reader to consume client-side. That is exactly the shape
`src/view/officer/transitions.py::_script_safe_json` was built to close
(v3.13.1, `roles_json` — a member name containing `</script>` could
terminate the script tag early). Rather than wait for an audit to find
the same shape again, `quote_book()` uses the identical fix
(`json.dumps(...).replace('<', '<')`) from the start. Covered by
`test_quote_text_is_script_safe_against_tag_breakout`, which posts a
quote containing a literal `</script><script>alert(1)</script>` and
asserts it never appears unescaped in the rendered page.

### The page-flip reader — `templates/quote_book/book.html`

Vendored `page-flip` (npm, v2.0.7, MIT, dependency-free) rather than
hand-rolling CSS 3D transforms — `static/vendor/pageflip/` (byte-identical
to the npm dist build, per this codebase's provenance convention;
`.integrity.json` updated with source/version/sha256/sri). One request
builds every leaf up front from the JSON payload — a cover page, a table
of contents (each entry jumps straight to that member's chapter), then a
title page + one page per quote for each chapter — and hands them to
`PageFlip.loadFromHTML`. Flagging is wired through the same AJAX endpoint
described above; a successful flag hides that page's content in place
(no reload, no re-init of the flip instance, page count stays constant).
The flag URL is built from a Django reverse with a placeholder id
(`{% url "flag_quote" 0 %}`, then `.replace('/0/', '/<id>/')` client-side)
rather than a hand-built string, matching
`src/tests/guards/test_hardcoded_urls.py`'s convention (`/0/` is already
an allowlisted URL-fragment pattern there).

⚠️ **Two identical near-misses on the same mistake, both caught by the
test suite rather than by eye.** A JS comment reading `` {% url %} `` (no
args) and another reading `` {% static %} `` (no args) — both meant as
prose describing what the code below does, neither inside a string —
were parsed by Django's template engine as real template tags anyway,
because Django doesn't know about JS comment syntax and scans the whole
file for `{% %}`. Both raised `TemplateSyntaxError` on every request and
were only caught because `src/tests/quote_book/test_quote_book.py` exists
and exercises the view — reworded both comments to describe the tags
in prose instead of writing their literal syntax. Worth remembering for
any future template that discusses its own template tags in a comment.

### Home page presentation — and a live UI fix mid-build

Landed once as a "featured card" in the 4-up home-page grid
(`home_modern.html`) and once as a card in the 3-up grid
(`home_classic.html`), mirroring the existing Songbook/Kai/Service Hours
cards. Mason, watching the app while this was being built, flagged two
problems with the modern layout: **the card sat alone on its own row**
(a 5th card in a 4-column grid has nowhere to pair with) and its text
**didn't match the site's actual dark-mode convention** — the card used a
hardcoded `text-white`, which happened to be legible but wasn't the same
mechanism as the rest of the UI.

Fixed by moving it out of the featured-card grid entirely and into the
**Quick Links** pill row instead, using the exact same `btn-secondary
btn-sm` component every other Quick Link uses
(`text-gray-700 dark:text-gray-200` — a real dark-mode-aware color, not a
hardcoded one). Pills wrap without ever leaving an orphan, so the
"own line" problem can't recur as more get added later. `home_modern.html`
now matches the pattern already established for My Attendance (v3.22.0):
nav items are capped at 9 selections
(`UserPreferencesForm.clean()`), the nav is a scarce resource by design,
and a fun/non-critical feature doesn't compete for one of those nine
slots. `home_classic.html`'s card was left as-is — its grid is 3-up and
Quote Book isn't the last item there, so it was never orphaned.

Also fixed on the same live feedback: the book pages themselves read as
an odd saturated mustard-yellow (`#fdf6e3`/`#f1e6c8`, meant as "aged
paper," read as just "yellow"). Toned down to a near-white warm gray
(`#fdfcfa`) that keeps the serif/paper feel without the color being the
first thing noticed, and the cover page was rebuilt in the chapter's
actual royal blue (`#003da5` → `#002275`, the same `primary-600`/`800`
gradient used elsewhere in the app) with the canonical chapter seal
(`{% static 'images/am-coat-of-arms.png' %}`, per the Resources/CLAUDE.md
convention — never `/exportable_media/`) embedded on it, rather than an
unrelated brown gradient.

### PageToggle, not `show_X_menu`

Gated by `@require_page_enabled('quote_book')` on every view — a
`PageToggle` row (seeded `is_enabled=True` in `seed_feature_flags.py`),
the same on/off kill switch every other whole-page feature in this app
uses, giving officers a way to turn the feature off without a code
change if it ever needs to.

## Second round of live feedback

Mason kept using the feature as it was being built and sent seven more
requests in the same session. Each is its own subsection; all are in
`templates/quote_book/book.html`, `src/view/quote_book.py`,
`src/models/quote_book.py`, and `src/tests/quote_book/test_quote_book.py`
unless noted.

**Line breaks were collapsing to one line.** A quote submitted with an
Enter in the textarea rendered as a single line — the newline character
wasn't stripped anywhere in the pipeline, but the browser's default text
flow collapses it like any other whitespace. `white-space: pre-wrap` on
the rendered quote text/context (both in the flip-book and the flagged-
quotes review list) fixes it without needing `<br>` conversion or extra
escaping.

**Multiple quotes per page.** Every quote had its own page; Mason asked
to fit several per page. Prerequisite fix: the byline was pinned to the
page bottom with `margin-top: auto`, which only made sense with exactly
one quote on the page — with several, it would land below all of them,
not the one it belongs to. Restructured to `.quote-page-body` (a flex
column holding N `.quote-block`s, `QUOTES_PER_PAGE = 3`) with each
quote's byline flowing directly under its own text, separated by a thin
top border between quotes on the same page. `overflow-y: auto` on the
page body rather than the page's usual `hidden`, since three long quotes
can run past the fixed page height — not adaptive to quote length (true
per-page pagination-by-content would need to measure rendered text,
which the fixed-size canvas doesn't make easy); a flat count is a
reasonable trade for a feature this size.

**Jump back to the table of contents.** Deep in a chapter (Mason's
example: page 40), Prev was the only way back — one click per page. New
"Table of Contents" button next to Prev/Next calls `pageFlip.flip(tocIdx)`
directly (the TOC's page index, captured when it's built rather than
hardcoded, since cover/TOC order is a detail of `addPage` call order).

**A visible book spine.** The flip library only draws a shadow *while* a
page is turning; at rest there was no sense of a binding, which Mason
asked for. Added a static `.quote-book-spine` — an absolute-positioned
gradient sibling over the canvas, `pointer-events: none` so it never
blocks the drag-to-flip gesture — restructured `.quote-book-stage` under
a new `.quote-book-stage-wrap` to have something to position it against.
**Follow-up bug, same request:** the static spine stayed visible *during*
an actual flip too, sitting on top of the animating page and reading as
a second, conflicting crease. Fixed by listening for PageFlip's own
`changeState` event (`'read'` = at rest, `'flipping'`/`'user_fold'` =
actively animating) and toggling the spine's opacity to 0 for anything
that isn't `'read'`.

**Cover page layout.** First version centered the seal image and both
lines of title text together as one vertically-centered group. Mason
asked for the title at the top and the seal centered in the remaining
space. `.book-cover-page` now uses `justify-content: flex-start` (title
flows normally from the top) with the seal wrapped in
`.book-cover-seal-wrap` (`flex: 1`, its own internal centering) filling
what's left below the text, rather than the whole block being centered
as a unit.

**The submitter can flag/remove their own submission — not just the
quoted member.** `can_be_flagged_by` widened to include `submitted_by`.

**Self-authored, self-quoted quotes delete outright — no flag, no
restore.** The sharpest of the seven. Mason: *"I submitted a quote for
myself then flagged it. I cannot remove my own quote flagged by
myself."* — the immediate bug was that `can_be_restored_by` (built in the
"flagged-quote review" section above) didn't yet exist in a form that
covered self-flagging; it does now (the flagger is one of the three
standings `can_be_restored_by` checks). Then Mason asked for something
further: *"if the person who flag[ged] it is the author and it's for
themself they can just delete it, no flag needed."* New
`Quote.can_be_deleted_outright_by(user)` — true only when `user` is BOTH
`submitted_by` and `quoted_member` on that exact row. `flag_quote` checks
this FIRST, before the normal flag path: if true, it calls `quote.delete()`
(a genuine hard delete, the one deliberate exception to this codebase's
soft-delete convention, reasoned about explicitly in the model's
docstring) and logs a new `quote_deleted` ActivityLog entry
(structural-only, same discipline as the other three action types) instead
of setting `flagged_at`. Nobody else gets this shortcut — not an officer,
not the quoted member alone, not the submitter alone — because in every
other case there's a party whose record a restore might need to bring
back; here there isn't. The reader's flag button becomes "Delete Quote"
with different confirm text (`delete_not_flag` in the JSON payload) when
this applies to the viewing user, but hits the same endpoint — the server
decides which action actually happens, not the client.

**"Did you set perms so the person who submitted the flag cannot approve
its removal?"** Answered directly rather than guessed at: restoring a
flag you placed yourself was never treated as "approving" anything in
this design (there's no approval step to begin with) — but a genuine
outside party (an uninvolved bystander) still cannot restore a flag they
have no standing over. New `review_flagged_quotes` / `restore_quote`
views (officer-only at first, then widened the same day once Mason said
"I do like that the person can see quotes they flagged and remove the
flag if they change their mind"): officers see and can restore every
flagged quote; anyone else sees and can restore only what
`can_be_restored_by` gives them standing over (a quote they flagged, or a
flagged quote on their own chapter) — scoped at the QUERY level, not
filtered after rendering, so a bystander with no standing can't tell from
the page that an unrelated flagged quote even exists. A "Flagged" button
with a count badge appears on the main book page for anyone with
something to see (officers always; everyone else only when
`flagged_count` is non-zero for them specifically).
