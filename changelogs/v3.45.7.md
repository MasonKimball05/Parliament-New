## 🟡 No Alpine expression has run in production since 06-14-26

### Before
`static/js/alpinejs.min.js` was the standard Alpine 3.14.3 build. It turns
every `x-data`, `x-show`, `@click` and `x-model` string into a function with
the `AsyncFunction` constructor. The production CSP (`script-src 'self'
'nonce-…'`, set by `InputSanitizationMiddleware.add_security_headers`) has no
`'unsafe-eval'`, so the browser refuses every one of them. `'unsafe-eval'` was
removed on 04-24-26; Alpine was added on 06-14-26, so it has never worked in
production. With `DEBUG=True` the middleware sends no CSP at all, which is why
it worked locally.

Checked in Chromium with each page's real HTML and real CSP header:

|---|---|
| `/onboarding/` (first login) | All six steps on the page at once; "Get started", "Save email" and "Skip" did nothing |
| `/home/` Getting Started checklist | Would not collapse; **Dismiss** did nothing |
| `/guide/` | Typing in the search box filtered nothing (27 of 27 cards stayed) |
| `/service-hours/events/create/` | Reminder time fields always shown, whatever the checkbox |
| `/admin-v2/url-explorer/` | Sections never opened from a click; the filter did nothing; 622 console errors |

Members were not locked out: the wizard's "Finish" is a plain form and its
password step is a plain link.

### After
- `static/js/alpinejs.min.js` is now **`@alpinejs/csp` 3.17.3**
  (`dist/cdn.min.js`, MIT, published 09-14-26). It parses expressions itself
  instead of using `eval`. 72 KB instead of 45 KB.
- The CSP build cannot parse methods written inside an `x-data` attribute, and
  cannot see `window` or `document`. So:
  - New `static/js/alpine-components.js` registers `guideSearch`,
    `urlExplorer` and `onboardingChecklist` with `Alpine.data`. Loaded in
    `base.html` just before Alpine.
  - `guide/index.html`: `x-data="guideSearch"`.
  - `admin_v2/url_explorer.html`: `x-data="urlExplorer"`. Each row's text is in
    `data-*` attributes (auto-escaped) instead of a JS object literal built with
    `escapejs`; the "No routes match" check is a method (the old one used
    `document.querySelectorAll` with an invalid selector).
  - `components/onboarding_checklist.html`: `x-data="onboardingChecklist"`,
    Dismiss calls `dismiss()`.
  - `onboarding/wizard.html`: registers its existing `onboarding()` function
    with `Alpine.data`. The function itself is unchanged.
  - `service_hours/create_service_event.html`: unchanged; its expressions are
    simple enough for the CSP build.
- Alpine is loaded with `{% static_v %}` in `base.html` and the wizard, so the
  new file has a new URL. With the plain `{% static %}` URL, browsers would
  keep the old build for up to 30 days (`immutable`).

Checked in Chromium after the change, same pages and CSP: zero Alpine errors on
all five; the wizard shows one step and moves welcome → email → password; the
checklist collapses and Dismiss POSTs and removes it; guide search "slating"
shows 1 of 27 cards and clearing shows 27; URL explorer opens a section on
click, "logout" shows 3 rows, a nonsense filter shows "No routes match";
the reminder fields hide and show with the checkbox.

### Why not add `'unsafe-eval'` instead
With the standard build and `'unsafe-eval'`, any HTML that reaches a page with
an `x-data` / `x-init` attribute in it runs as script, with or without the
nonce. That would undo what the nonce CSP is for. The CSP build only calls
what is registered.

## 🟢 `{% static_v %}` hashes the file nginx serves

v3.45.6's tag hashed the source file under `static/`. nginx serves the copy in
`STATIC_ROOT`. If Daphne restarted after `git pull` but before `collectstatic`,
the OLD file got the NEW url, and `immutable` (and Cloudflare) kept that pair:
the later `collectstatic` produced the same url, so browsers never fetched the
new file. Now, with `DEBUG` off, the tag hashes the `STATIC_ROOT` copy when
there is one, and falls back to the source. With `DEBUG` on (runserver serves
the source) it hashes the source, as before.
