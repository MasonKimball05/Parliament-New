# v3.15.1 — pledge-class registry: colors, dropdown, canonicalization

Mason's idea (07-19-26): every pledge class gets a unique highlight color on
the directory (like the Founders' gold), a dropdown makes the class easy to
pick, and the Greek letter is tracked automatically.

## Design: computed, not stored (no cron, no migration)

`src/pledge_classes.py` is the single source of truth. The full class list is
**derived from the current date** every time it's needed — Fall 2022 =
Founders, then Spring 2023 = Alpha, one per semester (Jan/July boundary). So:

- **No scheduled task.** The next class appears automatically the moment the
  calendar crosses the semester boundary — nothing to run in August/January.
  (A cron that *wrote* classes would just add a second source of truth that
  could drift.)
- **No migration.** Badge colors aren't stored on the user; they're resolved
  at render time from the `pledge_class`/`pledge_class_greek` fields members
  already have. An existing "spring 24" renders as Gamma without touching the
  DB.

## Colors — unique + guaranteed-distinct (Mason's two requirements)

`CLASS_PALETTE` is a 48-entry (24-year) palette generated once by
farthest-point sampling in CIELAB space (`scripts/gen_class_palette.py`,
deterministic, reproducible):

- **Unique** — no two classes share a color (test-asserted).
- **Noticeably different** — guaranteed min pairwise ΔE ≈ 14 across all 48
  entries plus the founder gold, well above the ~10 "clearly different to the
  eye" threshold (test-asserted).
- **Stable** — class index i always maps to `CLASS_PALETTE[i]`; adding a new
  class never recolors an existing one.
- Past 48 classes (~24 years) it wraps — the only case a color repeats
  (Mason's "unless it runs out of hexes" caveat), flagged in code.

## Dropdown + auto-filled Greek (live, both directions)

Profile edit and the admin edit-user form got a `<datalist>` of every class
("Spring 2024 — Gamma Class") on the semester field — pick or type freely.

`templates/components/pledge_class_sync.html` (shared include, emits the class
list via `json_script`) wires **live client-side sync**: picking or typing a
recognized semester instantly fills the Greek field AND canonicalizes the
label; typing a Greek name fills the semester. So one selection completes both
fields — nothing to type twice.

On save, `apply_to_fields()` canonicalizes server-side as the safety net: a
recognized semester rewrites to the canonical label AND sets the Greek from
the registry. Free-text that doesn't resolve is preserved verbatim
(legacy/non-standard members keep full freedom).

`normalize()` accepts the obvious shorthands: `Fall 2022`, `fa22`, `f 22`,
`fall '22`, `sp2024`, a Greek name (`beta`, `alpha beta`), `founder(s)`.

## Directory + House Map badges

`profile_card_json` now returns `pledge_class_badge` = resolved
`{greek, color, is_founders}` (or null). `directory.html` and the House Map
profile modal render each class in its own color pill; Founders keep the gold
gradient; unresolved legacy values fall back to the old plain text. House Map
family-tree nodes also get a small class-color dot beside each name (gold
gradient for founders), so classes are visible at a glance in the tree.

## Grandfathering existing members (optional, re-runnable — NOT a migration)

`python manage.py normalize_pledge_classes` (dry-run) / `--apply` (writes)
tidies stored free-text into canonical form and **lists any it can't match
for manual review**. Not required for badges to work (render-time
normalization already covers display) — it just makes the stored roster data
consistent. Safe to run anytime; idempotent.

## Tests / verification
