## 🟢 Second push, 10-27-26 (after the banner fix was deployed)

### `me/` says who can post announcements
New `can_post_announcements` on `GET /api/mobile/v1/me/`, for the app's
"New announcement" home screen quick action (hold the app icon). It is the
announcement page's own rule (`user_is_officer_or_chair`, behind
`officer_required`): officers, chairs and admins. `is_officer` alone would miss
chairs. The test checks it against the real create page for each member type.
- `src/mobile/views_auth.py`
- `src/tests/mobile/test_tokens_and_me.py`

### Fix: the app's calendar range lost late events on the day clocks change
`events/?to=` ended at the last day's midnight + 24 hours. In Central time,
2026-11-01 is 25 hours long, so an event after 11 PM that day was left out (and
on a spring-forward day an hour of the next day was let in). It now ends at the
next day's local midnight. Found because the existing test's "five days from
today" landed on Nov 1; the new test uses fixed dates for both changes.
- `src/mobile/views_calendar.py`
- `src/tests/mobile/test_calendar.py`

## 🟢 Third push: phone audit of the site (Mason, 10-27-26)

Ran the app in the iOS Simulator against a local copy, plus a script that loads
every page at 390px and flags anything wider than the screen, inputs under
16px and tiny tap targets. Fixes:

### Fix: about 17 pages had buttons that did nothing in prod
Prod CSP has no `'unsafe-inline'`, so `onclick=` / `onchange=` / `onsubmit=`
attributes are dead in prod and fine in dev (no CSP there). The CSP guard had
been carrying 17 such templates as a known-bug list, including the chat "mark
all read" × on every page, the profile checklist's Hide/skip, Restart
Onboarding, the recruitment and service-event delete/apply confirmations, the
status filters that submit on change, the QR copy buttons, the committee
document Replace dialog, and clickable table rows. All rewired to `data-*`
attributes handled by the new `static/js/base/data-actions.js`
(`data-confirm`, `data-autosubmit`, `data-href`, `data-copy`,
`data-select-on-click`, `data-show`, `data-hide`) or the page's own nonce'd
script. The known-offender list is now empty, so the guard bans them outright.

### Fix: the calendar hid Friday and Saturday on phones
The month grid had `min-w-[500px]` at every width, so on a phone Fri/Sat sat
off to the side of a scroll box. All 7 days now fit (`sm:` keeps the old
minimum on wider screens). The legend wraps.

### Fix: iPhones zoomed in on every small text field
iOS zooms the page when a field under 16px gets focus (Profile had 24 such
fields, Vote 7, ...). Under 768px every text field, select and textarea is
16px (`static/css/tailwind-input.css`).

### Fix: date/time fields spilled out of their boxes on iPhone
iOS gives date inputs a native minimum width that `w-full` doesn't beat (the
announcement form's Publish Date and Event Date). Fixed once in the base CSS
for date, datetime-local, time and month inputs.

### Fix: archived events sent officers to the login page
`user_passes_test(lambda u: u.is_admin)` answers a signed-in non-admin with a
login redirect. The three archived-event views now use `admin_required`
(403 "Admins only."). Test: `src/tests/events/test_archived_events_access.py`.

### Layout
- Announcements: phone padding, title/badge wrap, short search placeholder,
  filter row wraps, "Posted by" and the date on their own lines. New/Manage
  buttons now show for admins too (same rule as the pages they open).
- Officer activity / legislation cards: buttons go under the text on phones
  (they ran 12px off the screen).
- Changelog pages: long file paths in `code` wrap (the page was 625px wide).
- Page guide close (×), profile checklist Hide/skip: bigger tap targets.
- Chat: the message box placeholder is just "Message #channel" (the Enter /
  Shift+Enter hint was cut off on phones, where it doesn't apply); the hint
  shows under the box on wider screens.

## 🟢 Fourth push: admin-v2 modernized (Mason, 10-27-26)

No migrations. Adds CSS and a JS file: run `collectstatic`, then restart.

### New layout and search
- A grouped sidebar (Overview, People, Content, Comms, Security, System)
  replaces the 13-tab bar; on phones it's a drawer from the ☰ button. The
  sections are one list, `src/admin_v2_nav.py`, read by the sidebar and the
  search, so they can't drift.
- ⌘K / Ctrl+K (or "/", or the search box) searches admin pages by name or
  keyword ("2fa", "ip", "backup") and members by name, username, email or
  number. Enter opens the highlighted result. `static/js/admin_v2/palette.js`,
  no inline handlers.
- Dashboard: a "Needs attention" strip at the top with only what's waiting:
  lockdown, critical and new security alerts, active lockouts, quarantined
  accounts, failed announcement emails (24h), API token requests, new bug
  reports, unread contact messages, CSP violations. Each links to its page
  (`src/admin_v2_attention.py`; a failing source is skipped, not a 500).

### Member page (`/admin-v2/members/<id>/`)
Everything about one member on one screen: profile, roles, committees (and
which they chair), 2FA and passkeys, failed sign-ins in 30 days, watch flag,
app devices, web sessions, recent sign-ins and activity (Kai rows excluded).
Actions: edit profile, login security, release lockout (comes back here),
reset password (opens the existing form with its options), **sign out
everywhere** (every web session and app install), and **sign out one app
install**. Both new actions are logged. Names in the Members list link here.

### Mobile app page (`/admin-v2/mobile/`)
Signed-in installs (total, members, iPhone, Android, push on, active this
week), app versions in use, recent sign-ins, a server setup check (Expo token,
iOS team and bundle, Android package and certificate: set or not, never the
values), pushes awaiting an Expo receipt, and **send a test push** to a member.

### Ops
- **Backups** (`/admin-v2/backups/`): newest backup's age (warns past 48h, the
  verify drill's limit), the restore drill history from SecurityNotificationLog
  (a failure newer than the last success shows as a red banner), and the backup
  folder's file names, sizes and dates. It never opens or runs a backup.
- **Maintenance** (`/admin-v2/maintenance/`): maintenance mode on/off with a
  confirm, lockdown status, and every feature flag and page switch; the toggles
  come back to this page.
- System logs, bug triage and the static-asset monitor are in the sidebar
  (their pages are unchanged).

Tests: `src/tests/admin_v2/` (22).
