## 🔴 Anonymous ballots were written to the officer-visible log by name

`src/ballots.py` `cast()` and `cast_committee()` logged
`<username> voted 'no' on '<bill>'` to the `function_calls` logger for every
bill, anonymous or not. That logger writes `logs/django_actions.log`, and
`/officers/system-logs/` shows its last 200 lines to every officer (its
redaction only covers Kai lines). The old web vote view did the same before
v3.55.0; the shared ballot code carried it to app ballots and committee ballots
too.

- On an anonymous bill the line now reads `<username> voted (anonymous) on …`.
  Open bills still log the choice.
- Test: `src/tests/legislation/test_anonymous_ballot_log.py`.
- **Not done by this release:** lines already in prod's `django_actions.log`
  (and its rotated copies) still hold past anonymous choices. Scrubbing them is
  a server-side step for Mason; see the 10-28-26 auto-run report.

## 🟡 Location check-in

- **Hidden and archived events.** `POST events/<id>/checkin/location/` looked
  the event up by id only, so a member could check in to an event they can't
  see, and the `too_far` reply's `distance_m` let them find where it was. The
  lookup now uses the same rule as `checkin-areas/` (`visible_to_q`,
  `archived=False`); anything else is a 404.
- **An officer's "absent" or "excused" is kept.** A check-in only fills a
  missing or `pending` row. It used to overwrite anything but present/late, so
  the next geofence ping undid an officer's "absent". New refusal
  `checkin_already_marked` (409) with a message for the member.
- **`nan` / `inf` / out-of-range coordinates** are a 400 instead of a 500, and a
  non-finite or negative accuracy is `checkin_inaccurate`.
- **`MobileDevice.checkin_key_hash`** is now in `MobileDeviceAdmin.exclude` (and
  so out of the CSV export), like the other device hashes, and in the test's
  `SECRET_FIELDS`.

## 🟡 Admin v2 "Remove all roles" left Kai permissions in place

`roles.clear()` sends `m2m_changed` with `pk_set=None`, and the Kai and
Education permission resets in `src/signals.py` only run with a `pk_set`. So
bulk "Remove all roles" on an outgoing Kai chair (the end-of-year case the
action exists for) kept every `KaiMemberPermission` grant and Kai chat guest.
Bulk edit and `ParliamentUser.anonymize()` now use
`roles.remove(*roles.all())`, which goes through the same path as a single
"Remove role". Test in `src/tests/admin_v2/test_bulk_members.py`.
