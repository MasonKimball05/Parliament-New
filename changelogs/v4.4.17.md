## Archived elections can still be managed

The slating dashboard and the app's Slating screen listed only active
periods, so once a period was archived nothing linked to it. Its chair
couldn't get back to destroy the interview notes, as the bylaws require, or
delete the period. The pages themselves still worked; there was just no way
to reach them.

- **The slating dashboard** gains **Archived Elections**, shown to whoever ran
  or reviewed a period: each archived period with how many interviews still
  have notes, and links to **Interviews** (where the notes are destroyed),
  **Results** and, for the people running it, **Manage election** (where a
  site admin can delete it). Ordinary members don't see it.

### In the app

- `slating/` gains `archived`: each `{id, name, term, is_chair, is_committee,
  notes_remaining}`, for the archived periods this member ran or reviewed.
- The app's Slating screen lists them under **Archived elections**:
  Interviews (with how many still have notes), Results, and for the chair
  Election setup (Delete the election).

## Django admin list pages stop running a query per row

The dev panel showed `/admin/` list pages firing the same query 11 to 16
times a page. Measured on the local demo chapter: Chat messages 37 queries
before, 16 after; Roles 18 to 12; Committees 17 to 13. The savings grow with
the number of rows on the page.

- **Linked columns are joined.** Django joins a link column itself only when
  the link can't be empty, so a chat message's channel or committee cost a
  query per row. Every admin list now joins all its link columns, including
  ones that can be empty. A column that prints something further along (an
  application shows its applicant and election, a section its document)
  joins that too.
- **Counts are counted once.** Members per role, members and chairs per
  committee, documents per tag, votes per legislation and views per
  announcement were each a query per row. They're now counted in the page's
  one query, and those columns can be sorted.
- **Committee documents' tags** are loaded once for the page.

A test reads every admin list, so a new link column that would query per row
fails the suite.

## Destroying the committee's notes covers everything, from Election setup too

*Added after the first v4.4.17 deploy, same day.*

"Destroy interview notes" erased only each interview's notes, strengths and
concerns. The recommendation level, recommended positions, the committee's
verdicts on applications (Slated, Recommended and the rest), review notes and
GPA checks all survived. It's now **Destroy the committee's notes**, and erases:

- each interview's notes, strengths, concerns, **recommendation level** and
  **recommended positions** (also on interviews whose notes were destroyed
  before today);
- the committee's **verdicts on applications**: Under review, Interview
  scheduled, Interviewed, Recommended, Not recommended and **Slated** go back
  to Submitted (Draft and Withdrawn stay);
- each application's **review notes** and reviewer;
- **GPA screenshots** (the files too), GPA levels and the verified check (the
  GPA the applicant typed stays);
- **draft and alternative slates nobody voted on**.

What stays: the applications as sent, interview dates and who interviewed,
every slate that was voted on, and the results. The results summary's
interviewed and slated counts read zero afterwards.

- **Only once the results are published** (or the period is archived). It now
  resets statuses and deletes slates, so it would wreck an election still in
  progress. Before then the panel says so instead of offering the button.
- **Election setup** shows the panel right under the status card once the
  results are published, as well as on Interviews.
- It's logged with how many interviews, applications and slates it touched.

### In the app

- `slating/periods/<id>/interviews/` gains `destroy`: `{interviews,
  applications, slates, any, allowed}`. `destroy-notes/` refuses with 409
  `too_early` before the results are published.
- Interviews shows **Destroy the committee's notes** with what it erases (or
  "Available once the results are published"), and Election setup gains a
  button to it once the results are out.
