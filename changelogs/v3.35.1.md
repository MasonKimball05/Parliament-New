## C&B cross-references corrected

These are the four findings from `check_cnb_references` (v3.35.0). Mason decided to fix them directly rather than through a resolution. They are wording corrections only; no rule changed.

| Where | Was | Now | Why |
|---|---|---|---|
| Constitution V §1 3(a) | "Article VII, Section 1 (a) (vi-x) be met" | "… (vi-x) **of the Bylaws** be met" | The Constitution has no Article VII. Bylaws VII §1 (a) vi–x is the Kai recusal chain. |
| Bylaws VI §2 3(g) | Kai operations "in Article **VI**, Section 1 (a)" | "Article **VII**, Section 1 (a)" | VI §1 is board expectations; the Kai procedures are VII §1 (a). |
| Bylaws VII §10 c.i.2 | "See Article **VI** of the Bylaws for amendments to the Bylaws" | "Article **X**" | Bylaws Art. X is Amendments to the Bylaws. |
| Bylaws VII §10 c.i.2 | "See Article **VII** of the Constitution for amendments to the Constitution" | "Article **VI**" | Constitution Art. VI is Amendments to the Constitution. |

### How the change reaches each database
- **Existing databases (prod):** `0055_fix_cnb_cross_references` makes the edit.
  - It replaces each phrase only if that exact phrase is present, so a section a resolution already reworded is left alone.
  - It records the outgoing text as a `SectionRevision` (`direct_edit`, with a note), so the history page and `?as_of=` stay correct.
  - Re-running it is a no-op. It reverses cleanly.
- **Fresh installs:** the seed text (`src/management/data/cnb_data.py`) got the same edits.

### Tests
- `KNOWN_PROBLEMS` in `test_cnb_crossrefs.py` is now empty.
  - The strict-mode test and the manage-tab test now plant a bad reference, so the failure paths are still exercised.
  - A new test checks that `--strict` passes on the clean seed.
- New `src/tests/legislation/test_cnb_crossref_fix_migration.py`:
  - it fixes the old wording and records history;
  - it is idempotent;
  - it leaves a reworded section alone;
  - it reverses;
  - the checker is clean after it runs.

## Deploy
1. `git pull`
2. `python manage.py migrate` (applies `0055`)
3. `sudo systemctl restart parliament-gunicorn.service`

There are no static files, Celery changes or dependency changes. Afterwards, the C&B Manage tab should show no cross-reference problems.

**Note:** if prod never received v3.35.0's `seed_cnb_documents --force --only …bylaws:VII:10` step, the Bylaws VII §10 wording on prod differs from the seed text. The migration then skips that section, and the checker will still flag it. Running that v3.35.0 step first, then `migrate`, fixes it.
