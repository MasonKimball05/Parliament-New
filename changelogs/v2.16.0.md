# Changelog v2.16.0

**Date:** May 24, 2026
**Status:** Deployed

---

## Features

### Directory: Alumni Display
- Added "Show Alumni" toggle to the member directory header
- Clicking the toggle reloads the page with `?show_alumni=1` and appends an Alumni section below Advisors
- Alumni cards use an indigo color scheme with roll number and Alumni badge displayed
- Alumni are fully searchable via the existing client-side search when shown
- Toggle chip changes to "Hide Alumni" (with an X) when active

### Directory: Export Options Modal
- Replaced the simple export format dropdown with a full Export Options modal
- **Format selection:** CSV, Text, or Excel (.xlsx) via radio buttons
- **Member options:** Checkbox to include alumni in the export
- **Field options:** Toggle individual columns on/off per export
  - Roll Number (on by default)
  - User ID (off by default)
  - Email (on by default)
  - Phone (on by default)
  - Member Type (on by default)
  - Member Status (off by default)
  - Roles (on by default)
- Export view uses a `_export_submitted` sentinel to distinguish form submissions from direct links, preserving backward-compatible defaults for the latter
- All three export formats (CSV, TXT, XLSX) now share a single dynamic column spec — adding a field in the future only requires one change

### Non-Repudiation: Voting Audit Trail
All chapter and committee voting actions now write to `ActivityLog`. These were previously only written to the Python application logger with no permanent DB record.

**Vote cast** (`vote_view.py`, `committee/vote.py`):
- Anonymous votes: logs that the user voted, the legislation, and vote mode — **does not record their choice**
- Non-anonymous votes: logs full choice(s) in metadata
- Handles both single-select and multi-select (plurality) voting
- Committee votes also include the committee code in metadata

**Vote ended** (`end_vote.py`, `committee/vote.py`):
- Logs who ended the vote, the result (passed/failed), vote mode, and total vote count
- Non-anonymous: also logs the full vote breakdown in metadata
- Committee vote recalculation (chair action) also logged

**Legislation created** (`vote_view.py`, `end_vote.py`, `committee/vote.py`):
- New legislation and runoff vote creation now logged with vote mode, anonymous setting, and options in metadata

### Non-Repudiation: Extended ActivityLog Coverage
Added `ActivityLog` entries to user-facing actions that previously only wrote to the Python application logger (text files). All entries include IP address, user agent, and metadata with field-level detail.

**Profile changes** (`profile_view.py`):
- Profile info updates (username, preferred name, email, phone) — metadata includes a `changes` list with `field`, `old`, and `new` values for each changed field
- Profile picture upload — metadata includes filename
- Profile picture removal
- Password change via profile page
- Notification preference updates — metadata includes the new notification settings

**Password changes** (`change_password.py`, `forced_password_change.py`):
- Standalone password change view now writes an `ActivityLog` entry
- Forced password change (admin-initiated reset flow) writes an entry with `metadata: {forced: true}` to distinguish it from voluntary changes

**Bug reports** (`bug_report.py`):
- Submission of a bug report is now logged with issue type, priority, page, and URL in metadata

### New ActivityLog Action Types
Added to `ActivityLog.ACTION_TYPES` (no migration required — choices are metadata only):
- `profile_updated` — profile field changes (category: user)
- `profile_picture_changed` — picture upload or removal (category: user)
- `bug_report_submitted` — bug report creation (category: other)
- `email_sent` — general-purpose email audit type (category: other)
- `kai_action` — Kai committee action (category: kai)

Added `kai` to `ACTION_CATEGORIES`.

### Non-Repudiation: Kai Audit Trail
All Kai committee actions now write privacy-safe entries to `ActivityLog` (action category: `kai`, action type: `kai_action`). Descriptions include only the case number and action taken — no title, description, category, or party names.

**Logged actions** (`kai_reports.py`, `kai_user_dashboard.py`):
- `submitted` — report created by submitter
- `mark_reviewed` / `mark_pending` / `archived` — chair status changes
- `update_notes` / `update_tags` / `update_deliberation` — chair field edits
- `notify_submitter` / `notify_accused` — outbound notification emails
- `link_report` / `unlink_report` — related case management (metadata includes linked case ID)
- `update_accused` — accused person set or cleared
- `approve_closure` / `deny_closure` — closure request decisions
- `request_closure` / `request_drop` — user-initiated requests
- `bulk_mark_reviewed` / `bulk_archive` / `bulk_mark_pending` — bulk actions (single log entry with count, no per-case detail)

### Kai: Submitter Email Read Tracking
The Kai chair can now see whether the submitter opened their outcome notification email, mirroring the existing accused email tracking.

- `KaiReport` model gains two new fields: `submitter_notified_at` and `submitter_email_viewed_at`
- Migration `0162` adds both columns
- `notify_submitter` action now sends an HTML email via `EmailMultiAlternatives` with a 1×1 tracking pixel at `/kai/track-submitter-email/<id>.gif`
- Sending a new notification resets `submitter_email_viewed_at` (same behavior as accused)
- `manage_report.html` Notify Submitter section now shows "Notified [date]" + "Viewed [date]" / "Not yet viewed*" badges identical to the accused section; button label changes to "Send Again" after first send

### Admin-v2: User Activity History Panel
Added an "Activity History" section to the per-user security page (`/admin-v2/users/<id>/security/`), placed above the existing Login History table.

- Shows up to 100 most recent `ActivityLog` entries for the user
- Filter by **action category** (Auth, User, Settings, etc.) and **date range** (24h / 7d / 30d / 90d / all)
- Columns: timestamp, category badge (color-coded), action type, description, IP address, metadata toggle
- "Show / Hide" button on each row expands raw metadata as formatted JSON
- If capped at 100, a link to the full Activity Logs page is shown with the user pre-filtered
