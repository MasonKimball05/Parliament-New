## 1 — overdue tasks are visible

`PledgeTask.due_date` has existed since the model was written and was surfaced
**nowhere**. A task three weeks late rendered identically to one due tomorrow,
on the pledge's page and on the chair's.

New `PledgeTask.is_overdue_for(completion)`.

⚠️ **Overdue is a property of a (task, pledge) PAIR, never of a task alone** —
the same task is finished for one pledge and late for another, so a badge on the
task row would be wrong for somebody. The method takes the completion and
handles `None`, because *a pledge who has never been marked is the common case
and the one most worth flagging*.

`waived` counts as done: a chair has decided he does not need to do it, and
nagging him about someone else's decision is not a feature.

**On My Tasks:** a count in the header (*"2 tasks past due"*), the row tinted,
and the due-date chip turning red with *"Past due — was Aug 4"*. The header
banner exists because the alternative is scanning every phase group for red
text, which is the same "make them hunt for it" problem in a new costume.

## 2 — "everyone came except two"

Taking attendance for a fifteen-pledge class meant fifteen individual choices to
record one fact. There are now **Present / Absent / Clear** bulk buttons above
the roster, then you change the exceptions.

⚠️ **Client-side only, deliberately.** The buttons move radio inputs; nothing is
written until *Save attendance*. So a misclick costs nothing, and **no endpoint
exists that can bulk-write a roster** — a test asserts that, so if someone adds
one later it gets its own authz review rather than arriving as a UI convenience.

## 3 — a page per pledge

`/committee/EDUCATION/education/pledge/<pk>/`, reached by clicking a pledge's
name anywhere on the dashboard.

The grid answers *"who has not done task 4"*. It is useless for *"how is Jack
doing"*, which is the actual question before a progress conversation or an
initiation vote — and answering it meant reading across a grid and doing
arithmetic in your head. One page now shows his tasks and marks, what is
overdue, which meetings he attended and missed, and the points from both.

Two decisions worth keeping:

- **Read-only.** Marking still happens on the grid and the attendance page, so
  there is exactly one place to change each thing and this page cannot disagree
  with them.
- **Tasks assigned to other pledges are excluded, not greyed out.** Counting a
  task that does not apply to him would misreport his progress — and this page
  is read before an initiation vote. `test_required_progress_counts_only_
  applicable_tasks` pins it.

## ⚠️ Sixth self-inflicted comment bug, caught by the same guard again

v3.16.3's `test_template_comments` failed twice in this release, both times on a
multi-line `{# … #}` I had just written. Django's hash comment is
**single-line only** — a multi-line one is not a comment, it renders and is
evaluated.

That check has now caught me three times in one day and cost nothing each time,
which is the argument for this kind of test in miniature: it is not clever, it
does not need maintaining, and it turns a subtle rendering bug into a named file
and line before the code leaves the machine.

**The lesson is about me, not the guard:** in a Django template, reach for
`{% comment %}` by default and keep `{# #}` for genuinely one-line notes.
