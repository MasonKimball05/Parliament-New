## Slating: ballots can't be traced back in the database

Slating votes were already kept apart from the record of who voted, with no
shared key, and the admin pages hid anything that could pair them up. But
anyone reading the database directly could still match them:

- **Timestamps.** Each vote stored the time it was cast, which matched the
  voter's "has voted" record to the microsecond.
- **Numbering.** Votes were numbered in the order they came in, so the 5th
  vote of a round belonged to the 5th person who voted.

Now:

- Votes have **no timestamp at all**.
- Votes are keyed by a **random ID** instead of a number.
- Votes already recorded, including Saturday's, lose their timestamps and
  get new random IDs. The table is then reordered by those IDs, so even its
  storage order no longer follows the order ballots were cast.

Nothing changes for members or the committee: who has voted, the counts,
rejection reasons, results and publishing all work as before.

**One thing to know:** database backups taken before this deploy still have
the old timestamps. If ballot secrecy for Saturday's election matters to
you, delete or lock down the older backups once a new one has been taken.

**For developers:** never add a creation time, a sequence, or anything else
ordered by casting time to `SlatingVote` (see the model's docstring). Tests:
`src/tests/slating/test_ballot_unlinkable.py`, including a run of the real
migration over existing votes.

## Slating pages in the refreshed look

The last part of the site still in the old look (with the refresh on:
Admin v2 → Feature Flags → "Website refresh", or `?ui=refresh`). With the
refresh off, every slating page is exactly as before.

- **Members:** the slating dashboard, applying, My Applications, both
  ballots and the results pages. On the whole-slate ballot, Approve / Reject /
  Abstain are large cards that fill in when picked; Reject now says up front
  that you'll pick at least one position, and the position list is clearly
  marked. Position ballots get large option cards. Results show stat tiles,
  a thicker approval bar with the threshold marked, and a clear verdict.
- **Committee:** application review (status counts as tiles, compact rows),
  application details, interviews (filter tabs as a segmented control),
  scheduling and recording interviews, the slate builder and preview,
  attendance (a pill-style present/absent toggle), paper ballots, manual
  results and the next-round form. Approve and "mark present" buttons stay
  green.
- **Setup:** period setup (settings as cards, and a Save bar that stays at
  the bottom of the window), positions, the form builder, importing
  applications, filling in imported answers, transferring the manager role,
  and the officer transition pages.

**Fixed (both looks):** during deliberation, the stage card on period setup

## System Logs, reworked

Officers → System Logs (and Admin v2 → Operations → System logs) had not
changed in a long time, and several things on it didn't work:

- **Fixed:** it opened scrolled to the bottom, but the newest lines are at
  the top, so you landed on the oldest ones. It now opens at the top.
- **Fixed:** the green "Live" dot was decoration; nothing refreshed.
- **Fixed:** an error's traceback showed as separate lines *above* the
  error (the list is newest first). Each traceback now sits under its error,
  collapsed to "4 more lines".
- **Fixed:** colors came from words anywhere in the text, so any line
  mentioning "INFO" turned blue. The level is now the logged level, written
  on every row.

New:

- **Filters:** level (all, info and up, warnings and errors, errors only),
  source (with a count for each), and search, which also looks inside
  tracebacks. Click any row's source to see only that source.
- **Counts** of errors, warnings and entries at the top; click one to filter.
- **More history:** the last 200, 500 or 1,000 lines; newest or oldest first.
- **Live:** a Live / Paused switch checks for new lines every 10 seconds
  (it waits while you have a traceback open). Remembered in your browser.
- **Download .txt** and **Copy** of what's shown, with timestamps.
- **Expand details** opens every traceback at once.
- Rows grouped under the day they're from, and it works on a phone.
- In an Admin v2 session with the console look on, the page uses the
  console look; officers otherwise keep the site look.

The same redaction applies throughout (Kai reporters and case details are
removed), including the download and the auto-refresh. The Django admin's
old "View logs" copy, which read the whole file without that redaction, now
opens this page. The app's System Logs screen is unchanged.

## CI fixes (main was red after the 11-07 push)

- **Security scan:** the admin console's icon tag used `mark_safe`, which
  the bandit scan fails on. The icon shapes are fixed text that escaping
  doesn't change, so it's gone; a test checks every icon still renders the
  same.
- **Admin console query test:** the number of queries depended on whether
  the machine had Redis. With Redis the background-worker check errored and
  skipped reading the job schedule; on CI it didn't, one query more. The
  test now fakes that check, so every machine counts the same (classic
  dashboard 47, console 38).
