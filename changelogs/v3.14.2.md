# v3.14.2 — file-serving hardening, filename sanitization, dispatcher removal

07-19 batch (Mason-directed). Part 1: the header fixes from the morning
review. Part 2 (same day): upload filename sanitization at the storage
layer, removal of the legacy `/vote/` POST dispatcher, and the
`docs/ARCHITECTURE.md` handoff overview.

## `src/view/serve_media.py`

- **X-Accel-Redirect path is now percent-quoted** (`urllib.parse.quote`).
  Before, a space / `%` / non-ASCII character in an uploaded filename would
  produce an invalid internal URI once `MEDIA_ACCEL_PREFIX` is enabled —
  nginx would 404 or error on the mismatched location.
- **Content-Disposition built with `django.utils.http.content_disposition_header`**
  (RFC 5987/6266). The old `f'inline; filename="{name}"'` broke on a `"` in
  the filename and mangled non-ASCII names.

## `src/view/songbook.py`

- Same `content_disposition_header` swap in **both** `serve_song_audio` and
  `serve_exportable_media` (identical raw f-string pattern).
- **Traversal-guard tightening in `serve_exportable_media`:** the check was
  `startswith(exportable_root)` without a path-separator suffix, so a
  hypothetical sibling directory (`exportable_media_x/`) would have passed.
  Now `startswith(exportable_root + os.sep)`, matching `serve_media.py` and
  the audio view. Defense-in-depth only — no such sibling directory exists,
  and the path is joined from a URL segment under `BASE_DIR`, so this was
  not exploitable as deployed.

## Upload filename sanitization (`src/storage.py` + settings `STORAGES`)

- New `SanitizedFilenameMixin.get_valid_name`: slugified stem (`'file'`
  fallback), lowercased alphanumeric-only extension. Wired into a new
  `SanitizedFileSystemStorage` (now the settings-level default storage) and
  into `DualLocationStorage`, so **every FileField** gets it — no
  per-field `upload_to` churn, no migrations (`makemigrations --check`
  clean). Collisions still get Django's random suffix.
- Root-causes the header-quoting bug class for future uploads; existing
  files on disk keep their names (the serve-view header fixes above cover
  those).
- Note: `Storage.save()` called directly bypasses the hook (only the
  FileField `generate_filename` path sanitizes). Verified no view calls
  `storage.save()` with a user filename; documented in the test.
- Tests: `src/test_upload_sanitization.py` (9: mixin unit coverage on both
  storage classes, STORAGES wiring, end-to-end save).

## Legacy `/vote/` POST dispatcher removed (`src/view/vote_view.py`)

- The v3.14.1 forwarding dispatcher is gone; `vote_view` keeps an explicit
  guard that answers ANY POST with the "page may be out of date — reload"
  error. Rationale: since v3.14.1 never deployed, there are no live tabs
  posting old-style forms — but the guard must stay so a stale tab across
  the upcoming deploy gets told to reload instead of silently dropping a
  ballot (the v3.13.3 rule). Do not reduce `vote_view` to bare GET-only.
- `test_vote_reauth.py` rerouted to the split endpoints (10 call sites) +
  new regression test: a well-formed old-style cast POSTed to `/vote/`
  records nothing and shows the reload error.
