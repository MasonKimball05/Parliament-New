Fixes from the 11-19-26 penetration test of `main`, which was run against a
local copy, never against production. Each fix has a regression test that
fails on v4.4.14.

## Committee document visibility now applies to the file itself

A committee document set to **Committee Members Only**, **Chairs Only**,
**Officers Only** or **Custom** was hidden from the lists. Its file, though,
could still be opened at its `/media/` address by any signed-in member,
pledges included, who knew the file name. Earlier versions of a document had
the same gap.

`/media/committee_documents/` and `/media/document_versions/` now look up the
document that owns the file and apply that document's own visibility rule,
the same `can_user_view` the document pages use. A file with no owning
document isn't served. Links on every page keep working for the people
allowed to see the document.

- `src/view/serve_media.py`: a new `OBJECT_CHECKED_MEDIA_PREFIXES`, a third
  kind of upload folder next to the public and private sets.
- `src/tests/guards/test_media_classification.py` knows about the new kind.
  Every upload folder still has to be classified.
- **Still to decide:** `committee_minutes/` and `committee_legislation/` are
  readable by any member through `/media/`. Their pages are limited to the
  committee. They have no per-object rule yet, so they were left as they are.

## The app's activity-log export follows the "signed in from abroad" rule

The website refuses bulk exports to a session that signed in from outside the
United States. The app's activity-log export didn't check this, so it handed
over the CSV to an install that had signed in from abroad. The honeypot "clear
all" action had the same gap.

The check now lives in the app's shared base view. Any app screen that mirrors
one of the website's restricted exports gets it automatically. A new guard
test walks the app's routes to make sure none of them bypasses it.

## Pledge restrictions cover a section's pages

Restricting a page for pledges matched only that exact page. So restricting
the **Directory** still left the directory export (everyone's email and phone,
as CSV or XLSX) and the member profile cards open to pledges.

A restriction on a section's page now also covers the pages under it. For
example, `directory/` covers `directory/export/` and `directory/<id>/card/`.
Pages pledges must always reach (sign-in, 2FA, password change and the rest)
are still never blocked.

## Server errors

These answered with a 500 instead of a proper response:

- `GET` on the app's excuse-review route, and on the education "delete page
  restriction" route. Both are POST-only and inherited a `get()` that didn't
  take their URL argument. They now return 405. A new guard test checks every
  app route's handlers against that route's URL arguments, which is how the
  second one was found.
- The Scheduled Maintenance admin, with a missing or non-numeric id. It now
  shows Django's "doesn't exist" message, or a 404 on Start and Complete.
- The debug panel's database info on SQLite, where the database name is a
  path.

# Smaller attack surface

Five follow-ups from the same test. Each one removes a way in instead of
patching one.

## The debug API needs the Admin v2 sign-in

The 14 `/api/debug/` endpoints used to answer any admin. They run database
queries, turn feature flags on and off, clear caches and logs, and edit the
session.

- **Who gets in now:** only admins on the developer list (`ADMIN_V2_USER_IDS`)
  who have also signed in to Admin v2 in the last 7 days. That's the same rule
  as Admin v2 itself. Anyone else gets a 404. Local development (`DEBUG`)
  works as before.
- **The panel:** the maintenance-mode Dev Tools panel and its button only
  appear for those accounts.
- **The session editor:** it can no longer set or delete keys that decide
  sign-in or access. That covers anything starting with `_`, plus the Admin
  v2, 2FA, passkey, sign-in location, device and impersonation keys. Before,
  it could write the Admin v2 sign-in flag itself.

## The changelog and roadmap need sign-in

`/changelog/`, `/changelog/<version>/` and `/roadmap/` were public. The
changelog entries explain past security bugs in detail: what was exposed and
how it was fixed. Visitors who aren't signed in now go to the login page.

## "Log in as" is the platform owner's alone, and needs a confirmation

Any admin could sign in as any member, including other admins, from a plain
link. That reaches everything the member can see, Kai and ballots included.

- **Who:** only the platform owner can start it, and never toward their own
  account. Anyone else gets a 404.
- **How:** opening the link shows a confirmation page. The switch happens on a
  CSRF-protected button, so a link or image on another page can't start it.
- **Django admin:** the "Login As User" button goes to the same confirmation
  page. There is now a single place that starts an impersonation.
- **Still required:** the `login_as_user` feature flag, which is off by
  default.

## The origin only talks to Cloudflare

- **The forwarded IP (`nginx_proxy_common.conf`):** nginx now overwrites
  `CF-Connecting-IP` with the address it has already checked. Before, a
  request that reached the server directly could send its own value and choose
  its IP for the login limits, the blocklist, honeypot bans and audit rows.
  This holds whichever way a request arrives. Leave `CLOUDFLARE_VERIFY_ORIGIN`
  off behind this nginx: nginx hands Django the visitor's address, so that
  check would flag every visitor as forged.
- **Cloudflare only (`nginx.conf`):** the `include nginx_cloudflare_only.conf;`
  line is now on. It refuses connections that don't come from Cloudflare, with
  the server itself (loopback) allowed.

## Uploads are private by default

Before, `/media/` served any folder that wasn't on the private list to every
member. That's how committee documents ended up readable by everyone. Now it
serves only folders that were classified on purpose: public, or checked
against their owning record. A new or unknown folder, or a file at the top
level, gets a 404 until someone classifies it, and the classification guard
test makes sure every upload folder is.

## Deploying

1. **Before deploying, run the 10-second check.** On the server, look at the
   addresses nginx is logging now:

   ```
   docker logs --tail 20 parliament-nginx
   ```

   - If the first column shows **real visitor IPs**, Docker passes the true
     source address through, and turning on the Cloudflare-only line is safe.
   - If they're **all `172.x` / `10.x` (Docker's own network)**, comment the
     `include nginx_cloudflare_only.conf;` line back out before deploying. It
     would refuse everyone, and the existing `real_ip` setup isn't seeing real
     peers either. The `CF-Connecting-IP` change is safe both ways.
2. Pull, then `docker exec parliament-nginx nginx -t`, then reload nginx and
   restart the app.
3. Open the site through its normal address, and sign in. If anything is
   refused, comment out the include line and reload. That's the whole rollback.
4. If you use `login_as_user`, it now works from your account only.
