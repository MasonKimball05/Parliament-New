### Django 5.2.18
- CVE-2026-84429 (moderate): slow parsing of HTTP headers with many
  separators. Reachable by anyone who can send a request.
- CVE-2026-87975 (moderate): model formsets could delete or create rows
  outside their queryset when the primary key is editable. I did not check
  whether any formset here meets those conditions.
- CVE-2026-77050 (low): memory use from very long language codes.
- CVE-2026-87890 (moderate): GeoDjango rasters. Not used here.

### What was checked
- Full suite with all six installed: 3,145 tests. Two fail, neither from this
  change: the pre-push hook test (it needs the hook installed in the checkout)
  and the ledger test (v3.44.6 was pushed unstamped).
- `pip-audit` on the installed set: no known vulnerabilities, before and after.
- **reportlab 5:** the Constitution & Bylaws PDF (41 pages, seeded data) was
  built under 4.1.0 and 5.0.1 and compared page by page: same text, no pixel
  differences. reportlab 5 blocks remote image URLs by default and drops
  `renderPM`; the code uses neither. The minutes PDF was not compared by eye;
  its font tests pass.
- **qrcode 8.2:** `render_qr_svg` output is byte-identical to 7.4.2.
- **markdown 3.11:** all 262 `.md` files in the repo rendered under both
  versions with the changelog page's extensions. 261 are identical. The one
  that differs, `changelogs/v3.31.1.md`, was cut off under 3.8.1 at a
  `<tag ...` inside backticks and now renders in full.
- **DRF 3.18** changes the error format for `many=True` serializers. Every
  `many=True` here is read-only, so no error format changes.

## 🟡 Referer redirects go through `safe_next` (brought over from multi-chapter)

Commit `f6d9a38` had only ever been on the `multi-chapter` branch. It routes
the "go back where you came from" redirects in `set_email`, `admin_v2` and
`recalculate_vote` through `src.next_url.safe_next`, so a `Referer` header
pointing off-site falls back to a fixed page. It also removes an unused
`csrf_exempt` import in `edit_landing_page`. From the 10-01 white-box audit.

### Files
- `requirements.txt`
- `src/view/set_email.py`, `src/view/admin_v2.py`,
  `src/view/committee/recalculate_vote.py`, `src/view/officer/edit_landing_page.py`

### Deploy
`git pull`, then `venv/bin/pip install -r requirements.txt`, then restart
`parliament-gunicorn.service` and the Celery worker and beat services. No
migration, no `collectstatic`. If `pip install` refuses markdown 3.11, the
server is on Python 3.10: stop and pin `markdown==3.10.2` instead.
