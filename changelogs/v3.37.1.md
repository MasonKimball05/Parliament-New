## 🟡 "This and following" moved the wrong events when the date moved a week or more (v3.36.0)

**Found by:** the 09-30-26 auto-run review, confirmed with failing tests.

**What was wrong.** When you edit an event in a recurring series with the
"this and following" scope, `edit_event` saves the form first and then works
out which other events to change. That lookup used the edited event's *new*
time as the starting point:

- **Moved later by more than one interval** (for example +8 days in a weekly
  series): the next occurrence came before the new start point, so it was
  skipped and stayed where it was.
- **Moved earlier by a week or more** (for example −7 days): the previous
  occurrence was now on or after the start point, so it was moved too, even
  though it's before the split.

Small moves (an hour, a day) were unaffected, which is why the +1 hour test
passed.

**Fix.** `affected_events()` in `src/event_series.py` takes an optional
`pivot`, and `apply_series_edit` passes `before['date_time']`, the time the
event had before the form moved it. "All upcoming" and delete are unchanged:
"all" starts from *now*, and delete doesn't move anything.

**Tests.** Two new tests in `test_recurring_series_bulk`:
`test_following_pivots_on_the_time_before_the_move` (+8 days) and
`test_following_moved_earlier_leaves_earlier_events_alone` (−7 days). Both
fail without the fix.

## 🟢 A calendar test failed on the last day of every month

`test_qol.CalendarApiAddToCalendarTests` created an event for "tomorrow" and
then asked for *this* month's calendar. On the 30th or 31st, tomorrow is next
month, so the test failed, and the pre-push hook refused the push. The test
now asks for the event's own month.
