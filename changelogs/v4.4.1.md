## A deleted account holds no office after the purge

Until now a member who deleted their account kept their current roles for
good, so a deleted President still showed as President. Now the nightly purge
(`src/account_deletion.py`, 30 days after the request) ends them the way the
officers' transition tool does: the role is removed and any open role-history
row with that name is closed with the semester in progress, so the record
still shows they held it. The admin audit entry for the purge lists the roles
ended.

During the 30 days the roles stay, so officers can see who needs replacing (the
admins' deletion email already lists them) and a restore brings the account
back as it was. The website's delete page now says so.

**Tests:** `users.test_account_deletion`
(`test_purge_ends_current_roles_and_closes_their_history`; the purge test now
expects no current roles).

## The app: legislation drafts

Members can start, edit and delete their private drafts from My Work in the
app, and officers can publish one (`src/mobile/views_legislation_drafts.py`,
`legislation/drafts/...`). Publishing is the website's own code, moved into
`publish_draft()` in `src/view/legislation_drafts.py` so both make the same
bill with the same notices. Attaching or replacing the draft's document stays
on the website; an edit from the app never touches it.

## The app: filing with Kai

Members can file a Kai report (templates, the form builder's custom fields, a
photo attachment), file a commendation, and on their own case request closure,
ask to drop it, or appeal (`src/mobile/views_kai_filing.py`, `kai/...`). The
website's views now call the same helpers (`file_kai_report`,
`file_kai_commendation`, `file_closure_request`, `file_drop_request`,
`file_kai_appeal`), so the rows written, the chairs' emails and the
confidentiality rules are the same either way. Documents (PDF, Word) as the
main attachment still go through the website.

## The app: officer tools

* **All Activity** (`officer/activity/`), for officers, chairs and advisors.
* **Houses and bigs**: assign a member's house or big from their card, or work
  through the unassigned list. Bigs set on the education dashboard stay
  education's to change. Logic shared with the website in `src/house_utils.py`
  (the directory page now uses it too).
* **Kai commendations** for the Kai chairs and granted reviewers: list, detail,
  status, assignment and notes, with the website's access rule. Reviewers who
  aren't officers find it on their Kai page.
* **Resolutions** (admins): create, edit and delete resolutions and their
  section impacts. Uploading a resolution's document stays on the website.

The officer hub only shows the rows the user may open.

## Recurring events keep their time across daylight saving

Moving a recurring series, or setting its excuse deadline, added elapsed
time. When the move or the deadline's gap crossed a daylight-saving change, every other
meeting in the series landed an hour off: moving the Mar 3 meeting to Mar 10
put the rest at 6 PM, and a deadline "three days before" a November meeting
put the others' deadlines at 6 PM. Creating a series stepped through the dates
in UTC, so an evening meeting's weekday was checked against the next day.
Series arithmetic is now on the chapter's clock (`shift_local` /
`local_delta` in `src/event_series.py`, used by bulk edits and by
`generate_recurring_events`). Existing events aren't changed; re-save a series
time if one was moved across a change and is an hour off.

**Tests:** `events.test_recurring_series_bulk` (new `DaylightSavingTests` at
fixed dates on both changes; the fixture is now date-independent; it failed
on 11-01-26).

## The app: committee chair tools

Chairs can create committee votes, recalculate, push a vote to the chapter or
take it back, and delete; add and remove members, voters, advisors and chairs;
set member permissions; take today's attendance; and publish, unpublish or
delete documents (`src/mobile/views_committee_management.py`). The web views
now share `src/committee_management.py` with the app. Uploading documents, ending
a vote early, runoffs and the chat / education / Kai permission pages stay on
the website. Create vote on the website now gives a form error, not a 500, for
a missing date or a non-number threshold.

## The app: roles and role transitions

Officers manage roles (create, edit, delete, assign and remove holders;
admin-granting roles and admins' accounts stay admin-only) and run end-of-term
transfers, with a dry run that lists exactly what a transfer will change
before it's confirmed (`src/mobile/views_officer_roles.py`; shared helpers in
`src/view/officer/manage_roles.py` and `transitions.py`). The transition
checklist and the server log viewer stay on the website.

## The app: user guide, C&B history, study hours

* **User guide:** the guide's pages and published articles, native
  (`src/mobile/views_guide.py`; the web guide now reads one `GUIDE_PAGES`
  table, so its search words live there and in the template — edit both).
* **C&B:** each section's history with a coloured word diff, and the documents
  "as of" a date (`cnb/sections/<id>/history/`, `cnb/?as_of=`).
* **Study hours:** the education committee's week view and requirements, and
  an event's time screen (visits, adjustments, add or remove minutes with a
  reason) (`src/mobile/views_study_hours.py`).

## Kai report form fixes (website and app)

* "Directed to" only accepts an active member. The dropdown was already limited
  to them, but any user id could be posted.
* Tags are saved in the list's own spelling (`Follow Up` saves as
  `follow-up`), and a tag that isn't on the list is named in the error.
* The form's quick-add tag buttons "Academic" and "Social" weren't on the
  allowed list, so using them made the report fail. They're now "Repeat
  incident" and "Documentation pending".
