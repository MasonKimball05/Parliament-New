## 🟢 Edit or delete a whole recurring series at once

Editing or deleting an event that belongs to a recurring series now asks
which events the change applies to, the same three choices Google Calendar
gives:

- **This event only.** The old behaviour, and the default.
- **This and following events.**
- **All upcoming events in the series.**

The choice shows only for events in a series of 2 or more, with a count next
to each option. The series view (**Manage Events → Series → an event's
instances**) also has **Edit series** and **Delete upcoming** buttons, which
open the next upcoming occurrence with "all upcoming" preselected.

**Rules** (`src/event_series.py`):
- **Only the fields you change are copied.** If one week was moved to another
  room, a later series-wide title change keeps that room.
- **A new date or time moves every affected event by the same amount.** Moving
  7 PM to 8 PM moves them all an hour, and excuse deadlines move with them. A
  changed excuse deadline keeps the same distance before each event.
- **Finalized attendance is never touched.** Events whose attendance is
  finalized are skipped by bulk edit and delete, and "all upcoming" leaves
  past events alone, so a bulk change never rewrites history.
- **Not copied:** the repeat pattern itself (weekly → biweekly) and the RSVP
  announcement email. The email would otherwise go out once per occurrence.
  To change the pattern, delete the following events and create a new series.

## 🟠 Deleting a series' first event deleted the entire series

**What was wrong.** A series is one root row plus one row per occurrence with
`parent_event = root` and `on_delete=CASCADE`. Deleting the root, which is
usually the first and oldest meeting, silently deleted **every** occurrence,
past ones with attendance records included. The confirmation page only said
"the event will be permanently removed".

**Fix.** When the root is deleted but other occurrences remain, the earliest
survivor becomes the new root first: it gets the recurrence settings, and the
rest are re-pointed to it. "This and following" also sets the series' end date
to the last remaining occurrence.

## 🟡 Occurrences of a recurring committee meeting weren't committee meetings

**What was wrong.** `generate_recurring_events` didn't copy `committee`, so
only the first occurrence of a recurring committee meeting was scoped to the
committee. Every later one was chapter-wide: attendance, excuses and reminders
covered everyone. Sign-up settings (`requires_signup`, `max_signups`,
`signups_open`, `allow_waitlist`) were likewise first-occurrence-only.

**Fix.** They're copied now. `rsvp_email_enabled` is deliberately not copied.
Existing series are unchanged; use the new bulk edit to set the committee on
their upcoming events.
