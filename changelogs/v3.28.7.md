Requested by Mason, following up on the recently-added event QR
self-check-in: a QR code for an announcement poll, embeddable in a slide
deck (PowerPoint linked picture, Google Slides "Insert image by URL", OBS,
etc.) the same way `EventCheckinEmbed` already does for event attendance.

## What it does

Two new officer-only views plus one public one, off `poll_results`
("QR Code" button):

- `manage_poll_qr` / `poll_qr_image` — an officer can view and download the
  QR directly (login-gated, matching `qr_checkin_image`'s reasoning: not
  because the image is more sensitive than the `take_poll` link everyone
  eligible can already navigate to, but so a bookmarked URL doesn't outlive
  the officer's own access).
- `generate_poll_qr_embed_link` / `revoke_poll_qr_embed_link` +
  `poll_qr_embed_image` — the same stable, unauthenticated bearer-token
  pattern as `EventCheckinEmbed`, for pasting into a deck once. New model
  `AnnouncementPollEmbed` (one row per poll, `OneToOneField`), deliberately
  **not** registered in `/admin/` for the same reason as
  `EventCheckinEmbed`/`CalendarSubscription` — `token` is a bearer
  credential and an editable admin field would be one more place it sits
  in plaintext.

## Where this differs from the event version (and why)

A poll has no rotating, time-boxed token to protect — `EventCheckinWindow`
exists because an event QR that never expired would just be a photo
waiting to be shared into a group chat, checking in whoever has the
picture rather than whoever's in the room. `take_poll`'s URL is just the
announcement's permanent id, and the poll's own `is_open`/`closes_at`
already govern whether it accepts responses. So there's no "window" model
here, and `poll_qr_image` (the officer preview/download view) never 404s
for "nothing open right now" — it always renders the same code, useful or
not. The embed endpoint's placeholder-vs-live choice is driven directly by
`announcement.is_published()` / `poll.is_accepting_responses()` instead,
with its own wording (`POLL_WAITING_PLACEHOLDER_SVG`, new in
`src/utils/qr_svg.py`, alongside the existing check-in one) rather than
reusing the check-in placeholder's "Check-in / not open yet" text, which
would have been actively misleading here.
