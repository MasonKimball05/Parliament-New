## They didn't — same gap this codebase already fixed once for polls

`Announcement.linked_documents` (`src/models/announcements.py`) is a
`ManyToManyField` to `CommitteeDocument`, and the in-app announcements list
has always shown a linked document as a clickable chip right on the post
(`templates/announcements.html`, linking to `download_chapter_document`).
But `emails/announcement_notification.html` never rendered anything about
it — `send_announcement_notification` (`src/notifications.py`, the
publish-triggered task path) and `warmup_announcement_email`
(`src/view/officer/manage_announcements.py`, the manual-send path behind
the officer's confirm-email page) both built a context dict with
`announcement`/`site_url`/`tracking_url`/`user` and the poll keys added in
v3.29.5/v3.29.10, and nothing about linked documents. Same shape as that
poll-email gap, just never asked of this M2M too.

## Fix

Both send paths now fetch `list(announcement.linked_documents.all())`
**once**, outside the per-recipient send loop — same N+1 avoidance already
applied to the poll fetch in both functions (an M2M `.all()` read from
inside the template would otherwise be a fresh query per recipient, and
this list can be dozens to hundreds of users) — and pass it into the
template as `linked_documents`.

`templates/emails/announcement_notification.html` gets a new
`.documents-info` block (styled to match the existing `.poll-info` block),
rendered only `{% if linked_documents %}`, placed after the poll section
and before the "View All Announcements" button — same ordering as the
on-site template. Each document renders its `title` and a link built as
`{{ site_url }}{% url 'download_chapter_document' doc.id %}` — the same
view the in-app chip already links to, so the access gate is identical:
`@login_required` + `CommitteeDocument.can_user_view(request.user)` +
`published_to_chapter=True`. No new authz surface, no change to
`serve_media.py`'s `PUBLIC_MEDIA_PREFIXES` classification of
`committee_documents/` — this is purely a missing context key + missing
template block, same as the poll fix before it.

`_build_test_announcement_context()` (`src/view/admin_v2.py`, backs the
admin-v2 "Send Test Email"/"Preview in Browser" buttons) gets an explicit
`'linked_documents': None` added to its base context, matching the
existing `poll`/`poll_questions`/`poll_url` fields — no mock document was
built (unlike the mock poll), since a believable fake document would need
a real uploaded file to point at and `MockAnnouncement.id = 0` isn't a
real row.

New `src/tests/announcements/test_announcement_document_email.py` (7
tests, modeled directly on the existing `test_announcement_poll_email.py`):
document name + download link render on the publish-triggered send path
and the manual warmup path, multiple linked documents are all listed with
correct per-document links, the label pluralizes ("Attached Document" vs.
"Attached Documents"), and an announcement with no linked documents
renders no `.documents-info` block at all.
