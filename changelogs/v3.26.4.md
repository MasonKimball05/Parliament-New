## Why v3.25.3's auto-heal didn't catch it

v3.25.3 added an auto-heal to this hook's `_gate_check` step: if `src.W003`
(the standalone system check for ledger staleness) was the *only* thing
blocking, run `stamp_ledger.py`, commit the result, and re-check. That step
lives near the bottom of the script. But `test_the_tool_has_nothing_left_to_do`
checks the identical fact from **inside the main test suite**, which runs
and can fail long before the script ever reaches `_gate_check` — so the very
release that added the auto-heal was blocked by a gap in *where* it was
placed, not in what it did. Same shape as several other entries on this
repo's list: a rule stated correctly, a helper written to enforce it, and
one more caller of the same fact left outside the helper's reach.

## Fix

Mason's call: *"Let's have it just run stamp ledger first. If there's
nothing to add it just stops itself anyways so that'd nbd."* Moved the
stamp to the very top of the script, right after resolving the Python
interpreter and before the test suite runs at all. `scripts/stamp_ledger.py`
is idempotent and safe to run unconditionally — a clean tree prints "every
committed release is already stamped. Nothing to do." and the hook moves
on with one fast `git log` call spent. A stale one gets fixed and committed
before either check (the test-suite one or the standalone `_gate_check` one)
ever gets a chance to see it stale.

The original `_gate_check`-level auto-heal from v3.25.3 stays in place as a
backstop (e.g. a changelog edited between the top-of-script stamp and that
later check) rather than being deleted — same logic as before, just no
longer the primary mechanism.
