# v2.13.4 - JSON Storage Migration

**Release Date:** May 11, 2026

**Deployment Status:** Not yet deployed

**Type:** Code Quality / Maintainability

---

## Overview

Three model fields that stored structured data as plain comma-separated strings were converted to `JSONField`. The data is now stored natively as JSON lists, which makes it queryable by the ORM, eliminates runtime string parsing, and removes a security-critical manual split from the lockdown whitelist check.

This is a data migration — existing rows are converted automatically. No behavior visible to users has changed.

---

## Changes

### `KaiReport.tags` — `CharField(500)` → `JSONField(default=list)`

**What the problem was:**

Tags were stored as a raw string: `"urgent, follow-up, academic"`. Every read required splitting the string and stripping whitespace. The `get_tags_list()` method existed precisely to paper over this — it was only needed because the field wasn't storing a list in the first place.

```python
# Before
tags = models.CharField(max_length=500, blank=True)

def get_tags_list(self):
    if self.tags:
        return [tag.strip() for tag in self.tags.split(',')]
    return []
```

**What was done:**

- `tags` changed to `JSONField(default=list)`
- `get_tags_list()` simplified to `return self.tags or []`
- `KaiReportForm.tags` overridden as a `CharField` with a `clean_tags()` method — users still type comma-separated tags in the form, the form converts them to a list before saving
- CSV exports updated to join the list before writing
- Email notification updated to join the list for display
- `manage_report.html` "update tags" form now renders the list as comma-separated for editing
- `user_view_report.html` updated to iterate `get_tags_list` instead of calling `.split()` on a string
- `print_report.html` updated to use `|join:', '` filter

---

### `KaiReportTemplate.suggested_tags` — `CharField(500)` → `JSONField(default=list)`

**What the problem was:**

Same pattern as `KaiReport.tags` — comma-separated string, no native list support.

**What was done:**

- `suggested_tags` changed to `JSONField(default=list)`
- Create/edit template views now parse the POST value to a list before saving
- `edit_template.html` and `manage_templates.html` render the list with `|join:', '`
- `submit_report.html` `data-tags` attribute renders the list with `|join:', '` — the existing JavaScript reads this as a comma-separated string to auto-populate the tags input, which still works correctly

---

### `SystemLockdown.whitelisted_ips` — `TextField` → `JSONField(default=list)`

**What the problem was:**

This was the most security-relevant of the three. The whitelist was stored as `"192.168.1.1, 10.0.0.5"` and `is_ip_whitelisted()` split it manually every time it was called:

```python
# Before — runs on every request during lockdown
def is_ip_whitelisted(self, ip_address):
    if not self.whitelisted_ips:
        return False
    whitelist = [ip.strip() for ip in self.whitelisted_ips.split(',')]
    return ip_address in whitelist
```

Manual string parsing in a security-critical path is exactly where subtle bugs live — extra whitespace, trailing commas, or encoding issues could silently misbehave.

**What was done:**

- `whitelisted_ips` changed to `JSONField(default=list)`
- `is_ip_whitelisted()` simplified to `return ip_address in self.whitelisted_ips`
- `activate()` signature changed from `whitelisted_ips=''` to `whitelisted_ips=None` (empty string is not a valid list default)
- Admin view (`admin_v2.py`) updated to parse the comma-separated POST input to a list before passing to `activate()` and before direct assignment in `update_whitelist`
- `lockdown_control.html` whitelist textarea now renders the list with `|join:', '`

---

## Migration

Migration `0157_json_storage_migration` handles the data conversion in two steps:

1. **RunPython (before AlterField):** Reads each row while the column is still `text`, converts comma-separated strings to JSON-formatted strings (e.g., `"urgent, follow-up"` → `'["urgent", "follow-up"]'`). Empty strings become `'[]'`. This step is required because PostgreSQL's CAST from `text` to `jsonb` rejects empty strings.

2. **AlterField × 3:** Changes each column type. PostgreSQL casts the JSON-formatted strings to native `jsonb`.

---

## Breaking Changes

None. The public interface is identical — `get_tags_list()` still returns a list, `is_ip_whitelisted()` still returns a bool.
