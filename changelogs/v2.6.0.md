# Parliament v2.6.0 - Officer Member Management & Role Numbers

**Release Date:** February 3, 2026
**Status:** ✅ Deployed to Production
**Type:** Minor Feature Release - Member Management

---

## Overview

This release introduces a comprehensive officer-level member management system. Officers can now add, edit, and delete members directly from the user list page without needing Django admin access. The release also adds batch pledge initiation with role number assignment, enabling officers to initiate multiple pledges at once while assigning permanent chapter roll numbers.

Additionally, this release fixes a critical bug where slow-loading announcement forms could result in duplicate submissions when users clicked the submit button multiple times.

## New Features

### 1. In-App Member Management

Officers can now manage members directly from the `/users/` page without needing Django admin access.

**Add Member Modal:**
- Full name and unique member ID (required)
- **Auto-generate ID button** for temporary pledge IDs (format: P-XXXXXX)
- Auto-generates ID when Pledge is selected and ID field is empty
- Optional email address
- Member type dropdown (Pledge, Member, Chair, Officer, Advisor)
- Member status dropdown (Active, Inactive, Alumni)
- Role assignment (checkboxes)
- **Auto-generated username**: first initial + last name (e.g., "John Smith" → "jsmith")
- Username uniqueness enforced (appends number if needed: jsmith1, jsmith2, etc.)
- **Pledge passwords**: For pledges, password is set to their username for simplicity
- **Non-pledge passwords**: Auto-generated 12-character alphanumeric password
- Username and password displayed after creation for officer to share
- Force password change on first login

**Edit Member Modal:**
- Pre-populated with current member data via AJAX GET
- Editable: name, preferred name, email, member type, status, roles, roll number
- Member ID displayed as read-only (cannot be changed)
- Admin indicator shown for admin users (cannot modify admin status)
- Save changes via AJAX POST

**Delete Member:**
- Soft delete option (set status to Inactive)
- Hard delete option (permanent removal)
- Confirmation modal with radio button choice
- Cannot delete yourself or admin accounts

### 2. Batch Pledge Initiation with Role Numbers

Officers can now initiate multiple pledges to full membership in a single operation.

**Selection:**
- Checkbox column in user list for pledge rows only
- "Select All" checkbox in header to toggle all visible pledges
- Initiate button appears when 1+ pledges selected, showing count
- Selections cleared on filter change

**Initiation Modal:**
- Shows list of selected pledges with role number input fields
- Each pledge must have a unique roll number assigned
- Validates: all role numbers provided, no duplicates, no existing conflicts
- On success: changes member_type from "Pledge" to "Member", assigns roll number
- Sends in-app notification to each initiated member

---

### 3. Role Number (Roll Number) System

Members now have a permanent roll number assigned at initiation.

**Features:**
- `role_number` field on ParliamentUser model (unique, nullable)
- Displayed in user list table with `#` prefix (e.g., "#1234")
- Pledges show "Pending" indicator
- Non-pledges without roll numbers show dash
- Searchable in user list search
- Editable via edit member modal (with duplicate validation)
- Included in CSV export

**Display Locations:**
- Desktop table: dedicated "Roll #" column
- Mobile cards: icon with "Roll #" label

Added dark mode support to the edit announcement page with proper styling for all elements.

## Bug Fixes

### 1. Global Form Double-Submit Prevention

**Problem:** When the site loaded slowly, users could click submit buttons multiple times, resulting in duplicate submissions and operations.

**Solution - Announcement Forms (Explicit):**
- Submit button disabled immediately after first click
- Loading spinner shown during submission
- Button text changes to "Creating..." or "Updating..."
- Opacity and cursor styles indicate disabled state

**Solution - All Forms (Global Protection):**
- Global JavaScript listener on all form submissions
- Tracks submitted forms using WeakSet for memory efficiency
- Automatically disables submit buttons and shows loading indicator
- Auto-recovery after 10 seconds in case of errors
- Can be disabled per-form with `data-no-double-submit-protection` attribute

**Files Changed:**
- `templates/officer/create_announcement.html`
- `templates/officer/edit_announcement.html`
- `templates/base.html` (global protection)

### 2. Performance Monitoring Dashboard (Admin-v2)

New performance monitoring section in the Admin-v2 dashboard for diagnosing slow site issues.

**Features:**
- **Real-time Health Check**: Click "Run Check" to measure server response time vs network latency
- **Automatic Diagnosis**: Determines if slowness is server-side or network-side
- **Performance Metrics**: Average response time, slow requests count, DB queries per request
- **Slow Requests Table**: Lists recent requests taking >1 second with path and timing details
- **Server-Timing Header**: All responses now include timing information for browser DevTools

**How It Works:**
- Middleware tracks all request timings and stores in memory
- Health check endpoint measures actual server processing time
- Client-side JavaScript calculates network round-trip time
- Dashboard shows aggregated metrics and identifies issues

**Files Added:**
- `src/middleware/performance.py` - Performance tracking middleware

**Files Changed:**
- `Parliament/settings_postgres.py` - Added PerformanceMiddleware
- `src/view/admin_v2.py` - Added health_check endpoint and performance data
- `templates/admin_v2/dashboard.html` - Added performance monitoring UI
- `src/urls.py` - Added /api/health-check/ endpoint

### 4. Mobile PDF Scrolling Fix

**Problem:** On mobile devices, PDF documents couldn't be scrolled when viewed in the document viewer.

**Solution:**
- Replaced `<embed>` tag with `<iframe>` for better mobile browser support
- Added `-webkit-overflow-scrolling: touch` for iOS momentum scrolling
- Added `touch-action: pan-y pinch-zoom` CSS for proper touch handling
- Mobile view now uses a taller iframe with scroll container
- Added "Open PDF" button at bottom of mobile view for fallback

**Files Changed:**
- `templates/view_document.html`

---

### 5. User List Responsive Table Improvements

**Problem:** On medium-sized screens, users had to scroll horizontally to see the edit button. Additionally, a checkbox column was always visible even when no pledges existed.

**Solution:**
- Made pledge checkbox column conditional (only shown when pledges exist in current view)
- Added responsive column hiding at breakpoints:
  - Email: hidden below `lg` (1024px)
  - Status: hidden below `xl` (1280px)
  - Roles: hidden below `xl` (1280px)
  - Last Login: hidden below `2xl` (1536px)
- Reduced column padding for better space utilization
- Actions column now always visible without horizontal scroll

**Files Changed:**
- `templates/user_list.html`
- `src/view/officer/user_list.py` (added `has_pledges` context variable)

---

### 6. Roll Number Fallback Display

**Enhancement:** When a member doesn't have a roll number assigned, the Roll # column now shows their Member ID instead of a dash (except for pledges who show "Pending").

**Display Logic:**
- Members with roll number: Shows `#1234` (the roll number)
- Pledges without roll number: Shows "Pending" (italic)
- Other members without roll number: Shows the member ID

**Files Changed:**
- `templates/user_list.html` (desktop table and mobile cards)

## API Endpoints

### Add Member
```
POST /officers/members/add/
Content-Type: application/json

{
    "name": "John Smith",
    "user_id": "jsmith123",
    "email": "john@example.com",
    "member_type": "Pledge",
    "member_status": "Active",
    "roles": [1, 2, 3]
}

Response:
{
    "success": true,
    "member": {...},
    "temp_password": "Ab3Cd5Ef7Gh9",
    "message": "Member John Smith created successfully."
}
```

### Edit Member
```
GET /officers/members/{user_id}/edit/
Response:
{
    "success": true,
    "member": {
        "user_id": "jsmith123",
        "name": "John Smith",
        "preferred_name": "Johnny",
        "email": "john@example.com",
        "member_type": "Member",
        "member_status": "Active",
        "roles": [1, 2],
        "is_admin": false,
        "role_number": "1234"
    }
}

POST /officers/members/{user_id}/edit/
Content-Type: application/json
{...updated fields...}

Response:
{
    "success": true,
    "message": "Member John Smith updated successfully.",
    "changes": ["name: John Smith -> Jonathan Smith"]
}
```

### Delete Member
```
POST /officers/members/{user_id}/delete/
Content-Type: application/json

{
    "hard_delete": false
}

Response:
{
    "success": true,
    "message": "Member deactivated."
}
```

### Initiate Pledges
```
POST /officers/members/initiate/
Content-Type: application/json

{
    "pledges": [
        {"user_id": "pledge1", "role_number": "1234"},
        {"user_id": "pledge2", "role_number": "1235"}
    ]
}

Response:
{
    "success": true,
    "message": "Successfully initiated 2 pledge(s) as full members.",
    "count": 2,
    "names": ["Alice Johnson", "Bob Williams"],
    "role_numbers": ["Alice Johnson (#1234)", "Bob Williams (#1235)"]
}
```

### Get All Roles
```
GET /api/roles/

Response:
{
    "success": true,
    "roles": [
        {"id": 1, "name": "President", "code": "PRES"},
        {"id": 2, "name": "Vice President", "code": "VP"}
    ]
}
```

## Security Considerations

- All member management endpoints require `@login_required` and `@officer_required` decorators
- Cannot delete your own account
- Cannot delete admin accounts
- Cannot modify `is_admin` flag through edit member
- Role number uniqueness enforced at database level
- All actions logged to ActivityLog with metadata

---

## Activity Logging

All member management actions are logged:

| Action | Log Description |
|--------|-----------------|
| Add member | `{officer} added new member {name} ({user_id})` |
| Edit member | `{officer} edited member {name}: {changes}` |
| Deactivate member | `{officer} deactivated member {name} ({user_id})` |
| Delete member | `{officer} permanently deleted member {name} ({user_id})` |
| Initiate pledges | `{officer} initiated {count} pledges: {names with roll numbers}` |
