# v2.13.1 - CSP Nonce Hardening

**Release Date:** May 10, 2026

**Deployment Status:** Deployed

**Type:** Security Update

---

## Overview

Removes `'unsafe-inline'` from `script-src` in the Content Security Policy by replacing it with a per-request cryptographic nonce. Any injected script — even one that slips through input sanitization — is blocked by the browser because it won't carry the nonce. No user-visible behavior changes.

---

## Security Fixes

### CSP `script-src` — Remove `unsafe-inline` (High)

**Issue:** The Content Security Policy permitted `'unsafe-inline'` in `script-src`, meaning any JavaScript injected into the page (via a stored XSS, a reflected value, or a future bypass of the sanitization middleware) would execute freely in users' browsers. This undermined the XSS attack detection already in place.

**Fix:**

- **Middleware** (`src/middleware/security.py`) — A cryptographically random nonce is generated per request using `secrets.token_urlsafe(16)` and attached to `request.csp_nonce` before `get_response()` is called (so templates can access it during rendering). `add_security_headers()` now includes `'nonce-{nonce}'` in `script-src` instead of `'unsafe-inline'`.

- **Templates** — All inline `<script>` tags across every template now carry `nonce="{{ request.csp_nonce }}"`. External `<script src="...">` tags are unaffected (covered by `'self'`).

`style-src` retains `'unsafe-inline'` — inline `style=` attributes are used throughout the templates and Alpine.js, and inline styles cannot execute code directly.

**Effect:** A script injected by an attacker has no nonce and is rejected by the browser's CSP enforcement before it runs, even if it reaches the page.

**Files changed:** `src/middleware/security.py`, all `templates/**/*.html` (inline `<script>` tags only)

---

## No Breaking Changes

All existing JavaScript functionality is preserved. The nonce is generated fresh each request and injected into every inline script block automatically — no changes to JavaScript logic required.

---

## Deployment Notes

No migrations required. No environment variables added. Restart the application server to apply. Monitor `/csp-report/` in the Admin-v2 security dashboard after deployment — any violations indicate an inline script that was missed and needs a nonce added.
