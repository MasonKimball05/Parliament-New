## Root cause: a duplicate `class` attribute, not a missing dark-mode class

Five buttons in `templates/cnb/resolution_detail.html` had **two** `class`
attributes on the same tag — one carrying a JS hook (`js-confirm-click`,
`js-open-amendment-modal`) written on its own line above the actual styling
classes on the next line:

```html
<button type="submit" class="js-confirm-click" data-confirm-msg="…"
        class="w-full text-left px-3 py-2.5 … text-gray-600 dark:text-gray-400 …">
```

Per the HTML parsing spec, when a start tag has two attributes with the
same name, the parser keeps the **first** occurrence and silently drops
every later one — no error, nothing in the console. So `class` resolved to
`js-confirm-click` alone; the entire second line, including every layout,
background, and dark-mode text-color class, was never applied. That's why
it wasn't just a missing `dark:` class — the buttons had **no** Tailwind
styling at all, in either mode, and rendered as bare unstyled browser
buttons (black text, no background, no rounding). Light mode happened to
still be legible because default black-on-white is close enough to the
intended styling to not stand out; dark mode wasn't, which is why only
that half got reported.

Affected: **Withdraw**, **Resolution Passed**, **Resolution Failed** (the
three `Actions` sidebar buttons sharing this exact pattern), and the two
amendment-editor **Add** buttons (the "Tracked Section Amendments" header
button with the `+` SVG icon, and the empty-state "Add one" link) — all
merged back into a single `class` attribute carrying both the JS hook and
the full styling.

## Collaborator row: split onto two lines so it has room

This session's earlier v3.29.6 change (in-place role editing for
collaborators) put a member's name, a role `<select>`, a Save button, and
a Remove button all on one row inside the sidebar's Collaborators card —
a column that's narrow regardless of screen width (it's `1/3` of the page
grid at the `lg` breakpoint, not the viewport itself, so `sm:`/`md:`
utilities can't be used to give it more room on a "wide enough" screen —
those breakpoints key off the *viewport*, and the page is already past
`lg` by the time the sidebar exists at all). That's very likely a piece of
what read as "not correctly in their boxes." Split into two rows: name +
Remove on top, the role select + Save on their own row underneath — same
functionality, room to breathe in a narrow column at any width.
