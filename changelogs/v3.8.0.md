# v3.8.0 — In-App Security Notifications & Token Expiry Alerts

**Release Date:** June 14, 2026
**Deployment Status:** ✅ Deployed — June 22, 2026
**Type:** Feature

---

## Overview

Two notification features that close gaps in the existing alert system. Security events (account lockouts, non-US logins) previously only notified via email — users without an email address received nothing. API token expiry had no user-facing warning at all. Both are now surfaced in the in-app notification bell.

---

## What Changed

### 1. In-App Security Alert Notifications

Added a `security` type to the `Notification` model and a new `notify_user_security_event(user, subject, body, ip_address)` function in `security_notifications.py`. The function:

- Always creates an in-app `Notification` (even for users without an email address — relevant for new members mid-onboarding wizard who haven't set their email yet)
- Sends an email in addition if the user has an address on file
- Invalidates the notification cache so the bell count updates immediately

**Wired into two events:**

- **Account lockout** — the lockout path in `login_view` was already calling `notify_user_security_event` but the function didn't exist, so it silently no-opped in the `except Exception: pass` block. Now works as intended for users with and without email.
- **Non-US login** — `run_post_auth_pipeline` already created an admin-facing `LoginAlert` for foreign logins. It now also calls `notify_user_security_event` so the user themselves gets an in-app (and email) alert when their account is accessed from outside the US.

The notifications page gains a **Security** filter tab (red, shield icon) and a generic bell fallback icon for any future notification types.

**Changed:** `src/models/notifications.py`, `src/security_notifications.py`, `src/utils/security_utils.py`, `templates/notifications.html`

### 2. API Token Expiry Notifications

New Celery task `notify_expiring_api_tokens` runs daily at 3:14 AM CST. It finds all active tokens expiring within 7 days and creates a `security`-type in-app notification for the token owner. A 7-day cache key prevents re-notifying the same token each day during the warning window.

The notification links to `/preferences/#api-tokens` so the member can act immediately.

Registered in `setup_celery_schedules.py` — run `python manage.py setup_celery_schedules` after deploying to create the beat entry.

**Changed:** `src/tasks.py`, `src/management/commands/setup_celery_schedules.py`

## Deployment Notes

- No migrations
- No new runtime dependencies
- No static file changes — Cloudflare purge not required
- **Run `python manage.py setup_celery_schedules` on the server** to register the `notify_expiring_api_tokens` beat task. Without this the task exists but won't run automatically.
