## 🟢 Mobile app: officer tools (Mason, 10-29-26)

`src/mobile/views_officer.py`. Officers, chairs and admins only
(`user_is_officer_or_chair`, `officer_required`'s rule).

- **Hub** (`officer/`): pending excuses, scheduled announcements, recent events
  waiting for attendance.
- **Announcements:** list, create, edit, hide and delete through
  `AnnouncementForm`.
  - Optional email on create, through `send_announcement_notification`. A
    scheduled announcement gets `send_email_on_publish` instead.
  - `officer/announcements/recipients/` gives the count the app shows in its
    "Post and email N members?" confirmation. It uses
    `src.notifications.announcement_email_recipients`, which has the send's
    filters; a test checks the two agree.
  - An edit from the app sends only the fields it changed. Polls, linked
    documents and GroupMe are untouched: `_save_groupme_channels` would clear
    channels the request didn't send, so the app never calls it.
- **Events:** create (single events), edit and delete through `EventForm`,
  starting from the event's own values, so recurrence, the second reminder,
  the check-in area and GroupMe stay as they are.
  - Series edits and deletes take `scope` like `edit_event` / `delete_event`,
    including clearing sent-reminder marks when the time moves.
  - The event detail (`events/<id>/`) gains `can_manage`,
    `can_take_attendance` and `attendance_finalized`.
- **Excuses:** list by status, approve or deny through
  `AttendanceExcuse.approve/deny` (which notify the member), and log it as
  `review_excuses` does.
- **Attendance:** the roster (`required_members`), mark present / late /
  absent or excuse with a reason, and finalize, as `mark_event_attendance` does.
  An approved excuse is never overwritten, and a finalized event is read-only.
- Tests: `src/tests/mobile/test_officer.py`.
