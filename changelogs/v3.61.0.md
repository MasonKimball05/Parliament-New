## 🟢 Mobile app: My Attendance, Service Hours, Chapter Documents (Mason, 10-29-26)

Three more `/api/mobile/v1/` endpoints, each built on its web page's own code,
so the app and the site show the same numbers.

### My Attendance — `GET my/attendance/?days=90`
- `days` is 30, 90, 180, 365, or 0 for all time. Returns the counts and rate,
  the chapter's rate over the same events, and one row per event with any
  excuse's status (up to 200).
- The web view's calculation moved into `attendance_overview(user, start_date,
  now)` in `src/view/submit_excuse.py`. `my_attendance` calls it, so its
  queries and results are unchanged; the series stats stay in the web view.
- Same feature flags as the page (`attendance_tracking`, `event_attendance`).

### Service Hours — `GET my/service-hours/`
- The current period's progress (`get_user_service_stats`), the member's
  submissions (drafts left out, newest first, up to 100) and manual adjustments.
- "Which period is current" moved into `current_service_period()`
  (`src/view/service_user_dashboard.py`), shared with the dashboard.

### Chapter Documents — `GET documents/`, `GET documents/<id>/file/`
- Published documents grouped as the web page groups them: folders, then
  chapter-level documents, then by committee. `can_user_view` decides
  visibility; the page toggle and pledge restriction apply.
- The file endpoint streams the file with the Bearer token (`/media/` needs a
  website session). Uses `apply_disposition`, so names are RFC 5987-encoded
  and `nosniff` is set.

### Deep links
`/my-attendance/`, `/service-hours/` and `/chapter-documents/` map to the
app screens `attendance`, `service_hours` and `documents`.
