Stages the Foreword of the new Constitution and Bylaws
(`exportable_media/legislation_docs/New-Bylaws.docx`, authored 8/6/26) so that
adopting it after the chapter vote is **a flag toggle, not a deploy** — and adds
the same on/off control to the three documents already in force.

---

## The Foreword is prose, and that decided the shape

The Appendix is articles and sections. The Foreword is not: four paragraphs of
argument, a dedication to Ian Viner, Brennan Paulus, Xander Guill and Jacob
Hoffman, and a signature block. Forcing that into `Article 1, Section 1` would
have rendered "Article 1 — Section 1" above a personal note.

So it is a `GoverningDocument` with **no Articles**, its entire text in
`preamble`. `GoverningDocument.is_prose_only` derives that from the absence of
articles rather than storing a flag — one less thing to keep in step with
reality — and the viewer uses it to label the block **Foreword** rather than
**Preamble**, which would be the wrong word in the first place a reader looks.

⚠️ **Consequence, recorded so it is a decision rather than a surprise: the
Foreword cannot be amended through the C&B resolution flow.** That flow targets
`Section` rows and there are none. Intended — a foreword is the author's note,
not legislation — but if it ever needs amending, the document has to be
restructured first. `ForewordStructureTests.test_the_foreword_has_no_amendable_sections`
is where someone will find that out.

## ⚠️ The Foreword fails CLOSED, and that took more than `is_enabled=False`

The seeded text is **governance that has not passed a vote**. Publishing it by
accident is the failure this release has to prevent, and the obvious
implementation does not prevent it.

`FeatureFlag.is_feature_enabled` **fails OPEN** — a name with no row returns
`True`. CLAUDE.md has carried that asymmetry since 07-25-26 (it is why the
calendar Subscribe button was invisible for weeks) and it is exactly backwards
here: an install that had not run `seed_feature_flags` — a fresh deploy, a
restored dump, a test database — would have read `cnb_foreword` as **enabled**
and published unpassed governance to the whole chapter.

Two independent guards, because either alone can be removed by a refactor:

1. **`cnb_foreword` is listed in `FeatureFlag.DISABLED_BY_DEFAULT`.** This is
   the load-bearing one — it inverts the missing-row default for this name only.
2. **`seed_feature_flags` ships the row `is_enabled=False`.**

And the three documents in force keep the normal fail-open default, deliberately:
a database with no flag rows should show the Constitution, not hide it. Hiding
governance is its own kind of failure, just a quieter one.

**The tests assert the outcome, not the mechanism** —
`test_with_no_flag_rows_at_all_the_foreword_is_hidden` builds a database with
zero `FeatureFlag` rows and asserts the Foreword is absent, so a rename of
`DISABLED_BY_DEFAULT` or a tidy-up of `enabled()` fails loudly instead of
silently publishing. Its negative control asserts the Constitution is still
visible in the same database, which is what stops an `enabled()` that returns
nothing from passing.

## Four per-document flags

| Flag | Default | Gates |
|---|---|---|
| `cnb_foreword` | **OFF** (+ `DISABLED_BY_DEFAULT`) | Foreword |
| `cnb_constitution` | ON | Constitution |
| `cnb_bylaws` | ON | Bylaws |
| `cnb_appendix` | ON | Appendix |

Consumed by `GoverningDocument.enabled()`, which is now what the **member-facing**
surfaces query: the viewer at `/constitution-bylaws/`, the resolution detail
amendment picker, and the three reference-document pickers in the resolution
form.

**Officer management at `/officers/cnb/*` is deliberately NOT gated.** You have
to be able to edit a document before you turn it on, which is the entire
workflow the Foreword exists for. `cnb_dashboard` and `manage_document` keep
querying every row, and `OfficerAccessToDisabledDocumentsTests` pins that.

A `doc_type` with no entry in `FLAG_FOR_DOC_TYPE` is treated as **visible**, so
adding a fifth document type without a flag fails toward the old behaviour
rather than vanishing with no error.

⚠️ CLAUDE.md records **16 seeded flags that gate nothing** and calls them a
handoff hazard, precisely because they look like they do something. These four
gate real behaviour and must not become the 17th through 20th — if a future
change stops consulting `enabled()`, delete the rows in the same commit.

## A latent bug this exposed: documents had no ordering at all

`GoverningDocument` had **no `Meta.ordering`**, and every query in
`view/officer/cnb.py` is a bare `.all()`. Document order on the viewer was
therefore whatever the database chose to return. It looked correct only because
the three rows were inserted in reading order and rarely updated — Postgres
returns unmodified rows roughly in insertion order, until an `UPDATE` moves one.

**A Foreword turns that from latent to certain**: it is created last and must
render first, so without an explicit order it would have appeared *after* the
Appendix, and the cause would have looked like a template problem.

Fixed with `display_order` (Foreword 0, Constitution 10, Bylaws 20, Appendix 30
— gaps so a document can be inserted without renumbering) plus
`ordering = ['display_order', 'doc_type']`, matching what `Article` and
`Section` have always had. `DocumentOrderingTests` creates the four documents in
**reverse** order, because insertion order is exactly what used to leak through.

## `--update` would have destroyed the Foreword

`seed_cnb_documents`' documented contract is that `--update` refreshes metadata
and never overwrites edited content; `--force` is the escape hatch. That
contract was written when content only ever lived in `Section.content`, and it
**silently stopped holding** the moment a document existed whose text is its
preamble. Editing the Foreword in the C&B manager and then running a command
documented as safe would have thrown the edit away with no warning.

`--update` now leaves a prose-only document's preamble alone (and says so on
stdout); `--force` still overwrites. Documents with articles are unaffected —
their preamble is a one-line header, which is what the old behaviour assumed.

## ⚠️ Multi-line `{# … #}` — third occurrence, now a test

Mason spotted a comment rendering above the Drafts tab on My Work. Django's
hash-comment syntax is **single-line only** — the lexer's pattern does not span
newlines, so a comment written across several lines is not a comment: the `{#`
is consumed and the rest is emitted as page text.

A sweep found **five in the tree**, and the distribution is the finding:

| File | Release | Author |
|---|---|---|
| `legislation_history.html:46` | v3.19.0 | Mason — the one he spotted |
| `legislation_history.html:612` | v3.19.0 | Mason |
| `legislation_draft_edit.html:141` | v3.19.0 | Mason |
| `cnb/viewer.html:96` | **v3.19.1** | **me, earlier in this same session** |
| `cnb/viewer.html:126` | **v3.19.1** | **me** |

All five converted to `{% comment %} … {% endcomment %}`.

**Two of them were written by someone who had read the rule that morning.**
CLAUDE.md has carried it since 07-30-26 (`5965773`, *"Forgot multi line comments
just show on the template lol"*), it is listed under v3.16.3 as a thing to
remember, and it was broken anyway within hours of being read — because nothing
enforced it, the failure is invisible in review (a comment block *looks* like a
comment block), and it only surfaces if someone loads the page and reads
carefully.

That is the argument for **new `src/test_template_comments.py`**: a rule that
lives only in prose is followed until attention is elsewhere. It scans raw
template text — deliberately not Django's lexer, since asking the lexer means
asking the component whose behaviour *is* the bug, and it reports nothing wrong
— and fails with file:line for every multi-line or unclosed `{#`.

It ships with **negative controls**, which this module needs more than most: a
test that passes when it finds nothing is indistinguishable from a detector that
*can* find nothing, and the entire premise here is that the bug is invisible. So
`test_the_detector_recognises_a_bad_comment` asserts against literals rather
than fixture files, so it cannot be quietly satisfied by someone tidying up
templates.

Verified against the current tree: 0 offenders, controls behave.

## Deploy

**Migration required.** Order matters:

```bash
git pull
manage.py migrate                 # 0015 — adds display_order, numbers existing rows
manage.py seed_feature_flags      # creates the four cnb_* flags
manage.py seed_cnb_documents      # creates the Foreword (invisible: flag is off)
manage.py check
# restart parliament-gunicorn.service
```

No static assets change → no `collectstatic`, no Cloudflare purge.

✅ **Seeding does not publish.** `test_seeding_does_not_publish` asserts running
both seed commands leaves the Foreword hidden. Adoption is one toggle at
`/admin-v2/` → Feature Flags → **C&B — Foreword**, the day it passes.

⚠️ **The three `cnb_*` flags for documents in force seed ENABLED**, so running
`seed_feature_flags` changes nothing visible for the Constitution, Bylaws or
Appendix. If any of them is already off in prod for some other reason,
`get_or_create` will not turn it back on — the seeder only sets defaults on
creation.

**Update `DEPLOYED.md` at the moment it ships**, and note this stacks on
v3.18.7 (middleware batch, code-only) and v3.19.0 (legislation drafts, migration
`0014`), both also uncommitted.
