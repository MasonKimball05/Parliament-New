# v3.15.3 — login-flood 502 fix + uptime watchdog

## The 07-19 502 incident

Daphne wedged (process alive, not serving; systemd had to SIGKILL it on
restart). Root cause from the journal: hung `POST /login/` ASGI instances.
The login path does a **synchronous external geo lookup** to `ip-api.com` —
and the failed-login handler used the **uncached** `get_geolocation_from_ip`.
A brute-force / scanner flood on `/login/` (the logs are full of it, plus
raw-IP `DisallowedHost` hits bypassing Cloudflare) turned that into a pile of
blocking, timing-out calls on Daphne's shared sync executor until it stalled →
502. Not caused by the deploy — bot traffic just triggered a latent DoS vector.

## Fix — bound the blocking calls

- **Circuit breaker in `geo_utils.get_ip_geo`** (the single external-call
  choke point): after `_BREAKER_FAIL_THRESHOLD` (5) failures/timeouts/rate-
  limit responses within a 2-min window, the breaker opens for 5 min and all
  uncached lookups return `{}` **instantly** — so no matter how many unique
  IPs hammer `/login/`, the number of slow blocking calls is bounded. Cached
  IPs still resolve while the breaker is open; a success resets it. State is
  in the shared cache (Redis), coordinated across workers.
- **`get_geolocation_from_ip` now delegates to `get_ip_geo`** instead of its
  own uncached `requests.get`. Both login paths (success + failed) now get 24h
  per-IP caching + the breaker. Private/unknown IPs still short-circuit with no
  call. Removed the now-unused `requests` import.

Net effect: a repeat IP is free; a flood of unique IPs trips the breaker after
a handful of calls and then costs ~nothing until ip-api recovers.

Tests: `src/test_geo_breaker.py` (7) — breaker opens + short-circuits, success
resets, open breaker still serves cached IPs, delegation maps the dict shape,
private/None fast-paths make no call, **failed lookups are negative-cached**,
**the failure counter survives concurrent increments**. Existing comprehensive/
login-pipeline/two-factor suites green (87 tests).

### Breaker hardening follow-up (07-22, from the 07-22 auto-run)

Two review notes on the breaker, both fixed:

1. **Atomic failure counter.** `_breaker_record_failure` was a non-atomic
   `get()`+`set()` — concurrent failures across workers could drop increments
   and delay the trip under exactly the flood the breaker guards against. Now
   `cache.add(key, 0, window)` seeds the counter once (fixing the window TTL to
   the first failure) and `cache.incr(key)` bumps it atomically; a `ValueError`
   (counter expired between add and incr) reseeds to 1.
2. **Negative-cache failed lookups.** A failed/non-success lookup now caches
   `{}` for `_NEG_CACHE_TTL` (5 min) so a repeat hit on the same bad/unresolved
   IP is served from cache instead of re-issuing the external call. Short TTL so
   a transient blip is retried soon; only the geo *label* is affected
   (`is_foreign_ip` treats empty geo as benefit-of-the-doubt, no security
   change), and once the breaker is open failures short-circuit before this
   point, so at most a handful of IPs are ever negative-cached.

Verified in isolation (LocMemCache, mocked `requests.get`): repeat failing IP =
1 call + `{}` cached; N distinct failures trip at exactly the threshold; 20-IP
flood bounded to `THRESHOLD` calls; success still resets; open breaker still
serves cached IPs with no call.

## Uptime / 502 watchdog (`scripts/check_uptime.sh`)

Requested after the incident: alert if the site is down for >15 min. A plain
shell script on **system cron** (every 5 min) — independent of the app it
watches, so it works when Daphne is the thing that's down.

- Curls the origin through nginx (cache-buster + `Host` header) so a
  Cloudflare-cached 200 can't hide an origin 502.
- Tracks consecutive failures in a state file. Emails **once** after 3
  consecutive fails (~15 min) and **once** on recovery — silent otherwise
  (no spam). Delivery via cron `MAILTO` (independent of Django SMTP), plus an
  optional direct `mail` send if `UPTIME_ALERT_EMAIL` is set.
- State machine verified end-to-end against a local server (down→alert→
  silent→recovery). Cron line + `MAILTO` note added to `scripts/crontab.txt`.

## Deploy

- No migration. Deploy the code (breaker takes effect immediately) and add the
  `check_uptime.sh` cron line + set `MAILTO` at the top of the crontab.
- Tonight's belt-and-suspenders (no deploy needed): Cloudflare rate-limit +
  challenge on `/login/`, and firewall the origin to Cloudflare IPs only (the
  raw-IP hits are bypassing Cloudflare).
- Optional future hardening: move login tracking entirely into a Celery task
  so `/login/` never makes any external call in-request. The breaker already
  removes the DoS; this would be architectural polish.
