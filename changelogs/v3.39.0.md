## 🟢 Pledge bigs on the education dashboard, with a separate reveal

**Asked (Mason, 10-01-26):** set pledge bigs from the education dashboard,
with a way to set a pairing ahead of time separately from when it goes live,
so pledges see it on the site after the reveal. Also show it on the pledge's
My Tasks page once it's set.

**Decisions (Mason):**
- Drafts are visible and editable only with the **Manage tasks** education
  permission (chairs, admins, delegated members).
- After a reveal, the pledge can't change his big on his own profile.
- No notifications. The reveal is a ritual, so they already know.

### How it works
- **New "Bigs" card on the education dashboard**, with one row per active
  pledge. Pick a big (an active, non-pledge member), then choose when it
  goes live:
  - **Manual:** stays a draft until someone clicks **Reveal now**, or
    **Reveal all** for the whole class after the ritual.
  - **Timed:** goes live at the date and time you set.
- **A draft is invisible outside that card.** It's stored in the new
  `PledgeBigAssignment` table, not in the profile's `big_brother` field, which
  the profile card, house map and profile page all read. Revealing it copies it
  to `big_brother` (and inherits the big's house, as setting it on a profile
  already did). From then on it shows everywhere at once.
- **Hide** takes a revealed big back off the profile and returns it to a
  manual draft, in case of a mistake. **Remove** deletes the pairing (and, if
  it was live, clears it from the profile). A house inherited at the reveal
  is not undone.
- **Timed reveals** run from a new Celery beat job, `tasks.reveal_due_bigs`,
  every minute. My Tasks and the education dashboard also apply any due
  reveal when they load, so if beat stops, the pledge still sees his big on
  My Tasks on time (the profile card and house map catch up on the next
  load of either page).
  `reveal()` claims the row with a conditional UPDATE, so the job and a page
  load can't double-apply.
- **My Tasks** shows a "Your Big Brother" card once his big is revealed:
  name, pledge class, house and roll number. The chair's "View as pledge"
  preview uses the same code, so it also shows only revealed bigs.
- **Profile lock:** once revealed, the profile page shows the big as
  read-only ("Set by the education committee"), and the save ignores the
  field. Education (Bigs card) and the admin-v2 profile editor can still
  change it.

## Deploy
1. `git pull`, then `python manage.py migrate` (0056).
2. `python manage.py setup_celery_schedules`, then restart `parliament-beat`
   and `parliament-worker`.
3. Restart `parliament-gunicorn.service`.
4. No CSS rebuild needed (`make check-css` is clean). No static changes, so no
   Cloudflare purge.

⚠️ **multi-chapter:** that branch already has its own `0056`/`0057`. When main
is merged in, run `python manage.py makemigrations --merge` there (or renumber).
