## 🟡 "Back where you came from" redirects work again

**Found by:** the 10-07-26 auto-run, reading v3.44.7 before it was pushed.

### What was wrong
v3.44.7 sent the Referer-based redirects in `set_email`, `admin_v2` and
`recalculate_vote` through `safe_next`. Since v3.38.2 `safe_next` only accepts
a path that starts with `/`. A Referer header is always a full URL
(`https://am-parliament.org/profile/`), so it was refused every time and the
redirect always went to the fallback page:

- Setting or changing an email from the pop-up (it is in `base.html`, so on
  any page) sent the member to the home page instead of back to their page.
- Admin v2: adding or removing an IP on the whitelist or blacklist, and
  removing a profile picture, went to the dashboard or the user list.
- Recalculating a committee vote without permission, or while voting is open,
  went to chapter documents.

Nothing unsafe: every case failed towards a fixed page. The same commit has
been on `multi-chapter` since 10-01-26 (`f6d9a38`), so that branch has behaved
this way since then.

### Fix
- New `safe_referer(request)` in `src/next_url.py`. The Referer's host must be
  this request's host. Only its path and query are kept, and those go through
  `safe_next`. Anything else gives `''` and the caller's fallback is used.
- The three views call it instead of `safe_next(request, <Referer>)`.

### Tests
`src/tests/security/test_referer_redirects.py` (10): same-site and off-site
Referers, look-alike hosts, a different port, malformed values, the set-email
redirect itself, and a check that no view passes the Referer to `safe_next`.
The set-email "goes back" test fails on v3.44.7.
