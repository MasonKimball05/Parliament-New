## Documents open in the app's own viewer

Three documents still opened as a website page inside the app. They now open
in the same viewer as chapter documents, with Share, Save to Files and Print:

- **A bill's attached document,** from the ballot, the Legislation Tracker and
  an officer's Edit Legislation screen.
- **An excuse's supporting document,** in the officers' excuse review.
- **The Constitution & Bylaws PDF,** from the C&B screen.

New app endpoints hand over the file itself, with the same rules as the
website:

| Endpoint | Who can open it |
|---|---|
| `legislation/<id>/document/file/` | any signed-in member (the web page asks for sign-in only) |
| `excuses/<id>/document/file/` | the excuse's author, or an officer or chair, with the excuse system on |
| `cnb/pdf/` | any signed-in member; built fresh on every request, as on the website |

Each one follows its web page's pledge restriction, and none of the files is
cached. The ballot, tracker, edit-legislation and excuse payloads gained a
`document: {file, name}` field (C&B: `web.pdf_file`). The old site links stay
in the payloads, so the current app keeps working.

## Attachments and uploaded files open in the viewer too

Every other uploaded file the app linked to also opened as a website page.
These now open in the app's viewer:

- Kai report and commendation attachments, and file answers on their forms
- Service-hours attachments and file answers (the member's own, and the VPP's review)
- A slating application's GPA screenshot and file answers
- A legislation draft's document
- A resolution's uploaded document

One app endpoint, `site-file/<site path>`, serves them all. It only accepts a
path that resolves to one of the website's file-serving views (the protected
upload views, the draft document view and `/media/`), then hands the request
to **that web view itself**. Each file therefore keeps exactly the access rule
it has on the website: a draft's document is still its author's alone, and
`/media/` still refuses the private folders. Any other path, a refusal or a
redirect comes back as not found. If the server can't hand a file over, the
viewer offers "Open on the website".

**Deploy the server before publishing the app update.** An app on the update
talking to an older server would get "not found" for these files (with the
website button as the way through).

## The whole event form in the app

The app's event form had a "More settings — on the website" row for
everything it couldn't set. It can now set all of it, through the website's
own `EventForm` and `create_event` steps:

- **Repeating events** when creating one: daily, weekly (on chosen days),
  every 2 weeks, monthly or custom, with an optional end date. The series is
  generated exactly as the website generates it. An edit leaves the series'
  rule alone, as before; the "this event / and following / all" choice still
  applies to edits.
- **A second push reminder**, and **"also email"** on either reminder.
- **"Email the chapter when sign-ups open"** for a sign-up event.
- **Location check-in area:** a saved place, or where the officer is standing
  at a chosen size, optionally saved as a new place. With an area, a
  **minimum time at the event** or **study hours** (time inside counts).
- **GroupMe reminder:** which groups get it and how many hours before. Only
  groups whose audience fits the event are offered, as on the website. Once a
  reminder has gone out, the groups stay as they were.

The officers' check-in list (Officer → Mobile app) now opens the event's own
page, where the area is set, instead of the website's event editor.

`groupme.save_event_channels` now calls a new `set_event_channels(events,
ids, hours)`, which takes values rather than a form post, so the app and the
website share one implementation.

## Service Hours links to its manager

The app's service-hours manager (submissions, periods, events, expectations)
was only reachable from Officer → Programs → Service hours, so it looked
missing from the member Service Hours screen. That screen now shows "Manage
service hours" to the VPP and admins (`can_manage`, the website's
`vpp_required` rule).

"Your submissions" on that screen is now sorted by the day of the service,
newest first (it was by when each was submitted, so the dates read out of
order); submissions for the same day keep newest-submitted first.

## The last website-only pages, in the app

- **Service-hour adjustments.** Service Hours → Hour adjustments grants or
  deducts a member's hours for the period, with a required reason, and lists
  and removes them (`officer/service-hours/periods/<id>/adjustments/`, the
  dashboard's rules; also capped at the field's 999.99).
- **An announcement's documents and GroupMe.** The app's announcement form
  links chapter documents and picks GroupMe groups, pre-ticked the way the
  website pre-ticks them, and only groups whose audience fits. Until now an
  announcement posted from the app never went to GroupMe. Its GroupMe post
  goes after its email, as on the website. Once it has posted, the groups
  can't change. `save_linked_documents` and `save_announcement_channels` are
  shared with the website's views.
- **Event sign-ups as a spreadsheet.** Share as a spreadsheet sends the
  website's CSV (names and emails) to the share sheet
  (`events/<id>/signups/export/`). Like the website's, it's refused to a
  sign-in from outside the United States. That check is now
  `refuse_export_abroad`, shared with the app's admin exports.
- **C&B manager.** The "on the website" rows are gone: the manager links to
  the C&B Resolutions tab and to the PDF in the app's viewer. Everything the
  website's manager does was already in the app.
- **Transition checklist.** The handoff checklist has its own screen
  (`transitions/checklist/<id>/`, `…/items/<id>/toggle/`; officers, chairs,
  admins and the incoming holder, as on the website). An incoming officer
  with an unfinished checklist sees it on the app's Home, as on the
  website's home page. Role Transitions opens it there.
- **Song recordings** already upload from the app on a build with the file
  picker (the new one has it); the website row only shows on older builds.

Still opening the website on purpose: the general "Open on the website"
links, Print and Preview for a resolution and a Kai report (print pages),
browser-push and developer-API preferences, Admin v2, and the officers' "All
officer tools" catch-all.

## The Chapter widget (app only)

From TestFlight feedback: the blue "NEXT UP" was hard to read on a dark
widget, and the widget showed little besides votes and chat. It now uses a
lighter blue in dark mode. The small widget's last line shows the most useful
thing: votes waiting, then unread messages, notifications, the event after
next, or the newest announcement. The medium widget adds a "Then:" line and
shows only the counts that aren't zero, or else the newest announcement, or
"All caught up". No server change; it comes with the app update (the widget's
layout is part of the app's JavaScript, not the build). The widget gallery's
one-line description is part of the build and still reads "votes waiting and
unread chat" until the next one.

## `manage.py app_review_check`

A read-only check of what Apple's reviewer needs on the live server, before
submitting: the review account can sign in (in `APP_REVIEW_USERNAMES`, active,
not closed, a plain Member); `/privacy/`, `/support/` and `/terms/` are on;
location check-in and chat are on, and the review account can read a channel
with messages; a Songbook song has a recording. It also warns if GeoLite2 or
the iOS update link isn't set yet. It prints PASS / WARN / FAIL with what to
fix, and exits 1 on a FAIL.

```bash
python manage.py app_review_check
```
