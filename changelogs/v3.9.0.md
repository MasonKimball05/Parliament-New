# v3.9.0 — Admin Audit Log, Auto-Expiring Quarantines & QOL Hardening

**Release Date:** June 17, 2026
**Deployment Status:** 🔲 Not Deployed
**Type:** Feature / Security / UX

---

## Overview

Three new officer-facing features (audit log viewer, auto-expiring quarantines, onboarding completion widget), a full audit-logging pass wiring quarantine and committee role actions, and a batch of UX/hardening fixes across the admin panel, preferences, and the 403 response path.

---

## What Changed

### 1. Admin Action Audit Log Viewer

A new officer-facing page at `/admin-v2/security/audit-log/` browses the `AdminActionLog` table with filters for action type, actor, and date range. Paginated at 30/page. Action badges are color-coded by type (quarantine, token, blacklist, role). Linked from the security dashboard nav.

**Files:** `src/view/admin_v2.py` (`audit_log()`), `templates/admin_v2/audit_log.html`, `src/urls.py`

---

### 2. Auto-Expiring Quarantines

Officers can now set an optional expiry date/time when quarantining a user. Expired quarantines are auto-released nightly by a new Celery task (`release_expired_quarantines`) scheduled at 3:11 AM CST.

- `QuarantinedAccount.expires_at` — new nullable `DateTimeField`
- `QuarantinedAccount.is_active` property — updated to check both `released_at` and `expires_at`
- `QuarantinedAccount.quarantine_user()` — accepts optional `expires_at`
- `src/tasks/cleanup.py` — `release_expired_quarantines` task
- `src/management/commands/setup_celery_schedules.py` — task registered at 3:11 AM CST
- `templates/admin_v2/quarantine_management.html` — datetime-local input for expiry; card shows "Auto-releases: … (in X days/hours)"

**Files:** `src/models/security.py`, `src/tasks/cleanup.py`, `src/management/commands/setup_celery_schedules.py`, `src/view/admin_v2.py`, `templates/admin_v2/quarantine_management.html`

---

### 3. Audit Logging for Quarantine & Committee Role Changes

- `quarantine_set` and `quarantine_lifted` now call `log_admin_action()` with reason, IP, and expiry detail
- Committee membership/chair changes now call `log_admin_action(action='role_changed')` with a filtered `detail` field (only membership-relevant change strings, not unrelated fields like `is_active`)

**Files:** `src/view/admin_v2.py`, `src/view/committee/committee_index.py`

---

### 4. Onboarding Completion Widget on Dashboard

The admin dashboard member card now shows a progress bar: "X/Y (Z%) onboarding complete" with color coding (green = 100%, primary = ≥75%, yellow = <75%). Backed by a single `aggregate()` query.

**Files:** `src/view/admin_v2.py`, `templates/admin_v2/dashboard.html`

---

### 5. 403 Response Hardening

`_render_403()` helper extracted in `security.py` — all four block paths now return a styled 403 with `Cache-Control: no-store, no-cache, must-revalidate, private` and `Pragma: no-cache`. `add_security_headers()` now intercepts any 403 that reaches it: JSON 403s get no-cache headers; plain-text `HttpResponseForbidden` responses get re-rendered as the styled template; already-styled HTML 403s get no-cache headers only. Prevents Cloudflare/bfcache from serving stale block pages.

**Files:** `src/middleware/security.py`

---

### 6. Django Admin Dark Mode Fix

`base_site.html` now overrides the `dark-mode-vars` block (using `static/admin/css/dark_mode.css` + `static/admin/js/force_dark.js`) instead of inline CSS hacks. The admin path is excluded from Parliament's CSP header so the inline script is safe. `localStorage.setItem('theme', 'dark')` persists across reloads.

**Files:** `templates/admin/base_site.html`, `static/admin/js/force_dark.js`

---

### 7. Preferences Page — PWA/bfcache CSRF Fix

`getCsrfToken()` now reads `csrftoken` from `document.cookie` at submit time instead of using the `{{ csrf_token }}` value embedded at render time (which goes stale when bfcache serves the page). `alert()` calls replaced with an inline `#pref-save-error` banner visible in PWA standalone mode. HTTP non-200 responses before `.json()` now throw explicitly with the status code.

**Files:** `templates/preferences.html`

---

**Files:** `shell/README.md`
