# v3.7.0 — Security Hardening & CI Gates

**Release Date:** June 13, 2026
**Deployment Status:** ✅ Deployed — June 22, 2026
**Type:** Security / Maintenance

---

## Overview

Second security hardening pass. Closes remaining gaps from the auto-run report recommendations: per-account lockout, breached-password detection, shorter session lifetime, scope narrowing on token approval, and a traversal guard on audio serving. Also upgrades CI to block on real security findings and adds Dependabot for ongoing dependency monitoring.

---

## What Changed

### 1. Per-Account Login Lockout

`is_rate_limited()` previously keyed only on IP address, meaning a distributed or IP-rotating attack on a single username would never trigger a lockout. Added a parallel per-account counter keyed on username.

- After 10 failed attempts across any IPs, the account is locked for 15 minutes
- The user receives a security notification email when their account locks
- Successful login clears both the IP and account counters
- Account lockout check runs early in the login view, before authentication, so it can't be bypassed by submitting different passwords rapidly

Threshold is intentionally higher than IP lockout (10 vs 5) to avoid false positives from mistyped passwords.

**Changed:** `src/view/login_view.py`

### 2. Breached-Password Checking (Have I Been Pwned)

Added `PwnedPasswordValidator` to `AUTH_PASSWORD_VALIDATORS`. Uses the HIBP k-anonymity range API — only the first 5 characters of the password's SHA-1 hash are ever transmitted. The full password never leaves the server.

Applies to all Django password change flows (`ForcedPasswordChangeForm`, `ChangePasswordForm`, password reset). Fails open: if the HIBP API is unreachable (network error, 3-second timeout), the password is accepted so users aren't blocked by a third-party outage.

**Changed:** `src/validators.py`, `Parliament/settings_postgres.py`

### 3. Session Cookie Lifetime Reduced

`SESSION_COOKIE_AGE` reduced from 30 days to 7 days. With `SESSION_SAVE_EVERY_REQUEST = True` (already set), the cookie slides on every request, so active users are unaffected. A stolen or abandoned cookie now expires after 7 days of inactivity instead of 30.

**Changed:** `Parliament/settings_postgres.py`

### 4. Scope Narrowing in Token Approve Modal

Previously, approving a token granted exactly the scopes the member requested with no way to narrow them. The approve modal now shows the member's requested scopes as pre-checked checkboxes — admins can uncheck any scope before approving.

The backend validates all submitted scopes against `ALL_SCOPE_KEYS` and saves only the approved subset.

**Changed:** `templates/admin_v2/api_tokens.html`, `src/view/api.py`

### 5. `serve_song_audio` Path Traversal Guard

`serve_song_audio` built a file path from `song.audio_file.name` (a `FileField` value, not user input) without a `realpath` check. Low-risk since the value comes from the DB, but added the same `os.path.realpath` guard used by `serve_exportable_media` for uniform defense-in-depth.

**Changed:** `src/view/songbook.py`

### 6. CI Security Gates Upgraded

- Replaced `safety` (now requires a paid API key) with `pip-audit` for dependency vulnerability scanning
- Bandit now **fails the build** on HIGH-severity findings (previously `continue-on-error: true` on everything)
- MEDIUM findings still run with `continue-on-error` as a warning
- Added `dependabot.yml` — weekly dependency update PRs for pip packages, Django major version updates excluded (require manual review)

**Changed:** `.github/workflows/ci.yml`, `.github/dependabot.yml` (new)

> **Manual step required:** Enable **Secret scanning → Push protection** in GitHub repo Settings → Code security. Prevents future accidental secret commits.
