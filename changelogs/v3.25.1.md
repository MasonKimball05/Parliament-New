## `make stamp-ledger` could not clear the gate that recommends it

The v3.25.0 push was refused by `src.W003`, correctly. The pre-push hook printed
its standard remedy:

```
[pre-push]   Fix it with one command:
[pre-push]     make stamp-ledger
```

`make stamp-ledger` ran, reported **four lines updated**, and said *"now commit
them"*. `manage.py check` was still red, on the other half of the same warning:

```
?: (src.W003) … also, changelogs that are committed but have no
   DEPLOYED.md row: v3.22.0, v3.23.0, v3.24.0, v3.25.0
```

`src.W003` reports **two** problems — a `**Committed & pushed:**` line that
still says "not yet", and a committed release with **no ledger row at all**.
`stamp_ledger_rows()` iterated the rows in `DEPLOYED.md` and rewrote the Commit
cell of any that needed it. It could not create a row that did not exist, so for
a brand-new release it fixed one half and left the other, and the next `git
push` was refused again.

> ⚠️ **A TOOL THAT RESOLVES ONE OF THE TWO THINGS A CHECK REPORTS HAS MOVED THE
> FAILURE, NOT FIXED IT.** Same shape as v3.21.7's `IntegrityError` replacing a
> `ValidationError` — and worse here, because the hook's own message promises
> *"Fix it with one command"*, so the natural next move for anyone in a hurry is
> `--no-verify`. That is how the pre-push hook sat uninstalled for a month
> (v3.19.9).

This is the eleventh push `stamp_ledger.py` exists to stop being blocked, and
the first where the script itself was the reason.

### Why it went four months unnoticed

**`scripts/stamp_ledger.py` had no tests.** `src/test_ledger_check.py` covers
`src.W003` in twenty-seven tests — every phrase, the scoping, the shallow-clone
case, a correction note that quotes "not yet" — and stops at the edge of the
tool that exists to satisfy it. The script whose entire job is to clear a gate
was never once run against that gate.

Every release before v3.22.0 had its row added by hand at some point, so the
missing half was only ever exercised by a human who did not notice they were
doing the tool's job for it.

## The fix

`stamp_ledger_rows()` now **inserts** a row for a committed release that has
none, at the end of the table.

⚠️ **A new row is written `*not deployed*`, and that is not the script breaking
its own rule.** The script opens by stating that it never infers deployment,
because *"a plausible-looking unverified claim is indistinguishable from a
checked one"* — the 07-23 → 07-31 eight-report error. `*not deployed*` is the
**absence** of a claim, and it is the same thing a person writes by hand. An
inferred date would be the claim. `test_a_new_row_never_claims_a_deploy` pins
it, and `test_an_existing_deployed_date_is_never_overwritten` pins the other
half.

⚠️ **Insertion is scoped to what the ledger already covers**, by the same rule
`src/checks_ledger.py::_ledger_begins_at` states at length: `DEPLOYED.md` was
reconstructed on 07-31-26 and starts at v3.13.0, and **73 older changelogs are
legitimately absent from it**. Without the scope this would have written
seventy-odd rows nobody asked for — the tool-shaped version of the guard that
cried wolf on its own first run.

⚠️ **A row appended after the prose is not a row.** `DEPLOYED.md` continues past
the table with several paragraphs, and markdown ends a table at the first
non-`|` line, so an insert in the wrong place would both fail to register and
silently break the rendering. `test_the_new_row_lands_inside_the_table` parses
the table the way `checks_ledger` does and requires the new row to be reached
before the prose.

## New — `src/test_stamp_ledger.py`, 9 tests

Eight against a temporary ledger (creation, the Deployed rule in both
directions, the pre-ledger scoping control, idempotence, dry-run, a missing
file, and the in-table placement), plus one end-to-end:
`TheRealLedgerIsStampedTests` runs the real script in report-only mode against
the real repository and requires it to have nothing left to do.

That last one is `src.W003` from the other side. The check says *the ledger
disagrees with git*; this says *the tool that fixes that has no work left*. They
sound like the same statement and for four months they were not.

**Negative control:** loaded `HEAD:scripts/stamp_ledger.py` — the pre-fix
script — and ran the fixture through it. `changed -> []`, no row created. The
four row-creation tests fail against it.
