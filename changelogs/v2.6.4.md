## Key Features

### Kai Report System

- **User Dashboard**: Personal dashboard showing all submitted Kai reports
- **View Own Reports**: Users can view details of their submitted cases
- **Request Closure**: Users can request case closure (requires Kai chair approval)
- **Form Builder**: Kai chairs can customize the report form with additional fields

### Plurality Voting

- **Multi-Select Voting**: Allow voters to select 1-10 options in plurality votes
- **Runoff Voting**: Create runoff votes from top N options of a tied/close vote
- **Works for Both**: Chapter legislation and committee voting support these features

## Kai Report System Enhancements

### User Kai Dashboard (`/kai/`)

A new landing page when users click the Kai button on the home page.

**Features:**
- Lists all reports the user has submitted
- Shows report status (pending, reviewed, archived)
- Shows deliberation outcome
- Links to view individual report details
- Button to submit new reports

**Access:** Any logged-in user

---

### User Report View (`/kai/my-report/<id>/`)

Read-only view of the user's own report.

**Features:**
- Full report details (title, category, description, attachments)
- Current status and deliberation outcome
- Closure request history (pending, approved, denied)
- Activity timeline
- Option to request closure (when eligible)

**Eligibility for Closure Request:**
- Report status must be "reviewed" or "archived"
- Deliberation outcome must NOT be "pending"
- No pending closure request already exists

---

### Request Closure (`/kai/my-report/<id>/request-closure/`)

Form for users to request their case be closed.

**Workflow:**
1. User submits closure request with reason
2. Kai chairs receive email notification
3. Chairs see pending request in manage report view
4. Chair can approve (archives report) or deny (with required reason)
5. User receives email notification of decision

---

### Form Builder (`/kai/form-builder/`)

Kai chairs can customize the report submission form.

**Features:**
- Add custom fields with various types
- Drag-and-drop field reordering
- Edit or delete custom fields
- Toggle fields active/inactive
- Built-in fields (title, category, description, etc.) cannot be deleted

**Supported Field Types:**
| Type | Description |
|------|-------------|
| `text` | Single-line text input |
| `textarea` | Multi-line text area |
| `number` | Numeric input |
| `email` | Email address input |
| `date` | Date picker |
| `select` | Dropdown single-select |
| `multiselect` | Multiple selection |
| `checkbox` | Checkbox (yes/no) |
| `radio` | Radio buttons |
| `file` | File upload |
| `member_select` | Member dropdown |

**Access:** Kai committee chairs and admins only

---

### Closure Request Management

In the manage report view, Kai chairs can now:

- See all closure requests for a report
- View request reason and requester
- Approve requests (archives the report automatically)
- Deny requests (must provide reason)
- View past closure request decisions

**Email Notifications:**
- Requester notified on approval with optional review notes
- Requester notified on denial with reason

## Plurality Voting Enhancements

### Multi-Select Voting

Plurality votes now support allowing voters to select multiple options.

**Configuration:**
- "Votes Allowed" field (1-10) when creating plurality vote
- Default is 1 (single selection)
- Validation ensures voters don't exceed allowed selections

**Chapter Voting:**
- Create/edit legislation with plurality type
- Set number of votes allowed
- Results show vote counts per option

**Committee Voting:**
- Same functionality for committee legislation
- Works with existing voting deadline system

---

### Runoff Voting

Create automatic runoff votes from close or tied plurality results.

**How It Works:**
1. Enable "Allow Runoff" when creating plurality vote
2. Set number of top options to include in runoff (default: 2)
3. After voting ends, "Create Runoff" button appears in results
4. Runoff vote is created with only the top N options
5. Runoff is linked to parent vote for tracking

**Runoff Tracking:**
- Runoff votes show "Runoff Vote" badge
- Link to original vote displayed
- Parent vote shows link to runoff
- Results can be compared easily

## Database Changes

### New Models

**KaiFormField**
```python
field_name      # CharField, unique identifier
label           # CharField, display label
field_type      # CharField, one of the supported types
options         # JSONField, for select/radio options
is_required     # BooleanField
validation_rules # JSONField
display_order   # IntegerField
section         # CharField, group fields by section
is_active       # BooleanField, soft delete
is_builtin      # BooleanField, cannot delete if True
```

**KaiReportFieldResponse**
```python
report          # ForeignKey to KaiReport
field           # ForeignKey to KaiFormField
text_value      # TextField, for text responses
number_value    # DecimalField, for numeric responses
json_value      # JSONField, for multiselect/checkbox
file_value      # FileField, for file uploads
```

**KaiClosureRequest**
```python
report          # ForeignKey to KaiReport
requested_by    # ForeignKey to User
reason          # TextField
status          # CharField (pending/approved/denied)
reviewed_by     # ForeignKey to User (nullable)
reviewed_at     # DateTimeField (nullable)
review_notes    # TextField
requested_at    # DateTimeField (auto)
```

### Model Field Additions

**Legislation & CommitteeLegislation:**
```python
plurality_votes_allowed    # PositiveIntegerField, default=1
plurality_runoff_enabled   # BooleanField, default=False
plurality_runoff_count     # PositiveIntegerField, default=2
plurality_is_runoff        # BooleanField, default=False
plurality_parent           # ForeignKey to self (nullable)
```

**KaiReportActivity:**
- Added new action choices: `closure_requested`, `closure_approved`, `closure_denied`

## Deployment Instructions

### 1. Deploy Code Changes

```bash
cd /var/www/Parliament-New
git pull origin main
```

### 2. Run Migrations

```bash
source .venv/bin/activate
python manage.py migrate
```

### 3. Restart Gunicorn

```bash
sudo systemctl restart gunicorn
# or
sudo systemctl restart parliament
```

### 4. Verify

- Visit `/kai/` as a regular user to see the new dashboard
- As a Kai chair, visit `/kai/form-builder/` to test form customization
- Create a test plurality vote with multi-select enabled

## User Guide

### For Regular Users

1. **Access Dashboard**: Click the Kai button on the home page
2. **View Reports**: Click on any report to see details
3. **Request Closure**: On eligible reports, click "Request Closure" button
4. **Submit New Report**: Click "Submit New Report" button on dashboard

### For Kai Chairs

1. **Customize Form**: Go to `/kai/form-builder/`
2. **Add Field**: Click "Add Custom Field" and configure
3. **Reorder Fields**: Drag and drop fields to reorder
4. **Review Closures**: Check manage report view for pending closure requests
5. **Approve/Deny**: Click approve or deny with required notes

### For Chapter/Committee Voting

1. **Multi-Select**: When creating plurality vote, set "Votes Allowed" (1-10)
2. **Enable Runoff**: Check "Allow Runoff" and set top N count
3. **Create Runoff**: After voting ends, click "Create Runoff" if enabled
