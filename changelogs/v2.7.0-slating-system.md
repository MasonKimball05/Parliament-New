**Release Date:** February 2026
**Status:** In Development
**Type:** Major Feature Release

---

## Overview

This release introduces a comprehensive, highly modular slating system for officer elections. The key design principle is **extreme modularity** - forms, templates, positions, and voting rules can all be configured from the site by the slating committee chair or admin without requiring any code changes.

The system follows the chapter's Constitution and Bylaws (Article II: Officers) including:
- GPA level requirements (Level 1, 2, 3)
- 60% voting threshold (configurable)
- Up to 3 slate voting attempts before individual position votes
- Secret ballot implementation
- Confidential interview notes with destruction capability

## Key Features

### 1. Dynamic Form Builder

The cornerstone of the system's modularity. Committee chairs and admins can create custom application forms without any code changes.

**Supported Field Types:**
| Type | Description |
|------|-------------|
| `text` | Single-line text input |
| `textarea` | Multi-line text area |
| `number` | Integer number |
| `decimal` | Decimal number |
| `email` | Email address with validation |
| `phone` | Phone number |
| `date` | Date picker |
| `datetime` | Date and time picker |
| `select` | Dropdown selection |
| `multiselect` | Multiple selection dropdown |
| `checkbox` | Checkbox (single or group) |
| `radio` | Radio button group |
| `file` | File upload |
| `image` | Image upload |
| `gpa` | Special GPA entry with screenshot upload |
| `position_preference` | Position ranking interface |
| `member_select` | Select from member list |

**Form Builder Features:**
- Drag-and-drop field reordering
- Conditional field display (show field X only if field Y has value Z)
- Field sections for organization
- Required/optional field settings
- Custom validation rules
- File type and size restrictions
- Confidential fields (only visible to committee)

### 2. Configurable Positions

Positions are not hardcoded. For each slating period, the chair/admin can:
- Add any positions they want to slate
- Link positions to existing Role records (optional)
- Set position-specific GPA requirements
- Define eligibility criteria (member types, class years)
- Set custom requirements per position

**Default Positions (from Bylaws):**
- President
- EVP & IFC Delegate
- VP of Brotherhood
- VP of Recruitment
- VP of Education
- VP of Risk Management
- VP of Finance
- VP of Administration
- VP of Programming

---

### 3. GPA Level System

Following the chapter bylaws, candidates are categorized into GPA levels:

| Level | Description |
|-------|-------------|
| **Level 1** | Meets or exceeds the minimum GPA requirement |
| **Level 2** | Within 0.20 below the minimum requirement |
| **Level 3** | Below Level 2 threshold |

**Configurable Settings:**
- `min_gpa_requirement` - The minimum GPA (default: 2.50)
- `gpa_level_2_threshold` - How far below minimum for Level 2 (default: 0.20)

GPA verification includes screenshot upload from DegreeWorks.

---

### 4. Secret Ballot Voting

The voting system implements true secret ballot as required by bylaws:

**How It Works:**
1. `SlatingBallot` records track WHO voted (for audit/quorum)
2. `SlatingVote` records store the actual votes with NO link to voters
3. One-way cryptographic hashes ensure votes cannot be traced
4. Password verification required before casting vote

**Voting Flow:**
1. Full slate vote (approve/reject/abstain)
2. If slate fails after 3 attempts → individual position votes
3. 60% approval threshold (configurable per period)

---

### 5. Period Status Workflow

Each slating period progresses through defined statuses:

```
setup → nominations_open → nominations_closed → deliberation → voting_open → voting_closed → results_published → archived
```

| Status | Description |
|--------|-------------|
| `setup` | Chair configuring positions and form |
| `nominations_open` | Candidates can submit applications |
| `nominations_closed` | Applications being reviewed |
| `deliberation` | Committee discussing candidates |
| `voting_open` | Chapter voting on slate |
| `voting_closed` | Voting ended, calculating results |
| `results_published` | Results announced to chapter |
| `archived` | Historical record |

Track candidate interviews with confidentiality protections:

## How It Works

### For Admins/Committee Chairs

1. **Create a Slating Period**
   - Name the period (e.g., "Fall 2026 Officer Elections")
   - Set academic term
   - Configure GPA requirements
   - Set voting threshold (default 60%)
   - Assign slating committee

2. **Configure Positions**
   - Add positions to slate
   - Set position-specific requirements
   - Link to existing Roles if desired

3. **Build Application Form**
   - Use drag-and-drop form builder
   - Add required fields (GPA, position preferences built-in)
   - Add custom questions
   - Organize into sections

4. **Open Nominations**
   - Change status to "Nominations Open"
   - Members receive notification
   - Applications can be submitted

5. **Review Applications**
   - View all submitted applications
   - Schedule and conduct interviews
   - Record recommendations

6. **Build the Slate**
   - Assign candidates to positions
   - Create primary slate
   - Committee approves slate

7. **Open Voting**
   - Change status to "Voting Open"
   - Members receive notification
   - Secret ballot voting begins

8. **Publish Results**
   - View vote tallies
   - Announce results
   - Destroy confidential notes

### For Candidates

1. **View Open Periods**
   - See which elections are accepting applications
   - Check eligibility requirements

2. **Submit Application**
   - Fill out dynamic form
   - Upload GPA screenshot
   - Rank position preferences
   - Save as draft or submit

3. **Track Application**
   - See application status
   - Receive interview scheduling
   - Withdraw if needed

### For Voting Members

1. **View Slate**
   - See proposed officer slate
   - Review candidate information (non-confidential)

2. **Cast Vote**
   - Verify identity with password
   - Vote approve/reject/abstain
   - Confirmation of vote recorded

3. **View Results**
   - See election results when published

## User Workflows

### Application Submission Flow

```
Member visits /slating/
    ↓
Sees open periods → clicks "Apply"
    ↓
Dynamic form loads based on SlatingFormField definitions
    ↓
Member fills form, uploads GPA screenshot, ranks positions
    ↓
Saves as draft (can return) or submits
    ↓
Application status: "submitted"
    ↓
Committee notified of new application
```

### Committee Review Flow

```
Committee member visits /slating/period/{id}/applications/
    ↓
Sees list of submitted applications
    ↓
Clicks application to review
    ↓
Views responses, GPA level, position preferences
    ↓
Schedules interview → status: "interview_scheduled"
    ↓
Conducts interview, records notes
    ↓
Submits recommendation → status: "interviewed"
    ↓
Chair builds slate from recommended candidates
```

### Voting Flow

```
Chair opens voting → status: "voting_open"
    ↓
Members notified
    ↓
Member visits /slating/period/{id}/vote/
    ↓
Sees slate with all positions/candidates
    ↓
Enters password to verify identity
    ↓
Selects: Approve / Reject / Abstain
    ↓
SlatingBallot created (tracks who voted)
SlatingVote created (anonymous, tracks how)
    ↓
If 60%+ approve → slate passes
If <60% after 3 attempts → individual position votes
```

## Data Models

### Core Models

| Model | Purpose |
|-------|---------|
| `SlatingPeriod` | Election cycle with dates, status, configuration |
| `SlatingPosition` | Positions available for a period |
| `SlatingFormField` | Dynamic form field definitions |

```
    │       └── SlateCandidate (many)
    ├── SlatingBallot (many)
    ├── SlatingVote (many)

```

## Security Considerations

### Vote Anonymity
- `SlatingBallot` tracks who voted (for audit/quorum)
- `SlatingVote` stores votes with NO user reference
- One-way SHA-256 hashes prevent vote tracing
- Password verification before voting

### Confidentiality
- Interview notes marked as confidential
- `destroy_notes()` method for bylaw compliance
- Confidential form fields restricted to committee
- GPA screenshots only visible to committee

### Access Control
- Decorator-based permission checking
- Period-level committee assignment
- Role-based access (admin > chair > committee > member)
