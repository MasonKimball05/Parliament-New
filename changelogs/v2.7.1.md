### 2. Scheduled Announcement Emails

Announcements with future `publish_at` dates can now have emails automatically sent when they become published.

**How It Works:**
1. Create announcement with future `publish_at` date
2. Check "Send Email Notifications" checkbox
3. System remembers preference with `send_email_on_publish=True`
4. Cron job runs every 5 minutes to check for due announcements
5. When `publish_at` passes, emails are sent automatically
6. `email_sent_at` timestamp recorded, flag cleared

**Management Command:**
```bash
# Run manually
python manage.py process_scheduled_announcements

# Dry run (shows what would be processed)
python manage.py process_scheduled_announcements --dry-run
```

**Cron Setup:**
```bash
# Add to crontab (every 5 minutes)
*/5 * * * * cd /path/to/Parliament && /path/to/venv/bin/python manage.py process_scheduled_announcements >> /var/log/parliament_scheduled.log 2>&1
```

**Race Condition Protection:**
The scheduled announcement system uses database row locking to prevent duplicate emails:
- `select_for_update(skip_locked=True)` - Cron jobs skip announcements locked by other processes
- Announcements are marked as sent **before** emails are dispatched
- Email sending happens outside the database transaction to avoid long locks
- If two cron jobs overlap, each announcement is only processed once

### 3. Admin-v2 Manual Scheduled Email Trigger

Admins can now manually trigger scheduled announcement emails from Admin v2 → Email Logs without waiting for the cron job.

**Features:**
- New "Pending Scheduled Emails" section at top of Email Logs page
- Shows all announcements with `send_email_on_publish=True` that haven't sent yet
- "Send Now" button with confirmation popup
- Same race condition protection as cron job (uses `select_for_update(nowait=True)`)
- If cron is currently processing, shows "currently being processed by another job" message

**URL:** `/admin-v2/email-logs/`

## Bug Fixes

### System Logs Page Blank

**Issue:** The system logs page at `/admin/view-logs/` was completely blank.

**Cause:** Log parsing expected a different format than the actual log file structure. The code was splitting on ` - ` but logs used a different delimiter pattern.

**Fix:** Implemented proper regex-based log parsing:
```python
LOG_PATTERN = re.compile(r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3}) \[(\w+)\] ([^:]+): (.*)$')
```

### Email Logs Not Appearing

**Issue:** New announcements weren't appearing in the email logs list.

**Cause:** If any error occurred during the email send process, the entire function would fail before the log entry was saved.

**Fix:** Restructured `send_announcement_notification()` to:
1. Create the `AnnouncementEmailLog` record **first**
2. Wrap all processing in `try/finally` block
3. Always save the log record, even on errors
4. Capture error messages in `error_message` field

### Announcement Content Cutoff on Manage Page

**Issue:** Announcements with more than ~3 lines of content were cut off on the officer manage announcements page with no indication of additional content.

**Cause:** CSS `max-h-24 overflow-hidden` hard-limited the height without any visual cue.

**Fix:** Replaced with proper `line-clamp-4` CSS with a "Show more/Show less" toggle button:
- Content is initially clamped to 4 lines with ellipsis
- "Show more ↓" button appears only when content is truncated
- Clicking expands to show full content
- "Show less ↑" collapses back

## Deployment Steps

1. **Pull latest code**
   ```bash
   git pull origin main
   ```

2. **Run migrations**
   ```bash
   python manage.py migrate src
   ```

3. **Set up cron job** (for scheduled announcements)
   ```bash
   crontab -e
   # Add:
   */5 * * * * cd /path/to/Parliament && /path/to/venv/bin/python manage.py process_scheduled_announcements >> /var/log/parliament_scheduled.log 2>&1
   ```

4. **Restart application**
   ```bash
   sudo systemctl restart gunicorn
   ```
