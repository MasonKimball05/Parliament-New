# v3.11.0 — Candidate Notes, Education Quiz, Security Hardening (2026-06-24)

**Type:** Feature / Security Fix / Bug Fix

---

## New Features

### Structured Candidate Notes (`RecruitmentCandidateNote`)
Replaces the flat `RecruitmentCandidate.notes` text field with a proper note thread model. Chairs and members with committee access can add timestamped notes per candidate; chairs can delete any note, authors can delete their own. The candidate list page now has an expandable note thread per row with full AJAX add/delete and XSS-safe DOM insertion.

- New model: `RecruitmentCandidateNote` (`candidate` FK, `author` FK, `body`, `created_at`, `updated_at`)
- New endpoints: `add_candidate_note`, `delete_candidate_note` — both `@login_required` + `@require_page_enabled('committee_home')` + `@require_http_methods(['POST'])`
- `_candidate_list_legacy` query updated with `prefetch_related(Prefetch('note_entries', ...))`
- `candidate_list.html` — expandable note rows, AJAX JS, XSS-safe `_esc()` helper
- Migration: `0219_recruitmentcandidatenote.py`

### Education Quiz Task Type (Full Flow)
`PledgeTask.task_type='quiz'` was previously a stub with no question model or submission flow. Now complete end-to-end.

**Chair side:**
- `PledgeTaskQuestion` model — free-text questions ordered by `display_order`, scoped to quiz tasks; optional `answer_hint` field visible only to chairs during grading
- `education_add_quiz_question` / `education_delete_quiz_question` endpoints
- `education_quiz_submissions` — paginated view of all pledge answers with model-answer hints; quick "Mark Passed / Mark Incomplete" grade buttons per pledge
- `education_home` now injects `quiz_questions_map` (keyed by task_pk) for dashboard display
- New template: `committee/quiz_submissions.html`

**Pledge side:**
- `pledge_take_quiz` view — GET shows quiz, POST saves answers and creates `PledgeTaskCompletion(status='pending')` for chair review; blocks resubmission; handles not-live / not-assigned / no-questions edge cases
- `my_tasks.html` — "Take Quiz" button for live quiz tasks; "Awaiting review" state for pending submissions
- New templates: `pledge/take_quiz.html`, `pledge/quiz_not_available.html`
- Migration: `0220_pledgetaskquestion_pledgequizanswer.py`

## Security Fix

### `pledge_page_allowed` — Default-Open Behavioral Regression (🟠)
The switch from `@exclude_pledges` (hard 403) to `@pledge_page_allowed(url_name)` on three sensitive views (`chapter_documents`, `slating_apply`, `slating_results`) silently made them **world-open to pledges** when no `PledgePageRestriction` row existed — which was the case on a fresh deploy since the original table migration seeded no rows.

**Fix:** Data migration `0218_seed_pledge_page_restrictions.py` seeds default-block rows (`allowed_phases=[]`) for all three pages using `get_or_create` (idempotent — safe to apply on instances that already have rows). Pledges are now hard-blocked by default until a VPE explicitly opens a page via the dashboard.

## Bug Fixes

### Weekly Digest Idempotency Guard
`send_weekly_chapter_digest` had no duplicate-send guard. If Celery retried (worker crash, soft timeout) or the periodic task was registered twice, every member received duplicate emails that week. A cache sentinel (`weekly_digest_sent_{year}-{week}`) is now set at task entry; a second invocation within 60 hours returns early.

### `@require_page_enabled` on Education Views
All 7 education committee views now carry `@require_page_enabled('committee_home')`, consistent with the rest of the codebase. Previously the education dashboard was reachable even when `committee_home` was disabled.
