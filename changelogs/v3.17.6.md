## 🔴 1. Two security tests went quiet instead of failing

**Files:** `src/test_query_narrowing.py`, `src/test_dev_mode_rows.py`

Both fetched `/passed_legislation/` by literal path. After the rename that is a
404 — and neither test noticed, because of what each asserts:

- **`test_pages_do_not_select_credentials_on_a_join`** scans a page's `JOIN`s
  for password/token columns. Measured: the page at its real path issues **2
  joins**; the 404 issues **0**. Zero joins means nothing to inspect, so the
  test passed by having nothing to look at. This is the guard that keeps
  `MEMBER_ACCOUNT_FIELDS` out of every list page.
- **`test_no_ballot_content_reaches_the_page`** is a stack of `assertNotIn`
  calls against the rendered body. **A 404 body satisfies every absence
  assertion trivially.** This is the guard on the dev-mode row inspector never
  rendering ballot rows.

**This is the fourth time this codebase has been bitten by a check that appeared
to run and did not:** the IP-blacklist sweep silently shrinking to 132 of 282
pages (v3.17.4), the attendance test passing against the very field definition
it existed to catch (v3.17.4), the detail-route sweep rendering 83 of 319, and
now this.

**The lesson they share: a test that cannot fail is worse than no test, because
it is trusted.** Where the assertion is "X is absent", prove first that there was
something for X to be absent from.

**Fix:** both now resolve by *name*, and both assert the page rendered before
asserting anything about it — `_load()` in `test_dev_mode_rows` raises on any
non-200, and the credential scan asserts 200 per URL.

`static()` only registers a route when `DEBUG=True`, so the old path kept
working locally. That is the same DEBUG-masks-it mechanism recorded in
CLAUDE.md for the 07-18-26 mobile broken-seal bug.

## 🟡 3. Old paths 404'd with no redirect

A renamed path breaks four things that live outside the codebase: bookmarks,
links in **emails already sent**, `Notification.link` values **already stored in
the production database**, and the removed `/admin_v2/` alias.

Eleven legacy routes added at the bottom of `src/urls.py`, using `pattern_name`
so they follow any future rename and `query_string=True` because the stored
notification links carry `?status=personal` and a redirect that drops it lands
on the wrong tab. Verified end to end: `/passed_legislation/?status=personal`
→ 302 → `/passed-legislation/?status=personal` → 200.

`permanent=False` (302) on purpose: a 301 is cached by browsers indefinitely and
is very hard to take back.

## New: `src/test_hardcoded_urls.py`

Scans `src/`, `templates/` and `Parliament/` for string literals that look like
site paths and fails on any Django cannot resolve. The allowlist is for strings
that only look like paths — JS URL fragments, filesystem paths, honeypot decoys,
middleware prefix comparisons — and each entry carries its reason. A second test
fails if an allowlist entry stops being needed.

**Verified against the regression, not just the fix:** with the legacy redirects
removed and one stale link restored, it reports
`src/tasks/votes.py:284  /passed_legislation/`.

Two things the test learned about itself on its first runs, both kept as
comments because both are the same mistake in miniature:

- Its first pattern required a closing quote directly after the path, so it
  **silently skipped every literal with a query string** — including the
  `tasks/votes.py` one, the single most consequential in the codebase. A scanner
  that quietly declines to look at a case is exactly the failure this module is
  about.
- It flagged the three `{% comment %}` blocks written in the same commit to
  explain the links being fixed. Comment blocks are now stripped — but only the
  **single-line** `{# … #}` form, because Django's hash comment is single-line
  only and treating the multi-line form as a comment would reproduce the bug
  CLAUDE.md records. (I made exactly that mistake writing those comments.)

## Deploy

⚠️ **`nginx.conf` changed** — `location /exportable_media/` → `/exportable-media/`.
Without the reload, new-path asset requests fall through to Django (still
correct, but they lose the `expires 30d` edge cache) while the old location keeps
serving a path nothing links to any more. `nginx -t && systemctl reload nginx`.

**Worth a separate decision, not changed here:** that nginx block serves
`exportable_media` files **directly from disk with no authentication**, bypassing
`serve_exportable_media`'s `@login_required` and traversal guard. That is
pre-existing and not caused by the rename — but it is the same shape as the
🔴 public `/media/` exposure found 07-18-26, and the `/media/` block was changed
to `return 403` for exactly that reason. Decide whether these assets are meant
to be public.
