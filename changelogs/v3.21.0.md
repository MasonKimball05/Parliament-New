## ⚠️ #9 could not be built as proposed, and that is the headline

The idea was *"which question did everyone get wrong — one grouped query"*.
**There was no query to write.** `PledgeQuizAnswer` stored free text and nothing
else: grading was whole-quiz (a status, and since v3.20.0 a score), so nothing
in the database recorded whether any individual answer was right.

I could have shipped a substitute — response rates, answer lengths, score
spread — and called it item analysis. That would have looked like the feature
and answered a different question.

So v3.21.0 adds **`PledgeQuizAnswer.is_correct`** (nullable: `None` means *not
marked*, which is distinct from wrong) and per-question **Right / Wrong / Clear**
buttons on the grading page. Marking is optional — a chair who only wants a
whole-quiz verdict ignores them and nothing breaks — and every row of the
breakdown reports how many answers are still unmarked, because **the analysis is
only as good as the marking somebody actually did.**

> *"0% correct"* and *"nobody has marked this yet"* are opposite messages, so
> they do not share a rendering: unmarked rows show **Not marked yet** and sort
> last. Weakest-first otherwise, because the page answers *what do I re-teach*
> and that should not be at the bottom.

### Visibility — educators by default, pledges if shared

Per Mason: `PledgeTask.show_analysis_to_pledges`, **default `False`**, per quiz.

⚠️ **Deliberately a model field and not a feature flag.** CLAUDE.md records that
`FeatureFlag.is_feature_enabled()` **fails OPEN** for an unseeded name — and a
gate on *who may see the class's results* is the wrong thing to be wrong about
in the open direction. A boolean defaulting to `False` fails closed with no
seeding step to forget.

Both pages are built by **one** context builder, so a pledge and a chair cannot
be shown different numbers. Neither page shows who answered what.

## #6 — a pledge can see his own attendance

He could see *"attendance points: 10"* with no way to find out why it was not
25. Now: every meeting he has been marked for, the status, and what he earned of
what was available.

> **If you score someone, the person being scored has to be able to audit it.**
> Otherwise the first he hears of a gap is at an initiation review, from someone
> holding a number he cannot check.

## #7 — excused-absence requests

Before this, an excused absence was a text message that existed only in a
chair's memory, and the pledge had no record he had ever asked.

- A pledge asks from the meeting card on My Tasks; the chair sees a queue on the
  dashboard and approves or denies with an optional note back.
- **Approving writes the attendance** (`excused`). An approval that left the
  roster untouched is the "I told him and he forgot" failure this exists to
  remove. **Denying writes nothing** — the meeting has not happened and he may
  still turn up.
- **Only for meetings that have not happened.** Asking to be excused from
  something that already took place is not a request, it is a dispute about a
  record — a different conversation, and one that should happen with a person
  rather than through a form that looks like it will be granted.

⚠️ **A new model, not `AttendanceExcuse`** — my own idea note said to check
whether that could be reused, and the answer is no: it hangs off `Event` and its
queue is read by **officers** for chapter events, so an education absence filed
there would reach the wrong reviewer and mix pledge records into chapter ones.
Same reasoning as `EducationMeetingAttendance`. The cost is a second excuse
flow, which is real; the alternative couples the two populations.

**No file upload, deliberately.** `AttendanceExcuse` takes a doctor's note, and
that pulls in the entire private-upload surface v3.19.6/7 had to fix. A reason
field answers the question a chair actually has.

## #8 — duplicate a task

Every pledge class needs roughly the same twenty tasks, retyped each term.
Cloning is the honest primitive: tasks are not semester-scoped, so *"copy last
term"* really means *"make me another one of these"*.

⚠️ **The clone is always a draft**, whatever the original was — a duplicate that
went live instantly would publish a half-edited task, still called *"… (copy)"*,
to every pledge's page. **The due date is not copied**: last term's date is
wrong by definition and a stale one is worse than none. Quiz questions come
with it (a quiz without them is not a copy of that quiz); answers and
completions do not — they belong to the sitting, not the paper.

## #10–#13 — the cross-cutting UI work

- **#10 One modal component.** `components/modal_open.html` + `modal_close.html`;
  all three education modals converted. A Django `{% include %}` cannot wrap
  arbitrary markup and inheritance is one-per-page, so a **pair** is the honest
  way to share a shell — and `src/test_modal_component.py` asserts every page
  closes as many as it opens, because an unbalanced pair is the one new failure
  mode and produces unclosed `<div>`s that browsers hide.
- **#11 Empty states.** Every list on the education pages now says what to do
  when it is empty rather than rendering a blank box.
- **#12 One status vocabulary.** `components/status_pill.html` — the same four
  states had three visual languages. Green means done/present, amber waiting,
  red a problem, everywhere.
- **#13 Mobile.** Headers stack instead of squashing; the completion grid's task
  column is **sticky**, because that table has a column per pledge and is
  scrolled sideways by the person most likely to be using it standing in a room
  — a scrolled-away row label makes every cell ambiguous.

## ⚠️ Three existing guards caught me, all correctly

Worth recording because it is the second release running where the tests did
more review than I did:

| Guard | What it caught |
|---|---|
| `test_template_comments` (v3.16.3) | a multi-line `{# … #}`, which Django does not treat as a comment |
| `test_template_compiles` | the same, in the new analysis partial |
| `test_hardcoded_urls` (v3.19.9) | my JS reversed one URL and string-replaced the id into it, hardcoding the literal `/mark/` |

The third is the interesting one. The fix is not a suppression: each row now
renders its own endpoint with `{% url %}` into a `data-mark-url` attribute, so
there is no path string in JavaScript at all. **A renamed route would have
updated every `{% url %}` in the project and left that fragment behind as a
silent 404** — which is exactly what that test says on the tin.
