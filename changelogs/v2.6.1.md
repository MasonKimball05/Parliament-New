## Overview

This release adds security visibility features for administrators and officers to identify members who haven't changed their default passwords and track login activity. It also includes significant improvements to the Kai (accountability) report management interface with better organization, more deliberation options, and accused notification capabilities.

## New Features

### 1. Default Password Detection

Administrators and officers can now identify members who haven't changed their default password.

**How It Works:**
- New `has_default_password()` method on `ParliamentUser` model
- Checks if current password matches any default pattern:
  - First initial + last name (lowercase) - e.g., "James W. Smith" → `jsmith`
  - Username (for users created via officer portal)
  - User ID (fallback)

**Display Locations:**

**Admin-v2 Manage Users (`/admin-v2/users/`):**
- New "Password" column in user table
- Yellow "Default" badge with warning icon if password unchanged
- Green "Changed" badge if password has been updated
- Tooltip shows the username for default passwords

**Officer User List Edit Modal (`/users/`):**
- "Password Status" field in edit member modal
- Yellow warning box: "Using default password"
- Green success box: "Password changed"

---

### 2. Last Login Visibility

Track when members last accessed the system.

**Admin-v2 Manage Users:**
- New "Last Login" column showing date and relative time
- Format: "Feb 08, 2026" with "2 days ago" below
- Shows "Never" (italic) for users who haven't logged in

**Officer Edit Member Modal:**
- "Last Login" field with full date/time and relative time
- Format: "Feb 08, 2026 at 10:30 AM (2 days ago)"
- Shows "Never logged in" for users who haven't logged in

---

### 3. Kai Report Accused Person Management

Officers can now set or update the accused person directly from the report management page.

**Features:**
- Member selection dropdown with all active members
- Auto-fills email when member is selected
- Option to update email address if different from stored value
- Clear accused option to remove association

**Activity Logging:**
- All accused person changes are logged
- Tracks who made the change and when

---

### 4. Accused Notification System

Send formal email notifications to accused persons about their Kai case.

**Features:**
- Custom message field to describe the allegation
- Formal email template with:
  - Case reference number
  - Date reported
  - Custom description of the matter
  - Instructions to contact Kai Committee chair
- Tracks notification status:
  - `accused_notified` - Boolean flag
  - `accused_notified_at` - Timestamp
  - `accused_notification_message` - Stored message
- Visual indicator showing notification history

**Form Protection:**
- Double-submit prevention on email send buttons
- Loading spinner and "Sending..." text during submission
- Button disabled after click to prevent duplicates

## Improvements

Reorganized the manage report page (`/kai/report/{id}/manage/`) for better usability.

**Layout Changes:**
- Two-column grid layout (2/3 main content, 1/3 sidebar)
- Consolidated header with title, status badges, and quick actions

  - Deliberation & Outcome

- Clear section headers with icons

### 2. Admin-v2 Manage Users Table Enhancements

## Security Considerations

- Default password detection uses Django's `check_password()` for secure hash comparison
- No plaintext passwords are ever stored or transmitted
- Password status is only visible to officers and admins
- Accused notifications are logged for audit trail
