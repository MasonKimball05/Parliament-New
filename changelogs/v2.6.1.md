# Parliament v2.6.1 - Member Security & Kai Report Improvements

**Release Date:** February 8-9, 2026
**Status:** ✅ Deployed to Production

## Overview

This release adds security visibility features for administrators and officers to identify members who haven't changed their default passwords and track login activity. It also includes significant improvements to the Kai (accountability) report management interface with better organization, more deliberation options, accused notification capabilities with email read tracking, profile picture viewing for admins, and various UI improvements.

## New Features

### 1. Default Password Detection

Administrators and officers can now identify members who haven't changed their default password.

**How It Works:**
- New `has_default_password()` method on `ParliamentUser` model
- Checks if current password matches any default pattern:
  - First initial + last name (lowercase) - e.g., "James W. Smith" → `jsmith`
  - Username (for users created via officer portal)
  - User ID (fallback)

**Display Locations:**

**Admin-v2 Manage Users (`/admin-v2/users/`):**
- New "Password" column in user table
- Yellow "Default" badge with warning icon if password unchanged
- Green "Changed" badge if password has been updated
- Tooltip shows the username for default passwords

**Officer User List Edit Modal (`/users/`):**
- "Password Status" field in edit member modal
- Yellow warning box: "Using default password"
- Green success box: "Password changed"

### 4. Accused Notification System

Send formal email notifications to accused persons about their Kai case.

**Features:**
- Custom message field to describe the allegation
- Formal email template with:
  - Case reference number
  - Date reported
  - Custom description of the matter
  - Instructions to contact Kai Committee chair
- Tracks notification status:
  - `accused_notified` - Boolean flag
  - `accused_notified_at` - Timestamp
  - `accused_notification_message` - Stored message
- Visual indicator showing notification history

**Form Protection:**
- Double-submit prevention on email send buttons
- Loading spinner and "Sending..." text during submission
- Button disabled after click to prevent duplicates

---

### 5. Kai Accused Email Read Tracking

Track when accused persons view their notification emails via tracking pixel.

**Features:**
- HTML email template with embedded tracking pixel
- Records timestamp when email is opened
- Visual indicators on report management page:
  - Blue "Viewed [date]" badge when email opened
  - Yellow "Not yet viewed*" badge when pending
- Activity log entry when email is viewed
- Footnote explaining tracking limitations

**Technical Details:**
- New `accused_email_viewed_at` field on `KaiReport` model
- Tracking endpoint: `/kai/track-email/<report_id>.gif`
- Resets view status when new notification is sent

**Limitations Note:**
- Some email clients (Apple Mail, privacy-focused clients) block tracking pixels
- "Not yet viewed" status may not be accurate for all recipients
- Works best with Outlook/Office 365 and Gmail

## Improvements

### 1. URL Linkification in Announcements

Fixed and improved the `linkify` filter for converting URLs to clickable links.

**Changes:**
- Rewrote filter to use custom regex instead of Django's `urlize`
- Now properly detects URLs with `http://`, `https://`, and `www.` prefixes
- Auto-prepends `https://` to URLs without protocol
- Added linkify support to officer manage announcements page
- Maintains XSS protection with proper HTML escaping

**Supported URL Formats:**
- `https://example.com/path`
- `http://example.com`
- `www.example.com/path`

    default=False,

## Security Considerations

- Default password detection uses Django's `check_password()` for secure hash comparison
- No plaintext passwords are ever stored or transmitted
- Password status is only visible to officers and admins
- Accused notifications are logged for audit trail
