# v3.4.0 — AJAX Interactions & Profile UI Cleanup

**Release Date:** June 11, 2026

**Deployment Status:** ✅ Deployed

**Type:** UX Enhancement / New Feature

---

## Overview

Forms across the Profile, Preferences, and Admin API Tokens pages now submit via AJAX and give instant in-page feedback — no full page reloads. Items are added and removed from lists in-place, buttons briefly show "Saved!" or "Changed!" to confirm the action, and errors surface inline without losing form state.

This is the first step of a long-term goal to bring no-reload interactions to most of the site.

The Profile page also received a structural UI cleanup to separate Account Settings from Security into distinct cards, and to clarify that the per-item sections in Public Profile each save independently.

---

## What Changed

### AJAX Interactions — Pattern

A consistent pattern is now established across the codebase for AJAX form handling:

**Backend:** At the top of each `POST` block, detect `is_ajax = request.headers.get('X-Requested-With') == 'XMLHttpRequest'`. When true, return `JsonResponse({'success': True, ...data})` or `JsonResponse({'error': '...'}, status=400)` instead of the normal redirect.

**Frontend:** Intercept `submit` with JS, post via `fetch` with `X-Requested-With: XMLHttpRequest` + `application/x-www-form-urlencoded`. On success, update button text ("Saved!" for 2 seconds) or add/remove DOM elements in-place. On error, show an inline message without losing form state.

---

### AJAX — Profile Page

All form submissions on the Profile page are now handled via AJAX.

**Account settings** (username, preferred name, email, phone): Shows "Saved!" on the button for 2 seconds. Email conflict shows an inline error message below the button without clearing the form.

**Public profile** (bio, chapter info, social handles, big brother, graduation): Shows "Saved!" on the button.

**Change password**: Shows "Changing…" while in-flight, then "Changed!" on success and clears all password fields. On failure, parses `form.errors.as_json()` and displays the specific error messages in an inline `<p>` below the button.

**Role history add/delete**: Add appends a new row to the list in-place and clears the form. Delete removes the row without any re-indexing (uses DB primary key `rh_id`).

**Custom social links add/delete**: Add appends a new row with a bound delete handler. Delete removes the row and re-indexes the remaining `cs_index` hidden inputs so subsequent deletes reference the correct positions.

**Academic items add/delete** (majors, minors, concentrations): Same pattern per type. Delete re-indexes `ai_index` within the relevant list.

**Initiation chapters add/delete**: Add appends a new row. Delete re-indexes `ic_index`.

If the list doesn't exist yet when adding (first item), the JS creates the `<ul>` element and inserts it before the add form, replacing the "none yet" placeholder paragraph.

All user content inserted into `innerHTML` via DOM builders passes through `escHtml()` to prevent XSS.

The profile picture form is intentionally left as a full-page submit — it uses a crop modal with a `<canvas>` element and file input, which does not fit the AJAX pattern cleanly.

**Changed:**
- `src/view/profile_view.py` — Added `from django.http import JsonResponse`; added `is_ajax` detection at top of POST block; all branches return `JsonResponse` when AJAX. `role_history_add` now captures the created object (`rh = RoleHistory.objects.create(...)`) to return its `id` in the response.
- `templates/profile.html` — Added `id` to all key forms (`profile-settings-form`, `public-profile-form`, `change-password-form`, `role-history-add-form`, `custom-social-add-form`, `initiation-chapter-add-form`); `js-academic-add-form` class + `data-ai-type` attribute on academic add forms. Added `id` to lists (`custom-social-list`, `initiation-chapter-list`, `role-history-list`); `js-academic-list` class + `data-ai-type` on academic lists. Added `js-cs-delete-form`, `js-ic-delete-form`, `js-ai-delete-form`, `js-rh-delete-form` classes to delete forms; `data-cs-index`, `data-ic-index`, `data-ai-index`, `data-rh-id` attributes to list items. Added `id` to save buttons (`profile-settings-save-btn`, `public-profile-save-btn`, `change-password-btn`) and inline error paragraphs (`profile-settings-error`, `pw-error-msg`). Added comprehensive AJAX JS block before `{% endblock %}` with `postAjax`, `btnLoading/btnSaved/btnReset`, per-form handlers, `bind*Delete` functions reused for dynamically-appended rows, and DOM builder functions for each list item type.

### AJAX — Preferences Page

The "Save Preferences" button now submits via AJAX.

Shows "Saving…" while in-flight, then "Saved!" for 2 seconds. The only case that still triggers a full page reload is a theme change — CSS variables must re-apply to the document after the theme class changes, which requires a reload. The backend returns `theme_changed: true` in the JSON response to signal this, and the JS redirects to `?theme_changed=1` exactly as the non-AJAX path did.

**Changed:**
- `src/view/preferences.py` — Added `from django.http import JsonResponse`; added `is_ajax` detection; returns `{'success': True, 'theme_changed': bool}` when AJAX.
- `templates/preferences.html` — Added `id="preferences-form"` to the form; added AJAX JS block.

---

### AJAX — Admin API Tokens

Approve, Reject, and Revoke actions now remove the token row from the table instead of calling `location.reload()`. The row disappears instantly on confirmation.

Edit Scopes now updates the scope badge chips in the row in-place: the scopes `<td>` content is rebuilt from `data.scopes` in the JSON response, and the Edit Scopes button's `data-scopes` attribute is updated so the modal opens with the correct checkboxes on subsequent uses.

**Changed:**
- `templates/admin_v2/api_tokens.html` — Replaced `location.reload()` with `removeTokenRow(currentTokenId)` in the approve, reject, and revoke handlers. Replaced `location.reload()` in the scopes handler with in-place `innerHTML` patch of the scopes cell + `data-scopes` attribute update.

---

### Profile Page UI Cleanup

Reorganized the profile page to separate concerns that had been combined into a single card.

**Account Settings / Security split:** The prior single card contained account fields (username, email, phone) followed immediately by 2FA, Passkeys, and Change Password accordions. These are now two separate cards. "Account Settings" holds the core fields; "Security" holds the accordions with its own heading and section wrapper.

**Additional Details divider:** A labeled divider was added in the Public Profile card above the per-item accordions (Custom Social Links, Academics, Initiation Chapters, Role History). It includes a one-line note — "Each section below saves individually when you add or remove an item" — to clarify why there is no single save button for these sections.

**Changed:**
- `templates/profile.html` — Closed Account Settings card `</div>` before the security accordions; opened a new Security card with heading. Added "Additional Details" divider `<div>` with heading and subtext before the per-item accordion block.
