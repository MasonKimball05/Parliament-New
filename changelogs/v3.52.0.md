## New: `/api/mobile/v1/`

| Route | What |
| --- | --- |
| `auth/login/` | Password sign-in through the same checks as `/login/` (shared `src/login_pipeline.py`). Returns tokens, or `mfa_required` + a 5-minute ticket, or `mfa_setup_required` (no token) |
| `auth/verify/` | Authenticator or backup code against the ticket; same failure counting and alert as the web verify page. A locked IP gets `locked` before the ticket is touched, so it isn't used up |
| `auth/passkey/begin/`, `complete/` | Native passkey sign-in; origins = the site plus `MOBILE_ANDROID_APK_KEY_HASH_ORIGINS` |
| `auth/refresh/`, `auth/logout/` | Token rotation; sign this device out |
| `auth/web-session/` | One-time code for the web-view handoff |
| `me/` | Profile, member type, flags and page toggles the app uses to show tabs; `links.education` (the Education dashboard path when the Home page shows that card, else `null`) |
| `ws-ticket/` | 30-second websocket ticket (sent as a subprotocol, never in the URL) |
| `devices/`, `devices/<id>/revoke/`, `devices/push-token/` | Your signed-in phones; register the Expo push token |

**Tokens:** 15-minute access, 30-day refresh, rotated on every use, never
stored except as SHA-256 hashes. A device can live 90 days
(`MOBILE_DEVICE_MAX_AGE_DAYS`) before a fresh sign-in. A replayed refresh
token gets one 60-second grace use; any other reuse revokes the device and
alerts the member.

**Every request re-checks the device** (`MobileDevice.still_allowed`): not
revoked or past its age, user active, not quarantined, not Removed, password
unchanged (via Django's session-auth hash, so any password change by any path
signs the app out), and, for a device signed in with a password alone, that the
member still has no 2FA and isn't required to.

**One error shape:** every mobile view subclasses `MobileAPIView` (or
`PreAuthAPIView`), so every error is `{"error": code, ...}`: `not_authenticated`,
`invalid_token`, `token_expired`, `signed_out_<reason>`, `not_found`,
`throttled`, ... (`views_session`, `views_devices`, `views_push` used to answer
DRF's code-less `{"detail"}`).

**Throttle:** signed-in mobile views have their own per-member `mobile` scope,
`MOBILE_API_THROTTLE_RATE` (default 1200/hour), not the site-wide DRF `user`
300/hour. Login, verify, passkey and refresh keep their stricter per-IP and
per-device limits.

**Guard test** `src/tests/guards/test_mobile_views_use_mobile_auth.py`: every
mobile route uses the mobile auth class and `MobileAPIView`, except the five
listed pre-auth ones (`PreAuthAPIView`).

## New: web view handoff (`POST /m/handoff/`)

The app's web view gets a normal session by POSTing a one-time code **and** the
same device's access token. The code alone does nothing, never appears in a
URL, and the redirect is sent with `Referrer-Policy: no-referrer`.

The token comes as the form field `access_token` or as `Authorization: Bearer`
(both checked the same way; if both are sent they must match). The form field
is there because Android's web view drops headers on a POST load. Either
credential in the query string is refused, the field is redacted from error
reports and never scanned into the attack log, and a request the browser marks
cross-site (`Sec-Fetch-Site`, or a foreign `Origin`) is refused, so nobody can
post their own code and token into someone else's browser. The session
is flushed first, then marked 2FA-verified exactly as the website does after
the verify step (or the passkey flag), and carries `mobile_device_id` and the
device's sign-in geo result, so the non-US export block still applies.

`MobileSessionGuardMiddleware` logs out any session whose device is no longer
allowed, on HTTP and on websockets. No LoginHistory row or new-device alert is
written per handoff; the app sign-in already recorded one.

## New: native push

- `send_push_notification` (same signature, so every call site is unchanged)
  now queues `send_web_push` and `send_native_push`; each retries only what
  failed. The old task declared retries but never retried.
- Expo's HTTP API is called directly, ≤100 messages per request, with
  `EXPO_ACCESS_TOKEN` (Enhanced Push Security; `src.W020` warns while it's
  empty). `DeviceNotRegistered` clears the token; receipts are checked every
  15 minutes (`tasks.check_expo_push_receipts`).
- Only devices that pass the live check get pushes; a failing device's push
  token is cleared.
- Pushes carry `{url, screen, id}`; `src/mobile/deeplinks.py` maps site paths
  to app screens and refuses anything that isn't a same-site path. `/chats/` is
  `chat` with no id (the channel list); the query string is ignored for
  matching but kept in `url` (`/calendar/?year=…&month=…`).
- **Now push (in-app before):** excuse reviewed, role knowledge base, chat
  mentions, security alerts, API-token expiry, scheduled reminders. Each has a
  push preference (new JSON keys, on by default; toggles on Preferences).
  Security alerts and excuse reviews push a generic line; details stay in-app.
- Web push: a 404 now removes the subscription, like 410.
- Event reminders linked members to an officer page that isn't a route; they
  now open the calendar on that month.

## New: app links

`/.well-known/apple-app-site-association` (universal links + passkey
`webcredentials`) and `/.well-known/assetlinks.json` (app links +
`get_login_creds`). Both 404 until the settings below are set, and are reachable
past 2FA, maintenance, lockdown and pledge rules. `/m/handoff/`, `/api/`,
`/admin` and `/logout/` are excluded from universal links.
`MOBILE_IOS_BUNDLE_ID` and `MOBILE_ANDROID_PACKAGE` take comma lists (production
first, then the dev / preview ids): every app id is listed in `applinks` and
`webcredentials`, and each package gets its own assetlinks statement with the
same fingerprints.

## Web changes

- **Lockout by email:** the account lockout is now also checked under the
  username an email resolves to. Before, a locked account could still be tried
  by typing its email.
- **"Sign out other sessions"** also signs out the member's phones (except the
  one whose web view pressed it).
- **Account → Sessions** lists "Your devices" with a sign-out button.
- Pages opened inside the app hide the site's navbar and footer
  (`in_mobile_app`; layout only, never a security decision). HTML pages now
  send `Vary: User-Agent`.
- `InputSanitizationMiddleware` no longer overwrites a view's own
  `Referrer-Policy`.
- The websocket router is wrapped in an Origin check; a missing Origin is
  accepted only for ticket sockets.
- Admin: `MobileDevice`, `MobileAuthTicket`, `MobilePushTicket` are registered
  view + delete only, with every hash, the fingerprint, push token and payload
  excluded (v3.16.2 rule; CSV export honours `exclude`).

## Known, not fixed

- A member with only a passkey (no authenticator) can still sign in with a
  password alone, on the web and in the app. Same as before.
- Regenerating backup codes signs the app out (the old code set is deleted).
- Each handoff updates `last_login`, which invalidates an outstanding password
  reset or 2FA recovery link.
- Expo has no per-conversation grouping field, so chat pushes aren't threaded.
- The app must create an Android notification channel named `default`.
- `role_kb_available` pushes have no preference toggle.

## Follow-up (10-26-26 auto-run): mobile tickets are pruned

`MobileAuthTicket` rows were never deleted. The app mints one on every web-view
open (handoff code), every socket (ws ticket), every 2FA step and wrong code,
and every `auth/passkey/begin/`. That last endpoint is unauthenticated, so
anyone could grow the table at the throttle rate (20/min per IP, more from many
IPs).

- New `tasks.prune_expired_mobile_auth_tickets` (`src/tasks/cleanup.py`) runs
  daily at 3:16 AM Central and deletes tickets that expired more than a day
  ago. A used or expired ticket can never be redeemed, so nothing changes for
  members.
- Scheduled in `setup_celery_schedules` (already part of this release's deploy
  steps). Tests: `src/tests/mobile/test_ticket_prune.py` (4).
- Not done, your call: revoked or expired `MobileDevice` rows are also kept
  forever. They're one row per install, so growth is slow, and they show up in
  the admin as history.
