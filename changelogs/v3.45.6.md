## 🟡 PDF previews are rendered outside Daphne, and kept

### Before
The document viewer's page images were rendered with PyMuPDF inside Daphne,
the one process that serves the whole site. Opening a 26-page PDF added
**42 MB** to Daphne, kept until restart, and every later view rendered every
page again.

### Now
- `src/pdf_preview_helper.py` renders pages in a short-lived process of its
  own (`python -I`, no Django; starts in ~0.1 s), writes JPEGs to
  `PDF_PREVIEW_CACHE_DIR` (default `cache/pdf-previews/` in the app folder,
  outside `MEDIA_ROOT`), and exits.
- A request for page N renders N and the next 3 pages in one run. One helper
  runs at a time, so a phone loading 20 pages never starts 20 copies.
- The page count and sizes for the viewer come from the helper too, and are
  cached.
- The cache key is the file's path, size and modification time plus the
  render settings, so a replaced file is rendered fresh. Past 150 MB the
  oldest PDFs are removed. Nothing serves the folder directly: every page
  still goes through `pdf_preview_page`'s token check. It is safe to delete.
- If the cache folder cannot be written, the page is rendered into a
  temporary folder for that request instead.

| 26-page PDF | Before | After |
|---|---|---|
| Daphne memory added by viewing it | +42 MB (kept) | +3 MB |
| All 26 page images, first view | 3.3 s | 4.1 s |
| All 26 page images, next view | 3.5 s | 0.5 s |
| 26 pages requested at once, empty cache | — | 4.0 s, all 26 OK |

## 🟡 base.html's JavaScript moved to static files

base.html is rendered for every page and carried 94 KB of inline JavaScript
in 15 blocks, so even a 404 page was 91 KB. Eleven of them now live in
`static/js/base/*.js`; the four left inline are the three that use template
values and one of a few lines.

- Each is loaded with a plain, synchronous `<script src>` at the same place
  the inline block was, so it runs at the same moment. Pages call
  `Parliament.post()` and `Parliament.toast()` from their own scripts while
  loading, which `defer` would break.
- The one template value core.js used (the CSRF refresh URL) is passed in
  `window.PARLIAMENT_CONFIG`, set just before it.
- `{% static_v %}` (`src/templatetags/static_version.py`) adds `?v=<hash of the
  file>`. nginx serves `/static/` with `immutable` for 30 days, so without it a
  browser would keep running an old script after a deploy.

| Page | Before | After |
|---|---|---|
| `/home/` | 113 KB | 51 KB |
| `/vote/` | 352 KB | 290 KB |
| `/announcements/` | 95 KB | 33 KB |
| a 404 page | 91 KB | 29 KB |

The browser downloads the files once (~98 KB) and caches them.

Checked in Chromium: twelve pages (home, vote, announcements, calendar,
directory, chapter documents, profile, notifications, C&B, preferences,
excuses, polls) show the same console output as before, `Parliament.post` and
`Parliament.toast` exist on all of them, and the notification bell and the
mobile menu open. The one console error on `/home/` (a CSP "unsafe-eval"
refusal) is there before the change too; not investigated.

## Not built: generated PDFs (C&B document, minutes)
Measured: reportlab adds **~10 MB** to Daphne, kept, and builds the C&B PDF
in 0.3 s. Moving it out means one of:
- a Django subprocess per PDF: +1 s here (more on the server) and a
  **~120 MB** spike each time someone downloads one. Worse than 10 MB kept.
- splitting the two builders (~900 lines with tables, lists and markdown)
  into a data step and a Django-free render step. Doable, but a large rewrite
  of working code for 10 MB.
Left as is unless memory is still tight after these two releases.

## Deploy

```bash
cd /var/www/Parliament-New && git pull origin main
venv/bin/python manage.py collectstatic --noinput     # BEFORE the restart
sudo systemctl restart parliament-gunicorn.service
```

Restarting first would serve pages that load scripts nginx does not have yet:
no `Parliament.post`, no CSRF refresh, until collectstatic runs. No Cloudflare
purge needed: the new script URLs carry a `?v=` that has never been cached.

The preview cache folder is created by Daphne on first use (it runs as
`parliament`, which owns the app folder). If it cannot create it, previews
still work, uncached; `journalctl -u parliament-gunicorn` says so.
