## Security fix: guide allowlist no longer permits `<a target>`

`_GUIDE_ALLOWED_ATTRS['a']` allowed `target` without forcing `rel="noopener"` — the same reverse-tabnabbing pattern fixed in `view_document.py` on 07-05. `target` removed from the allowlist (inherited by `_HANDOFF_ALLOWED_ATTRS` too). Guide article links now open in the same tab; existing stored `target` attributes are stripped at render time by bleach — no data migration needed.

**Changed:** `src/view/guide.py`

## Security hardening: Daphne service runs as dedicated `parliament` user, not root

`parliament-gunicorn.service` set `User=root`/`Group=root`, turning any app-level RCE into full-system compromise and undermining `NoNewPrivileges`/`PrivateTmp`. The repo unit now runs as a dedicated `parliament` system user with `UMask=0007` so nginx (added to the `parliament` group) keeps rw on the unix socket. **One-time prod setup steps are documented as comments in the unit file itself** (useradd, group membership, chown, copy unit, daemon-reload, restart, verify). Unit passes `systemd-analyze verify` (only sandbox-environment warnings).

⚠️ **Deploy note:** `git pull` does not update `/etc/systemd/system/` — the unit must be copied manually, and the `parliament` user must exist **before** restarting, or the service will fail to start.

**Changed:** `parliament-gunicorn.service`

## Bug fixes (Mason-reported, 07-06)

### Home page "My Committees" count included inactive/archived committees

`home.py` built `user_committees` from all committees the user belongs to, ignoring `is_active`/`is_archived` — inflating the stat card count (and the classic-home committee list). Now filtered to `is_active=True, is_archived=False`. Note: the committee index page itself still shows archived committees behind its explicit `show_archived` toggle — unchanged, that's by design.

**Changed:** `src/view/home.py`

### Admin-v2 dashboard showed every recent login as "Failed"

`dashboard.html` checked `login.success`, but `LoginHistory` has no `success` boolean — it has a `status` choice field (`success`/`failed`/`blocked`). The nonexistent attribute resolved falsy for every row, so all logins rendered red "Failed". Template now switches on `login.status` and renders `get_status_display` (green Success / amber Blocked / red Failed). Only this template had the bug — repo-wide grep found no other `login.success` uses.

**Changed:** `templates/admin_v2/dashboard.html`

## Docs: Fernet column-sizing ASCII assumption documented (07-08)

`_fernet_storage_length()` sizes columns from `max_length` in characters, but Fernet pads on UTF-8 bytes — exact for the ASCII-only `ip_address` field (the only current use), but a multi-byte-capable encrypted field could overflow its column. Docstring now warns the next maintainer and gives the fix (×4 worst-case sizing or ASCII validation). Flagged in the 07-08 auto-run report.

**Changed:** `src/encrypted_fields.py`
