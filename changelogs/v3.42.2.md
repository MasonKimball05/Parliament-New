Follow-ups to v3.42.0 (live editing on the resolution edit page), from Mason's
first use of it with the committee: the notices were unreadable in dark mode,
"changed the tracked amendments" said nothing, and it asked for a reload —
"isn't the point of the web socket that I do not need to reload and can just
see his changes as they're done?"

## 🟢 No reload: you see changes as they are made

- **Typing shows up live.** While someone is working in a field, everyone
  else sees that field locked *and* showing what they type, as they type it
  (sent ~0.3s after each keystroke). If they leave without saving, the field
  goes back to the saved text. Only the lock holder's text is relayed, and it
  is never stored; saving is still the normal POST with the conflict check.
- **Amendments update in place.** When someone adds, edits or removes an
  amendment, everyone else's "Tracked Section Amendments" list redraws on its
  own. The "Save my edits and reload" bar is gone. Unsaved text in the other
  fields is untouched.

## 🟡 Notices now say what happened, and read in dark mode

- The amendment notice names the change: "Tyler Koon added an amendment to
  Constitution Art. III § 3", "…updated the amendment to…", "…proposed
  striking all of…", "…removed the amendment to…".
- A save says which fields: "Tyler Koon saved: Whereas clauses, Title."
- Notices collect in one dismissible bar with the time, newest first (last 5).
- The presence bar explains what the locks and live text mean.
- All the live-editing bars, the conflict panel and the per-field notes had no
  dark-mode text colour, so they inherited near-black text on a dark tint.
  They now use the same light/dark text classes as the rest of the page.

## 🟡 Fixed while testing: watching a draft could steal the lock

Showing someone's draft (or reverting it) fires the field's `input` event so
the chips and citation panels refresh. The page's own input listener treated
that as typing and took the lock, locking the real author out. Programmatic
updates are now marked and ignored by that listener. Found with two browsers
against a running server; it never shipped.
