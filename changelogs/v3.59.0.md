## 🟢 Mobile app: Announcements, Directory, QR check-in (Mason, 10-27-26)

New endpoints under `/api/mobile/v1/` for the app's next native screens. Each
one follows the web page it mirrors: same flags, page toggles, pledge
restrictions and visibility rules.

### Announcements
- `GET announcements/` (newest first, `?before=` paging, `?q=` search) and
  `GET announcements/<id>/`. The web page's year window, `visible_to_q`
  audience and published/active filter. Reading records a view exactly as the
  web page does (`counted_in_target` included), so officers' view counts
  include people reading in the app. Polls and linked documents come back with
  their website URLs.
- Home's announcement items now carry their id, and `/announcements/` maps to
  the app screen `announcements` (was `home`) in `deeplinks.py`.
- `src/mobile/views_announcements.py`; the view-count guard
  (`test_view_stats_snapshot.py`) lists it as a creation site.

### Directory
- `GET members/` lists who the web directory lists (active by type, advisors,
  `?alumni=1` for alumni without the 1800s founders). `GET members/<user_id>/`
  is the web's own profile card: `profile_card_json`'s body is now
  `profile_card_data(member, viewer)` in `src/view/profile_card.py`, so pledge
  masking is shared. A pledge viewer gets no roll numbers in the list either.
- `GET members/<user_id>/photo/` streams the profile picture with the Bearer
  token, since `/media/` needs a website session.
- `/directory/` maps to the app screen `directory`.

### QR self-check-in from the app
- `POST events/<id>/checkin/` with `{"token"}`. The check-in logic moved out of
  `event_qr_checkin` into `self_check_in(request, event, token)`
  (`src/view/event_checkin.py`), and the web page and the app both call it.
  Results: 200 (`already_checked_in`), 410 `checkin_expired`, 409
  `checkin_finalized`, 403 `checkin_not_eligible`. The prefix matters: the app
  reads a bare `expired` as "this phone is signed out". The app's scanner
  reads the same QR codes officers project, and scanning one with the iPhone
  camera opens the app straight to the check-in.
- ⚠️ `qr_attendance_checkin` is disabled by default. Turn it on in feature
  flags if it isn't already, or the app hides "Check in".

### `me/` features
- Two more feature fields on `me/`: `announcements` and `qr_checkin` (the
  three check-in flags together). All the flags are now read in one query
  (`FeatureFlag.resolve_many`).
