## Same bug family as v3.29.18, one field behind

The home page's "Recently Passed Legislation" card (`src/view/home.py`,
`home()` view) builds its query with:

```python
recently_passed_legislation = Legislation.objects.annotate(
    total_votes=Count('vote'),
    yes_votes=Count('vote', filter=Q(vote__vote_choice='yes'))
).filter(voting_closed=True, status='passed').order_by('-voting_ended_at')[:3]
```

`total_votes` is a `Count('vote')` annotation — real `Vote` rows only. For
a bill closed via the officer "mark as voted" manual-entry tool (no real
`Vote` rows, only `historical_yes_votes`/`historical_no_votes`/
`historical_abstain_votes`), that annotation is `0`.

The render loop right below it already knew to fall back to historical
counts for `yes`:

```python
yes = leg.historical_yes_votes if leg.historical_yes_votes is not None else leg.yes_votes
total = leg.total_votes   # ← never got the same treatment
```

So the percentage shown ("100%") was computed correctly from
`yes`/`historical_no_votes` a few lines further down and came out right —
but the caption every vote-mode branch renders (`{{ item.total_votes }}
vote{{ item.total_votes|pluralize }}`, in `home.html`/`home_modern.html`/
`home_classic.html`) used the un-overlaid `0`. Same root cause as
v3.29.18 (a display path that forgot the historical-counts overlay), just
the one field `view_legislation_history.py` didn't have this particular
bug in — different view, different missed spot.

## Fix

`src/view/home.py` — when `historical_yes_votes` is set (the same gate the
existing `yes` fallback already uses), `total` is now the sum of all three
historical fields instead of the real-`Vote`-row annotation:

```python
if leg.historical_yes_votes is not None:
    total = (
        leg.historical_yes_votes
        + (leg.historical_no_votes or 0)
        + (leg.historical_abstain_votes or 0)
    )
else:
    total = leg.total_votes
```

Applies to all three vote-mode branches below it (plurality, piecewise,
percentage) since `total` is computed once before the branch, matching
how `yes` was already shared across all three.
