## 🟢 GroupMe reminders before events (#4)

- The create/edit event pages have a **GroupMe reminder** box. Tick the groups,
  pick how long before (1 h to 3 days, default 24 h), save. It's off unless a
  group is ticked.
- Same rule as announcements: a group is only offered if everyone in it can
  see the event ("Visible To"). The server checks again on save and on send.
- Posted once per event per group by the same 5-minute sweep as scheduled
  announcements: `⏰ Reminder: Title` / `Saturday, Oct 18 at 7:00 PM · The
  house` / calendar link. An event created after its reminder time posts on
  the next sweep, as long as it hasn't started.
- Recurring events: every occurrence gets the setting. Editing with "this and
  following" or "all" applies it to those occurrences.
- The dashboard log shows "Reminder: …" rows with Retry like announcements.

## 🟢 Grading a "points by % right" quiz says what it will give (#3)

v3.48.0 counts unmarked answers as wrong, so clicking Mark Passed before
marking answers gave a pledge 0 points with no warning.

- **Grading page:** a note at the top for by-% quizzes ("N pledges still have
  unmarked answers"), and next to each pledge's buttons "4 of 10 pts · 3 not
  marked".
- **Mark Passed with unmarked answers** still saves, then says: "*Name* is
  marked passed, but 3 of 10 answers aren't marked right or wrong yet, so he has
  4 of 10 pts for now." The dashboard grid shows the same thing as a toast.
- A typed score skips all this, since it's used instead of the marks.

## 🟠 Pledge page restrictions now work on every page (#5)

Only `chapter_documents`, `slating_apply` and `slating_results` had
`@pledge_page_allowed`. A restriction for any other page saved fine, showed in
the dashboard table, and did nothing. That included the dashboard's own example
of locking the songbook until Phase 2.

- New `PledgePageRestrictionMiddleware` (`src/middleware/pledge_pages.py`) checks
  every page a pledge opens, using the same rule and 5-minute cache. It costs
  non-pledges nothing and pledges one cache read per request.
- Pages pledges always need can't be restricted: sign in/out, home, password
  change/reset, 2FA, passkeys, onboarding. The middleware ignores rows for them
  and the dashboard refuses to save one.
- **The dashboard refuses a page name that doesn't exist** ("There is no page
  called 'songbok'"). The field suggests real names as you type.
- ⚠️ **Existing restriction rows start applying on deploy.** Before deploying,
  check the education dashboard's Page Restrictions table. Anything listed
  there that was doing nothing will now block pledges.

## 🟠 Officer and admin member edits are validated (#7)

Officers → Members (edit, add, bulk import) and admin v2's profile editor saved
whatever was posted.

- **Same text rules as a member's own profile page:** no `<` `>` in names and
  other short fields; email must be an email; name can't be blank; length limits.
- **Member type and status must be real choices.** Before, `member_type:
  "Superuser"` was saved as-is.
- **🟠 A non-admin officer can no longer edit an admin's account (403).** Before,
  an officer could change an admin's email, use "forgot password" on it, and
  take the account over (only an admin with 2FA turned on was protected). Deleting an admin
  was already refused for this reason.
- **Nothing saves a spreadsheet formula any more** (was "not changed" in
  v3.45.2): a value starting with `=` `+` `-` `@` is refused unless it is only
  digits and phone punctuation. Social handles may still start with "@"
  (`@masonk`).
- **Phone numbers** must be digits, spaces and `+ ( ) - .`, with "ext 12"
  allowed.
- These rules apply only to a value that **changed**. A member with an old odd
  value can still save the rest of their profile.
