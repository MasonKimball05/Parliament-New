# v3.15.10 — supply-chain check fixes + CSP template regression test

Mason-directed fix of the 07-24 auto-run findings (report items #3/#4/#5). No
migration, no new deps, no collectstatic, no template changes. All three
changes harden the *checks*, not the app — zero runtime behavior change.

## Integrity manifest: auto-discovery (07-24 item #3)

`check_env._update_integrity_manifest()` used a **hardcoded 3-file list**
(quill ×2 + tailwind.css), so `static/vendor/chart.min.js` (referenced by 6
templates, the largest vendored asset) and `cropper.min.js`/`.css` were never
hash-tracked — and the documented `--update-hashes` regenerate command could
never add them. Now it auto-discovers everything under `static/vendor/**`
(skipping `.integrity.json` itself) plus the locally-built
`static/css/tailwind.css`, so newly vendored files are picked up automatically.

`static/vendor/.integrity.json` regenerated: **6 entries** (was 3).
Previously-tracked hashes verified byte-identical; existing metadata
preserved. New entries carry source/version metadata (Chart.js 3.9.1,
Cropper.js 1.6.1 — versions read from the files' own headers) plus a note
that upstream provenance is presumed, not verified — worth a one-time
diff against the official release files when convenient.

## CDN drift detection: cdnjs + jsdelivr now hard-fail (07-24 item #4)

The chapter-stats Chart.js that CSP blocked in prod came from
**cdnjs.cloudflare.com — a host `check_supply_chain` never watched.**
`cdn_patterns` now includes `cdnjs.cloudflare.com` and `cdn.jsdelivr.net`,
and `unpkg.com/quill`/`unpkg.com/tailwind` broadened to `unpkg.com/`. The
separate "Chart.js CDN (known, low risk)" warn tier is gone — everything is
self-hosted as of v3.15.9, so any CDN ref in a template is a hard fail
(it's also dead-on-arrival under prod CSP `script-src 'self'`).

## New: `src/test_csp_templates.py` (07-24 item #5)

The v3.15.9 bug class — inline `<script>` without a nonce works in dev (no
CSP header) and is silently dead in prod — is now a test failure instead of
a months-later prod discovery. Two `SimpleTestCase` tests (pure file scan,
no DB):

1. **`test_inline_scripts_carry_csp_nonce`** — every executable inline
   `<script>` in `templates/` must contain `request.csp_nonce` in its tag
   (hardcoded nonce values also fail). Exempt: `templates/admin/` (the
   admin path is excluded from the CSP header by design);
   `application/json` / `text/template` data blocks (non-executing).
2. **`test_no_external_script_hosts`** — no template may reference a known
   CDN host (list kept in sync with `check_env`'s `cdn_patterns`, so the
   same guarantee runs in CI on every push, not just at deploy time).

Verified against the current tree: 308 templates / 208 inline scripts
scanned, zero offenders on both tests (logic run standalone in the sandbox;
Django's runner needs the local env).
