## 🔴 Login with an email address returned 500 (fixed in `2115781`; test added here)

`UnboundLocalError: cannot access local variable 'get_user_model'` in `login_view`.

**The cause:** a function-local `from django.contrib.auth import get_user_model` (line 395, from `958a4e7`, 05-23-26) made the name local to the whole function. So the email-address lookup at line 251 (from `225d4e9`, 06-11-26) hit it before assignment. The `except (User.DoesNotExist, …)` then raised a second `UnboundLocalError`.
- **Scope:** only logins typed as an email address. It was latent since June and surfaced in prod 09-24-26.
- **The fix** removed the local import; the name is already imported at module level.

**New `src/tests/security/test_login_with_email_address.py`:**
- An email login and an unknown-email login both return non-500.
- An AST guard fails if `login_view` imports a module-level name inside the function. Negative control: it flags `395:get_user_model` on `2115781~1`.

## 🟠 C&B importer was built from the January 2025 text: Bylaws Art. III §5 and three sections missing or outdated

Reported: Bylaws Art. III §5 is missing on prod and in the importer.

**The cause:** `src/management/data/cnb_data.py` says *"Sourced from … Jan_26_Approved_Document.pdf"* and was never updated to the **August 2025** document (`exportable_media/legislation_docs/Constitution and Bylaws of the Samford Chapter - August 2025.pdf`). Every install seeded from it, prod included, lacks what the chapter adopted after January.

**How it was checked:** a section-by-section diff of **headings and text** against the August 2025 PDF (`pdftotext`, then a word-level comparison per section). It was sanity-checked against the January PDF, which the data should match. Findings:

| Where | Problem | Fix |
|---|---|---|
| Bylaws Art. III §5 "Sweethearts" | Absent entirely | **Added** |
| Constitution Art. II §3 "Membership Procedures" | Item 3 (non-discrimination statement) absent | **Updated** |
| Bylaws Art. IV §2 "Budget" | Items 1(a)–(c) (Exec Board budget meetings) absent | **Updated** |
| Bylaws Art. VII §10 c.i.2–3 | Shortened vs **both** PDFs (cross-references and the stated amendment path dropped) | **Restored** |
| Bylaws Art. VII §3, §9 | `1.` vs `i.` numbering; one garbled PDF phrase tidied | Left as is (cosmetic) |

Text is verbatim from the PDF, **source typos included** ("shall take occur", "who meets", "passing the all"). It's governing text, so corrections belong in a resolution.

**`seed_cnb_documents --only`** (new) scopes create/update to listed `doc:article:section` keys. An unknown key is an error.
- **Why it was needed:** a plain run creates missing sections but never overwrites edited text (by design), so on prod it would add §5 and leave the three outdated sections as they are. The existing `--force` overwrites **every** edited section, which would wipe any resolution-applied amendment.

**Tests:** `src/tests/legislation/test_seed_cnb_sync.py` (5):
- §5 is present with its text, and the August 2025 wording is present;
- a plain seed on an existing install adds §5 and doesn't touch edited text;
- `--force --only` replaces only the listed section and leaves a "resolution-amended" one alone;
- an unknown `--only` key errors.

The full `src.tests.legislation` suite passes (296).

## 🟠 Error alerting: 500s reach a human (#3)

New `src/error_alerts.py`, attached to `django.request` in prod only (off under `DEBUG`, off in tests, `ERROR_ALERTS_ENABLED=False` to disable). Every unhandled 500 emails `ERROR_ALERT_EMAIL`, defaulting to `SECURITY_ALERT_EMAIL`, through the existing Celery `tasks.send_email`.
- **What's in the email:** method, path (no query string), status, user pk, exception type and message, and traceback **frames only**.
- **What's never in it:** POST data, cookies, headers, session or local variables.
- **On `/kai/` paths the exception message is also dropped.** The Kai confidentiality boundary applies to alert email too.
- **Rate-limited:** one email per distinct error per hour (repeats are counted) and at most 10 per hour in total. The handler can never raise.
- **Logging is unchanged:** it attaches alongside the existing `django.request` → `django` logging, with propagation kept, so file logging and 404 warnings are untouched.
- **Tests:** `src/tests/infra/test_error_alerts.py` (7).

## 🟠 C&B cross-reference checker (#1)

New `src/cnb_crossrefs.py`. It parses "Article X[, Section N] [of the Bylaws/Constitution]" and the builder's `Bylaws Art. X § N`.
- **ERROR:** the target doesn't exist.
- **WARNING (heuristic):** the sentence names another article's or section's title (e.g. "amendments to the Bylaws" → Art. X) but the reference points elsewhere.

On the live August 2025 text it finds **exactly the 4 known problems**:
- Constitution V §1 → "Article VII, Section 1" of the Constitution (doesn't exist);
- Bylaws VII §10 → "Article VII of the Constitution" (doesn't exist);
- Bylaws VII §10 → "Article VI of the Bylaws" for amendments (it's Art. X);
- Bylaws VI §2 → "Article VI, Section 1 (a)" for Kai (it's III §2 / VII §1).

**Where the findings show up:**
- `manage.py check_cnb_references [--strict]`.
- A **Cross-reference problems** panel on the C&B **Manage** tab, for CNB holders only.
- **The viewer now links** every valid reference to its section anchor (`bylaws-art-VII-sec-1`); broken ones stay plain text. Before, only the bracketed builder form was linked, and only to the top of the page.

**Found along the way:** `cnb_dashboard` and `templates/cnb/dashboard.html` are **dead**, because `/officers/cnb/` redirects to the viewer's Manage tab. The panel went on the Manage tab; the dead view and template are left for you to delete.

**Tests:** `src/tests/legislation/test_cnb_crossrefs.py` (9). `KNOWN_PROBLEMS` there is a list that should only shrink: remove an entry when a resolution fixes the wording.

## 💡 C&B section history and "View as of" (#7)

- **New `SectionRevision` model:** the text in force *until* `replaced_at`, plus the source (resolution / direct edit / import / backfill), who and which resolution. **Append-only**, read-only in admin.
- **Recorded on every change:** `Section.record_revision()` is called immediately before each overwrite, in `Resolution.apply_amendments`, `edit_section` (only when text or title actually changes) and `seed_cnb_documents --force`. Seeder placeholders are skipped.
- **Backfill (migration `0053`):** one revision per already-applied amendment, from its `original_text_snapshot` at `passed_at`. It's marked approximate, because the snapshot is taken when the amendment is drafted.
- **`Section.created_at`:** new, NULL = predates tracking. It lets the historical view hide sections added later, like today's Bylaws III §5.
- **History page:** `/constitution-bylaws/section/<id>/history/`, a **History** link on every section. It shows the current text and each past version with what replaced it and an escaped word diff. Members can read history for enabled documents only; CNB holders can read all.
- **"View as of" a date** on the viewer (`?as_of=YYYY-MM-DD`): rewrites the prefetched sections **in memory** (never saved), hides later sections, and shows a clear "Historical view — not the current text" banner. Future or invalid dates are ignored. Revisions are prefetched only when asked for.
- **Tests:** `src/tests/legislation/test_cnb_section_history.py` (9).

## 🛠 Follow-up fixes from the 09-25-26 auto-run review (uncommitted)

These fix what the review of this release (and two carried items) found: `Claude/Reports/09-25-26-Auto-Run.md`. No migrations.

**🟡 Error-alert emails could carry tokens from the URL path** (`src/error_alerts.py`)
- The alert used `request.path`. Five routes carry a live token **in the path**: calendar feed, password-reset confirm, 2FA-recovery confirm, email-change confirm and event check-in. A 500 on any of them would have emailed the token.
- **Fix:** new `_safe_path()` reports the matched URL **pattern** (`/calendar/feed/<str:token>/`). With no resolver match (a 404 or a middleware error), it keeps only the first path segment (`/calendar/…/`).
- **Kai redaction** now matches `kai` anywhere in the path or route, so `committee/<code>/kai-permissions/` is covered. Before, only `/kai/` was.
- **Suppressed-repeat count now actually reported.** The docstring promised it but the code never read it. Repeats, and occurrences dropped by the global cap, are tallied under a 7-day key. The next alert for that error says "N earlier occurrence(s) … were not emailed".
- **"When:" line filled in.** It used `record.asctime`, which is only set by a Formatter, so it was always blank. It's now the record's timestamp in UTC.

**🟡 C&B history gaps** (`src/view/officer/cnb.py`, `src/admin_extra.py`)
- `toggle_section_active` now records a revision before deactivating (note `Deactivated: <reason>`) or reactivating (`Reactivated`).
  - Before, `?as_of=` for a date before a ruling showed the section as already inactive.
- Django admin saves now record the outgoing version when `content`, `title` or `is_active` changed.
  - This covers `SectionAdmin.save_model` and the `SectionInline` under `ArticleAdmin`. Note: `Edited in the Django admin`.
- All three use `source='direct_edit'` plus a note, so no new choice and no migration.
- `SectionRevisionAdmin` can no longer delete, which matches the model's "append-only" docstring.
  - **Side effect:** the admin now refuses to delete a `Section` that has history, because the cascade would remove it. Deactivate the section instead.

**🟢 Meeting agendas** (`src/view/officer/meeting_agenda.py`)
- `create_agenda` parses `date` / `start_time` / `event` before use. Malformed input is now the form's error message, not a 500 (which, since this release, would also have sent an alert email).
- `start_minutes_from_agenda` locks the agenda row (`select_for_update`) before its idempotency check, so a double-click can't create two drafts.
