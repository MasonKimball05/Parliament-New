From the 10-21-26 auto-run, while checking where Pillow is reachable for
v3.51.5. `submit_bug_report` builds the `BugReport` straight from
`request.POST` and `request.FILES`, with no form. Any signed-in member can use
it (pledges included).

## What was wrong

- **500 on PostgreSQL:** `page_url` > 500, `feature` > 200 or `browser_info`
  > 500 characters raised `DataError` (confirmed on Postgres 16 without the
  fix). Same kind as the v3.51.2 resolution title/type fix.
- **Unchecked choices:** `issue_type`, `page` and `priority` were saved as sent
  (a 20+ character `issue_type` also 500'd).
- **Screenshot never checked.** A model `ImageField` only verifies the image
  inside a form, so any file of any size was stored as a "screenshot". Not an
  XSS: `bug_reports/` is a private media prefix, `_reject_browser_executable`
  refuses `.html`/`.svg`/`.js`, and downloads get `nosniff` + the disposition
  allowlist. It was just unbounded storage and a route for any file type to
  reach Pillow (see v3.51.5).

## Fix (`src/view/bug_report.py`)

- `_choice()`: unknown `issue_type` → `other`, `priority` → `medium`,
  `page` → blank.
- `_clip()`: `page_url`, `feature`, `browser_info` trimmed to the column's
  `max_length` (they're informational; trimming beats refusing the report).
- `_screenshot_error()`: PNG/JPEG/WebP/GIF by extension, ≤ 10 MB, and Pillow
  open + verify (the form `ImageField` check). A bad screenshot doesn't lose the
  report: it's saved without it and the member sees "Your report was saved
  without the screenshot. …".
- `templates/bug_report.html`: the file input's `accept` lists the four types.
