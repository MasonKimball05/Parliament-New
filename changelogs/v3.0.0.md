# v3.0.0 — WebSocket Chat, Passkeys, C&B Resolution Builder & Security Hardening

**Release date:** 2026-06-05
**Status:** ✅ Deployed to Production

## Summary

Major version release. Replaces HTTP polling with persistent WebSocket connections, overhauls the chat UI, adds passkeys (WebAuthn), delivers a comprehensive C&B resolution builder with word-level diff and amendment tracking, and applies targeted security hardening across the admin and chat layers.

---

## What's New

- **WebSocket chat** — messages now arrive instantly via a persistent `wss://` connection; HTTP polling removed entirely.
- **Chat UI overhaul** — message stacking, date separators, jump-to-bottom button, typing indicator, and inline error toasts.
- **Edit flow fixes** — timezone bug in the 1-hour edit window removed; `data-raw` prevents HTML from leaking into the edit textarea.
- **@Mention notifications** — in-app bell notification and blue toast when you're @mentioned; clickable `@username` spans open a profile card.
- **Passkeys (WebAuthn)** — users can register Face ID / Touch ID / PIN as a second login method from their profile; no TOTP code required.
- **C&B amendment type system** — amendments are auto-classified as `change`, `addition`, or `deletion` based on the diff; `scope_note` field added for targeting sub-clauses.
- **Amendment editor on edit page** — full amendment workflow (add, edit, remove) is now available while drafting the resolution, not just on the detail page.
- **Word-level diff engine** — live tracked-changes preview in the amendment modal using LCS; falls back to block replacement for full rewrites.
- **Copy [ref] citation system** — reference drawer now copies a bracketed code (e.g. `[Constitution Art. I § 1 (Addition) - 1]`) that can be pasted anywhere in the form.
- **Protected citation markers** — bracketed codes in all four textareas are write-protected; only the × chip removes them, one occurrence at a time.
- **PDF preview button** — opens the print view in a new tab from the edit page header without leaving the form.
- **Print view callouts & appendix** — citation codes render as inline callouts (section ref + delta text) and a full before/after appendix instead of raw bracket strings.
- **Save & Preview** — one button saves the form and redirects to the print view; eliminates the separate save → navigate → preview steps.
- **Unsaved changes warning** — browser confirm dialog fires if you navigate away with unsaved edits.
- **Amendment editing** — Edit button on each amendment card pre-fills the modal; no remove-and-re-add needed.
- **Section search in C&B drawer** — live filter input narrows sections by identifier, title, or content text.
- **Admin v2 rate limiting** — 5 failed login attempts triggers a 15-minute lockout; `ADMIN_V2_USER_IDS` env var replaces the hardcoded user ID and supports multiple admins.
- **Chat send rate limiting** — max 5 messages per 3 seconds per user; returns 429 when exceeded.
- **Chat timestamp validation** — the `since` polling param is now validated before hitting the database; returns 400 on bad input.

## Changes

### WebSocket Real-Time Chat

Replaces HTTP long-polling for chat messages with a persistent WebSocket connection powered by Django Channels and a Redis channel layer. Previously every connected client polled `GET /api/channel/{id}/messages/?since=...` every 3 seconds while active (20 seconds while backgrounded). Now a single `wss://` connection per client receives push events instantly.

**New files:**

**`src/consumers.py`** — `ChatConsumer(AsyncWebsocketConsumer)`

| Phase | Behavior |
|---|---|
| `connect` | Authenticates via Django session (`AuthMiddlewareStack`), checks `channel.can_read(user)` via `database_sync_to_async`, joins group `chat_{channel_id}`, accepts connection. Closes with code 4001 (unauthenticated) or 4003 (no read permission). |
| `disconnect` | Leaves group. |
| `receive` | No-op — clients send messages via HTTP POST, not WebSocket. |
| `chat_message` | Forwards broadcast to client as `{"type": "message", "message": {...}}`. |
| `chat_edit` | Forwards broadcast as `{"type": "edit", "message": {"id", "message", "edited_at"}}`. |
| `chat_delete` | Forwards broadcast as `{"type": "delete", "message_id": ...}`. |

**`src/routing.py`** — WebSocket URL patterns (`ws/chat/<channel_id>/`)

**Modified files:**

- `Parliament/asgi.py` — `ProtocolTypeRouter` with `http` → Django ASGI app and `websocket` → `AuthMiddlewareStack(URLRouter(...))`
- `Parliament/settings_postgres.py` — `daphne` and `channels` added to `INSTALLED_APPS`; `ASGI_APPLICATION` and `CHANNEL_LAYERS` configured (Redis in production, InMemory fallback)
- `src/view/chat/channel_chat.py` — `_ws_broadcast()` helper; broadcast calls after send/edit/delete
- `templates/chat/channel.html` — WebSocket client with exponential backoff reconnect, replacing all polling code

**`requirements.txt`:** `channels==4.2.0`, `channels-redis==4.2.0`, `daphne==4.1.2`

### Chat UI Overhaul

**Message stacking:** consecutive messages from the same sender are grouped with adjusted border-radius so the left border accent runs as a single unbroken bar.

**Date separators:** horizontal rule with label (`Today`, `Yesterday`, `Mon Jun 2`) inserted between messages from different days; idempotent on initial load and load-older.

**Jump-to-bottom button:** appears when scrolled more than 150 px above the bottom; animated in/out.

**Typing indicator:** `{"type":"typing"}` WS event sent from client (debounced 2.5 s); server broadcasts to group; shown as `X is typing…` below the message list, auto-clears after 4 s.

**Inline error toasts:** `showChatError(msg)` replaces all `alert()` calls.

**Status dot:** green "Live" (connected), yellow "Reconnecting…" (backoff), red "Connection error".

**Files changed:** `src/consumers.py`, `templates/chat/channel.html`

### Passkeys (WebAuthn)

Optional fast-path login — Face ID, Touch ID, or device PIN; no TOTP required. Multiple passkeys per user supported. Existing username/password + TOTP flow unchanged.

**New model — `WebAuthnCredential`:** `credential_id` (BinaryField, unique), `public_key` (BinaryField), `sign_count`, `name`, `aaguid`, `created_at`, `last_used_at`

**New views (`src/view/webauthn.py`):**
- `passkey_register_begin` / `passkey_register_complete` — adds passkey from profile
- `passkey_authenticate_begin` / `passkey_authenticate_complete` — signs in via passkey on login page
- `passkey_delete` — removes a passkey

**Login page:** "Sign in with a Passkey" button; hidden if browser doesn't support WebAuthn.

**Profile page:** Passkeys accordion between 2FA and Change Password; shows registered passkeys with add/remove controls.

**Middleware:** `Enforce2FAMiddleware` checks `webauthn_authenticated` session flag before redirecting to TOTP verify.

**Files changed:** `requirements.txt`, `src/models/webauthn.py` (new), `src/models/__init__.py`, `src/migrations/0189_webauthn_credential.py` (new), `src/view/webauthn.py` (new), `src/urls.py`, `src/middleware/two_factor.py`, `src/view/profile_view.py`, `templates/profile.html`, `templates/registration/login.html`

**Deployment:** `pip install webauthn==2.7.1 && python manage.py migrate  # migration 0189`

### C&B Resolution Builder — Amendment Type System (migration 0195)

Formalizes what kind of change each amendment makes.

**Model changes (`src/models/cnb.py`):**
- `ResolutionAmendment.amendment_type` — `CharField` with choices `change` / `addition` / `deletion`; default `change`
- `ResolutionAmendment.scope_note` — optional `CharField(300)` for sub-item targeting
- `proposed_text` set to `blank=True` to support whole-section deletions

**Auto-detection in `add_amendment`:**
- Empty `proposed_text` → `deletion`
- `original_text` is a substring of `proposed_text` → `addition`
- Otherwise → `change`

**`apply_amendments` logic:**
- Whole-section deletion → clears content, suspends section, sets `deactivation_reason`
- All other cases → writes `proposed_text` to section content

**Files changed:** `src/models/cnb.py`, `src/migrations/0195_resolutionamendment_amendment_type_scope_note.py` (new), `src/view/officer/cnb.py`

### C&B Resolution Builder — Word-Level Diff Engine

Live tracked-changes preview in the amendment modal using word-level LCS (Longest Common Subsequence) diff — shows exactly which words were added or removed.

**Algorithm:**
- Tokenizer: `/\s*\S+/g` — each token includes preceding whitespace
- Similarity threshold: < 40% shared tokens falls back to clean block replacement
- Renders: unchanged text normally, additions in green, deletions in red strikethrough

**Files changed:** `templates/cnb/resolution_form.html`, `templates/cnb/resolution_detail.html`

### C&B Resolution Builder — Protected Citation Markers

Bracketed reference codes in the body, whereas, resolved, and notes textareas are write-protected. Users cannot delete or modify them by typing — only the × chip next to each citation removes it (one occurrence at a time).

- `MARKER_RE` detects citation codes in all four textareas
- `markersIntact()` verifies all expected markers are still present after each keystroke; reverts the change and shows a toast if any are missing
- Per-occurrence × chips: if the same marker is pasted multiple times, each × removes only one instance (uses `.replace(marker, '')` not split/join)

**Files changed:** `templates/cnb/resolution_form.html`

### C&B Resolution Builder — Print View (Inline Callouts & Appendix)

The print view now renders citation codes as meaningful content instead of raw `[Constitution Art. I § 1 (Addition) - 1]` text.

**Inline callouts:** each citation in the resolution body is replaced with a compact indented block showing the section reference, amendment type, and only the delta text (added words in green / deleted words in red strikethrough).

**Appendix:** full before/after diff for each amendment, built entirely in JS (`document.body.appendChild`) to avoid Django template queryset double-evaluation issues.

**LCS diff engine in print view:** same tokenizer and similarity-threshold logic as the editor diff, rendered via `renderDiffHTML()` with CSS classes `.diff-add` / `.diff-del`.

**Files changed:** `templates/cnb/resolution_print.html`

### C&B Resolution Builder — QoL Improvements

**Save & Preview button:** submits the edit form and redirects to the print view in one click. A hidden `save_and_preview` field is set on click; the view detects it and redirects to the print URL instead of the detail page.

**Unsaved changes warning:** `beforeunload` fires a browser confirm dialog if any field has been edited without saving. `window._isDirty` flag is set on `input`/`change`; cleared on submit.

**Amendment editing:** "Edit" button on each unapplied amendment card pre-fills the modal (section, proposed text, scope note, stored original snapshot) and renders the diff immediately. Submitting re-uses the existing `add_amendment` view which upserts by `(resolution, section)` — no new endpoint needed.

**Section search in C&B drawer:** live-filter input at the top of the reference drawer. Filters section rows in the active document tab by identifier, title, and content. Matching articles auto-expand; non-matching articles are hidden. Clears on tab switch.

**Files changed:** `templates/cnb/resolution_form.html`, `src/view/officer/cnb.py`

### Security Hardening — Admin v2

Two 🔴 red-severity findings from the automated security report (2026-06-05).

**Rate limiting:** cache-based attempt counter per user (`admin_v2_attempts_{pk}`); 5-attempt ceiling, 15-minute lockout. Increments on bad password or bad secret key; clears on success.

**`ADMIN_V2_USER_IDS` env var:** replaces hardcoded `ALLOWED_USER_ID = '73'` with a comma-separated env var (e.g. `ADMIN_V2_USER_IDS=73,81`). Falls back to legacy `ADMIN_V2_USER_ID` for backwards-compatibility. Add future officers by appending their user ID.

**Files changed:** `src/view/admin_v2.py`, `.env`

---

### Security Hardening — Chat Endpoints

Two 🟡 yellow-severity findings from the automated security report (2026-06-05).

**Timestamp validation:** the `since` param in `get_channel_messages` was passed directly to `created_at__gt=since`. Wrapped in `parse_datetime()` + try/except; returns 400 on invalid input.

**Send rate limiting:** max 5 messages per 3-second window per user via cache key `chat_send_rate_{pk}`; returns 429 when exceeded.

**Files changed:** `src/view/chat/channel_chat.py`

## Deployment

> **Note:** This release requires switching from Gunicorn (WSGI) to Daphne (ASGI). Gunicorn cannot serve WebSocket connections.

```bash
# 1. Install new packages
pip install channels==4.2.0 channels-redis==4.2.0 daphne==4.1.2 webauthn==2.7.1

# 2. Run migrations
python manage.py migrate   # migrations 0189 (WebAuthn), 0190 (chat_mention), 0195 (amendment_type)

# 3. Switch process manager
#    Edit the systemd unit (parliament-gunicorn.service):
#    Change ExecStart from:
#      gunicorn Parliament.wsgi:application --bind unix:/run/parliament.sock ...
#    To:
#      daphne -u /run/parliament.sock Parliament.asgi:application

# 4. Update nginx to forward WebSocket upgrade headers:
#    proxy_http_version 1.1;
#    proxy_set_header Upgrade $http_upgrade;
#    proxy_set_header Connection "upgrade";

# 5. Add env vars
#    ADMIN_V2_USER_IDS=73

# 6. Reload and restart
systemctl daemon-reload
systemctl restart parliament-gunicorn

# 7. Collect static & purge Cloudflare cache
python manage.py collectstatic --noinput
# Cloudflare dashboard → Caching → Purge Cache
```
