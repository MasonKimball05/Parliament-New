## Technical Prerequisites (in order)

1. **Redis** — must be running on server before Celery can be added. `install_redis.sh` already in repo.
2. **Celery worker + beat** — systemd units needed alongside gunicorn
3. **VAPID keys** — generated once, added to `.env` (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`)
4. **HTTPS** — already done via Cloudflare
5. **iOS 16.4+** — already the baseline for any member with a relatively modern iPhone

## Open Questions

- **Pledge user ID:** UUID approach requires a new migration touching nearly every table. Mapping table approach is less invasive but adds indirection. Which is more maintainable for the next person?
- **Push notification opt-in scope:** Per notification type (votes, announcements, etc.) or a single master toggle? Per-type is better UX but more complex.
- **Celery broker:** Redis (already considered for caching) vs. RabbitMQ — Redis keeps the stack simpler.
- **models.py split timing:** Pre-3.0 or as part of 3.0? Splitting mid-development causes merge pain.
