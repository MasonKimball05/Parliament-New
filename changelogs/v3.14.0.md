# v3.14.0 — Voting system: live push, receipts, turnout, deadline-close parity, results page

**Date:** 07-15-26
**Type:** Feature batch (builds on v3.13.3; same deploy)

## 1. Deadline auto-close brought to parity with End Vote

`tasks.auto_open_close_chapter_votes` (already scheduled every minute) closed
votes but diverged from the manual End Vote path. Fixed:

- **Plurality votes never got a result** — the task computed turnout as
  `yes + no`, which is always 0 for plurality ballots, so auto-closed
  plurality votes stayed `passed=False` with no status. Real ballot count now
  used.
- **Ties passed** — a plurality tie now fails (single-clear-winner rule,
  matching end_vote).
- **No audit trail or notifications** — auto-closes now write an ActivityLog
  entry (marked `auto_closed`) and send the same vote-ended notification to
  voters that End Vote sends.
- Removed the dead "auto-open" branch (filtered `available_at__isnull=True`,
  but available_at is a required field — it could never match; opening is
  query-time and surfaced live by the poller/websocket).

## 2. Live push via WebSockets

New `VoteConsumer` at `/ws/votes/` (channels infra already runs chat).
Server pings the `vote_updates` group on ballot cast, open (upload /
Open Voting Now), and close (End Vote + auto-close) via
`src/utils/vote_events.broadcast_vote_event`. The payload is only an event
name + legislation id — **clients react by re-running their existing tally
poll**, which enforces per-user visibility server-side, so no ballot data
travels over the socket. The 15-second poller stays as fallback; a dead
socket or missing channel layer degrades gracefully.

## 3. Tamper-evident vote receipts

After casting, voters get a signed receipt token (flash message). It embeds
the vote row ids and a SECRET_KEY-keyed digest of the recorded choices —
nothing stored server-side. New page **`/vote/verify-receipt/`** (linked from
the vote page header) checks: signature genuine → ballots still exist →
choices unchanged. Verification never reveals the choice, so receipts are
safe for anonymous ballots; a failed integrity check tells the member to
contact an officer. `src/utils/vote_receipts.py`.

## 4. Turnout tracking for chairs/officers

Each open vote card now shows **"Turnout: X of Y present"** (ballots cast vs
voting-eligible members currently marked present/late) with an expandable
list of present members who haven't voted yet. Participation only — never
choices — so it's anonymous-ballot safe. Officer/Chair eyes only.

## 5. Results page (vote_result.html) rebuilt

Full dark-mode support and site-theme styling (cards, semantic banners,
icons — it was the last light-only page in the vote flow). Real bugs fixed
while in there:

- **Anonymous percentage votes had a broken chart** — the template used
  `in_favor.count`, which isn't in the context for anonymous ballots →
  JS syntax error, no chart. Chart data now comes from json_script islands
  for all modes.
- **The required-percentage marker never rendered** — it was a Tailwind
  arbitrary class built from a template variable (`left-[{{ x }}%]`), which
  is never in the compiled CSS. Now an inline style.
- **Piecewise votes had no result banner at all.** Added (required vs
  received yes votes).
- Chart legend/borders adapt to dark mode; plurality palette extended to 10
  options; back-to-votes link added.

## 6. "Now" is now server-resolved (fixes votes opening at the wrong time)

Confirmed live: the Now buttons filled fields with the **device's** wall
clock, which the server interprets in its own timezone — any skew scheduled
"now" into the future and the vote never opened. The buttons still fill the
field for display, but also send an `_is_now` flag the server resolves with
its own clock (cleared if the field is hand-edited afterward). Applied to
chapter + appointment forms. Upload confirmations for future-scheduled items
now also print the server's current time, so residual skew is self-evident.

**Template-comment leak fixed with it:** two `{# #}` comments spanned
multiple lines, which Django doesn't support — the raw comment text rendered
inside the vote form and on the results page.

## 7. Attendance marking soft-reloads the page

Marking someone present/late/absent now soft-reloads the vote page ~1 s after
the last change (debounced, so Mark All reloads once), refreshing ballot
forms (e.g. marking yourself present) and turnout. Mid-ballot users get the
refresh banner instead of losing input, and the officer panel remembers its
active tab across reloads.

## 8. Receipts: Personal tab, expiry, and notices

- The receipt token no longer dumps into a flash message. Ballot
  confirmations point to the new **Personal tab on the Legislation page**
  (`?status=personal`): every vote you've cast — your choice(s) (visible only
  to you, incl. anonymous ballots), when you voted, the result, and the
  receipt with Copy + one-click Verify (prefilled).
- `Vote.cast_at` added (migration `0007`) so regenerated receipts keep the
  original cast time; pre-existing ballots show "voted before ballot
  timestamps existed" and no receipt.
- **Receipts expire 3 months after the ballot** (`RECEIPT_MAX_AGE_DAYS = 90`):
  the Personal tab stops issuing tokens and verification refuses them.
  Receipts are stateless (regenerated on demand — nothing stored), so expiry
  is enforced on the embedded cast time; "purging" = the token becoming
  unobtainable + unverifiable.
- New daily task `tasks.notify_expired_vote_receipts` (3:15 AM CST) notifies
  members whose ballots crossed the 3-month line in the past day — the
  requested "inform the user once purged" handler.
- The verify page gained a Back button (returns to the pre-redirect page).

## 9. Ballot form hidden once you've voted

The chapter vote card now shows "Your vote has been recorded" (with a link to
your ballot + receipt) instead of re-offering the ballot form after you've
voted — parity with the committee vote page, which already did this.

## Review fixes (07-18-26, post-commit — from the 07-18 auto-run report)

`scripts/git_snapshot.sh` only (no app code, no tests affected):

1. **DB dump moved off the code branch** — `db_latest.dump.enc(+.hmac)` is no
   longer committed to `main`; it's pushed as a single parentless commit to a
   dedicated `db-dump` branch (git plumbing: `hash-object`/`mktree`/
   `commit-tree`, then `push -f`), so the remote branch always holds exactly
   one commit. Daily re-encrypted dumps (fresh salt → new bytes, no delta
   compression) would otherwise have grown the snapshot repo by ~one dump-size
   blob per day forever, eventually hitting GitHub's 100 MB file/push limits.
   Superseded blobs are GC'd by GitHub (unreachable) and pruned locally
   (`gc --prune=now` after each dump push). One-time `rm --cached` in the
   script migrates any repo that committed the dump before this change.
   Restore: `git fetch origin db-dump && git checkout origin/db-dump -- db_latest.dump.enc db_latest.dump.enc.hmac`.
2. **No more silent dump skip** — missing `*.dump` in the backup dir and
   missing/unreadable pass file each log a distinct WARNING instead of
   skipping quietly.
3. **Crash-consistency** — `dump.sha256` state is written only after a
   successful `db-dump` push, so a failed push is retried next run (before,
   the state was recorded at encrypt time and a push failure went unnoticed
   until the next dump change).
4. `SNAPSHOT_DUMP_DIR` / `SNAPSHOT_DUMP_BRANCH` env overrides added (defaults
   `/var/backups/parliament`, `db-dump`).

Verified in sandbox: 5-scenario end-to-end test against a local bare remote —
initial run, changed dump (branch stays at exactly 1 commit), no-change run
(commit-free), both warning paths, and the documented HMAC-verify + decrypt
restore procedure round-trips the dump byte-for-byte.

Also in this round — the two carried perf nits from the 07-16 sweep:

5. **Auto-close tally uses one GROUP BY** (`src/tasks/votes.py`): per-choice
   `.count()` calls (3 + N_options queries per closing bill) replaced with a
   single `values('vote_choice').annotate(Count)` aggregation; yes/no/
   plurality totals all read from the one dict.
6. **Officer turnout panel N+1 fixed** (`src/view/vote_view.py`): voter pks
   for ALL open votes fetched in one query (`legislation__in=open_legs`)
   instead of one `Vote.objects.filter(legislation=leg)` per bill; the
   uploader `vote_data` block got the same single-GROUP-BY treatment (was
   4–5 COUNT queries per owned bill).

Verified: `manage.py check` clean; 196 tests green on sqlite
