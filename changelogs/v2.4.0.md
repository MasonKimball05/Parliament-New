1. **Bug Report System** - Full-featured bug tracking with user submissions, public tracker, and admin management

## Key Features

### 1. Bug Report System

#### Overview
Users can now report bugs, issues, and feature requests directly within the Parliament application. The system includes a public bug tracker for transparency and an admin-only management interface.

#### User Features

**Bug Report Submission (`/bug-report/`)**
- Comprehensive form with multiple fields:
  - **Description** (required) - Detailed description of the issue
  - **Issue Type** - Bug, Feature Request, UI/UX Issue, Performance, Security, or Other
  - **Page** - Which page the issue occurred on (Home, Legislation, Committees, Calendar, etc.)
  - **Feature** - Free text for specific feature affected
  - **Priority** - Low, Medium, High, or Critical
  - **Steps to Reproduce** - How to recreate the issue
  - **Expected Behavior** - What should have happened
  - **Actual Behavior** - What actually happened
  - **Browser Info** - Browser and device information
  - **Screenshot** - Optional image upload for visual issues
- Success confirmation page after submission
- Email notification sent to admin (when email configured)

**My Bug Reports (`/my-bug-reports/`)**
- View all bugs submitted by the current user
- Track status of submitted reports
- See admin notes and resolution information

**Public Bug Tracker (`/bug-tracker/`)**
- View all reported issues and their status
- Filter by status (New, Acknowledged, In Progress, Resolved, Won't Fix, Duplicate)
- Filter by issue type
- Summary statistics (Total, New, In Progress, Resolved counts)
- Custom sorting: In Progress/Acknowledged first, then New, then Resolved
- Click through to view full bug details

**Bug Report Detail (`/bug-report/<id>/`)**
- Full details of any bug report
- Status badges with color coding
- Submitted by user and timestamp
- Steps to reproduce, expected/actual behavior
- Admin notes and resolution information
- Screenshot display (if attached)

#### Admin Features

**Bug Admin Dashboard (`/bug-admin/`)** - Restricted to user_id 73
- Overview statistics with clickable filter cards
- Filter by status, issue type, and priority
- Inline status updates for each bug
- Admin notes field for internal comments
- Quick view links to full bug details
- Automatic resolution tracking (resolved_at, resolved_by)

**Status Management**
- New → Acknowledged → In Progress → Resolved
- Additional statuses: Won't Fix, Duplicate
- Resolution timestamp automatically set when marking as resolved
- Resolved by user automatically recorded

#### Email Notifications
- Automatic email sent when bug report submitted
- HTML email template with full bug details
- Link to Django admin for quick access
- Fails silently if email not configured

#### Routes
```python
# User routes
GET/POST /bug-report/                    # Submit bug report form
GET /bug-report/success/<bug_id>/        # Success confirmation
GET /my-bug-reports/                     # User's submitted reports
GET /bug-tracker/                        # Public bug tracker
GET /bug-report/<bug_id>/detail/         # Bug detail view

# Admin routes (restricted to user_id 73)
GET /bug-admin/                          # Admin dashboard
POST /bug-admin/<bug_id>/update/         # Update bug status
```

#### File Locations
- **Model:** `src/models.py` (BugReport class)
- **Views:** `src/view/bug_report.py`
- **Templates:**
  - `templates/bug_report.html` - Submission form
  - `templates/bug_report_success.html` - Success page
  - `templates/my_bug_reports.html` - User's reports
  - `templates/bug_tracker.html` - Public tracker
  - `templates/bug_report_detail.html` - Detail view
  - `templates/bug_admin.html` - Admin dashboard
  - `templates/emails/bug_report_notification.html` - Email template
- **URLs:** Added to `src/urls.py`

### 2. Brevo Email Integration

#### Overview
Migrated from SMTP-based email to Brevo's API-based email service to resolve DigitalOcean's outbound SMTP port blocking (ports 25, 465, 587, 2525 are blocked by default).

#### Implementation
- Uses `django-anymail` package with Brevo backend
- API-based delivery bypasses blocked SMTP ports
- Maintains same email functionality (password reset, notifications, etc.)
- Free tier: 300 emails/day

#### Configuration
```python
# In settings_postgres.py
INSTALLED_APPS = [
    # ... other apps ...
    'anymail',
    'src',
]

# Anymail (Brevo) Configuration
ANYMAIL = {
    'BREVO_API_KEY': os.getenv('BREVO_API_KEY', ''),
}
```

#### Environment Variables
```bash
EMAIL_BACKEND=anymail.backends.brevo.EmailBackend
BREVO_API_KEY=your-brevo-api-key
DEFAULT_FROM_EMAIL="Alpha Mu Parliament <your-email@domain.com>"
```

## Bug Fixes

### 1. IP Address Storage Issue
**Problem:** ActivityLog was storing multiple IP addresses from X-Forwarded-For header (e.g., "104.245.151.106, 104.23.187.155") which caused PostgreSQL inet field errors.

**Fix:** Updated `src/view/admin_v2.py` to use `get_client_ip()` function which properly extracts only the first (client) IP address.

**Files Changed:**
- `src/view/admin_v2.py` - Added import for `get_client_ip` and updated ActivityLog creation

### 2. WSGI/ASGI Settings Module
**Problem:** `wsgi.py` and `asgi.py` were pointing to `Parliament.settings` instead of `Parliament.settings_postgres`.

**Fix:** Updated both files to use correct settings module.

**Files Changed:**
- `Parliament/wsgi.py`
- `Parliament/asgi.py`

### 3. ActivityLog Field Names
**Problem:** Test email function was using `action='send_test_email'` but ActivityLog model uses `action_category` and `action_type` fields.

**Fix:** Updated to use correct field names: `action_category='settings'`, `action_type='settings_changed'`.

**Files Changed:**
- `src/view/admin_v2.py`

### 4. User ID Comparison
**Problem:** Bug admin access check was comparing string user_id to integer 73 (`request.user.user_id == 73`).

**Fix:** Updated to compare strings: `str(request.user.user_id) == '73'`.

**Files Changed:**
- `src/view/bug_report.py`

## Database Changes

### New Model: BugReport

```python
class BugReport(models.Model):
    ISSUE_TYPES = [
        ('bug', 'Bug'),
        ('feature', 'Feature Request'),
        ('ui', 'UI/UX Issue'),
        ('performance', 'Performance'),
        ('security', 'Security'),
        ('other', 'Other'),
    ]

    PAGE_CHOICES = [
        ('home', 'Home'),
        ('legislation', 'Legislation'),
        ('committees', 'Committees'),
        ('calendar', 'Calendar'),
        ('profile', 'Profile'),
        ('admin', 'Admin'),
        ('other', 'Other'),
    ]

    PRIORITY_CHOICES = [
        ('low', 'Low'),
        ('medium', 'Medium'),
        ('high', 'High'),
        ('critical', 'Critical'),
    ]

    STATUS_CHOICES = [
        ('new', 'New'),
        ('acknowledged', 'Acknowledged'),
        ('in_progress', 'In Progress'),
        ('resolved', 'Resolved'),
        ('wont_fix', "Won't Fix"),
        ('duplicate', 'Duplicate'),
    ]

    # Core fields
    description = models.TextField()
    issue_type = models.CharField(max_length=20, choices=ISSUE_TYPES, default='bug')
    page = models.CharField(max_length=50, choices=PAGE_CHOICES, blank=True)
    page_url = models.URLField(blank=True)
    feature = models.CharField(max_length=200, blank=True)
    priority = models.CharField(max_length=20, choices=PRIORITY_CHOICES, default='medium')

    # Detailed info
    steps_to_reproduce = models.TextField(blank=True)
    expected_behavior = models.TextField(blank=True)
    actual_behavior = models.TextField(blank=True)
    browser_info = models.CharField(max_length=200, blank=True)
    screenshot = models.ImageField(upload_to='bug_screenshots/', blank=True, null=True)

    # Status tracking
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default='new')
    admin_notes = models.TextField(blank=True)

    # Metadata
    submitted_by = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.SET_NULL, null=True)
    submitted_at = models.DateTimeField(auto_now_add=True)
    resolved_at = models.DateTimeField(null=True, blank=True)
    resolved_by = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.SET_NULL, null=True, related_name='resolved_bugs')
```

### Migration Required
Run migrations to create the `src_bugreport` table:
```bash
python manage.py makemigrations
python manage.py migrate
```

## Deployment Guide

### Step 1: Install Dependencies
```bash
pip install django-anymail
```

### Step 2: Update Environment Variables
Add to `.env`:
```bash
EMAIL_BACKEND=anymail.backends.brevo.EmailBackend
BREVO_API_KEY=your-brevo-api-key
DEFAULT_FROM_EMAIL="Alpha Mu Parliament <your-email@domain.com>"
```

### Step 3: Pull Code Changes
```bash
cd /var/www/Parliament-New
git pull origin main
```

### Step 4: Run Migrations
```bash
source venv/bin/activate
python manage.py makemigrations
python manage.py migrate
```

### Step 5: Collect Static Files (if needed)
```bash
python manage.py collectstatic --noinput
```

### Step 6: Restart Services
```bash
sudo systemctl restart parliament
```

### Step 7: Verify Deployment
1. Test bug report submission at `/bug-report/`
2. Check bug tracker at `/bug-tracker/`
3. Test email sending from Admin v2 → Settings → Send Test Email
4. Verify bug admin access at `/bug-admin/` (user_id 73 only)
