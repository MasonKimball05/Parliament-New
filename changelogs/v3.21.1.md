# v3.21.1 — pledge ids are not numbers, and my fixture said they were

**Date:** 08-19-26
**Type:** Bug fix. **No migration.**
**Committed & pushed:** *not yet*
**Deployed:** *not deployed*

Reported by Mason, on the education dashboard:

```
NoReverseMatch at /committee/EDUCATION/education/
Reverse for 'education_pledge_detail' with arguments '('EDUCATION', 'P-C7JKZY')'
not found. 1 pattern(s) tried:
  ['committee/(?P<code>[^/]+)/education/pledge/(?P<pledge_pk>[0-9]+)/\\Z']
```

✅ **1,513 tests, 0 failures, 3 skipped**, two partitionings. `manage.py check`
silent, bandit exit 0. **34 of the education tests verified failing against the
old converter.**

---

## 🔴 The bug

`ParliamentUser.user_id` is a **CharField** primary key. Initiated brothers
carry a roll number, which *looks* numeric — but **a pledge carries `P-C7JKZY`**
until initiation. Three routes declared `<int:…>` for a member id:

| Route | What it did |
|---|---|
| `education_pledge_detail` (v3.20.2) | **`NoReverseMatch` — a hard 500** on the dashboard the moment a real pledge existed |
| `education_toggle_completion` (pre-existing) | the completion grid. Builds its URL in **JavaScript**, so instead of raising it **404'd quietly**. It has presumably never worked for a real pledge. |
| `get_member_adjustments` (pre-existing) | service hours — **outside education entirely** |

All three now take `<str:…>`.

⚠️ **The second one is the more interesting failure.** My new page used
`{% url %}`, so Django refused to render and the error arrived immediately with
the offending id in it. The older grid built its path by string concatenation in
JS, so the same defect produced a silent 404 — the exact shape of v3.20.0's
CSRF bug, which is why `Parliament.post` now exists. **A route that raises at
render time is a better bug than one that 404s at click time.**

---

## ⚠️ And the tests were green the whole time

The education fixture used numeric pledge ids — and carried a comment I wrote
asserting that *"real chapter ids are numeric; a fixture that is not would test
a URL space the app does not have."* That sentence is exactly backwards, and it
is the reason a 500 shipped past 119 passing tests.

> **A fixture that is easier than production tests something else.** The
> numeric-brother / `P-`-pledge split is obvious on the live site and invisible
> in a database somebody seeded by hand.

The fixture now uses `P-C7JKZY` and `P-9QW2LM`, which is what makes the `<str:>`
routes load-bearing in the suite rather than incidental. Verified by reverting
the converters: **34 failures**.

This is also the sharpest instance yet of a category CLAUDE.md already tracks —
**a comment that was confidently wrong from the moment it was written.** The
previous ones described a deployment that had changed underneath them. This one
was never true; I asserted a fact about the chapter's data without checking it,
and then used the assertion to justify the fixture that hid the consequence.

---

## The response is the enumeration, not the three fixes

`src/test_user_pk_routes.py` derives the population rather than listing the
offenders: it scans every view for kwargs used to look up a `ParliamentUser`,
then fails on any URL pattern capturing one of those with the `int` converter.
A fourth instance breaks the build.

It also pins the fixture: if the education tests go back to digits, the `<str:>`
routes stop being exercised here and the next converter mistake sails through
again. That assertion is the one doing the real work.
