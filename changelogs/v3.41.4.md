## 🟡 "Leave site? Changes may not be saved" when saving an amendment

**Reported by:** Mason, 10-02-26.

**Why it happened.** The resolution edit page warns before leaving with
unsaved edits in the main form (title, whereas, resolved text). Saving an
amendment, removing one, or posting a note submits a *different* form and
reloads the page, which the browser counts as leaving. The warning was
accurate: clicking "Leave" threw the unsaved main-form edits away.

**Fix** (`templates/cnb/resolution_form.html`). When another form on the edit
page is submitted while the main form has unsaved edits, the page first saves
the main form in the background, then lets the other form go. No prompt, and
nothing is lost. If that background save fails, it asks before continuing.

Also: the unsaved-changes script found the main form with
`form[method="post"]`, which is the first post form on the page. That is
base.html's set-email form when it is rendered. It now uses an id.

The create page is not wired for this (its URL would create a resolution).

**Checked in a real browser** with the network stubbed: edit the title, submit
the amendment form → one background save carrying the new title, then the
amendment form submits, no prompt.

**Tests:** 1 added to `test_cnb_amendment_preview.py`.
