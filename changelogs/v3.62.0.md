## 🟢 Mobile app: My Excuses and Polls (Mason, 10-29-26)

Two more web pages get `/api/mobile/v1/` endpoints, with the same rules as the
web views they mirror (`src/mobile/views_excuses_polls.py`).

### My Excuses — `GET/POST my/excuses/`, `POST my/excuses/<id>/cancel/`
- `GET` returns the member's requests (newest first, up to 100, with the
  officer's decision and notes), the Pending / Approved / Denied counts, and the
  upcoming events they can still ask to be excused from — the same filters as
  `my_excuses` (visible, excuses allowed, before the deadline, not finalized,
  required of this member, not already requested).
- `POST {event_id, reason}` applies every check `submit_excuse` does, with the
  web's refusal messages as error codes (`deadline_passed`,
  `excuses_not_allowed`, `not_required`, `already_submitted`,
  `reason_too_short`). A supporting document is still attached on the website.
- Cancel withdraws a pending request only, as `cancel_excuse` does. Both log
  to the activity log like the web.
- Same feature flags as the page (`attendance_tracking`, `excuse_system`).

### Polls — `GET polls/`, `GET/POST polls/<announcement id>/`
- The list is `polls_view`'s: polls on active, published announcements the
  member's type can see, split into open and closed, with "you answered".
- `POST {answers: {"<question id>": [option ids] | "text"}}` answers or
  changes an answer while the poll is open, updating the member's one response
  row in place as `take_poll` does. Unlike the web form (which relies on the
  browser's `required`), required questions are checked on the server, and
  every answer is validated before anything is written.

### Deep links
`/excuses/`, `/polls/` and `/announcements/<id>/poll/` map to the app screens
`excuses`, `polls` and `poll`. Older app builds open them on the website.
