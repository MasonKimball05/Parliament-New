# v3.15.5 — code-quality cleanup (07-22 sweep follow-up)

Three low-risk cleanups from the 07-22 config/code-quality pass. No behavior
change for correctly-configured prod; no migration.

## DEBUG-gated authorization cleanup

- **`src/view/service_user_dashboard.py`** — `is_vpp` was
  `… or settings.DEBUG`, the same "authz depends on DEBUG" pattern removed from
  `vpp_required` in v3.15.4. Here it only controlled whether the VPP admin link
  is shown (the pages themselves are gated by `@vpp_required`), so it was a
  cosmetic bypass — but it diverged from the real gate and would show the link
  to every member if `DEBUG` were ever true in prod. Removed the `settings.DEBUG`
  clause.
- **Left intentionally:** the `settings.DEBUG and user.user_id == '73'` slating
  test-admin shims in `committee_detail.py` / `committee_home.py`. Double-gated
  (DEBUG **and** a specific dev id), dead in prod, and they support the dev
  workflow — not the same broad risk. Noted, not changed.

## `print()` → logging

Debug output on stdout replaced with proper module loggers:

- **`src/view/officer/view_logs.py`** — 8 `[VIEW_LOGS]` `print()` traces in an
  officer-facing view → `logger.debug/warning`, and the `except` branch's
  `print()` + `traceback.print_exc()` → `logger.exception(...)`.
- **`src/view/slating/transition.py`** — the scheduled-transition success/error
  `print()`s → `logger.info` / `logger.exception` (so scheduled-transition
  outcomes land in the log files, not gunicorn stdout).

## Bare `except:` → `except Exception:`

Converted all **17** bare `except:` clauses so they no longer swallow
`KeyboardInterrupt` / `SystemExit` / `GeneratorExit` and only catch real
errors. Files: `kai_reports.py` (13), `service_user_dashboard.py` (2),
`committee_detail.py` (1), `service_hours.py` (1). Behavior for normal
exceptions is unchanged; the fix is purely narrowing what gets caught.

## Verify

`py_compile` clean on all touched files. `grep` confirms 0 bare `except:`
remain and no `print(` left in the two target views. Full suite to be run on
Mason's machine (sandbox lacks the Postgres/Celery/Redis stack).
