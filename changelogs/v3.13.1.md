# v3.13.1 — Login-pipeline regression tests

**Date:** 07-13-26

## Added

- `src/test_login_pipeline.py` (4 tests) — regression tests for the v3.13.x post-auth
  login refactor (specced in the 07-04 auto-run report):
  - **Single write path:** exactly one `LoginHistory` row per password login
    (guards against the old double-write where both `run_post_auth_pipeline`
    and the `user_logged_in` signal handler created a row).
  - **Known-IP not re-flagged:** a second login from the same IP/location/device
    produces no `New IP address` / `New login location` / `New device` risk
    factors and no `LoginAlert`. This is the negative case that would have
    caught the Fernet-ciphertext `.filter(ip_address=...)` bug on day one.
  - **Perf guard:** the signal handler reuses the pipeline's cached geo
    (`request._login_pipeline`) instead of a second uncached ip-api.com call
    (07-04 auto-run finding 4).
  - **Non-pipeline logins:** impersonation-style logins (no pipeline stash)
    still write exactly one `LoginHistory` via the fallback geo lookup.

  Geo is mocked at both call sites (`src.geo_utils.get_ip_geo`,
  `src.signals.get_geolocation_from_ip`) so tests never hit ip-api.com.
