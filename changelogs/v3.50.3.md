## Four tests failed on PostgreSQL (CI runs Postgres)

Found by the 10-19 auto-run, which ran the full suite on a real PostgreSQL 16.
Both are test bugs, not app bugs. They pass on SQLite, which is why local runs
never showed them.

- **`src/tests/kai/test_kai_commendation_migration.py` (3 errors).** The raw
  `INSERT`s used SQLite-only SQL: `datetime('now')` and `0`/`1` for boolean
  columns. Postgres: `function datetime(unknown) does not exist`. The values
  now go in as query parameters (`timezone.now()`, `True`/`False`), which also
  removes the five `# nosec B608` string-formatted queries.
- **`src/tests/infra/test_digest_activity_and_infra_sections.py` (1 failure).**
  `test_shows_not_applicable_on_the_sqlite_test_backend` expected "DB
  connections: n/a", but on Postgres `get_connection_pressure()` really
  answers. It now patches that to `None` (the sqlite / unreachable case) and is
  renamed `test_shows_not_applicable_when_pressure_is_unavailable`. The
  Postgres case is already covered by the test right below it.
