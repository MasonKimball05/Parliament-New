# v2.20.0 — Push Notification Admin Management

**Date:** 05-28-2026
**Deployment Status:** Deployed
**Type:** Feature
**Migration required:** No

---

## Summary

Extends the Pillar 2 push notification infrastructure with admin-v2 management tools and a member-facing reconfigure button. Admins can now view, individually delete, or mass-clear push subscriptions without touching the database, and toggle push notifications on/off per notification type or site-wide. Members who already have Parliament installed as a PWA have a one-click way to resync their push subscription if notifications stop arriving.

---

## New Files

- **`templates/admin_v2/push_subscriptions.html`** — Dedicated subscriptions list page. Shows every registered device in a table: member name + type, user agent (truncated, full text on hover), subscribed date, last used date, truncated endpoint. Each row has an individual delete button. Header has a "Clear All" shortcut.

---

## Modified Files

- **`src/view/admin_v2.py`**
  - Added `PushSubscription` to imports.
  - Dashboard view now seeds 5 push feature flags via `get_or_create` on first load (no manual DB work required):
    - `push_notifications_enabled` — master kill switch for all push
    - `push_announcements`, `push_legislation`, `push_events`, `push_slating` — per-type toggles
  - Adds `push_stats` (`total_subscribers`, `total_devices`) and `push_flags` queryset to dashboard context.
  - **`push_subscriptions_list`** — lists all `PushSubscription` records ordered by user name.
  - **`delete_push_subscription`** — deletes a single subscription by ID, logs the action, redirects to the list.
  - **`clear_push_subscriptions`** — unchanged behavior, but now also reachable from the subscriptions list page.

- **`src/urls.py`**
  - Added `admin-v2/push/subscriptions/` → `push_subscriptions_list` (name: `admin_v2_push_subscriptions`)
  - Added `admin-v2/push/subscriptions/<id>/delete/` → `delete_push_subscription` (name: `admin_v2_delete_push_subscription`)

- **`templates/admin_v2/dashboard.html`** — New "Push Notifications" card in the main grid:
  - Subscriber and device count mini-stats.
  - Per-flag ON/OFF toggle buttons (master flag highlighted in blue, per-type in gray).
  - "View All Subscriptions" link → subscriptions list page.
  - Danger-zone "Clear All" form with a JS confirm dialog.

- **`templates/preferences.html`** — Added "Reconfigure" button alongside the existing "Disable" in the push-enabled state row. Clicking it:
  1. Tells the browser to unsubscribe the current endpoint (and notifies the server via `POST /push/unsubscribe/`).
  2. Immediately re-subscribes with `pushManager.subscribe()`.
  3. Posts the new subscription to `POST /push/subscribe/` and reloads.
  Handles the case where notifications have stopped arriving because the browser rotated the endpoint, the subscription expired, or an admin cleared subscriptions server-side. Also displays a clear error if the browser's notification permission is `denied`.

## Deployment Steps

1. `git pull origin main`
2. `python manage.py collectstatic --noinput`
3. `systemctl restart parliament`
4. Purge Cloudflare cache
5. Open admin-v2 dashboard once — push feature flags will be seeded automatically on first page load.

> No `migrate` required — no new models.
