## Overview

This release focuses on hardening the 2FA and authentication systems in preparation for the graduation handoff, and lays the groundwork for the 3.0.0 REST API. Key additions include self-service 2FA recovery, a "remember this device" cookie, backup code acknowledgement tracking with a site-wide warning banner, targeted auth view fixes surfaced by an audit, and a read-only REST API scaffolded on Django REST Framework.

## 2FA — Self-Service Recovery

Members who lose access to their authenticator app can now recover without admin intervention.

**Flow:**
1. User clicks "Lost your authenticator?" on the 2FA verify page
2. A time-limited (1 hour) HMAC-signed re-enrollment link is emailed to them
3. Clicking the link removes all TOTP and backup devices, logs the user in, and redirects to 2FA setup
4. Admins receive an email notification whenever a recovery link is used (potential account-takeover indicator)

**Security details:**
- Token is generated via a `PasswordResetTokenGenerator` subclass with a `2fa_recovery` domain suffix — prevents token reuse between flows
- Rate limited to 3 requests per user per 24 hours (cache-based)
- Recovery requires a verified email address — users without an email are shown a "contact administrator" fallback
- All recovery events logged to the security logger and `ActivityLog`

**Files changed:**

## 2FA — Remember This Device for 30 Days

Users can check "Remember this device for 30 days" when completing TOTP verification. Parliament sets an HttpOnly, Secure, SameSite=Lax signed cookie that the 2FA middleware validates on subsequent visits — skipping the verify page automatically.

**Security details:**
- Cookie is signed with `TimestampSigner` using a `2fa_device` salt — cannot be forged without the secret key
- Cookie is cleared on logout, on 2FA disable, and via a new "Forget this device" button on the profile page
- Only set for TOTP verification — backup code logins do not set the cookie

**New URL:** `POST /accounts/two-factor/forget-device/`

**Files changed:**
- `src/view/two_factor.py` — cookie helpers, verify sets cookie, disable clears cookie, new `two_factor_forget_device` view
- `src/middleware/two_factor.py` — `_check_remember_cookie()` validates cookie before redirecting to verify
- `src/view/logout_view.py` — clears remember cookie on logout
- `src/urls.py` — added forget-device route
- `templates/two_factor/verify.html` — "Remember this device" checkbox
- `templates/profile.html` — "Forget this device" button (shown when device is remembered)

## 2FA — Backup Code Acknowledgement & Warning Banner

Parliament now tracks whether a user has downloaded their backup codes and warns them site-wide if they haven't.

**New model field:** `ParliamentUser.backup_codes_acknowledged` (BooleanField, default False)
- Set to `True` when the user visits the backup code reveal page
- Reset to `False` whenever backup codes are regenerated

**Warning banner** (amber, in `base.html`) appears on every page when:
- 2FA is enabled but backup codes have never been viewed/downloaded
- All backup codes have been used (0 remaining)
- 3 or fewer backup codes remain

Banner is suppressed on the backup codes reveal and regenerate pages to avoid redundancy.

**Context processor** (`src/context_processors.two_factor_status`) injects `backup_codes_warning` and `backup_codes_remaining` globally so templates don't need per-view logic.

**Migration:** `0183_parliamentuser_backup_codes_acknowledged`

**Files changed:**
- `src/models/users.py` — added `backup_codes_acknowledged` field
- `src/migrations/0183_parliamentuser_backup_codes_acknowledged.py` — new migration
- `src/view/two_factor.py` — reveal view sets flag, regenerate resets it
- `src/context_processors.py` — new `two_factor_status()` processor
- `Parliament/settings_postgres.py` — registered context processor
- `templates/base.html` — amber warning banner
- `templates/profile.html` — inline warning in backup codes section

## Auth Audit Fixes

A review of all auth-adjacent views surfaced the following gaps, all now addressed:

### Logout activity logging
`logout_view` now records an `ActivityLog` entry before calling `logout()`.

### Password change rate limiting
`change_password` now enforces a limit of 5 attempts per user per hour (cache-based). Exceeding the limit shows an error and redirects to the profile page.

### 2FA recovery rate limiting
`two_factor_recovery_request` now limits recovery email requests to 3 per user per 24 hours. Exceeding the limit renders a "Too Many Requests" state on the recovery page.

### 2FA recovery admin notification
`two_factor_recovery_confirm` now emails all `is_staff` users when a recovery link is successfully used. The notification includes the member's username, email, and IP address.

**Files changed:**
- `src/view/logout_view.py`
- `src/view/change_password.py`
- `src/view/two_factor_recovery.py`
- `templates/two_factor/recovery_request.html` — added `rate_limited` state

## REST API — 3.0.0 Foundation

Scaffolded a read-only REST API under `/api/v1/` using Django REST Framework. This is the groundwork for the 3.0.0 external integrations goal.

**Authentication:** Token auth (`Authorization: Token <key>`) or session auth. No anonymous access.

**Endpoints:**

| Method | URL | Description |
|--------|-----|-------------|
| `POST` | `/api/v1/auth/token/` | Exchange credentials for an API token |
| `GET` | `/api/v1/members/` | Active member directory |
| `GET` | `/api/v1/members/me/` | Requesting user's own record |
| `GET` | `/api/v1/members/{user_id}/` | Single member detail |
| `GET` | `/api/v1/events/` | All events visible to the requesting user |
| `GET` | `/api/v1/events/upcoming/` | Events in the next 30 days |
| `GET` | `/api/v1/events/{id}/` | Single event (visibility enforced) |
| `GET` | `/api/v1/legislation/` | All active, non-removed legislation |
| `GET` | `/api/v1/legislation/active/` | Legislation currently open for voting |
| `GET` | `/api/v1/legislation/{id}/` | Single legislation item |

**Security decisions:**
- Sensitive fields omitted from all serializers: email, phone, password hash, security flags (`is_quarantined`, `force_password_change`, `backup_codes_acknowledged`, etc.)
- Event visibility enforced via `Event.is_visible_to_user()` — no logic duplication
- Browsable API enabled in `DEBUG` mode only; JSON-only in production
- 2FA middleware already exempts `/api/` paths (token auth is not session-based)
- Throttle: 300 requests/hour per authenticated user

**Migration required:** `python manage.py migrate` — `rest_framework.authtoken` adds a `Token` table.

**New dependency:** `djangorestframework==3.16.0`

**New files:**
- `src/api/__init__.py`
- `src/api/serializers.py`
- `src/api/views.py`
- `src/api/urls.py`

**Files changed:**
