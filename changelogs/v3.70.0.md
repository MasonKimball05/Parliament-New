## 🟢 Mobile app: Songbook and Quote Book (Mason, 10-30-26)

`src/mobile/views_songbook.py`.

- **Songbook** (`songbook/`): every active song with its category, first line
  and lyrics. The list comes in one response, and the app searches and filters
  it on the phone.
  - `songbook/songs/<id>/` is one song. `songbook/songs/<id>/audio/` serves its
    recording with the sign-in token, and the app keeps a copy on the phone.
  - `songbook/pdf/<sheet_music|songbook>/` serves the printed songbook PDFs
    when they are on disk.
  - Same gate as the web pages: no page toggle, the pledge restriction applies.
  - Adding and editing songs stays on the website (`can_manage` shows the link).
  - `song_audio_path` and `exportable_media_url` were moved out of
    `serve_song_audio` / `songbook_list` so both sides use one copy.
- **Quote Book** (`quote-book/`, behind `PageToggle('quote_book')`): one chapter
  per member, built as `quote_book` builds it.
  - Add a quote, either as a POST to `quote-book/` or from
    `quote-book/members/`, which lists everyone not removed.
  - Flag a quote (or delete it, for your own quote about yourself) and restore
    one, with the same `Quote.can_be_*_by` rules and activity log entries as
    the web.
  - `quote-book/flagged/` is scoped like `review_flagged_quotes`: officers see
    every flagged quote, everyone else only the ones they flagged or that are
    about them.
- `me/` `pages` gains `quote_book`, so the app hides the row when the page is
  off.
- Tests: `src/tests/mobile/test_songbook_quotes.py`.

## 🟢 Mobile app: attendance in roll call order (Mason, 10-30-26)

- The officer attendance roster (`officer/events/<id>/attendance/`) comes in
  roll call order: members by roll number (as a number, so 2 before 10), those
  without one after them, then pledges by last name. Same order as the chapter
  minutes' roll call; the rule is now `src/roll_call.py`.

  number and switch to last-name order.

## 🟢 Officer portal: Mobile App page (Mason, 10-30-26)

`/officers/mobile-app/` (`src/view/officer/mobile_app.py`), linked from
Officer Home's Quick Links. Officers and chairs. Three tabs:

- **Notifications:** every active member's app status: notifications on (a
  signed-in phone with a push token, by the same `still_allowed` check the
  push sender uses), app with notifications off, signed out, or no app; their
  devices and app versions; and the push kinds they've turned off in
  Preferences. The cards filter the list. Read-only: it never clears a token.
- **Location check-in:** whether it's on (its three flags), attendance events
  in the next 30 days with or without a check-in area (linking to the event
  form), and the saved places, which can be renamed or deleted here (logged;
  events keep their copied areas).
- **App versions:** which app versions members' signed-in phones run, and the
  update-notice builds an admin has set.

`static/css/tailwind.css` rebuilt for the new template.

## 🟢 Mobile app: the Mobile App page in Officer tools (Mason, 10-30-26)
