# v3.13.2 — Credential re-auth (recovered), backend-agnostic schema, snapshot hardening

**Date:** 07-14-26
**Deployed:** 07-15-26 (together with v3.13.3)

## Security fixes

### 1. Password re-authentication for credential changes — recovered v3.5.1 hardening

The v3.5.1 changelog and `src/test_security_reauth.py` (added v3.8.0) documented password
re-auth for 2FA disable / passkey delete / passkey register — but `git log -S check_password`
shows the view code was **never committed** (likely written in an out-of-sync working copy
and lost). The entire test module had been failing since 06-15-26. Now actually implemented:

- **`two_factor_disable`** requires the current password; 5 attempts per 15 min per user
  (`2fa_disable_attempts_<pk>`); security-logged with IP; notification email
  ("Two-Factor Authentication was disabled on your account") via `notify_user_security_event`.
- **`passkey_delete`** requires the current password (`cred_remove_attempts_<pk>`, same
  limits); notification email ("A passkey was removed from your account").
- **`passkey_register_begin`** requires the current password
  (`passkey_register_attempts_<pk>`); returns 403 (bad password) / 429 (rate-limited) JSON.
  Gating begin is sufficient — complete is useless without the session challenge.
- **`passkey_register_complete`** now sends a notification email
  ("A new passkey was added to your account") and security-logs with IP.
- **`/accounts/two-factor/disable/` removed from `Enforce2FAMiddleware` exempt paths** —
  a password-only session (exactly the attacker 2FA stops) can no longer reach it.
- **Voluntary 2FA is now enforced:** the verify-step gate keys off "user has a confirmed
  device", not "policy requires 2FA" — users who enabled 2FA voluntarily under policy
  `none` are actually protected. Unconfirmed (abandoned setup) devices don't gate.
- UI: `two_factor/disable.html` gained a required current-password field; profile passkey
  "Remove" and "Add a Passkey" reveal an inline password field on first click and submit
  on the second (register JS sends it form-encoded to begin and surfaces 403/429 errors).

### 2. `scripts/git_snapshot.sh` hardening (07-12/07-13 report findings 1–4)

- rsync excludes now use `--exclude '.env*'` — **all** `.env` variants (`.env.dev`,
  `.env.bak`, …) stay out of the snapshot repo, not just literal `.env`. Belt-and-braces
  sweep now `find`s any stray `.env*` (except `.env.enc`/`.env.enc.hmac`) in staging.
- **Ciphertext is now authenticated:** every `*.enc` gets a companion `*.enc.hmac`
  (HMAC-SHA256 keyed with the snapshot passphrase, computed via python3 so the key never
  hits argv). AES-CBC alone is malleable; verify the HMAC before decrypting a restore.
- **Off-server DB dump copy:** the newest `/var/backups/parliament/*.dump` is encrypted +
  HMAC'd into the snapshot repo as `db_latest.dump.enc` (re-encrypted only when the dump
  changes). A dead server no longer takes all DB backups with it.
- **Log rotation:** new `scripts/logrotate.parliament-snapshot` (monthly, 6 rotations,
  copytruncate). Install: `sudo cp scripts/logrotate.parliament-snapshot /etc/logrotate.d/parliament-snapshot`.

## Fixed

### 3. Schema is backend-agnostic again — sqlite dev/test works

`plurality_options` (Legislation + CommitteeLegislation) was a Postgres-only `ArrayField`,
so `DB_BACKEND=sqlite` couldn't even run `migrate` (`near "[]": syntax error` in
`0001_initial`) and no tests could run without Postgres. Swapped to `models.JSONField`
(usage was already pure Python lists — no ArrayField lookups anywhere):

- `0001_initial` edited to declare `JSONField` (it never produced a working column on
  non-postgres backends; prod applied it via the 07-05 fake-initial cutover, so its
  recorded state follows the file).
- New `0004_plurality_options_jsonfield` converts prod's real column with
  `USING to_jsonb(plurality_options)` (there is **no direct** `varchar[]::jsonb` cast —
  Django's autogenerated `AlterField` would have failed on prod). Postgres-only via
  `RunPython`; no-op-safe on fresh DBs where 0001 already made jsonb; skipped on sqlite.

### 4. Test suite repairs (now green on sqlite: ~374 tests, 1 postgres-only skip)

- `test_comprehensive`: 3 event-archiving tests used `client.get()` against
  `@require_POST` views (405 → nothing archived) — now POST.
- `test_two_factor`: 3 tests updated to the new contract (OTP-verified session to reach
  the disable page; password on disable POST; verified session for profile browse).
- `test_login_pipeline` (v3.13.1): `force_login()` fires `user_logged_in` with a bare
  `HttpRequest` (no `REMOTE_ADDR`) → NOT NULL insert failure inside the signal poisoned
  the test transaction. Non-pipeline test now drives `auth.login()` on a real
  `RequestFactory` request — mirroring `login_as_view` exactly.
- `test_pledge_permissions.test_pledge_home_shows_filtered_events`: skipped on
  non-postgres backends (`visible_to__contains` JSONField lookup is postgres-only);
  CI still runs it.
