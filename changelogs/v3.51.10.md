## Votes

- **Cross-committee ballot (IDOR).** `committee_vote` looked up the
  legislation by id with no committee filter, so a voting member of one
  committee could cast a ballot on another committee's legislation. It's now
  scoped to the committee in the URL.
- **Committee voting 500'd after every ballot.** Every POST redirected to the
  URL name `committee_vote`, which doesn't exist. The ballot was saved, then
  the page crashed. Broken since v3.14.0. Redirects now go to `vote`.
- **Committee ballot checks.** Single-select accepts only yes/no/abstain or a
  listed plurality option. Abstain is refused when `allow_abstain` is off.
  Ballots before voting starts are refused. Multi-select refuses duplicate
  picks and writes all-or-nothing.
- **Chapter `cast_vote` ignored `allow_abstain`.** Fixed.
- **Double ballots.** Ballots are written inside a transaction with a row lock
  on the legislation, and `Vote` gets a unique (user, legislation,
  vote_choice) constraint (`CommitteeVote` already had one). A duplicate shows
  the normal "already voted" message and no receipt.
- **Committee result page 500'd for non-voting viewers**
  (`committee.non_voting_members` doesn't exist).

**Migration `0064_vote_unique_ballot` deletes nothing.** If prod already holds
duplicate `Vote` rows, it stops and lists each user id, legislation id and row
count. It does not print the choice, so an anonymous ballot isn't exposed in
the deploy log. Resolve by hand and re-run `migrate`.

## Chat

- **@mentions leaked message text.** Naming anyone sent them a `chat_mention`
  notification with the first 200 characters, even with no access to the
  channel (Kai included). Mentions now only match people who can read it.
- **Notification-level setting always 500'd** (the view never returned).
- **One access rule.** `has_access`, `can_read` and `can_write` disagreed;
  `can_read` (used by the websocket) ignored role grants, and expired role
  grants still let people in. There is now one implementation
  (`_has_access_cached`); `can_read` is an alias, `can_write` uses the same
  rule with write grants, and global search uses it too.
  - **Narrower:** expired role grants no longer admit; admins read and post in
    restricted/committee channels only through "View All" mode (matching the
    v3.16.2 rule that admin isn't an access grant); committee membership alone
    doesn't admit to a channel set to restricted; write-without-read grants
    can't post; search hides inactive and no-access channels.
  - **Wider (write only):** a role grant with `can_write` (on by default) now
    lets those members post in a restricted channel they could already read.
    Committee channels (Kai) still honour only membership and per-user grants.
- **Private push previews.** Pushes for restricted and committee channels say
  "Parliament" / "New message in a private channel". Open channels keep the
  channel name and text. Members who lost access get no push.

## Calendar

- **Sign up / cancel ignored visibility.** Any member could sign up for an
  event hidden from him, or an archived one, by id. Now 404.
- **`/api/calendar-data/` 500'd** on a non-numeric or out-of-range year or
  month. Now 400 JSON.
- **Subscription feed** kept serving with the `calendar_subscriptions` flag
  off, and for inactive, quarantined or Removed members. Now 404. Alumni and
  Inactive members (who can still sign in) keep their feed.

## Sessions

- **"Sign out other sessions" did nothing on prod.** `revoke_other_sessions`
  and the single-session revoke deleted `Session` rows, which don't exist under
  the cache (Redis) session engine prod uses. They now delete through the
  configured engine. Tested on both engines.

## Not fixed (noted for later)

- `Event` has no `updated_at`, so subscribed calendars may not pick up edits
  (`SEQUENCE` stays 0). Needs a field + migration.
- Admin "View All" chat mode still lets any admin read Kai committee chat,
  which conflicts with the v3.18.2 Kai rule. Needs a decision.
- `can_edit_messages` / `can_delete_messages` keep their own admin bypass.
- @mention autocomplete lists only per-user grants on restricted channels.
