## Two-Factor Authentication System

### User-Facing Features

**2FA Setup (`/accounts/two-factor/setup/`)**
- Scan QR code with Google Authenticator, Authy, or Microsoft Authenticator
- Manual key entry option for accessibility
- 6-digit verification code confirmation
- "Remind me later" option to dismiss setup prompt for 1 hour

**2FA Verification (`/accounts/two-factor/verify/`)**
- Required during login when 2FA is enabled
- 6-digit TOTP code entry
- Automatic redirect after successful verification

**2FA Disable (`/accounts/two-factor/disable/`)**
- Users can disable 2FA from their profile
- Requires confirmation before removing

### Policy Modes

Administrators can configure 2FA requirements using these policy modes:

| Mode | Description |
|------|-------------|
| `none` | No 2FA required for anyone |
| `admins_only` | Only admins require 2FA |
| `officers_and_admins` | Officers and admins require 2FA |
| `all_members` | All active members require 2FA |
| `custom` | Only individually marked users require 2FA |

### Individual Overrides

Per-user 2FA requirements can override the global policy:
- **Required**: User must have 2FA regardless of policy
- **Exempt**: User is exempt from 2FA regardless of policy

## Dismiss for 1 Hour Feature

Users can postpone 2FA setup for 1 hour instead of being immediately redirected.

**How it works:**
1. User clicks "Remind me later (skip for 1 hour)" on setup page
2. Session stores `2fa_setup_dismissed_until` with expiration timestamp
3. Middleware checks timestamp before enforcing 2FA redirect
4. After 1 hour, user is prompted again

**Files Changed:**
- `src/view/two_factor.py` - Added `two_factor_dismiss` view
- `src/middleware/two_factor.py` - Added dismissal check logic
- `src/urls.py` - Added `/accounts/two-factor/dismiss/` route
- `templates/two_factor/setup.html` - Added dismiss link

## Bug Fixes

### 2FA Verification Loop Fix

**Issue:** After entering a correct 2FA code, users were stuck in a loop redirecting back to the verify page.

**Root Cause:** The code was manually setting `request.session['_otp_device_id']` instead of using django-otp's proper login function.

**Fix:** Changed to use `otp_login(request, device)` from `django_otp`:

```python
# Before (broken)
request.session['_otp_device_id'] = device.persistent_id

# After (correct)
from django_otp import login as otp_login
otp_login(request, device)
```

**Files Changed:**
- `src/view/two_factor.py` - `two_factor_verify` function

### Middleware Session Handling Fix

**Issue:** Tests were failing because middleware expected `request.session.get()` but RequestFactory doesn't provide a session.

**Fix:** Changed to use `getattr(request, 'session', {}).get()` for safe session access:

```python
# Before
dismiss_until = request.session.get('2fa_setup_dismissed_until')

# After
dismiss_until = getattr(request, 'session', {}).get('2fa_setup_dismissed_until')
```

**Files Changed:**
- `src/middleware/two_factor.py`

## Database Changes

### New Model: TwoFactorRequirement

```python
class TwoFactorRequirement(models.Model):
    REQUIREMENT_CHOICES = (
        ('required', 'Required'),
        ('exempt', 'Exempt'),
    )

    user = models.OneToOneField(
        ParliamentUser,
        on_delete=models.CASCADE,
        related_name='two_factor_requirement'
    )
    requirement = models.CharField(max_length=20, choices=REQUIREMENT_CHOICES)
    reason = models.TextField(blank=True)
    set_by = models.ForeignKey(
        ParliamentUser,
        on_delete=models.SET_NULL,
        null=True,
        related_name='two_factor_requirements_set'
    )
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
```

### TOTP Token Generation

Custom helper function for generating valid TOTP tokens in tests:

```python
def generate_totp(device, interval=30, digits=6):
    """Generate a valid TOTP token for a device"""
    counter = int(time.time() // interval)
    msg = struct.pack('>Q', counter)
    h = hmac.new(device.bin_key, msg, hashlib.sha1).digest()
    o = h[19] & 15
    code = (struct.unpack('>I', h[o:o+4])[0] & 0x7fffffff) % (10 ** digits)
    return str(code).zfill(digits)
```
