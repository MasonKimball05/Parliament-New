# Parliament v2.5.1 - Minutes Editor Bug Fixes & UX Improvements

**Release Date:** January 28, 2026
**Status:** ✅ Deployed to Production
**Type:** Patch Release - Bug Fixes & UX Improvements

---

## Overview

This patch release addresses bugs discovered during initial use of the Chapter Minutes editor introduced in v2.5.0. Fixes include permission errors on minutes deletion, published minutes not updating their PDF, marker deletion breaking adjacent sections, and text file display in the document viewer. Several UX improvements were also added to the minutes editor, and file upload validation was extended to cover newly supported text and data file types.

## Bug Fixes

### 1. Delete Minutes Permission Error
**Problem:** Deleting chapter minutes threw `AttributeError: 'ParliamentUser' object has no attribute 'is_superuser'`. The delete view and template both referenced `is_superuser` which doesn't exist on the custom user model.

**Fix:** Changed `request.user.is_superuser or request.user.is_admin` to `request.user.is_admin` in the delete view function. Updated the template to use `request.user.is_admin` in the conditional for showing the delete button.

**Files Changed:**
- `src/view/officer/chapter_minutes.py` — Fixed admin check in `delete_chapter_minutes()`
- `templates/officer/chapter_minutes_list.html` — Fixed template conditional

---

### 2. Published Minutes PDF Not Updating on Edit
**Problem:** Editing already-published minutes did not regenerate the PDF document in Chapter Documents. The published document remained stale after edits.

**Fix:** Added PDF regeneration logic to both `save_minutes_data()` and `save_minutes_attendance()`. When saving published minutes, the system now calls `generate_minutes_pdf_buffer()` and updates the linked `CommitteeDocument` file with the fresh PDF.

**Files Changed:**
- `src/view/officer/chapter_minutes.py` — Added PDF regeneration in save functions for published minutes

---

### 3. Text Files Not Displaying in Document Viewer
**Problem:** The document viewer couldn't display `.txt` files (and other plain text formats) — it showed a "can't display" error even though the file existed and was valid.

**Fix:** Added text file reading support to the document viewer. New `read_text_file()` helper reads text files with encoding fallback (UTF-8 → Latin-1) and size truncation (500KB max). Updated `get_file_type_info()` to detect text file extensions. Updated all view functions to pass `text_content` to the template. Added styled `<pre>` block rendering for text content in `view_document.html`.

**Supported Extensions:** `.txt`, `.md`, `.csv`, `.log`, `.json`, `.xml`, `.html`, `.css`, `.js`, `.py`

**Files Changed:**
- `src/view/view_document.py` — Added `read_text_file()`, updated file type detection, updated all view functions
- `templates/view_document.html` — Added text content rendering block with fallback

---

### 4. Marker Deletion Breaking Adjacent Sections
**Problem:** Deleting a section end marker (or any marker) could break the section header on the line above it. The delete functions consumed both the leading AND trailing newlines around the marker, which merged adjacent lines. For example, deleting `──── §/ ────` directly after `──── § Title ────` would produce `──── § Title ────More text`, breaking the header regex and causing the header to disappear.

**Fix:** Changed all three marker deletion functions (`deleteMotion`, `deleteSection`, `deleteSectionEnd`) to only consume one surrounding newline instead of both. The new logic prefers consuming the trailing newline; if there is no trailing newline, it consumes the leading newline. This prevents adjacent lines from merging.

**Before (broken):**
```javascript
if (start > 0 && text[start - 1] === '\n') start--;
if (end < text.length && text[end] === '\n') end++;
```

**After (fixed):**
```javascript
if (end < text.length && text[end] === '\n') {
    end++;
} else if (start > 0 && text[start - 1] === '\n') {
    start--;
}
```

**Files Changed:**
- `templates/officer/chapter_minutes_editor.html` — Fixed `deleteMotion()`, `deleteSection()`, and `deleteSectionEnd()` functions

### 5. Section Cards Displayed in Wrong Order
**Problem:** Section header and section ender cards below the textarea were grouped by type (all headers first, then all enders) instead of being displayed in the order they appear in the text. This made it confusing to manage paired header/ender sections.

**Fix:** Updated `renderSections()` to parse the textarea text for marker positions, collect all headers and enders with their text positions, sort by position, and render cards in the correct order of appearance.

**Files Changed:**
- `templates/officer/chapter_minutes_editor.html` — Rewrote section card rendering in `renderSections()`

---

### 6. File Upload Validation Gap for New Text File Types
**Problem:** The document viewer (v2.5.0) added support for displaying text-based file types (`.txt`, `.md`, `.csv`, `.log`, `.json`, `.xml`, etc.), but the upload validation pipeline did not allow most of these types. The central `ALLOWED_FILE_TYPES` in `file_validation.py` only covered `.txt`, `.md`, `.rtf`, and `.csv`. The `CommitteeDocumentForm` in `forms.py` was even more restrictive, only allowing Office documents and PDFs. The `ALLOWED_DOCUMENT_TYPES` setting in `settings_postgres.py` also lacked text/data MIME types. This meant users could not upload files the viewer was designed to display.

**Fix:** Extended file upload validation across all three layers:

1. **`src/utils/file_validation.py`** — Added `.log`, `.json`, `.xml` to `ALLOWED_FILE_TYPES` with MIME type mappings (`text/plain`, `text/x-log`, `application/json`, `application/xml`, `text/xml`)
2. **`Parliament/settings_postgres.py`** — Added all text and data MIME types to `ALLOWED_DOCUMENT_TYPES` (`text/plain`, `text/markdown`, `text/csv`, `application/csv`, `application/rtf`, `text/rtf`, `text/x-log`, `application/json`, `application/xml`, `text/xml`)
3. **`src/forms.py`** — Updated `CommitteeDocumentForm`:
   - `allowed_extensions` now includes `.txt`, `.md`, `.rtf`, `.csv`, `.log`, `.json`, `.xml`
   - File input `accept` attribute updated to match
   - Fallback `allowed_mimes` list updated with all text/data MIME types

**Security Notes:**
- `.js` remains in `BLOCKED_EXTENSIONS` — script files are never uploadable
- `.py`, `.html`, `.css` are intentionally excluded from upload validation — they are code files with potential security risks (server-side execution, XSS)
- The document viewer can still safely *display* these types if they exist on the server (rendered in an escaped `<pre>` block), but users cannot upload them
- All uploads still pass through MIME type verification via `python-magic` to prevent extension spoofing

**Files Changed:**
- `src/utils/file_validation.py` — Added `.log`, `.json`, `.xml` to `ALLOWED_FILE_TYPES`
- `Parliament/settings_postgres.py` — Added text/data MIME types to `ALLOWED_DOCUMENT_TYPES`
- `src/forms.py` — Updated `CommitteeDocumentForm` extensions, accept attribute, and MIME types

## UX Improvements

### 1. Edit History on Published Minutes PDF
When published minutes are edited, the regenerated PDF now includes an "Edit History" section at the bottom with amber styling showing:
- "DOCUMENT EDITED AFTER PUBLICATION" header
- Last edit timestamp and editor name
- Edit reason (if provided)

**Files Changed:**
- `src/view/officer/chapter_minutes.py` — Added edit history section to PDF generation

---

### 2. Section Headers Feature
Added ability to organize minutes into named sections (e.g., "Officer Reports", "Old Business"). Section headers appear as purple markers in the textarea and render as styled headings in the PDF.

- New section type `header` with `title` field on `MinutesSection` model
- "Add Section Header at Cursor" button in the editor
- Quick presets: Officer Reports, Old Business, New Business, Committee Reports, Announcements, Good of the Order
- Edit and delete section headers via cards below the textarea
- Purple styling in PDF output

**Files Changed:**
- `src/models.py` — Added `title` field to `MinutesSection`
- `src/view/officer/chapter_minutes.py` — Added header handling in save and PDF generation
- `templates/officer/chapter_minutes_editor.html` — Added section header UI, form, presets, and JS functions

**Migrations:**
- `0070_add_title_to_minutessection.py`

---

### 3. Section Enders (Boxed Sections)
Added section end markers that pair with section headers to create visually boxed sections in the PDF. Content between a header and its ender is rendered inside a bordered box with a purple left border and light purple background.

- New section type `section_end` on `MinutesSection` model
- "End Section at Cursor" button in the editor
- Section end markers displayed as `──── §/ ────` in the textarea
- Marker protection prevents accidental editing/deletion
- PDF renders paired header/ender content in boxed sections

**Files Changed:**
- `src/models.py` — Added `section_end` to section type choices, increased `max_length` to 20
- `src/view/officer/chapter_minutes.py` — Added boxed section rendering in PDF generation
- `templates/officer/chapter_minutes_editor.html` — Added section ender UI and JS functions

**Migrations:**
- `0071_add_section_end_type.py`

---

### 4. Adjourn Meeting Button
Added a prominent "Adjourn Meeting" button at the bottom of the minutes editor, near the Publish section. Previously the adjournment time input was only in the header bar and easy to miss.

- Red "Adjourn Meeting" button sets end time to current time
- Shows formatted confirmation time after clicking (e.g., "Adjourned at 9:45 PM")
- Initializes display on page load if end time is already set
- Placed directly above the Publish section for end-of-meeting visibility

**Files Changed:**
- `templates/officer/chapter_minutes_editor.html` — Added adjourn button HTML and `adjournMeeting()` JS function

---

### 5. End Time (Adjournment) Field
Added `end_time` field to the `ChapterMinutes` model so the adjournment time can be recorded separately from the start time. Displayed in the editor header and included in the PDF output.

**Files Changed:**
- `src/models.py` — Added `end_time` to `ChapterMinutes`
- `src/view/officer/chapter_minutes.py` — Added end time to save and PDF generation
- `templates/officer/chapter_minutes_editor.html` — Added end time input and save logic

**Migrations:**
- `0068_add_end_time_to_chapterminutes.py`

---

### 6. Edit Tracking for Published Minutes
Added audit trail for edits to published minutes. When an officer edits published minutes, they're prompted for a reason, and the edit metadata is stored.

- Fields added: `edited_after_publish`, `last_edit_at`, `last_edit_by`, `last_edit_reason`
- Warning banner displayed when editing published minutes
- Orange "Edited" badge shown next to "Published" badge
- Edit prompt shown before saving published minutes

**Files Changed:**
- `src/models.py` — Added edit tracking fields to `ChapterMinutes`
- `src/view/officer/chapter_minutes.py` — Added edit tracking to save functions
- `templates/officer/chapter_minutes_editor.html` — Added edit prompt and warning banner

**Migrations:**
- `0069_add_edit_tracking_to_chapterminutes.py`
