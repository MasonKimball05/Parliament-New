## v3.29.13 solved the wrong half of the problem

v3.29.13 fixed `download_chapter_document`'s response headers
(`Content-Disposition: inline` for a PDF/image instead of unconditional
`attachment`) and left both announcement templates linking to that same
URL. That's a real improvement on its own, but it wasn't what Mason was
actually asking for: he wanted the announcement-linked document to behave
like every other document already does on the Chapter Documents page —
`view_chapter_document`, this app's own viewer page (PDF iframe on
desktop, page-image rendering on mobile, DOCX-to-HTML, an "Open in new
tab" button and a separate "Download" button) — not a raw file load that
depends on the browser's own PDF-handling configuration to render inline
correctly.

## Fix

Both `templates/announcements.html`'s document chip and
`templates/emails/announcement_notification.html`'s document link now
point at `view_chapter_document` instead of `download_chapter_document`.
Same access gate underneath (`@login_required` + `published_to_chapter=True`
+ `can_user_view()` — `view_chapter_document` already applied all three,
identically to `download_chapter_document`), so no authz change; only
which of the two already-existing views the link visits.

`download_chapter_document` is left as-is (v3.29.13's disposition fix
stays — a real improvement for anything that does link to it later) but
is no longer referenced from any template. Checked
`src/tests/guards/test_reachable_pages.py`'s orphan-page ratchet before
leaving it unlinked: that test only flags routes whose view calls
`render()` — `download_chapter_document` returns a `FileResponse`, so it
was never counted as a "page" by that test in the first place (same
category as an API endpoint), and doesn't need adding to `KNOWN_ORPHANS`.

Updated `src/tests/announcements/test_announcement_document_email.py`
(all four tests) to assert `view_chapter_document` in the rendered email
instead of `download_chapter_document`, and added a docstring note
recording why v3.29.13's approach changed rather than deleting the
history silently.
