## 🟠 2FA recovery link: single use, and nothing happens on GET

**The bug.** The recovery token's hash was `pk + password + last_login`. The
only thing that changed after use was `last_login`, set by `auth_login` in the
confirm view. That view skipped `auth_login` when the browser was already
signed in as the member, which is the normal flow, because the request page is
`@login_required`. So the link stayed valid until it expired. Opening it from
any other browser deleted the member's new authenticator and backup codes and
signed that browser in as the member, with no password.

The wipe also ran on GET, so a mail client or link scanner fetching the URL
performed it.

**The fix** (`src/view/two_factor_recovery.py`):

- The token hash now also covers the ids of the member's TOTP and backup-code
  devices. Using the link changes them, and so does re-enrolling.
- The confirm view always calls `auth_login`, so `last_login` moves too.
- GET validates the token and shows a confirmation page
  (`templates/two_factor/recovery_confirm.html`). The wipe is on POST.

**Also corrected:** the email and three pages said the link lasts 1 hour. The
generator's `timeout = 3600` attribute was never read by Django; the real
lifetime is `PASSWORD_RESET_TIMEOUT`, 30 minutes. The copy now says 30 minutes
and the dead attribute is gone.

**Effect on deploy:** recovery links already in an inbox stop working. The
member requests a new one.

**Tests:** `src/tests/security/test_two_factor_recovery.py` (6). The replay
was reproduced against the old code first.

## 🟡 API no longer lists legislation before its release time

`/api/v1/legislation/` (list, detail and `active/`) filtered on status only.
The web pages hide a bill until `available_at` from everyone but its author;
the API returned the title and description of scheduled bills to any approved
token with `legislation:read`. `LegislationViewSet.get_queryset()` now applies
the same rule. Test added to `src/tests/api/test_api.py`.

## 🟡 Email tracking pixels only count for a signed URL

The pixel URLs carried sequential ids and need no login, so anyone could write
"Accused person viewed notification email" onto a Kai report, or mark any
member as having read an announcement or reminder.

- New `src/utils/tracking_sig.py`: every pixel URL ends in `?s=<HMAC>` over the
  pixel's kind and ids, keyed on `SECRET_KEY`.
- All four views (`track_kai_accused_email_view`,
  `track_kai_submitter_email_view`, `track_email_view`,
  `track_event_reminder_email_view`) return the same GIF and record nothing
  without a valid signature.
- All five places that build a pixel URL sign it.

**Effect on deploy:** opening an email sent before this release is no longer
recorded. A recorded view still only means something fetched the image; mail
clients prefetch.

**Tests:** `src/tests/security/test_tracking_pixel_signatures.py` (9); the
existing reminder-pixel tests now use signed URLs.

## 🟡 `?next=` must be a path

`safe_next` accepted a bare word. `redirect('logout')` resolves that as a
route name, so `?next=logout` on the 2FA verify page went to `/logout/` after a
correct code, and any other word was a 500. It now requires one leading `/`.
Tests: `src/tests/security/test_next_url.py` (3).

## 🟡 Backup drill

- **A database error while checking the restored copy now fails the drill
  properly.** A `psycopg2.Error` (the copy has no `django_migrations`, or can't
  be connected to) escaped as a traceback with no alert. It is now a
  `DrillFailed`, so the critical alert is sent.
- **The unit talks to Postgres directly.** `parliament-backup-verify.service`
  sets `DB_PORT=5432` after `EnvironmentFile`. Through pgbouncer, `createdb`
  and the scratch database are unreachable. **If you already installed the
  unit, copy it again and `systemctl daemon-reload`.** If Postgres is not on
  5432, edit that line.

Two tests added to `src/tests/infra/test_verify_backup.py`.

## 🟡 Deleting "this and following" from a series' first event

When the first event of a series was deleted with "this and following" and a
later finalized event survived, the series end date was not trimmed. The
survivors were re-read through a queryset keyed on the deleted root. Fixed in
`src/event_series.py`; test added to `test_recurring_series_bulk.py`.

## 🟡 Docker Compose: Postgres is no longer published

`docker-compose.yml` published `5432:5432` on every interface with a
`change_this_password` fallback. The `ports:` block is removed (containers
reach `db:5432` on the compose network), and `DB_PASSWORD` is now required:
compose refuses to start without it. Prod runs on systemd and is unaffected.

## 🟡 Script-embedded JSON on the slating and Kai pages

The slating setup page embedded member names in a `<script>` with a bare
`json.dumps`. New shared helper `src/utils/script_json.py`, used there and for
the Kai dashboard's chart data. Tests:
`src/tests/security/test_script_safe_json.py` (2).

### Not done here

From finding 10 of the audit; each is a design choice or needs a migration:

- **Hashing API tokens at rest.** Needs a migration and changes how a token is
  shown after creation.
- **Impersonation on POST only.** The admin list link is a plain anchor; it
  needs a small form.
- **Re-checking chat permission after connect.** Costs a query per message per
  socket, or a group-level "kick" event.
- **Paginating the API's event and committee lists in SQL.**
- The three older private `_script_safe_json` copies still exist next to the
  shared helper.
