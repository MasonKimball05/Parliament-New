# Included from v3.9.1 — Performance: Context Processor Caching & Query Reduction

**Original Release Date:** June 18, 2026
**Type:** Performance

---

## Overview

Targeted query reduction across the most trafficked code paths. Every authenticated page load was firing 3–5 unnecessary uncached DB queries via context processors. The home view had several N+1 patterns. Two composite indexes added for the most common queryset filters.

---

## What Changed

### 1. `two_factor_status` Context Processor — Cached (5 min)

Previously fired 2 uncached DB queries on every single page load for every authenticated user (`StaticDevice.filter().first()` + `token_set.count()`). Now cached per-user at `2fa_status_{pk}` for 5 minutes. Cache is invalidated immediately when backup codes are regenerated (`_generate_backup_codes`) or acknowledged (view-backup-codes page).

**Files:** `src/context_processors.py`, `src/view/two_factor.py`

---

### 2. `user_preferences` Context Processor — Cached (5 min)

Previously called `UserPreferences.objects.get_or_create(user=request.user)` on every request with no caching. Now cached per-user at `user_prefs_{pk}` for 5 minutes. Cache is invalidated immediately on form save in the preferences view.

**Files:** `src/context_processors.py`, `src/view/preferences.py`

---

### 3. Chat Unread Count — N+1 → Single Annotated Query

On cache miss the chat unread badge was fetching all `ChatReadReceipt` rows for the user and calling `get_unread_count()` in a Python loop — one COUNT query per channel. Replaced with a single annotated queryset using `Subquery` + `Coalesce`: newer-than-last-read messages are counted in the DB, with a fallback to all-messages for receipts with no `last_read_message`. A user in 10 channels went from 11 queries to 1.

**Files:** `src/context_processors.py`

---

### 4. `home.py` — Four Query Fixes

**`new_announcements_week` / `new_events_week`**
Was loading all recent announcements/events into Python then calling `is_visible_to_user()` in a loop. Replaced with ORM COUNT queries using the `_vis_q` visibility filter already built on the same page. 2 full-table fetches → 2 indexed COUNT queries.

**`user_committees` double query**
`user_committees.count()` in the context dict was firing a second DB round-trip after the queryset was already being evaluated in the template. Queryset is now forced to a `list()` and `len()` used for the count.

**Legislation preview loop — plurality N+1**
Plurality mode was calling `votes.filter(vote_choice=opt).count()` in a Python loop per option per legislation item. Now a single `values('legislation_id', 'vote_choice').annotate(n=Count('id'))` prefetch covers all items; the loop reads from the in-memory dict.

**Legislation preview loop — percentage extra query**
Percentage mode called `Vote.objects.filter(legislation=leg, vote_choice='no').count()` per item when `historical_no_votes` was None. Eliminated by the same prefetch above.

**Files:** `src/view/home.py`

---

### 5. Composite Indexes — Announcement & Event

Added indexes on the two most-queried filter patterns that had no composite coverage:

- `Announcement(is_active, -posted_at)` — covers `filter(is_active=True).order_by('-posted_at')`
- `Event(is_active, archived, date_time)` — covers `filter(is_active=True, archived=False).order_by('date_time')`

**Files:** `src/models/announcements.py`, `src/models/events.py`

---

### 6. `active_quarantines` ORM — Excludes Expired Records

Three `filter(released_at__isnull=True)` queries in `admin_v2.py` (dashboard count, security view, quarantine management page) were not excluding records where `expires_at` had passed but the nightly Celery task hadn't run yet. Added `Q(expires_at__isnull=True) | Q(expires_at__gt=now)` to all three so the UI stays consistent with the `is_active` property.

**Files:** `src/view/admin_v2.py`

# Added in v3.10.0 — June 21, 2026

## New Features

### 7. Event Sign-Up Waitlist

Events with a `max_signups` cap can now optionally enable a waitlist (`allow_waitlist` checkbox in create/edit event forms). When the event is full and a member tries to sign up, they are queued at the next available `waitlist_position` (1-based) rather than rejected. When a confirmed member cancels, the member at position #1 is automatically promoted to a confirmed slot and the remaining positions are compacted. The `event_signup` view wraps all of this in `select_for_update()` so concurrent requests serialize correctly.

The sign-up list page (`event_signup_list`) now shows a dedicated amber-highlighted Waitlist section with numbered position badges, visible alongside the confirmed roster and the existing cancelled section. The waitlist count is also shown in the page header.

**New fields:** `Event.allow_waitlist` (BooleanField, default False), `EventSignup.waitlist_position` (PositiveIntegerField, nullable)

**Changed:** `src/models/events.py`, `src/forms.py`, `src/view/calendar.py`, `templates/calendar/event_signup_list.html`, `templates/officer/create_event.html`, `templates/officer/edit_event.html`

---

### 8. Sign-Up Roster CSV Export

Officers can now download the active sign-up roster (confirmed + waitlisted) as a CSV from the sign-up list page. The export view (`event_signup_export`) is officer-gated, includes `X-Content-Type-Options: nosniff` and `Cache-Control: no-store`, and follows the same pattern as the audit log export. An "Export CSV" button appears in the sign-up list header.

**New view:** `event_signup_export` in `src/view/calendar.py`

**New URL:** `calendar/event/<id>/signups/export/`

**Changed:** `src/urls.py`, `templates/calendar/event_signup_list.html`

## Bug Fixes & Hardening

### 9. `edit_service_event` — Email Reminder Reset Was Dead Code

The date-change check `if date_time and date_time != se.event.date_time` always evaluated to `False` because `se.event` is the same Python object as `event` and `event.date_time` had already been mutated before the comparison. Additionally, the body was `pass`, so even if the condition had been correct, nothing would have happened.

Fixed by capturing `old_date_time = event.date_time` before mutation. When the date changes and the reminder has already been sent (`email_reminder_sent_at` is set), it is now cleared and included in `update_fields` so the Celery task re-evaluates against the new send window.

**Changed:** `src/view/service_hours.py`

---

### 10. `service_event_attendance` — N+1 + Duplicated Save/Finalize Blocks

The attendance save path issued one `update_or_create` + one `delete` per active member (O(n) queries), and the save and finalize branches were near-identical duplicated blocks (~110 lines each).

Extracted `_bulk_save_service_attendance(event, members, present_ids, marked_by)` — fetches all existing records in one query, bulk-updates existing present records, bulk-creates new ones, and bulk-deletes absent present marks, for a constant ~4 queries regardless of roster size. Also extracted `_parse_hours_overrides(members, post_data)` to de-duplicate the override parsing. The view now has a single shared `action in ('save', 'finalize')` block.

**Changed:** `src/view/service_hours.py`

---

### 11. `event_signup_list` — Double `.count()` Query

`signups.count()` was called on a lazy queryset that was also passed to the template (which would evaluate it again). Fixed by forcing `list()` upfront and using `len()` for the count.

**Changed:** `src/view/calendar.py`

---

### 12. Cache Invalidation on Admin User Edits

`invalidate_user_session_caches(target.pk)` is now called from `edit_user_profile` in `admin_v2.py`, busting `user_prefs_{pk}` and `2fa_status_{pk}` immediately after any admin-side user edit.

**New file:** `src/utils/cache_utils.py`

**Changed:** `src/view/admin_v2.py`

---

### 13. `nosniff` Header on Audit Log CSV Export

`response['X-Content-Type-Options'] = 'nosniff'` added to the `audit_log` CSV download response.

**Changed:** `src/view/admin_v2.py`

---

### 14. `dismiss_chat_unread` — N+1 → Subquery + Bulk Update

The dismiss-all-unread endpoint previously looped over all of a user's `ChatReadReceipt` rows and issued one `ChatMessage` query per channel. Replaced with a `Subquery(OuterRef('channel'))` annotation to find the latest message ID per channel, then a single `bulk_update` to advance all receipts at once. Constant 2 queries regardless of channel count.

**Changed:** `src/view/chat/channel_chat.py`

---

### 15. Recruitment Dashboard Button Replaces "New Event" Shortcut

The "New Recruitment Event" button in the committee home header (which was only visible to managers) has been replaced with a "Recruitment Dashboard" link visible to all committee members. The create-event action is already available from within the dashboard itself.

**Changed:** `templates/committee/committee_home.html`
