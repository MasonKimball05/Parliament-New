## More of the website in the app

### Two-factor authentication (Settings → Two-factor authentication)

Members can manage 2FA in the app instead of the website:

- See whether it's on, and how many backup codes are left.
- **Turn it on:** open the authenticator app straight from the screen (or
  copy the key, or scan the QR from another device), then enter the 6-digit
  code. The backup codes are shown once, right after, with Copy and Share.
- **New backup codes** and **turning it off** both ask for the password (the
  same 5-tries-in-15-minutes limit as the website's password checks).
- Turning it off isn't offered when the member's role requires 2FA.
- The same email, notification and security log as the website. Turning it
  off or making new codes signs out the member's other app installs and
  keeps the phone that made the change, like a password change.
- The key and codes are never logged, cached or shown again.

Recovery for someone who can't sign in stays on the website (it's an
emailed link), as does "forget this device", which has no app equivalent.

### Form builders

The Kai report and commendation forms, the service-hours submission form and
a slating election's application form can be edited in the app, from the Kai
committee's screens, the service-hours officer area and the election's setup:
add, edit, reorder (up and down), remove and restore fields, with a preview
of the form as members see it. Built-in fields can't be removed, as on the
website. One shared builder serves all three (on the server and in the app).

### Admin v2: notification schedules and site settings

- **Notification schedules:** grouped by type with on/off switches, the last
  time each sent and recent sends; create, edit and delete. Types the server
  never actually sends (dues reminders, custom messages, the custom audience)
  are marked "Sends nothing".
- **Site settings:** switches, number fields, JSON and a list of choices for
  the 2FA policy, each with its default ("Reset to default") and who changed
  it last. Logged like the website; security settings ask first.

### Admin v2: the rest

All under the app's Admin (the same allow list and unlock as the rest of it):

- **Reports:** Chapter health, and the Permissions map (read only, as on the
  website).
- **System:** System tools (clear a cache, run a scheduled job now, each asking
  first), Scheduled jobs, Backups, the **Push composer** (preview, then send,
  with the website's 15-minute one-use preview, master switch and 5-an-hour
  limit) and Browser push subscriptions.
- **Security** (site admins only, as on the website): the dashboard,
  Quarantine (add and release), Honeypot (delete, clear, block all) and CSP
  reports (dismiss).
- **Notifications:** the dashboard and the logs with filters.
- **Two-factor:** who has it, by role, and the 2FA policy. Changing the
  policy signs out app installs that signed in with a password only if the
  new policy requires 2FA of that member (as the website does); the
  confirmation says so.

Every one-way action asks first. The site map, URL explorer, test-email
targeting and the bulk member tools stay on the website.

### Officer and committee pages

- **A committee's attendance history** ("History" on the attendance screen):
  by date, with each member's status and who marked it, or by member with
  totals.
- **Upload Report** ("Upload" on Reports): committee, type, title, file,
  description, meeting date and "publish to chapter", with the website's
  file types and 20 MB limit.
- **Edit Landing Page** (officer menu): the tagline, banner, sections, contact
  details, link-preview image, visibility switches, photo library, social
  links, contact topics and form links, with Preview. A section with links or
  formatting is shown read-only with "Edit on the website", so formatting is
  never lost.

### Links open the app

Website links (in pushes, search results, posts and emails opened on the
phone) now open the native screen for: a slating election's ballot and
results, the elections list, an event's attendance marking and sign-up, a
poll's "thanks" page, a new folder in chapter documents, adding a section
impact to a resolution, the check-in places page, a Kai recusal, a
committee's attendance history, the 2FA pages, the form builders and the
landing page editor. Upload pages still open the website (an older app
build may not have the file picker).

- **My Attendance** and **Excuses** (the submit form and your requests): app

- **Kai** (your reports, a report, filing one), **My Tasks**, **Polls** and

- **Quote Book** and its add form (the page-flip book is unchanged),
  **Search** (each kind of result as a titled card of rows), **the Guide**
  (sections of rows with colored icons; filtering works), its articles, and

All work in dark mode and at phone width.

## Website fixes found along the way

- **Word files were refused** on committee documents, officer reports, chapter
  bills and bill drafts when saved by Word itself: the type check read only
  the first 2 KB, which can't tell a Word file from a plain zip. They now use
  the same check as Kai reports (it reads the file's contents list), and a
  zip pretending to be a Word file is still refused.
- **Landing page photos and the link-preview image** accepted any file on the
  website (only the browser's picker limited it). Now only real images.
- **2FA setup's "enter this key"** showed the key in hex, which authenticator
  apps don't accept; it's now the base32 key they expect, in groups of four.
  (Scanning the QR code always worked.)
- **A committee's attendance history:** "Total Present" counted every record;
  it now counts the members marked present.
- **Form builders: editing a field on the website** turned "confidential" off
  and reset a file field's size limit to 10 MB (the edit form has no inputs
  for them). An edit now keeps both.
