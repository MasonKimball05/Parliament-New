## 🔴 Times shown in UTC instead of Central (bug report, 10-28-26)

### Pledge tracker: "goes live" showed the wrong day and time
A timed task set to go live at 9 pm showed "goes live <next day> at 2:00 AM",
so it looked like it went live five hours late. It didn't: the task was saved
correctly and went live at 9 pm. Only the label was wrong.
`PledgeTask.activation_status_label` formatted the stored UTC time with
`strftime` without converting it to the chapter's time zone (9 pm CDT is 02:00
UTC the next day). It now uses `timezone.localtime` first.
- `src/models/education.py`
- `src/tests/education/test_timed_task_label_timezone.py` (fails on the old
  code with exactly the reported "6/2 at 2:00 AM")

### The same mistake elsewhere
Each formatted a stored time without converting it. All now use
`timezone.localtime`:
- Service hours: the adjustment history's timestamps (`src/view/service_hours.py`)
- Recruitment: a new note's timestamp (`src/view/committee/recruitment.py`)
- Calendar: "Signed up" times in the sign-up CSV (`src/view/calendar.py`)
- Chapter minutes PDF: "Last edited" (`src/view/officer/chapter_minutes.py`)
- Poll responses CSV: submission times (`src/view/officer/announcement_polls.py`)
- Admin v2: the "expires" time in the IP block message (`src/view/admin_v2.py`)

Model `__str__` methods that do the same appear only in the Django admin and
are left as they are.
