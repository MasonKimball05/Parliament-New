# v3.19.0 — Private legislation drafts on My Work

**Committed & pushed:** 08-06-26 (`97e2100`, "v3.18.7-v3.19.1" — one commit carrying v3.18.7, v3.19.0 and v3.19.1). Its templates were touched again in `2d64116`, but that was the multi-line-comment sweep and is recorded under v3.19.1.
**Deployed:** 08-07-26
**Migration:** `0014_legislation_drafts` — **includes a data backfill. Read the deploy notes.**

---

## Why

My Work was read-only: it showed what you had already submitted. There was no
way to start a bill you were not ready to present, and the only upload path
(`/legislation/upload/`) is officer-gated and puts the bill in front of the
chapter the moment it is saved.

This adds a **Drafts** tab. A draft is private to its author until they publish
it.

---

## The design decision, and why it is not `Legislation.is_draft`

The obvious implementation is a boolean on `Legislation`. It was rejected after
mapping the surface: **`Legislation` is queried from 35+ places** — every view in
`src/view/`, `src/api/views.py`, `global_search.py`, four Celery tasks,
`admin.py`, `chapter_stats.py` and five management commands.

A boolean means every one of those has to remember to exclude drafts. That is
exactly the shape this codebase has paid for in five consecutive releases
(v3.16.3, v3.18.1, v3.18.3, v3.18.4, v3.18.5): *a rule stated correctly, a
helper written to enforce it, then one call site left outside the helper.* Here
the consequence is an unfinished bill on the chapter ballot.

Filtering in the **default manager** fails closed, but breaks the reverse related
managers: `user.co_authored_legislation.all()` is used by the user-merge code in
`admin.py:440` and `manage_members.py:482`, and a filtered default manager would
silently drop a draft's co-authorship during a merge. `_base_manager` stays
unfiltered, so FK traversal would disagree with `_default_manager` about whether
a row exists — two answers to one question, which is the "second copy" pattern
again.

**A separate `LegislationDraft` table has neither problem by construction.** A
draft cannot leak into a `Legislation` queryset because it is not in that table.
The migration is purely additive: nothing that works today changes.

The cost is that publish copies fields across. That is the right cost to pay —
**a copy that is visibly wrong beats a filter that is invisibly missing.**

## The authz split — deliberate, and one line to change

| Action | Gate | Why |
|---|---|---|
| Create / edit / delete a draft | `@login_required` | Any member. New surface, no chapter-visible effect. |
| Publish to the chapter | `@officer_required` **+ author** | Pre-existing boundary — `/legislation/upload/` has always been officer-gated. |

Widening *drafting* is harmless. Widening *publishing* changes who can put
business before the chapter, which is a governance decision and not one to make
as a side effect of adding an upload button. A non-officer's ready draft shows
*"Ready — ask an officer to present it."*

**If members should publish their own bills**, swap `@officer_required` for
`@login_required` on `publish_legislation_draft`. The ownership check is
independent and stays either way — `test_a_plain_member_cannot_publish_their_own_draft`
is the test to update, and it says so in its own docstring.

Both gates apply independently: `test_an_officer_cannot_publish_someone_elses_draft`
covers the combination that a single `or` would have got wrong (v3.18.4's second-axis
lesson).

## Notification timing changed — and this affects the existing upload path

`upload_legislation._notify()` used to fire the moment the row was saved.
`available_at` is required and officers routinely set it in the future, so a bill
dated three weeks out pushed *"New Legislation: …"* to every active member for
something none of them could open — and nothing announced it again when it
actually became available. The notification was either premature or absent.

Now:

- **Available already** → announced inline, unchanged from a member's point of view.
- **Dated in the future** → silent, and `tasks.notify_available_legislation`
  (new, every minute) announces it the minute it lands.

Both paths go through `announce_legislation_availability()`, which **stamps
`Legislation.availability_notified_at` as its claim** using a conditional
`filter(..., availability_notified_at__isnull=True).update(...)`. The row count
that update returns is the lock: two workers racing produce one winner and one
no-op, so an overlapping beat tick, a dead worker or a manual re-run cannot
double-announce.

⚠️ **The stamp is not rolled back if the send fails**, deliberately.
`notify_all_active_members` creates one row per member and is not atomic, so a
failure partway through has already notified some of them; retrying would notify
those twice. An unsent announcement is a bill nobody was told about — visible on
the vote page anyway. A double announcement is a bug members report. The error
log names the bill and re-sending is a one-liner in the shell.

## ⚠️ Deploy notes — the backfill is the dangerous part

Migration 0014 stamps **every pre-existing bill** as already announced.

**Without it, the first beat tick after deploy would treat the entire historical
table as unannounced and push one notification per bill to all 47 active
members.** There is no undo for that.

Two independent guards, because one was not enough for something irreversible:

1. The `RunPython` backfill in 0014 (`availability_notified_at = available_at`,
   one bulk UPDATE).
2. A **seven-day lookback window** in the task itself. In a correct deploy this
   changes nothing; it exists for the deploy that is not correct — a skipped
   migration, a dump restored from before it, or a bulk insert via
   `queryset.update()` that no signal sees. Seven days is long enough that a
   worker outage over a weekend still sends.

Deploy order:

1. `git pull`
2. **`python manage.py migrate`** — do not skip; see above.
3. `python manage.py setup_celery_schedules` — registers *Notify chapter of newly
   available legislation*.
4. Restart `parliament-gunicorn.service`, **`parliament-worker` and
   `parliament-beat`** (the schedule changed).
5. `python manage.py check`
6. No static assets changed → no `collectstatic`, no Cloudflare purge.

## ⚠️ Before deploying

- **`python manage.py makemigrations --check`.** Migration 0014 is
  **hand-written** (no working Django in the review sandbox). The v3.18.1 CI gate
  exists precisely for this. If it reports pending changes, delete 0014 and run
  `makemigrations` — do **not** edit the models to match the migration. The index
  is explicitly named in *both* the model and the migration for this reason; an
  auto-generated name in one and a chosen name in the other is the most likely
  way this drifts.
- **`python manage.py test src.test_legislation_drafts`.** 26 tests, **never
  executed** — same sandbox limitation. Nothing here has a schema failure mode;
  the risk is a wrong render or a wrong gate.
- The two assertions most likely to need adjusting on first run are
  `test_the_task_announces_it_once_the_date_passes` and
  `test_the_control_a_bill_inside_the_window_is_still_announced`, which assert
  `Notification` rows were created. `notify_all_active_members` respects
  per-user preferences, so if the fixture users' default `UserPreferences`
  suppress this type the count is legitimately zero and the assertion should move
  to the `availability_notified_at` stamp instead.

## ⚠️ The leak test was wrong on its first run — recorded because the fix is the point

First execution, 08-05-26: 26 of 27 passed. The failure was
`global_search rendered a private draft to drf-other` — and it was a **false
positive**. The Legislation result set was empty; `SECRETBILLTITLE` appeared in
the body because the search page reflects the query into its `<input value=…>`
and into *Found 1 result for "…"*.

**The assertion could not distinguish the draft being rendered from the search
box repeating what the test typed** — which is this codebase's own rule from
v3.18.4, walked into by the module that quotes it.

The fix is not to skip the search page; that is the surface most likely to leak.
It is to probe with tokens that are **never submitted as input**, so their
presence can only mean the draft object was rendered:

| Token | Where it lives | Used as a query? |
|---|---|---|
| `SECRETBILLTITLE` | title | **yes** — so it is echoed, and is only asserted on non-echoing pages |
| `SECRETBODYTOKEN` | description | no |
| `PRIVATENOTETOKEN` | notes | no |
| `/legislation/drafts/<id>/` | — | no |

`SURFACES` entries now carry an `echoes_query` flag. Because an exemption is
exactly the kind of thing that later hides a real leak, a new test
(`test_the_search_page_echo_is_an_echo_and_not_a_result`) pins down *why* the
title appears there — asserting on `response.context['results']['legislation']`
rather than on HTML, so a template change cannot mask it.

**No production code changed as a result.** The separate-model design held; the
draft never reached a `Legislation` queryset.

## Tests — 28, in `src/test_legislation_drafts.py`

**The leak test asserts on rendered output, not on querysets.**
`TheDraftDoesNotAppearOnAnyChapterFacingPage` renders home, vote,
passed-legislation, global search, chapter documents and all-activity as
somebody who is not the author, and asserts the draft's title and private notes
survive nowhere in the body. It needs no advance list of which querysets exist,
so a surface added next month is covered without anyone remembering to add it
here. That shape is taken from v3.18.5's
`TheRedactionCoversEveryRenderedColumnTests`.

**Every assertion has a control.** `test_the_control_the_author_does_see_their_own_draft`
is the one that matters most: without it, every "the draft is absent" assertion
would still pass if drafts were never rendered anywhere at all — including if
the Drafts tab were silently broken. Each surface also asserts `status_code ==
200` before checking the body, because a 302 to login makes an absence assertion
pass for entirely the wrong reason.

**The fixture makes the author a plain member and the officer somebody else.**
v3.18.4's fixture lesson was that every Kai fixture granted both identity flags
together, so three of four combinations were never built. The equivalent trap
here is making the author an officer, which collapses "can draft" and "can
publish" into one person and stops testing the split at all.

Also covered: 404-not-403 on every ownership check (a 403 confirms the row
exists, and for a private document its existence is part of what is private);
`notes` not copied to the published bill; `voting_manual_open=True` forced at
publish; double-publish refused; the publish floor; task idempotency; the
lookback window and its control.

## Smaller things worth knowing

- **Draft URLs are `legislation/drafts/<id>/…`, not `legislation/<id>/…`.** A
  draft id and a legislation id are different keyspaces; sharing a route shape
  means a mistyped `reverse()` silently resolves to the wrong object.
- **`js-confirm-submit` has no global handler.** Every template using the class
  wires it up itself (`songbook_categories.html:218`,
  `cnb/resolution_detail.html:948`). Both new templates do — without it Publish
  and Delete submit with no confirmation, which for Delete is destructive and
  silent. Both inline scripts carry `nonce="{{ request.csp_nonce }}"`; a
  nonce-less inline script is dead in prod and fine in dev (v3.15.9).
- **`LegislationDraftForm` is deliberately more permissive than
  `LegislationForm`** — no document-or-20-characters floor while writing.
  Refusing to save an unfinished draft is how you get people writing bills in a
  Google Doc. The floor is not dropped, only moved to
  `ready_to_publish()`, which the UI reads to grey out the button *and say
  which half is missing*.
- **A bug in `LegislationForm.clean_document` was not copied.** Its `except
  Exception` swallows its own `ValidationError` into the generic "Unable to
  verify file type" message, so a spoofed `.pdf` reports the wrong error. The
  draft form re-raises `ValidationError` first. Worth fixing in the original
  separately — not done here to keep this release's diff about one thing.
- **`notes` never leaves the author.** Not copied at publish; the model
  docstring, the view comment and a test all say so.
- **Published drafts are kept, not deleted**, so My Work can link the draft to
  the bill it became and the author keeps their notes. The tab badge counts
  *unpublished* drafts only.
