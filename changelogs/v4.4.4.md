The app gets the rest of a committee vote's path to the floor (making it a

## The app: a committee vote becomes a chapter vote

A chair can make a closed committee vote into a chapter vote from the vote's
result or the committee's vote list. The form has the website's fields: the
title, description, when it opens, the voting mode and threshold, abstain, an
anonymous vote, and whether to show the committee's result. The chair can also
remove a chapter vote created by mistake. Both use the website's code, now
shared helpers in `src/committee_management.py`
(`committees/<code>/votes/<id>/chapter-vote/` and `.../chapter-vote/delete/`).

## The app: election setup

Slating chairs and the period's managers can set up an election from their
phone (`src/mobile/views_slating_setup.py`):

- the period's settings, schedule, committee, and its next stage
- positions: add, edit, reorder with up and down buttons, deactivate or
  reactivate, and copy the default positions
- transferring the slating committee's admin

Site admins can also create a new period, set its manager, delete a period,
and hard-delete a position. Opening voting stays on the chair's Run the vote
screen. The application form builder stays on the website.

## The app: the slate builder

The chair builds the slate in the app (`src/mobile/views_slating_slate.py`):
pick a candidate for each position from the eligible applicants (best fit
first, by their ranked choices), preview, approve, copy, and add or remove
write-ins. While voting is open they can edit the approved slate, and record
in-person results. Voting members can see the approved slate once voting
opens.

## Website fixes found along the way

- **Transfer admin never worked.** The member picker sent a blank value, so
  every transfer failed with "Please select a new admin".
- **Copying a slate broke the builder.** A copy is a second draft, and the
  builder and "approve the draft" then failed with a server error. Both now use
  the newest draft, so the builder opens on the copy.
- **A copy dropped runoffs and write-ins.** Copying a slate with a runoff failed;
  write-ins were copied without their member. Both are now copied.
- **Removing a write-in from a draft slate failed** with a server error, and
  the slate's candidate list failed on any slate with a write-in.
- **An incomplete "Edit approved slate" replacement emptied the position.** It
  removed the current candidate before rejecting the choice. The choice is now
  checked first.
- **Saving a position cleared what its form doesn't show.** The edit form only
  has the title, description, GPA and abstain, so every save cleared the
  position's linked role, "requires prior experience" and eligibility lists
  (including the roles "+ Default Positions" links). Those are now kept.
- **A resolution's author couldn't load a section to amend.** The amendment
  editor's section text was refused to authors who weren't the C&B chair or an
  editor, although authors may amend their own resolutions. It now loads for
  them, on the documents members can already read.
- **A refused "Record in-person results" left an approved, empty slate.** It
  approved the primary slate before checking that every position had a
  winner, so a form missing one left the slate behind. The winners are now
  checked first.
- **Abstain couldn't be turned off.** An unticked box sent nothing, which the
  server read as on. The form now sends "off" when it's unticked.

## The app: the resolution builder

Writing a Constitution & Bylaws resolution works in the app
(`src/mobile/views_cnb_resolutions.py`): create and edit it, amend a section
(pick the article and section, see its current text, enter the new text, or
remove the section), propose structure changes (a new article or section, or a
rename), move it through its statuses, and add or remove collaborators. The
same people can do it as on the website: the C&B chair, the author and
collaborators, with the same status locks. An edit someone else saved in the
meantime shows both versions instead of overwriting theirs. Print and the
document preview open the website.

## The app: export the activity logs

Activity Logs has an Export CSV button. It's the website's file for the same
filters, redaction, row limit and "exported" log entry (one shared
`activity_logs_csv`, `officer/activity-logs/export/`), opened in the share
sheet to save to Files or send.

## The app: more of Site admin

Site admin in the app gets most of the rest of Admin v2. Each screen runs the
website page's own code, moved into helpers both share, with the same fields,
page sizes and log rows:

- **Logs** (read only): email logs (waiting announcements, each send's counts
  and recipients by outcome), event reminder logs, login history (search,
  suspicious only), admin activity (by admin or action, search) and, for
  admins, security notifications. Sending a scheduled announcement email stays
  on the website.
- **IP allow and block lists:** add with a note or reason, remove with a
  confirmation (and a second one before blocking this phone's own address).
- **Exports:** the member roster, attendance and service hours CSVs, opened in
  the share sheet and logged as on the website, and refused to a sign-in from
  abroad, as the website does.
- **Page visits** (per-page totals, member and status filters, who visited)
  and **Trends** (12 weeks of sign-ins, app installs and failed sign-ins).
- **Account deletions:** restore a pending deletion, or rebuild an erased
  account, each confirmed.

Links to these Admin v2 pages open the app's screens.

## Getting to Admin v2 from the app

Members on the Admin v2 allowlist get an "Admin v2" Quick Link at the end of
Home's Quick Links. It comes from the server, so it reaches every build:
builds with Site admin open its unlock screen, and older builds open the
website's Admin v2 in the web view.

## Admin v2: new tools

- **Push composer** (Comms): send a push to everyone, the officers, a
  committee, a member type or status, or one member, with a title, message and
  an optional page on the site to open. The preview shows who it reaches, who
  turned announcement pushes off and who has no app or browser to push to.
  Sending is a separate confirmed step (a signed, single-use, 15-minute
  token), goes through the same push task as every other push, respects the
  master push switch, is limited to 5 an hour per admin, and is logged and
  listed under Recent sends.
- **Permissions map** (People): who holds what (the allowlist, site admins,
  officer roles, the Officer/Chair/Advisor types, committee chairs and admins,
  slating managers, Kai, education and recruitment access, committee grants,
  API tokens), with odd cases flagged: an admin not seen in 60 days, a chair of
  an inactive committee, a pledge or non-Active member with elevated access, a
  committee with no chair. Search and "Flagged only".
- **Chapter health** (Overview): members not seen in 30, 60 or 90 days (web,
  app or sign-in), never signed in, this semester's weekly attendance and the
  lowest attendance, members without the app, pledges with overdue tasks, and
  members below the service-hours requirement, using the same rules as Chapter
  Stats, the education dashboard and the service-hours export.
- **System tools** (System): clear one named part of the cache (flags and
  settings, page content, members' badges, admin reports, slow-page samples)
  without signing anyone out or resetting a lockout (there is deliberately no
  "clear everything"); run an enabled scheduled job now (not the permanent
  data purge); and see recent server errors from the log and the slowest
  recent pages, with passwords, tokens and cookies hidden. Each action is
  confirmed and logged.
- **Site map** (System, after URL explorer): a zoomable, collapsible tree of
  every page, built from the site's real routes and nested by path, with each
  committee and recent election filled in, "linked from" lines read from the
  templates (Home links to Committees; Committees is the parent of each
  committee and its pages), and pages whose parent has no route flagged. API,
  action and redirect addresses are hidden behind a toggle. Pick a page to see
  what decides who can open it (its access checks, page switch, feature
  flags, pledge restriction and, on committee pages, the committee's chairs
  and grants), check any member against it without running the page, and turn
  its page switch or feature flag on or off or change its pledge restriction,
  each confirmed and recorded in Admin activity. Rules written in code show
  the file and line instead. Pages that only exist for one kind of committee
  (the education, recruitment and Kai pages) are only listed under that
  committee, and links that change something just by being opened (email
  open tracking, sign in as a member) are listed as actions, not pages.
  "Open page" opens the page in the same tab with a "Back to the site map"
  bar across the top, like the bar shown while signed in as a member; it
  returns to the same page on the map.
## The website refresh (opt-in)

The member site can now look like the app: its light and dark colors
(off-white rather than pure white in light mode), cards, list rows, section
titles, pill-shaped Quick Links and the blue navigation bar. Home keeps every
section: the welcome banner with the coat of arms over the crest, the four
stat buttons as pressable cards, pending votes, the three columns, the
featured cards and every Quick Link. The top bar keeps each member's
Preferences links and pins a gold Officers button at its end. Committees
becomes one list. Members on the classic Home layout keep it, in the new
colors. Admin v2 is unchanged.

It's off until the new "Website Refresh (app look)" switch is turned on in
Admin v2 (or the app's Site admin). One browser can preview it with
`?ui=refresh` (`?ui=classic` for the old look, `?ui=default` to follow the
switch). With the switch off, every page is exactly as before.
