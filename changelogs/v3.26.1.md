## 🔴 `/admin/` "Add user" saved a row with an empty primary key, then crashed on the redirect

```
django.urls.exceptions.NoReverseMatch: Reverse for 'src_parliamentuser_change'
with arguments '('',)' not found.
```

`ParliamentUserAdmin.readonly_fields = ('user_id',)` (added in v3.24.0,
alongside making `user_id` a permanent opaque key — see
`src/test_user_id_is_permanent.py`) applied to the **add** form as well as the
change form. A readonly field is excluded from the `ModelForm` entirely, so
the add page never rendered `user_id` as an input and nothing validated it.
`ParliamentUser.save()` went through anyway with `user_id=''` — `CharField`'s
implicit default when no value is set — because the model field has no
`blank=True` to catch it, only the (now-inapplicable) form-level requirement
did. The crash only happened afterwards, when `response_add()` tried to
`reverse()` the change-page URL with an empty pk. **No exception during the
save itself is why nothing was logged before the 500** — the row was already
committed to the database by the time anything went wrong.

⚠️ **Any attempt through the broken admin page before this fix created an
unusable row with `user_id=''`.** These can't be reversed to or edited (the
same bug blocks the change-page URL for them). Worth a one-time check on
prod: `ParliamentUser.objects.filter(user_id='')`.

### Fix

`user_id` is readonly only once a row exists (`get_readonly_fields` returns
`()` on add). On the add form it's a real, optional input:

- Left blank, `save_model()` assigns one via the same
  `generate_member_uid()` the officer-facing "Add Member" page already uses.
- Typed by hand, it's used as-is (mirrors `AddMemberForm.clean_user_id()`).

Added `('src/admin.py', 'save_model')` to `_CREATION_SITES` in
`test_user_id_is_permanent.py` — this is a legitimate creation path and the
write is now allowlisted deliberately rather than merely missed by the
detector's variable-name heuristic (the `obj` parameter was renamed
`new_user` so it also reads correctly as one).
