# v3.16.1 — Django admin feature-area sections

Mason-directed 07-24-26, follow-up to the v3.16.0 full-coverage pass: 125
models in one alphabetical block made the index/sidebar unusable. No
migration, no static changes — code-only + restart.

## What changed

- **New `src/admin_sections.py`** — ordered `SECTIONS` mapping (22 sections,
  most-used first: Members & Roles, Voting & Legislation, Committees,
  Slating & Elections, Events, Service Hours, Recruitment, Pledge Education,
  Kai, CNB, Documents & Minutes, Announcements & Polls, Notifications, Chat,
  Security ×2, Audit & Activity, API, Landing Page, Guide, Songs, Site
  Config) + `build_sectioned_app_list()`, which re-buckets the standard
  permission-filtered app_list into pseudo-apps. Model dicts pass through
  untouched, so admin_url/add_url/perms keep working; alphabetical within
  each section.
- **`ParliamentAdminSite.get_app_list()` override** (admin.py) — applies the
  grouping to the index and the nav sidebar (both use `get_app_list`).
  Single-app views (`/admin/src/`) keep default behavior.
- **Safety net:** any model registered later but not yet mapped lands in a
  trailing **"Other / Unsorted"** section instead of vanishing — then just
  add its name to `SECTIONS`.
- The custom `templates/admin/index.html` dashboard iterates `app_list`
  generically — each section renders as its own module table, zero template
  changes.

## Also in this release

- **LogEntry admin registration was dead code.** The `@admin.register(LogEntry)`
  block in admin.py sat inside a triple-quoted string, and its field names
  (`action`, `date`, `reason`) don't exist on Django's LogEntry — so the
  built-in admin action log has never been viewable. Registered for real:
  read-only, correct fields (`action_time`/`user`/`content_type`/
  `object_repr`/`action_flag`), CSV export, in the "Audit & Activity" section.
- **Vendor provenance closed out:** chart.min.js, cropper.min.js, and
  cropper.min.css hash-compared against the official npm releases
  (`chart.js@3.9.1`, `cropperjs@1.6.1`) — **all three byte-identical**.
  `.integrity.json` notes updated from "presumed" to VERIFIED, sources
  pinned to the npm package paths.

## Preflight pip-audit follow-up: `pillow` pinned (undeclared direct dep)

Mason's first real `preflight` run failed only on the pip-audit check (72
findings, 13 packages). Triage: **zero were pinned Parliament deps** —
8 packages were genuine but *unpinned transitive* deps sitting stale in the
installed env (aiohttp←pywebpush, msgpack←channels-redis, urllib3/idna←
requests, click←celery, pyasn1←webauthn, pygments, pillow), and 3 (nltk,
authlib, ujson) aren't in Parliament's dependency tree at all — that env has
non-Parliament packages in it. A fresh `pip install -r requirements.txt`
resolves every flagged transitive at/above its fixed version (verified in
sandbox: full 90-package resolved tree audits clean).

Real repo bug exposed: **pillow was an undeclared DIRECT dependency** — four
ImageFields (profile_picture, landing photos, og_image, security screenshot)
require it, but it was only ever installed as reportlab's transitive dep.
Now pinned `pillow==12.3.0` in requirements.txt (covers all 27 pillow
PYSECs in the audit output). `pip-audit -r requirements.txt` re-verified
clean after the pin.

**Remediation for the flagged environment:** `pip install -r
requirements.txt` then `pip install -U aiohttp msgpack urllib3 idna click
pyasn1 pygments` (or cleanest: rebuild the venv from requirements.txt).
nltk/authlib/ujson: upgrade or remove — they're not Parliament's.
