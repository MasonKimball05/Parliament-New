# v3.16.1 — Django admin feature-area sections

Mason-directed 07-24-26, follow-up to the v3.16.0 full-coverage pass: 125
models in one alphabetical block made the index/sidebar unusable. No
migration, no static changes — code-only + restart.

## What changed

- **New `src/admin_sections.py`** — ordered `SECTIONS` mapping (22 sections,
  most-used first: Members & Roles, Voting & Legislation, Committees,
  Slating & Elections, Events, Service Hours, Recruitment, Pledge Education,
  Kai, CNB, Documents & Minutes, Announcements & Polls, Notifications, Chat,
  Security ×2, Audit & Activity, API, Landing Page, Guide, Songs, Site
  Config) + `build_sectioned_app_list()`, which re-buckets the standard
  permission-filtered app_list into pseudo-apps. Model dicts pass through
  untouched, so admin_url/add_url/perms keep working; alphabetical within
  each section.
- **`ParliamentAdminSite.get_app_list()` override** (admin.py) — applies the
  grouping to the index and the nav sidebar (both use `get_app_list`).
  Single-app views (`/admin/src/`) keep default behavior.
- **Safety net:** any model registered later but not yet mapped lands in a
  trailing **"Other / Unsorted"** section instead of vanishing — then just
  add its name to `SECTIONS`.
- The custom `templates/admin/index.html` dashboard iterates `app_list`
  generically — each section renders as its own module table, zero template
  changes.

## Verification (sandbox)

- `py_compile` clean ×2.
- Mapping audited against the registered set: **125/125 mapped, 0
  duplicates, 0 typos** (names mapped but not registered), 0 unmapped.
- Functional test of `build_sectioned_app_list()` with a synthetic
  app_list: 22 sections out, 125 models in/out (no loss), correct order,
  no Other section when fully mapped, and an unknown model correctly falls
  into Other / Unsorted.
- Real rendering check happens at next local `runserver` — load `/admin/`
  and eyeball the sections + sidebar.
